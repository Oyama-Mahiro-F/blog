**CPU（Central Processing Unit，中央处理器）**由**运算器**和**控制器**两大部件组成，是程序的最终执行者：既负责**数据加工**（算术/逻辑运算），又负责**指挥全机**（取指令、译码、按时序产生微操作控制信号、协调各部件）。408 对本部分的考查集中在：**CPU 的功能与基本结构（寄存器辨析）、指令周期与各周期数据流、数据通路（单总线微操作序列推演）、硬布线控制器与微程序控制器**。

## CPU 的功能与基本结构

### CPU 的五大功能

| 功能 | 说明 |
|:---|:---|
| **指令控制** | 控制**程序按规定顺序**执行：取指 → 分析 → 执行，遇转移指令改变执行顺序 |
| **操作控制** | 对每条指令逐条产生相应的**微操作控制信号**，送往对应部件 |
| **时间控制** | 各控制信号在**规定时刻**发出，各项操作严格按时序（节拍）配合 |
| **数据加工** | 对数据进行**算术运算和逻辑运算**（ALU 的核心职责） |
| **中断处理** | 处理运算中的**异常**与外设发来的**中断请求** |

### CPU 的基本组成

CPU 内部 = **运算器 + 控制器 + 寄存器组 + 内部总线**：

![CPU 内部结构](/blog/images/计组第5章 中央处理器.assets/cpu-structure.jpg)

| 部件 | 主要组成 | 功能 |
|:---|:---|:---|
| **运算器** | ALU、暂存器、ACC、通用寄存器组、PSW | 执行算术/逻辑运算，暂存操作数与运算结果 |
| **控制器** | PC、IR、指令译码器 ID、时序产生器、微操作信号发生器（CU） | 取指令、译码、产生控制信号、控制执行顺序 |
| **寄存器组** | 通用寄存器 + 专用寄存器（PC/IR/MAR/MDR/PSW） | 暂存指令、数据、地址与状态信息 |
| **内部总线** | 单总线 / 多总线 | CPU 内部各部件之间的数据传输通路 |

### 寄存器一览与"透明"概念

| 寄存器 | 全称 | 作用 | 位数 | 用户是否可见 |
|:---|:---|:---|:---|:---:|
| **PC** | 程序计数器 | 存放**下一条指令**的地址；可自动 +1，也可接收转移地址 | 与**主存地址位数**一致 | 可见 |
| **IR** | 指令寄存器 | 存放**当前正在执行**的指令 | 与**指令字长**一致 | **透明** |
| **PSW** | 程序状态字 | 保存 OF/SF/ZF/CF 等运算标志 | 与标志位有关 | 可见 |
| **ACC** | 累加器 | 暂存 ALU 的操作数或运算结果 | 机器字长 | 可见 |
| **MAR** | 存储器地址寄存器 | 存放**要访问的主存单元地址** | 与**主存地址位数**一致 | **透明** |
| **MDR** | 存储器数据寄存器 | 存放与主存交换的**指令或数据** | 与**存储字长**一致 | **透明** |
| R0&#126;Rn | 通用寄存器组 | 存放操作数、地址、中间结果 | 机器字长 | 可见 |

> **考点**：对程序员**可见**——通用寄存器、PC、PSW；**透明（不可见）**——MAR、MDR、IR（Cache、微程序结构也对用户透明）。汇编程序员能用转移指令"感知"并改变 PC，却无法直接读写 IR/MAR/MDR。
> **易错点**：MAR、MDR 按教材口径（唐朔飞）属于 **CPU 内部的用户透明寄存器**（也有教材把它们划归主存一侧，答题以题目给的口径为准，408 默认归 CPU）。"PC 自动 +1"中的 1 指**一条指令的长度**——变长指令系统下增量是本条指令的字节数，不一定是 1。

## 指令执行过程

### 三级周期

| 层级 | 定义 | 关系 |
|:---|:---|:---|
| **指令周期** | CPU **取出并执行完一条指令**所需的全部时间 | 含若干机器周期（不同指令的机器周期数可不同） |
| **机器周期**（CPU 周期） | 完成一个**基本操作**的时间，常以**一次主存访问（存取周期）**为基准 | 含若干时钟周期 |
| **时钟周期**（节拍） | 主频的倒数 $T = 1/f$，**微操作的最小时间单位** | 一个机器周期含若干节拍（T0、T1……） |

即**指令周期 ⊇ 机器周期 ⊇ 时钟周期**。例如 3 GHz 主频的时钟周期约为 $0.33\,\mathrm{ns}$；若一个机器周期含 4 个节拍、一条指令需 2 个机器周期，则指令周期为 $8T$。

### 四个子周期与数据流

指令周期通常划分为**取指、间址、执行、中断**四种机器周期的组合：

- **取指周期**：每条指令必有，完成"取指令 + PC+1 + 译码"，是所有指令的**公操作**；
- **间址周期**：仅当采用（存储器）间接寻址时才有，取出的是**有效地址 EA** 而非操作数；
- **执行周期**：完成指令规定的运算、访存或转移操作；
- **中断周期**：在**一条指令执行完毕后、下一条指令取指之前**检测到中断请求时插入——不是每条指令都有。

| 周期 | 节拍 | 数据流 | 说明 |
|:---|:---:|:---|:---|
| 取指 | T0 | (PC) → MAR，1 → R | 指令地址送主存，CU 发读命令 |
| 取指 | T1 | M(MAR) → MDR，(PC) + 1 → PC | 指令从主存读出；**PC+1 与访存并行** |
| 取指 | T2 | (MDR) → IR，OP(IR) → CU | 指令进 IR，操作码送 CU 译码 |
| 间址 | T0 | Ad(IR) → MAR，1 → R | 形式地址送 MAR |
| 间址 | T1 | M(MAR) → MDR | 从主存取出**有效地址 EA** |
| 间址 | T2 | (MDR) → Ad(IR)（或 → MAR） | EA 存回地址字段，供执行期直接访存 |
| 中断 | T0 | (SP) − 1 → SP，(SP) → MAR，1 → W | 栈指针减 1 指向新栈顶，发写命令 |
| 中断 | T1 | (PC) → MDR | **断点（PC 的内容）**送 MDR |
| 中断 | T2 | (MDR) → M(MAR)，中断向量 → PC | 断点压栈，转向中断服务程序 |

（断点也可存入固定单元（如 0 号地址），硬件更简单；**压栈方式支持多重中断嵌套**，是现代主流。中断周期还隐含**关中断、保存 PSW** 等操作。）

> **考点**：间址周期取的是**有效地址**、中断周期存的是**断点（PC）**——两条一句话就能拿分的结论。取指周期三拍是**公操作**，所有指令都执行。
> **易错点**：中断周期写入主存的是 **PC 的值（下一条指令地址）**，不是 IR 的内容；间址周期最后一步有的教材写 (MDR) → MAR，含义相同——EA 直达 MAR，执行期即可直接取操作数。

### 典型指令的周期差异

| 指令类型 | 需要间址周期 | 访存次数 | 机器周期数 |
|:---|:---:|:---:|:---|
| MOV R0, R1（寄存器 → 寄存器） | 无 | 1（仅取指） | 2 |
| LAD ACC, A（直接寻址取数） | 无 | 2 | 2 |
| LAD ACC, @A（存储器间接取数） | **有** | 3 | 3 |
| STO A, ACC（写主存） | 无 | 2 | 2 |
| JMP A（无条件转移） | 无 | 1 | 2 |

## 数据通路的功能和基本结构

### 数据通路与两类元件

**数据通路（Datapath）**：数据在指令执行过程中流经的**路径及其上的全部部件**（ALU、通用寄存器、状态寄存器、中断逻辑等）。控制部件（CU）按指令功能产生控制信号，决定数据"从哪里来、经过哪些部件、到哪里去"——数据通路的结构直接决定 CPU 性能。

| 类别 | 代表元件 | 特点 |
|:---|:---|:---|
| **组合逻辑元件**（操作元件） | ALU、译码器、MUX、三态门 | 输出只取决于**当前输入**，无记忆、不受时钟控制 |
| **时序逻辑元件**（状态元件） | 通用寄存器、PC、PSW、Cache/主存 | 含**存储单元**，必须在时钟节拍下工作 |

### 内部总线与三种通路结构

- **内部总线**：CPU 内部各寄存器与 ALU 之间的连线（本节数据通路的讨论对象）；
- **系统总线**：CPU、主存与外设之间的连线（地址/数据/控制总线）——两者不可混淆。

| 结构 | 说明 | 性能 |
|:---|:---|:---|
| **单总线** | 全部部件共享一条内部总线、**分时使用**：同一时刻**只允许一个部件向总线发送**，可同时有多个部件接收 | 结构简单、成本低；并行度低，一次加法需多个节拍 |
| **三总线** | 两条总线分别向 ALU 送两个操作数，第三条回传结果 | **一个时钟周期**即可完成加法 |
| **专用通路** | 部件间用独立连线，多路传输可**同时并行** | 硬件开销大；现代高性能 CPU 与流水线采用 |

```text
   +----+  +----+  +-----+  +-----+  +-----+  +--------+
   | PC |  | IR |  | MAR |  | MDR |  | ACC |  | R0..Rn |
   +--+-+  +--+-+  +--+--+  +--+--+  +--+--+  +---+----+
      |       |        |        |        |         |
  ====+=======+========+========+========+=========+=====  internal bus
      |          (Rout / Rin: tri-state gate + clock edge)
   +--+---+                               +----+----+
   |  Y   | ----->  ALU  -------------->  |    Z    |
   +------+                               +---------+
```

> **考点**：ALU 是**组合逻辑元件、没有存储功能**，做加法时两个输入必须**同时有效**——单总线下第一个操作数要先锁入暂存器 **Y**；ALU 的输出也**不能直接连到总线上**（否则输出经总线反馈回 ALU 输入端形成**振荡**），必须先存入暂存器 **Z**，下一拍再写回目标寄存器。

### 微操作序列例题：单总线执行 ADD (R0), R1

**指令功能约定**：`ADD (R0), R1` 表示 **((R0)) + (R1) → R1**——R0 的内容是主存操作数的地址（**寄存器间接寻址**），运算结果存回 R1。数据通路为单总线 + 暂存器 Y、Z。

因为 (R0) 属于寄存器间接（地址已现成放在 R0 中），**不需要独立的间址周期**，取操作数并入执行周期；若操作数采用存储器间接 Ad(IR)，则应在取指与执行之间插入独立的间址周期。

| 阶段 | 节拍 | 微操作 | 有效控制信号 |
|:---|:---:|:---|:---|
| 取指 | T0 | (PC) → MAR | PCout、MARin |
| 取指 | T0 | 1 → R | 读命令（与上行相容，可并行发出） |
| 取指 | T1 | M(MAR) → MDR | MDRinE（E 表示从系统数据线接收） |
| 取指 | T1 | (PC) + 1 → PC | PC 自增（与访存并行） |
| 取指 | T2 | (MDR) → IR | MDRout、IRin |
| 执行 | T0 | (R0) → MAR | R0out、MARin |
| 执行 | T1 | 1 → R；M(MAR) → MDR | 读命令、MDRinE |
| 执行 | T2 | (MDR) → Y | MDRout、Yin |
| 执行 | T3 | (R1) + (Y) → Z | R1out、ALU 做加法、Zin |
| 执行 | T4 | (Z) → R1 | Zout、R1in |

**推演说明**：

- 每个节拍发出的微命令必须**相容**（一个部件发送、另一部件接收）；同一拍绝不能出现两个输出使能（相斥）——单总线同一时刻只容纳一个发送者。
- 取指 3 拍是所有指令的公操作；执行期 T2、T3 之所以分开，是因为 MDR 中的操作数要**先**锁进 Y，R1 的内容才能与它一起进入 ALU。
- 若去掉 Z 直接写"ALU → R1"，则 ALU 输出占用总线的同时仍在运算，反馈路径会造成错误——这正是 Z 暂存器存在的意义。

> **考点**：写微操作序列三步法——**拆功能**（公操作取指 + 按寻址方式取数 + 运算写回）→ **一拍只安排一个总线事务** → **成对标控制信号**（`xout` + `yin`）。
> **易错点**：控制信号命名惯例 `Rout`（寄存器 → 总线）、`Rin`（总线 → 寄存器）；访存微操作（M(MAR) → MDR）受主存速度限制，不能与后续的总线传送挤在同一节拍。

## 控制器的功能和工作原理

控制器（CU）的**输入**：操作码译码信号、时序信号（机器周期电位 + 节拍 + 时钟脉冲）、PSW 状态标志、中断请求等；**输出**：两类微操作控制信号——送 CPU **内部**（寄存器传送、ALU 操作）与送 CPU **外部**（访存读写、I/O）。产生这些控制信号的方式就是控制器的两种形态：**硬布线**与**微程序**。

### 硬布线控制器

**基本思想**：把每条指令在每个节拍应发出的控制信号写成**布尔表达式**，用**组合逻辑门电路**直接产生——输入（操作码、时序、状态）一旦确定，输出即确定，因此又称**组合逻辑控制器**。

![硬布线控制器结构方框图](/blog/images/计组第5章 中央处理器.assets/hardwired-controller.jpg)

**与时钟的配合**：时序产生器输出机器周期电位（M1、M2……）与节拍电位（T0&#126;T3），每个控制信号在"**哪个机器周期 + 哪个节拍**"有效由操作时间表规定，寄存器在**时钟脉冲**边沿把总线上的数据打入——节拍电位保证操作"先后有序"，时钟脉冲保证"打入无误"。

**设计三步**：

| 步骤 | 工作内容 |
|:---|:---|
| ① 列**操作时间表** | 列出每条指令在各机器周期、各节拍下应发的微操作控制信号（取指周期为公操作，所有指令共用） |
| ② **微操作信号综合** | 把同一控制信号在不同指令/节拍下的所有出现情形**求或**，写出逻辑表达式并化简 |
| ③ 画**逻辑图** | 用门电路实现每个控制信号的逻辑表达式 |

$$\mathrm{C} = \mathrm{M} \wedge \mathrm{T} \wedge \mathrm{P} \wedge \mathrm{OP} \wedge \mathrm{State}$$

其中 M 为机器周期电位、T 为节拍电位、P 为时钟脉冲、OP 为操作码译码信号、State 为状态标志（仅条件转移类指令用到）。

**例**（设 M1 为取指周期电位、M2 为执行周期电位，各助记符为指令译码输出）：

- 取指读主存（所有指令共用）：$\mathrm{RD} = M_1$
- 打入 IR：$\mathrm{LDIR} = M_1 \cdot T_2$
- 打入 PC：$\mathrm{LDPC} = M_1 T_2 + M_2 T_4 \cdot \mathrm{JMP}$（取指期 PC+1 打入；执行期 JMP 装入转移地址）
- 打入地址寄存器：$\mathrm{LDAR} = M_2 \cdot T_4 \cdot (\mathrm{LAD} + \mathrm{STO})$

> **考点**：同一控制信号的逻辑表达式是**若干"机器周期 × 节拍 × 操作码"项的或**——这正是"微操作信号综合"的标准考法；取指周期的信号与操作码无关，可直接归并。
> **易错点**：硬布线**速度快**（仅一两级门延迟）但**设计与修改困难**——指令系统一变就要重新布线，故只适合指令**少而规整**的 RISC。

### 微命令、微指令与微程序（概念层级）

| 概念 | 定义 | 关系 |
|:---|:---|:---|
| **微命令** | 控制部件发出的**最小**（不可再分）控制信号，如 PCout、"ALU 加法" | **微命令是"因"，微操作是"果"** |
| **微操作** | 执行部件收到微命令后完成的**基本操作**，如 PC → MAR（需 PCout 与 MARin 同时有效） | 一个微操作可由多个微命令共同驱动 |
| **微指令** | **同一节拍**内发出的**一组相容微命令**的集合 = **操作控制字段 + 顺序控制字段** | 一条微指令对应一个节拍，**微指令周期 = 1 个时钟周期** |
| **微程序** | 实现一条**机器指令**功能的**微指令序列** | **1 条机器指令 = 1 段微程序 = n 条微指令（n ≥ 1）** |

```text
  PCout + MARin             micro-commands issued in one beat
           v
  micro-instruction = control field + next-address field  (1 clock cycle)
           v  (sequenced by)
  micro-program  ==  1 machine instruction (fetched from main memory)
```

**相容与相斥**：**相容**微命令控制不同资源、可同时有效（如 PCout 与 MARin），可放进同一条微指令并行发出；**相斥**微命令争用同一资源、不能同时有效（如 PCout 与 MDRout、ALU 加与减、1 → R 与 1 → W）。**互斥微命令编入同一字段**——这是下面"字段编码"划分字段的根本依据。

### 微程序控制器的组成与执行流程

![微程序控制器原理框图](/blog/images/计组第5章 中央处理器.assets/microprogram-controller.png)

| 部件 | 作用 |
|:---|:---|
| **控制存储器 CM** | 用 **ROM** 实现，固化**全部机器指令对应的微程序**，对用户透明 |
| **CMAR（μAR）** | 微地址寄存器：存放**即将读出**的微指令在 CM 中的地址 |
| **CMDR（μIR）** | 微指令寄存器：存放**刚从 CM 读出**的微指令（操作控制字段 + P 字段/下址字段） |
| **地址转移逻辑** | 根据操作码、状态标志与 P 字段，生成**下一条**微指令的地址并写入 CMAR |

**执行流程**：

1. 执行**取指公操作**对应的微程序，把机器指令取入 IR；
2. **操作码映射**：OP(IR) 经映射逻辑（如操作码后拼接若干 0）变换为该指令微程序的**入口微地址**，装入 CMAR；
3. 按 CMAR 访问 CM，读出微指令存入 CMDR，其**操作控制字段**发出微命令驱动数据通路；
4. 同时 P 字段与状态标志经**地址转移逻辑**形成下一条微地址（顺序 +1 或按条件转移）；
5. 循环第 3、4 步，直到遇到"返回取指"的微指令——一条机器指令执行完毕。

> **考点**：1 个**机器周期包含多条微指令**（微指令周期 = 时钟周期）；CM 必须用 **ROM**（断电不丢失、出厂固化）；**操作码映射**只在每条机器指令开头发生一次，用于定位微程序入口。
> **易错点**：微程序控制器**每个节拍都要先访问 CM 取微指令**才能发出控制信号，因此比硬布线多一个 ROM 访问延迟；微指令、微程序对汇编程序员**完全透明**。

### 微指令的编码方式

| 编码方式 | 原理 | 速度与字长 |
|:---|:---|:---|
| **直接编码** | 控制字段**每一位**对应一个微命令（1 发出 / 0 不发出），**不需要译码** | 速度最快、并行能力最强；**字长 = 微命令总数**，微指令最长 |
| **字段直接编码** | 把**互斥**微命令编入同一字段，各字段经**译码器**译出微命令，字段之间仍可并行 | n 位字段最多表示 $2^n - 1$ 个互斥微命令——**全 0 保留为"不发出任何命令"**；字长大幅缩短，但增加译码延迟 |
| **字段间接编码** | 某字段的含义还须由**另一字段的编码**来解释（二次译码） | 字长进一步压缩；速度更慢、设计更复杂，只少量字段使用 |

**例**：3 位字段按字段直接编码可定义 $2^3 - 1 = 7$ 个互斥微命令（000 表示不发命令）；同样的 7 个命令若用直接编码要占 7 位。

> **易错点**：字段直接编码的 n 位字段能表示 **$2^n - 1$** 个微命令而不是 $2^n$（全 0 编码被"无操作"占用）；字段划分依据是**互斥**（不是相容）——相容命令必须放**不同字段**才能同时发出。
> **考点**：三种编码是"**字长 ↔ 速度**"的权衡：直接编码快而长、字段编码短而稍慢；实际机器常用**混合方式**（部分位直接控制、部分字段编码）。

### 水平型与垂直型微指令

| 维度 | 水平型微指令 | 垂直型微指令 |
|:---|:---|:---|
| 编码思想 | 接近**直接编码**：一位（或短字段）直接对应微命令，不译码或轻译码 | 类似**机器指令**格式：微操作码 + 操作数描述字段，**必须译码** |
| 并行能力 | **强**：一条可同时定义多个微命令 | 弱：一条只完成 1&#126;2 个微操作 |
| 微指令字长 | **长** | **短** |
| 微程序长度 | **短**（微指令条数少） | 长 |
| 执行速度 | **快** | 慢 |
| 编写难度 | 难（需熟悉硬件细节） | 易（与汇编指令相似） |

### 微地址的形成方式

| 方式 | 原理 | 特点 |
|:---|:---|:---|
| **增量计数器法** | 让 CMAR 兼作微地址计数器（μPC）：顺序执行时 **μPC + 1**；需要分支时由**微地址转移逻辑**按 P 字段测试的状态条件，把转移地址改写入 μPC | 与机器指令的 PC 机制类似；顺序执行快、控制逻辑简单 |
| **断定方式** | 下一条微指令地址由**本条微指令的顺序控制字段（下址字段）直接"断定"**，还可与状态标志经多路器组合实现多路分支 | 分支灵活（可多路转移）；微指令更长、下址字段占用位数多 |

**增量计数器法小例**（入口由操作码映射、分支由 P 字段判定）：

```text
CM addr   micro-operation              next micro-address
0000      PC -> MAR, 1 -> R            uPC + 1 = 0001
0001      M(MAR) -> MDR, (PC) + 1      uPC + 1 = 0002
0002      MDR -> IR, P1 tests opcode   opcode map: ADD -> 1000 (load into uPC)
1000      R0 -> MAR, 1 -> R            uPC + 1 = 1001
1001      M(MAR) -> MDR                uPC + 1 = 1002
1002      MDR -> Y                     uPC + 1 = 1003
1003      (R1) + (Y) -> Z, P2 tests ZF   ZF=1: next field 1200 -> uPC
                                       ZF=0: uPC + 1 = 1004
1004      Z -> R1                      back to fetch (micro-program ends)
```

顺序地址靠 μPC 自动 +1，只有 P1/P2 测试点才由**地址转移逻辑**改写 μPC——这就是"增量 + 转移"的分工。

### 硬布线 vs 微程序控制器

| 对比项 | 硬布线控制器 | 微程序控制器 |
|:---|:---|:---|
| 实现方式 | **组合逻辑门电路**（+ 触发器） | **ROM 存微程序**，逐条读出产生控制信号 |
| 速度 | **快**（仅 1&#126;2 级门延迟） | **较慢**（每个节拍都要先访问 CM） |
| 规整性 | 差（门电路庞杂、不规整） | **好**（微指令格式统一，呈存储逻辑） |
| 修改与扩展 | **难**：改一条指令就要重新设计电路 | **易**：修改 CM 中的微程序即可，可灵活增删指令 |
| 设计复杂度 | 高（布尔表达式综合化简繁琐） | 低（"编程"式设计，规整） |
| 硬件成本 | 低（简单机器尤其明显） | 较高（需 CM、CMAR、CMDR 及译码电路） |
| 故障诊断 | 难 | 易（微指令逐条可追踪） |
| 典型应用 | **RISC**（指令少、格式规整、追求速度） | **CISC**（指令复杂多变）；现代 CPU 常两者**混合** |

> **考点**：核心权衡是**速度 vs 规整性/易修改**——RISC 选硬布线、CISC 选微程序；"现代 CPU 混合使用：常用简单指令走硬布线、复杂指令走微程序"是简答题的常用结语。

## 高频考点速记

| 考点 | 记忆 |
|:---|:---|
| CPU 五大功能 | **指令控制、操作控制、时间控制、数据加工、中断处理**——数据加工是唯一"干活"的，其余是"指挥" |
| 寄存器可见性 | 可见：**通用寄存器、PC、PSW**；透明：**MAR、MDR、IR**（Cache、微程序结构也透明） |
| 位数对应 | PC、MAR 与**主存地址位数**一致；IR 与**指令字长**一致；MDR 与**存储字长**一致 |
| PC 的两个动作 | 顺序执行**自动 +1**（增量 = 指令字长）；转移时**接收转移地址**——PC 存的是**下一条**指令地址 |
| 三级周期 | **时钟周期（节拍）⊆ 机器周期（以存取周期为基准）⊆ 指令周期**；$T = 1/f$ |
| 四个子周期 | **取指（必有）+ 间址（间接寻址才有）+ 执行（必有）+ 中断（有请求才插入）**；中断周期插在**本条执行完、下条取指前** |
| 取指数据流 | **PC→MAR，1→R，M(MAR)→MDR，MDR→IR，OP(IR)→CU，PC+1**——公操作，PC+1 与访存并行 |
| 间址 vs 中断 | 间址周期取**有效地址 EA**（Ad(IR)→MAR，M(MAR)→MDR）；中断周期存**断点 PC**（压栈或存 0 号单元）并关中断 |
| 单总线规则 | 同一时刻**只能一个部件发送**、可多个接收；一拍一个总线事务；`xout` 与 `yin` 成对出现 |
| Y/Z 暂存器 | 两个操作数须**同时有效** → 先锁 **Y**；ALU 输出不能直连总线（**反馈振荡**） → 先锁 **Z** |
| 组合 vs 时序元件 | 组合：ALU、译码器、MUX、三态门（无记忆）；时序：寄存器、PC、主存（时钟控制） |
| 微程序层级 | **微命令（最小控制信号）→ 微指令（一个节拍 = 控制字段 + 顺序字段）→ 微程序（对应一条机器指令）**；1 微指令周期 = 1 时钟周期 |
| 微程序控制器 | **CM 用 ROM** 固化微程序 + **CMAR（微地址）+ CMDR（微指令）**；入口由**操作码映射**定位；全部对用户透明 |
| 编码方式 | 直接编码（1 位 1 命令，快而长）；字段直接编码（互斥同段，n 位表 $2^n-1$ 个，全 0 = 无操作）；字段间接编码（二次译码，最短最慢） |
| 水平 vs 垂直 | 水平型：并行强、字长、条数少、**快**；垂直型：短、需译码、一次 1&#126;2 个微操作、易掌握 |
| 微地址形成 | **增量计数器法**（μPC+1，转移由地址转移逻辑改写）+ **断定方式**（下址字段直接给出）；总口径：硬布线快难改（RISC）、微程序慢易改（CISC） |
