**文件管理**是操作系统对**信息资源**的管理：把磁盘这块"一维的原始空间"组织成用户眼中"按名存取的文件树"。408 对本章考查密度极高：**文件的逻辑/物理结构、FCB 与索引结点 inode、打开文件表、UNIX 混合索引计算、位示图换算、硬链接与软链接、成组链接法、VFS 与挂载**都是高频命题点，其中**混合索引**与**位示图**两类计算题几乎年年出现。

## 文件的基本概念

**文件（File）**：以计算机**外存**为载体、以**文件名**为标识的一组相关信息的集合，是操作系统**信息管理的最小单位**。文件由**文件名 + 文件属性 + 文件内容**构成：用户按名存取，系统按属性管理。

### 文件的属性

| 属性 | 说明 |
|:---|:---|
| **名称** | 用户可见的**符号名**（可重名、可修改） |
| **类型** | 普通文件、目录文件、设备文件等 |
| **位置** | 数据在外存上的**物理地址**（记录在 FCB 中） |
| **大小** | 文件长度（字节数或块数） |
| **保护** | 访问控制信息（谁可读/写/执行） |
| **时间与用户标识** | 创建、最近访问、最近修改时间，创建者 |
| **标识符** | 系统**内部唯一编号**（如 inode 号），对用户透明 |

> **考点**：文件名是给**用户**用的符号名；系统定位文件最终靠**标识符（inode 号）**，二者通过目录建立映射。

### 文件系统的三个层次

自顶向下一句话：**用户接口**（提供 open/read/write 等系统调用）→ **文件目录系统**（按名检索目录，完成"文件名 → inode/FCB"映射）→ **文件实现层**（把逻辑块地址换算成物理块地址，管理磁盘空间与缓冲）。注意：**逻辑结构与物理结构相互独立**——逻辑结构解决"用户怎么看文件"，物理结构解决"文件怎么落盘"。

## 文件控制块 FCB 与索引结点 inode

### 文件控制块 FCB

**文件控制块（FCB, File Control Block）**：存放文件全部管理信息的数据结构，是**文件存在的标志**；**目录项 = FCB**——目录文件的内容就是一个个 FCB。

| 类别 | 内容 |
|:---|:---|
| **基本信息** | 文件名、类型、大小、**逻辑结构、物理结构** |
| **位置信息** | 数据块指针（起始块号 / 索引块地址等） |
| **访问控制信息** | 文件属主、访问权限 |
| **使用信息** | 打开计数、创建/修改时间 |

### 索引结点 inode：目录检索提速的关键

检索目录的本质是**逐个比较目录项中的文件名**：FCB 越大，一块磁盘能放的目录项越少，按名查找要读的盘块就越多。于是把 FCB 中**除文件名外的全部信息**抽出来放进**索引结点（inode, index node）**，目录项瘦身为"**文件名 + inode 号**"。

**瘦身的收益（完整演算）**：FCB 为 64B，盘块大小 1KB，目录共 640 项。

- 不引入 inode：每块放 $1KB \div 64B = 16$ 项，640 项占 $640 \div 16 = 40$ 块；目标等概率出现在任意位置，平均读 $40 \div 2 = 20$ 次磁盘
- 引入 inode：目录项 = 14B 文件名 + 2B inode 号 = 16B，每块放 $1KB \div 16B = 64$ 项，占 $640 \div 64 = 10$ 块，平均读 $10 \div 2 = 5$ 次磁盘
- 目录盘块数与平均访盘次数都降为原来的 **1/4**

> **考点**：inode 的收益 = **目录变小 → 检索目录的磁盘 I/O 次数成比例下降**；目录小了也更容易常驻内存/缓存，进一步加速按名检索。

### 磁盘 inode 与内存 inode

| 对比项 | 磁盘 inode | 内存 inode |
|:---|:---|:---|
| 存放位置 | 磁盘上的 inode 区 | 文件被**打开**时复制进内存 |
| 内容 | 文件类型、权限、物理地址、长度、**链接计数** | 磁盘 inode 全部内容 + **打开标志、引用计数、锁标志、是否被修改** |
| 作用 | 持久保存元数据 | 支持多进程并发打开、加快访问 |

> **易错点**：内存 inode **不是磁盘 inode 的简单副本**——它多出"打开计数、锁标志、修改标志"等动态信息；文件是否写回磁盘由修改标志决定。

## 文件的操作与打开文件表

### 文件的基本操作

| 操作 | 系统做的事 |
|:---|:---|
| **create** | 分配 FCB 并在目录中登记目录项 + 分配外存空间 |
| **delete** | 删除目录项 + 回收外存盘块 |
| **read / write** | 按物理结构在内存与外存间搬运数据（配合读写指针） |
| **truncate** | **长度置 0、保留属性**（FCB 与目录项不动，空间重新分配） |
| **seek** | 调整读写指针位置，为读写定位 |

> **易错点**：截断 ≠ 删除——删除连"外壳"（FCB/目录项）一起删掉，截断只清空内容、保留属性。

### open 的本质（高频）

`open("file")` 做两件事：

1. **检索目录**：按路径逐级找到目录文件，比对文件名找到目录项，**并检查该用户的访问权限**；
2. **复制登记**：把该文件的 FCB（inode）**复制到内存中的打开文件表**，并把表项编号——**文件描述符 fd** 返回给用户。

此后 `read(fd)/write(fd)` **只凭 fd 定位打开文件表项，不再按名检索目录**——这就是"打开之后访问更快"的原因：一次按名检索的代价被摊销到后续所有读写上。**close** 则反向收尾：删进程级表项 → 回收资源 → 系统表打开计数 **count 减 1**，**count = 0 时才删除系统级表项**（文件被修改过则先写回磁盘）。

### 两级打开文件表

| 表 | 范围 | 内容 | 作用 |
|:---|:---|:---|:---|
| **系统级打开文件表** | 全系统一张 | FCB 副本、**打开计数 count**、读写位置 | 多进程共享同一打开文件 |
| **进程级打开文件表** | 每个进程一张 | **fd → 系统表项的索引**、打开方式、各自读写指针 | 各进程独立定位与权限 |

![文件系统在内存中的结构：fd、进程打开文件表与系统打开文件表](/blog/images/OS第4章 文件管理.assets/open-file-table.png)

> **考点**：open = 检索目录（含权限检查）+ FCB 复制进打开文件表 + 返回 fd；之后 read/write 凭 fd 直接定位，**不再检索目录**。
> **易错点**：fd 是**进程级表项的下标**，不是磁盘地址；不同进程打开同一文件的 fd 可以不同，但最终指向**同一系统级表项**；其他进程仍打开该文件（count > 0）时，系统级表项与磁盘 FCB 均不动。

## 文件的保护

目标是防止**未经授权的访问与破坏**，限制"谁能对文件做什么操作"，三种手段对比如下：

| 方法 | 原理 | 优点 | 缺点 |
|:---|:---|:---|:---|
| **口令保护** | 访问前验证口令（口令存 FCB 或专门文件） | 实现简单、开销小 | **口令易泄露**，安全性最差 |
| **加密保护** | 文件**内容加密**存储，凭密钥解密 | 文件被窃也读不出（护内容） | **加解密开销大** |
| **访问控制 ACL** | 每个文件一张表，列出**各用户及其允许的操作** | **最灵活精确**，可按用户授权 | 表项多时开销大 |

**精简 ACL（UNIX 9 位权限）**：把用户归为**属主（Owner）/ 组（Group）/ 其他（Others）**三类，每类用 **rwx** 三位表示读/写/执行，共 9 位（如 `rwxr-x---`）。

> **考点**：ACL 以**文件**为中心（"这个文件谁能访问"），**收回权限容易**（删掉该用户的表项即可）；与之相对的**能力表**以**用户**为中心（列出该用户能访问哪些文件），收回权限困难。访问类型不止 rwx，还有**添加、删除、列表清单**等。

## 文件的逻辑结构

逻辑结构是**用户视角**的文件组织形式，与物理存储无关。先分两大类：

- **无结构文件（流式文件）**：字节流序列，无记录概念（.txt、可执行文件）；UNIX 把所有文件都看作字节流
- **有结构文件（记录式文件）**：由记录组成，分为顺序文件、索引文件、索引顺序文件三种

### 顺序文件

记录按顺序排列。**定长记录可随机存取**：第 i 条记录的地址 = 起始地址 + $i \times$ 记录长度；**变长记录只能顺序存取**——不知道第 i 条从哪开始，只能从头逐条累加长度。

### 索引文件

为**每条记录**建一个索引项（键值 → 记录指针），**索引表本身定长、按关键字有序**，可对索引表做二分查找；从而解决了**变长记录的随机访问与快速检索**问题，代价是索引表占用额外空间。适合变长记录且按键快速存取的场合（如数据库文件）。

### 索引顺序文件

记录**分组**，**每组只留一个索引项**（组内顺序查找）。检索代价从 $\frac{n}{2}$ 量级降到 $\sqrt{n}$ 量级：

- 10000 条记录不分组：顺序查找平均 $5000 = \frac{10000}{2}$ 次
- 分成 $\sqrt{10000} = 100$ 组、每组 100 条：先查索引（平均 50 次）定位组，再组内平均查 50 次，共约 **100 次 = $\sqrt{n}$**

> **考点**：索引顺序文件取**分组数 = $\sqrt{n}$、每组 $\sqrt{n}$ 条**时检索代价最优，约为两次 $\frac{\sqrt{n}}{2}$ 相加 ≈ $\sqrt{n}$；分组多了索引变长、分组少了组内变长，都是次优。

### 三种有结构逻辑结构对比

| 对比项 | 顺序文件 | 索引文件 | 索引顺序文件 |
|:---|:---|:---|:---|
| 索引粒度 | 无索引 | **每条记录一个索引项** | **每组一个索引项** |
| 随机存取 | **定长可以、变长不行** | 可以（查索引表） | 先查索引定组、再组内顺序 |
| 检索代价 | 定长 O(1)，变长约 n/2 | O(log₂n)（索引有序） | ≈ **√n** |
| 额外空间 | 无 | 索引表较大 | 索引表小 |
| 适用场合 | 成批顺序处理 | 变长记录、按键检索 | 记录多且按序使用的大型文件 |

## 文件的物理结构（重点）

物理结构 = 文件在盘块上的**分配方式**，决定"逻辑块号 → 物理块号"的映射速度与空间开销。

### 连续分配

FCB 记**起始块号 + 文件长度**，物理块号 = 起始块号 + 逻辑块号，**一步寻址**，顺序存取、随机存取都快。缺点：产生**外部碎片**（需紧凑搬移，代价大）、**文件难以扩展**（文件尾部空间可能已被占用）。

### 链接分配

- **隐式链接**：每个盘块末尾藏**下一块的指针**，FCB 记**首块号（+末块号）**；只能**顺序存取**，某块损坏则**断链**、其后内容丢失，指针还占块内空间
- **显式链接（FAT）**：把所有指针集中搬进**文件分配表（FAT, File Allocation Table）**，FCB 只记首块号；**开机后 FAT 读入内存常驻**，查表在内存进行，**支持随机访问**，代价是 FAT 占内存大（U 盘的 FAT32 即此结构）

**FAT 占用空间小例**：磁盘共 $2^{20}$ 块、块大小 1KB（盘容量 1GB），每表项 4B → FAT 占 $2^{20} \times 4B = 4MB$ **内存**。

### 索引分配

为每个文件建一个**索引块**（数据块号数组），FCB 记**索引块地址**。单级索引访问一个数据块 = 读索引块 + 读数据块 = **2 次读盘**；两级索引 = 3 次，**每多一级 +1 次**。无外部碎片、扩展容易，但小文件也要付"多读索引块"的代价——于是引出混合索引。

### 物理结构四方式大对比（必背）

| 对比项 | 连续分配 | 隐式链接 | 显式链接（FAT） | 索引分配 |
|:---|:---|:---|:---|:---|
| 访问第 i 块读盘次数 | **1**（直接算出） | **i + 1**（沿链逐块走） | **1**（FAT 在内存查 i 次） | 单级 **2**，k 级 **k + 1** |
| 随机存取 | **支持** | **不支持**（只能顺序） | 支持（查内存 FAT） | **支持** |
| FCB/目录项内容 | 起始块号 + 长度 | 首块号 + 末块号 | 首块号 | **索引块地址** |
| 外部碎片 | **有** | 无 | 无 | 无 |
| 文件扩展 | **困难** | 容易 | 容易 | 容易 |
| 主要缺点 | 碎片 + 难扩展 | 只能顺序、断链 | FAT 常驻内存、占空间 | 索引块占空间、小文件不划算 |
| 典型应用 | 早期系统 | — | U 盘 FAT32 | UNIX（混合索引） |

> **考点**：FAT 显式链接能"随机访问"的前提是 **FAT 常驻内存**——沿链查表不读盘，所以访问第 i 块仍只需 **1 次读盘**。
> **易错点**：隐式链接访问第 i 块需 **i + 1 次读盘**（读出第 j 块才知道第 j+1 块在哪）；索引分配读第 i 块的次数与 i **无关**。

### UNIX 混合索引（必考计算）

UNIX 的 inode 中设 **10 个直接地址 + 1 个一次间址 + 1 个二次间址 + 1 个三次间址**：直接地址直接指向数据块；间址指向"装地址的索引块"。

**例题**：块大小 4KB，每个地址 4B。求最大文件长度；并判断偏移 5MB 处的字节位于第几级索引、读它需几次访盘。

**第一步：每个索引块能装多少地址？**

$$4KB \div 4B = 4096 \div 4 = 1024 = 2^{10} \text{ 个地址}$$

**第二步：各级索引覆盖的数据块数与容量**

| 索引级 | 数据块数 | 覆盖容量 | 累计容量 |
|:---|:---|:---|:---|
| 直接地址 × 10 | 10 | $10 \times 4KB = 40KB$ | 40KB |
| 一次间址 × 1 | 1024 | 4MB | 40KB + 4MB |
| 二次间址 × 1 | $1024^2 = 1048576$ | 4GB | 4GB + 4MB + 40KB |
| 三次间址 × 1 | $1024^3 = 1073741824$ | 4TB | **4TB + 4GB + 4MB + 40KB** |

$$最大文件 = (10 + 1024 + 1024^2 + 1024^3) \times 4KB = 4TB + 4GB + 4MB + 40KB \approx 4.004TB$$

**第三步：偏移 5MB 落在哪一级？**

- 逻辑块号 $= \lfloor 5MB \div 4KB \rfloor = \lfloor 5242880 \div 4096 \rfloor = 1280$
- $1280 \geq 10$ → 不在直接地址；$1280 - 10 = 1270 \geq 1024$ → 也不在一次间址
- $1270 - 1024 = 246$ → 在**二次间址**：二次间址块 → 第 0 个一次间址块 → 其第 246 项 → 数据块

**验算**：一次间址末端累计 $40960 + 1024 \times 4096 = 4239360B \approx 4.04MB < 5MB$，而二次间址上限约 4GB ≫ 5MB ✓。读该字节需读盘：二次间址块 + 一次间址块 + 数据块 = **3 次**。

| 偏移示例 | 逻辑块号 | 所在索引级 | 读盘次数 |
|:---|:---|:---|:---|
| 4095 B | 0 | 直接块 0 | 1 |
| 1MB（1048576B） | 256 | 一次间址第 246 项 | 2 |
| 5MB（5242880B） | 1280 | 二次间址（其下第 0 个间址块的第 246 项） | 3 |

> **考点**：混合索引兼顾**小文件快**（直接地址 1 次读盘）与**大文件大**（多级间址扩容）；判断级数的口诀——逻辑块号依次减去 10、1024、1024²，在哪一级**首次减得动（非负）就在哪一级**。
> **易错点**：题目常给变式（如 8 个地址项、块 1KB → 2009 真题答案 66053KB）；**先算每块地址数（块大小 ÷ 地址大小）再逐级累加**，间接级容量 = 该级块数 × 块大小，别忘乘间址块个数。

## 目录管理

### 目录与目录项

**目录本身也是文件**——目录文件的内容是一张**目录项表**（FCB 或"文件名 + inode 号"），故称"**目录 = 特殊文件**"。目录的作用：**按名存取、加快检索、实现文件共享与保护**。

### 树形目录与路径解析

- **绝对路径**：从**根目录 /** 出发的完整路径；**相对路径**：从**当前目录（工作目录）**出发，`..` 表示上一级目录
- 每个进程维护自己的当前目录；用相对路径访问其下的文件时，**不必从根目录逐级查起，减少了目录检索（读盘）时间**
- 树形目录层次清晰、便于分类管理，但**不便于文件共享**（一个文件只有一个父目录位置）→ 在树形上加共享链接构成**无环图目录**解决

> **考点**：从根到目标文件要逐级读多个目录文件；设置当前目录后按相对路径检索，**中间层目录不必再查**——这就是相对路径省时间的原理。目录的实现可用**线性表**（简单、查找慢）或**哈希表**（查找快、需处理冲突）。

### 硬链接与软链接

![硬链接共享同一 inode，软链接存目标路径](/blog/images/OS第4章 文件管理.assets/hard-soft-link.png)

**硬链接（基于索引结点的共享）**：多个目录项指向**同一个 inode**，inode 中维护**引用计数（link count）= 指向它的目录项个数**；删除其中某个名字只把计数 −1，**计数为 0 才真正释放 inode 与数据块**——因此"删除原文件"后其余硬链接依然完好，数据不丢。

**软链接（符号链接）**：一个**独立的新文件**（有自己的新 inode），内容是**目标文件的路径名**；访问它要先读出路径、再按路径检索目标（**多一次目录检索/访盘**）；原文件被删除后它成为**悬空链接**，访问报错。类似 Windows 的快捷方式。

| 对比项 | 硬链接 | 软链接 |
|:---|:---|:---|
| 本质 | 多个目录项 → **同一 inode** | 新 inode，内容存**目标路径** |
| 共享层次 | inode 层（直接共享元数据与数据） | 路径层（间接跳转） |
| 原文件删除后 | **仍有效**（引用计数 −1） | **失效（悬空链接）** |
| 访问开销 | 1 次按名检索 | **2 次**（读链接文件 + 按路径检索目标） |
| 能否跨文件系统 | **不能**（inode 号只在本卷内有效） | **可以**（路径可指向任何卷） |
| 典型例子 | UNIX `ln` 命令 | UNIX `ln -s`、Windows 快捷方式 |

> **考点**：判断"删除后是否失效"看共享的是 **inode 还是路径**；inode 引用计数归零是真正删除的唯一条件。
> **易错点**：硬链接不能对**目录**建立（否则沿链接遍历会成环）、不能跨文件系统；软链接两者皆可，代价是访问慢且可能悬空。

## 文件系统的全局结构

### 外存（磁盘）上的结构

![磁盘分区与 UNIX 文件系统在盘上的布局](/blog/images/OS第4章 文件管理.assets/disk-layout.png)

| 区域 | 内容 |
|:---|:---|
| **MBR 主引导记录** | **磁盘 0 号扇区**：磁盘引导程序 + **分区表**（各分区的起始与结束地址） |
| **分区引导块** | 每个分区开头，负责**启动安装在该分区的操作系统** |
| **超级块 superblock** | 分区的**全部关键参数**：块总数、块大小、空闲块数与指针、空闲 inode 数量等；**系统启动/文件系统首次使用时读入内存** |
| **空闲管理区** | 位示图、成组链接等空闲块管理信息 |
| **inode 区** | 每个文件一个磁盘 inode（FCB 瘦身后的主体） |
| **根目录与数据区** | 根目录文件以及各普通文件的数据块 |

> **易错点**：MBR 在**整块磁盘**的 0 号扇区（全盘只有一个）；引导块与超级块在**分区**内（每个分区各一套）。FAT 文件系统用 FAT 表取代 inode 区，其余布局思想相同。

### 内存中的结构

| 结构 | 作用 |
|:---|:---|
| **安装表（mount table）** | 每个已挂载的文件系统分区一条记录 |
| **目录缓存** | 缓存最近访问的目录信息，加快目录检索 |
| **系统级打开文件表** | 打开文件的 FCB 副本 + 打开计数 |
| **进程级打开文件表** | fd → 系统表项索引、读写指针 |

> **考点**：磁盘四件套 = **MBR（0 号扇区）→ 引导块 → 超级块 → 空闲管理区**（再接 inode 区与数据区）；内存四件套 = **安装表 + 目录缓存 + 系统/进程打开文件表**。

## 外存空闲空间管理（重点）

### 空闲表法

表项 =（**起始盘块号，连续空闲块数**），分配算法与内存**动态分区分配**相同（首次适应/最佳适应等），回收时相邻空闲区**合并**——适合连续分配方式的文件系统。

### 空闲链表法

- **空闲盘块链**：所有空闲盘块逐个串成链（块内存下一块指针），分配/回收以**块**为单位，简单但链长、难一次拿到连续空间
- **空闲盘区链**：把**连续的空闲盘区**串成链（节点含区长度），可一次分配多个连续盘块

### 位示图法（必考计算）

用 **1 个二进制位对应 1 个盘块**（0 = 空闲，1 = 已分配），位示图按**字**组织。**编号口径有两种，做题必须先看清**：

**口径一（字号、位号、块号都从 0 开始，408 主流口径）**，字长 32 位时：

$$字号 = \lfloor i / 32 \rfloor, \qquad 位号 = i \bmod 32, \qquad 反求：i = 字号 \times 32 + 位号$$

**口径二（都从 1 开始编号）**：

$$字号 = \lfloor (i-1)/32 \rfloor + 1, \qquad 位号 = (i-1) \bmod 32 + 1, \qquad 反求：i = (字号-1) \times 32 + 位号$$

**例题**：字长 32 位，求盘块 100 的字号与位号；再由"字 3、位 4"反求块号。

| 口径 | 字号 | 位号 | 反求（字 3、位 4） |
|:---|:---|:---|:---|
| 从 0 编号 | $\lfloor 100/32 \rfloor = 3$ | $100 \bmod 32 = 4$ | $3 \times 32 + 4 = 100$ ✓ |
| 从 1 编号 | $\lfloor 99/32 \rfloor + 1 = 4$ | $99 \bmod 32 + 1 = 4$ | $(3-1) \times 32 + 4 = 68$ |

**验算**（口径一）：字 0 覆盖块 0&#126;31，字 1 覆盖 32&#126;63，字 2 覆盖 64&#126;95，字 3 覆盖 96&#126;127；100 ∈ 96&#126;127 ✓，块内偏移 $100 - 96 = 4$ ✓

> **易错点**：同一盘块在两种口径下**字号差 1**（位号多数情况相同）；"从 1 编号"必须**先减 1 再取整/取模，结果加 1**——直接套 $\lfloor 100/32 \rfloor = 3$ 在口径二下就是错的（应为 4）。

### 成组链接法（UNIX）

空闲盘块**每 100 块左右分组**：**每组第一个盘块**登记**下一组的全部空闲块号**（组内按栈管理）；**超级块中的空闲栈**只保存**当前第一组**的块号与数量——内存只需维护这一组。

- **分配**：从栈顶取一个块号；当栈中只剩最后一个号时，该号其实是"下一组块号表所在的盘块"——先把其中内容**读入超级块**，再把这个盘块分配出去
- **回收**：栈未满则直接压栈；**栈满**时把栈中全部内容**写入这个回收的盘块**，使它成为**新一组的第一个盘块**

> **考点**：成组链接 = **分组 + 栈**，克服了位示图占空间、空闲链表太长的缺点，**适合大型文件系统**；分配与回收都发生在栈顶，O(1)。

### 空闲管理四方法对比

| 方法 | 原理 | 优点 | 缺点 |
|:---|:---|:---|:---|
| **空闲表法** | (起始块号， 连续块数) 表 | 可分配连续大区，算法现成 | 表项随分配/回收变化，需合并 |
| **空闲链表法** | 空闲盘块/盘区串链 | 实现简单 | 链长查找慢，难快速分配连续区 |
| **位示图法** | 1 位对应 1 盘块 | **占用空间小**、易找连续块 | 大磁盘位图变大，需常驻内存 |
| **成组链接法** | 分组 + 超级块空闲栈 | **适合超大磁盘**、分配回收 O(1) | 实现复杂（UNIX 采用） |

## 虚拟文件系统 VFS

**VFS（Virtual File System）**：在用户与各**具体文件系统（ext4、FAT32、NTFS……）之间**插入的抽象层，向上提供**统一的系统调用接口**（open/read/write/close 与具体文件系统无关），向下通过**函数指针表**调用各文件系统的实现——**同一套 API 即可访问任何已挂载的文件系统**。

VFS 定义四个核心对象（以 Linux 为例）：

| 对象 | 对应概念 | 内容 |
|:---|:---|:---|
| **超级块对象 superblock** | 一个已挂载的文件系统 | 文件系统整体信息 |
| **索引结点对象 inode** | 一个具体文件 | 属性、数据块地址 |
| **目录项对象 dentry** | 路径的一个组成部分 | 缓存路径解析结果，**加速路径查找** |
| **文件对象 file** | 一个**已打开**的文件 | 读写位置、打开方式（与 fd 对应） |

> **考点**：VFS 存在于**内存**中，随系统启动建立；UNIX 的 **v-node** 是其思想源头——进程打开文件得到 v-node，其中含指向**具体文件系统函数表**的指针，从而实现"接口统一、实现各异"。
> **易错点**：dentry 对应**路径的一个分量**（目录名或文件名），不是磁盘上目录项的本体；同一文件可对应多个 dentry（经不同路径访问），但 inode 只有一个——这正是硬链接在 VFS 层的体现。

## 文件系统挂载

**挂载（mount）**：把一个文件系统（卷）的根**安装到全局目录树的某个目录（挂载点）**上，使其中的文件可按统一路径访问。**挂载点必须是一个目录**；挂载完成后，访问挂载点目录就等于访问该文件系统的根（挂到非空目录时，原内容被"遮住"）。

| 对比项 | Windows | UNIX / Linux |
|:---|:---|:---|
| 卷的标识 | **盘符**（C:\、D:\，每卷各一棵树） | **挂载点**（所有卷拼成**一棵目录树**） |
| 挂载操作 | 启动时自动分配盘符 | `mount` 挂载 / `umount` 卸载 |

> **考点**：挂载前先检查该文件系统的**类型等元信息**，并在**安装表**中登记；卸载时若卷上仍有文件**被打开**，则拒绝卸载。

## 高频考点速记

| 考点 | 记忆 |
|:---|:---|
| 目录项与 FCB | **目录项 = FCB**；检索目录 = 逐项比较文件名，FCB 越大检索越慢 |
| inode 瘦身 | 目录项 = 文件名 + inode 号；640 项从 64B 瘦到 16B，平均访盘 **20 → 5 次** |
| 磁盘/内存 inode | 内存 inode 多**打开计数、锁标志、修改标志**等动态信息 |
| open 与 close | open = 检索目录 + **FCB 复制进打开文件表** + 返回 fd；close 删进程级表项，**count = 0 才删系统级表项** |
| fd | **进程级打开文件表的下标**，不是磁盘地址；不同进程 fd 可不同，指向同一系统表项 |
| 文件保护 | 口令易泄露、加密开销大、**ACL 最灵活**；UNIX 9 位 = 属主/组/其他 × rwx |
| 逻辑结构 | 顺序（**定长可随机、变长只能顺序**）/ 索引（每记录一项）/ 索引顺序（**检索约 √n 次**） |
| 连续分配 | 访问任意块 **1 次读盘**；缺点是**外部碎片 + 文件难扩展** |
| 隐式 vs 显式链接 | 隐式只能顺序（第 i 块 **i+1 次读盘**）；**FAT 常驻内存**支持随机、仍 1 次读盘 |
| 索引分配 | 单级 **2 次**读盘、k 级 **k+1 次**；无外部碎片，索引块占空间 |
| 混合索引 | 10 直接 + 1024 + 1024² + 1024³ 块（4KB 块、4B 地址）→ 最大 **4TB + 4GB + 4MB + 40KB** |
| 硬链接 vs 软链接 | 硬：同一 inode、**计数归零才真删**；软：新 inode 存路径、原文件删则**悬空**、2 次访盘、可跨卷 |
| 相对路径 | 从**当前目录**检索，免去从根逐级查找，**减少目录检索时间** |
| 空闲管理四法 | 空闲表（动态分区式）/ 空闲链 / **位示图** / 成组链接（分组 + 栈、超大盘） |
| 位示图换算 | 从 0 编号：字 = ⌊i/32⌋、位 = i mod 32；从 1 编号**先减 1 再算、结果加 1** |
| VFS 与挂载 | VFS 统一接口 + **superblock / inode / dentry / file** 四对象；**挂载点必须是目录** |
