大型数据库中数据存储在磁盘，**磁盘 I/O 次数**是性能瓶颈。平衡 BST 每次比较可能访问一个新结点（一次磁盘 I/O），$\log_2 n$ 次 I/O 无法接受。

**解决思路**：让一个结点容纳多个关键字 → **多路查找树**。一个结点大小 ≈ 一个磁盘页，一次 I/O 读取多个关键字，大幅降低树高。

> R. Bayer 和 E. McCreight（1972）提出 **B 树**（变体 B+ 树）——多路平衡查找树，专为外存索引设计。

**B 树的四个特征**：多路（$m$ 阶，$m\gg 2$）→ 树高 $O(\log_m n)$ / 绝对平衡（叶同层）/ 结点内有序 / 满则分裂、少则借或合并。

## 一棵 m 阶 B-树的定义

1. 根结点或者是叶子，或者至少有 **2** 棵子树，至多有 **$m$** 棵子树
2. 除根结点外，所有非终端结点至少有 **$\lceil m/2 \rceil$** 棵子树，至多有 **$m$** 棵子树
3. 所有叶子结点都在树的**同一层**上（绝对平衡）
4. 结点信息：$(n,\ A_0,\ K_1,\ A_1,\ K_2,\ A_2,\ \dots,\ K_n,\ A_n)$——$K_i$ 有序且 $K_i < K_{i+1}$，$A_i$ 为指向孩子的指针
5. 每个结点关键字个数 $n$ 满足：

$$\lceil m/2 \rceil - 1 \leq n \leq m-1$$

$n+1$ 为子树的棵数。

## B 树查找

从根开始，在结点关键字向量中查找（可用折半查找）：

① 若 $key[i] = K$，则**查找成功**；

② 否则选定子树继续：
- 若 $K < key[1]$：走最左子树 $ptr[0]$
- 若 $key[i] < K < key[i+1]$：走 $ptr[i]$
- 若 $K > key[keynum]$：走最右子树 $ptr[keynum]$

③ 直到 $T$ 是叶子结点且未找到相等的关键字，则**查找失败**。

```c++
int BTree_Search(BTreeNode *T, KeyType K, int &pos) {
    int i;
    while (T != NULL) {
        i = 1;
        while (i <= T->keynum && K > T->key[i]) i++;  // 找到第一个 ≥ K 的位置
        if (i <= T->keynum && K == T->key[i]) {        // 命中
            pos = i;
            return 1;                                  // 查找成功
        }
        T = T->ptr[i - 1];                             // 沿子树继续查找
    }
    return 0;                                          // 查找失败
}
```

## B 树查找分析

B-树的查找次数等价于树高 $h$。含有 $n$ 个关键字的 $m$ 阶 B-树，其高度范围为：

$$
\log_m(n+1) \leq h \leq \log_{\lceil m/2 \rceil}\left(\frac{n+1}{2}\right) + 1
$$

> **结论**：$m$ 阶 B 树高度为 $O(\log_m n)$，因 $m \gg 2$，远低于 BST 的 $O(\log_2 n)$。

## B 树插入（分裂）

**插入思想**：**插入看上界**（$m-1$），**超过看分裂**（中间上移、左右分家），**根分高一层**。

① 查找关键字 $K$，若找到则已存在返回；否则在叶子结点插入；

② 插入时：
- 关键字数 $< m-1$：**直接插入**
- 关键字数 $= m-1$：**"分裂"**

**分裂过程**（插入后关键字数达到 $m$ 时）：
1. 将 $m$ 个关键字分为三部分：左半（$\lceil m/2 \rceil - 1$ 个）、**中间关键字** $K_{\lceil m/2 \rceil}$、右半（$m - \lceil m/2 \rceil$ 个）
2. 中间关键字**上移**到父结点
3. 左、右两部分各成为一个新结点
4. 若父结点也因此溢出，**递归向上分裂**，最坏可能一直分裂到根

> 分裂是 B 树**向上生长**的唯一方式——根结点分裂时树高 $+1$。

## B 树删除（借与合并）

非叶子结点的处理：**用右子树的最大值或者左子树的最小值代替**——删除最终都归结为**从叶子结点中删除一个关键字**。

**从叶子结点中删除的三种情况**：

| 情况 | 条件 | 操作 |
|:---|:---|:---|
| (1) 直接删除 | 结点关键字数 $> \lceil m/2 \rceil - 1$ | 直接删除，树不做调整 |
| (2) 向兄弟借 | 结点关键字数 $= \lceil m/2 \rceil - 1$，且兄弟关键字数 $> \lceil m/2 \rceil - 1$ | 兄弟最大（最小）关键字**上移**到父结点，父结点中紧靠的关键字**下移**到结点 N（本质是一次旋转） |
| (3) 合并 | 结点和兄弟的关键字数都 $= \lceil m/2 \rceil - 1$ | 删除 K 后，与兄弟及父结点中的分割关键字**合并**；若父结点因此下溢，向上递归合并 |

> **一句话总结**：**自己够→直接删**；**不够找兄弟借**（旋转）；**都不够→合并**（父关键字下移，向上递归）。

## B+ 树

一棵 $m$ 阶 B+ 树与 $m$ 阶 B 树的主要差异：

1. 若一个结点有 $n$ 棵子树，则必含有 **$n$ 个关键字**；且叶子结点按关键字大小**顺序链接**（横向链表）
2. 所有**叶子结点**中包含了**全部记录**的关键字信息及记录的指针
3. 所有**非叶子结点**只含有其子树的根结点中**最大（或最小）关键字**（仅起索引作用）

## B 树 vs B+ 树对比

| | B- (B树) | B+树 |
|:---|:---|:---|
| 根结点关键字数 | 1 ~ (m-1) | 1 ~ m |
| 中间结点关键字数 | ⌈m/2⌉-1 ~ m-1 | ⌈m/2⌉ ~ m |
| 结点重复 | 否 | 是（非叶关键字会出现在叶结点） |
| 查找 | 只有随机方式 | 随机方式 + 顺序方式（范围查询） |
| 存储信息 | 结点中都含记录的存储地址 | 叶结点存信息，非叶结点仅索引 |
| n 个关键字 | 对应 n+1 个子树 | 对应 n 个子树 |

> **核心差异**：B 树结点存数据，查找可能在任何层命中；B+ 树叶结点存全部数据并通过链表相连，支持**范围查询**和顺序遍历。

## 高频考点速记

| 考点 | 记忆 |
|:---|:---|
| B 树性质 | $m$ 阶：根 $2\sim m$ 子树、其余 $\lceil m/2\rceil\sim m$、关键字 $\lceil m/2\rceil-1\sim m-1$、**叶同层** |
| B 树高度 | $\log_m(n+1)\le h\le\log_{\lceil m/2\rceil}((n+1)/2)+1$，$O(\log_m n)$ |
| B 树插入 | 看上界 $m-1$；**超过分裂**（中间上移）；根分高一层（树高+1） |
| B 树删除 | 非叶用后继/前驱替换归结到叶；够→直接删、不够→**借兄弟**、都不够→**合并** |
| B+ 树 | $n$ 子树 $n$ 关键字；叶结点链表串**全部记录**；非叶仅索引；支持**范围查询** |
