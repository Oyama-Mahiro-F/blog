**计算机网络（Computer Network）**是**互连的、自治的**计算机系统的集合，它以**网络协议**为核心，实现**数据通信**与**资源共享**。本章是整个计网的"总纲"：计算题集中在**时延、时延带宽积等性能指标**，概念题集中在**分层结构、协议三要素、协议/接口/服务的辨析**以及 **OSI 与 TCP/IP 两大参考模型的对比**。

## 计算机网络的定义、组成与功能

**定义**：将位置分散、具有**独立功能**的多台计算机系统，通过**通信设备与线路**互连起来，由功能完善的**网络软件（协议）**实现**资源共享和信息传递**的系统。定义抓住两个关键词：

| 关键词 | 含义 |
|:---|:---|
| **互连** | 通过通信链路互连，能互相交换信息 |
| **自治** | 每台计算机**独立运行、无主从关系**，去掉任何一台其余仍能工作 |

> **考点**：**"自治"** 是计算机网络与**多处理器系统**（共享内存、由操作系统统一调度）的分界线；网络三要素是**计算机、通信链路、网络协议**，其中**协议是核心**。

### 计算机网络的组成

| 视角 | 划分 | 内容 |
|:---|:---|:---|
| **组成部分** | 硬件、软件、协议 | 主机、链路、路由器/交换机；网络操作系统等软件；**协议是核心** |
| **工作方式** | 边缘部分 + 核心部分 | **边缘** = 主机（用户直接使用，C/S 或 P2P）；**核心** = 路由器 + 网络（为边缘提供分组转发） |
| **功能组成** | 通信子网 + 资源子网 | **通信子网** = OSI 低三层（负责传数据）；**资源子网** = 高三层（负责供资源） |

边缘部分主机的两种工作方式：

| 对比项 | C/S 方式（客户/服务器） | P2P 方式（对等） |
|:---|:---|:---|
| 地位 | 客户**请求**、服务器**响应**，**不对等** | 每个节点**既是客户又是服务器**，对等 |
| 瓶颈 | 服务器承担全部负载，易成**瓶颈** | 无中心服务器，负载分散 |
| 典型应用 | Web、FTP、电子邮件 | BT 下载、即时通信 |

> **考点**：**通信子网 = 物理层 + 数据链路层 + 网络层**（OSI 低三层），传输层是"承上启下"的边界层，**不算**通信子网。

### 主要功能

| 功能 | 说明 |
|:---|:---|
| **数据通信** | **最基本、最重要**的功能 |
| **资源共享** | 硬件（打印机）、软件、数据共享，互联的**最终目的** |
| **分布式处理** | 多台计算机分担同一任务的不同部分（如 Hadoop） |
| **提高可靠性** | 一台故障，替代机继续工作 |
| **负载均衡** | 任务分摊到各计算机，提高利用率 |

## 计算机网络的分类

### 按分布范围

| 类型 | 全称 | 特点 |
|:---|:---|:---|
| **广域网 WAN** | Wide Area Network | 跨国家/地区，范围最大，因特网核心 |
| **城域网 MAN** | Metropolitan Area Network | 覆盖一个城市，多以以太网技术实现 |
| **局域网 LAN** | Local Area Network | 校园/企业小范围，**速率高、时延低** |
| **个人区域网 PAN** | Personal Area Network | 个人身边数米内，蓝牙等 |

### 按交换技术（重点）

| 交换方式 | 原理 | 优点 | 缺点 |
|:---|:---|:---|:---|
| **电路交换** | 建立专用通路 → 独占传输 → 释放 | 时延小、有序、无冲突、**实时性强** | 建连时间长、**线路利用率低**、无纠错 |
| **报文交换** | 整个报文**存储转发** | 无需建连、利用率高、可动态选路 | 转发时延大、节点需大容量缓存 |
| **分组交换** | 报文切成**分组**后存储转发 | 缓存易管理、重传代价小、时延较小 | 有转发时延、**额外首部开销**、可能失序/丢失 |

> **考点**：**因特网采用分组交换**；报文交换与分组交换的本质区别是**存储转发的单位**（整个报文 vs 定长分组），分组更小使时延与缓存需求都下降。

### 按拓扑结构、传输技术与使用者

| 分类标准 | 类型 | 要点 |
|:---|:---|:---|
| 拓扑结构 | 总线 / 星型 / 环型 / 网状 | **网状可靠性最高**（广域网常用）；星型集中管理，中心节点故障全网瘫痪 |
| 传输技术 | **广播式网络** | 共享公共信道，一主机发送全体收到（局域网典型） |
| 传输技术 | **点对点网络** | 分组经**存储转发**逐跳传递（广域网典型） |
| 使用者 | 公用网 / 专用网 | 付费即可用（电信运营商）/ 部门专建（军队、铁路、银行） |

## 性能指标

### 速率、带宽与吞吐量

| 指标 | 含义 | 要点 |
|:---|:---|:---|
| **速率（数据率/比特率）** | 单位时间传送的**比特数** | b/s、kb/s、Mb/s，**以 $10^3$ 为底**进位 |
| **带宽（Bandwidth）** | 信道能通过的**最高数据率**（额定上限） | 原指信号的**频带宽度（Hz）**，网络中引申为最高速率 |
| **吞吐量（Throughput）** | 单位时间**实际通过**网络/信道的数据量 | **实测值**，受带宽额定速率限制 |

> **易错点**：速率换算以 **$10^3$** 为底（1 Mb/s = $10^6$ b/s），**存储容量**换算以 **$2^{10}$** 为底（1 KB = $2^{10}$ B）——bit 用十进制、Byte 用二进制，选择题常在此设坑。

### 时延

数据从网络一端传到另一端所需时间，由**四部分**组成：

$$总时延 = 发送时延 + 传播时延 + 处理时延 + 排队时延$$

$$发送时延 = \frac{数据长度}{发送速率（带宽）} \qquad 传播时延 = \frac{信道长度}{电磁波传播速率}$$

| 时延 | 决定因素 | 特征 |
|:---|:---|:---|
| **发送时延（传输时延）** | 数据块长度、**发送速率** | **与距离无关**，由发送端决定 |
| **传播时延** | **信道长度**、介质种类 | **与数据长度无关**，由链路决定 |
| **处理时延** | 节点检查首部、查找路由表 | 取决于路由器性能 |
| **排队时延** | 输入/输出队列中的等待 | 随流量波动，**拥塞时剧增** |

> **考点**：电磁波在铜缆/光纤中传播速率约 **$2\times10^8$ m/s**（真空中为光速 $3\times10^8$ m/s）；**发送时延看发送端、传播时延看链路**；习题通常默认忽略处理时延与排队时延，只算前两种。

### 例题：时延与时延带宽积计算

**题目**：主机 A 经 **1000 km** 链路向主机 B 发送 **2 KB** 数据，链路带宽 **10 Mb/s**，信号传播速率为 $2\times10^8$ m/s。求发送时延、传播时延、总时延与时延带宽积。

**分析**：默认忽略处理/排队时延，总时延 = 发送时延 + 传播时延；所有长度统一换算成 **bit** 与 **m**。

| 指标 | 计算 | 结果 |
|:---|:---|:---|
| 数据长度 | 2 KB = $2\times1024\times8$ | **16384 bit** |
| 发送时延 | $16384 \div 10^{7}$ s | **1.6384 ms** |
| 传播时延 | $10^{6} \div 2\times10^{8}$ s | **5 ms** |
| 总时延 | $1.6384 + 5$ | **6.6384 ms** |
| 时延带宽积 | $5\times10^{-3}\,\text{s} \times 10^{7}\,\text{b/s}$ | $5\times10^{4}$ bit = **6250 B** |

**验算**：发送时延换字节法——发送速率为 $10^{7}$ b/s = **1.25 MB/s**，2048 B ÷ 1.25 MB/s = 1.6384 ms ✓；总时延含义——**最后一个比特**在 1.6384 ms 时刻才发完，再经 5 ms 到达对端，$1.6384 + 5 = 6.6384$ ms ✓

**结论**：本题**传播时延占主导**（5 ms 远大于 1.6384 ms）——短数据 + 长链路时传播时延主导；反之发送大文件时发送时延主导。**两类时延谁占主导没有普适结论，必须分别计算后再比较**。

### 时延带宽积、往返时延与利用率

| 指标 | 定义/公式 | 说明 |
|:---|:---|:---|
| **时延带宽积** | $传播时延 \times 带宽$，单位 **bit** | "**以比特为单位的链路长度**"——链路上最多同时"容纳"的比特数（正在"飞行"的比特） |
| **往返时延 RTT** | 从**发送数据开始**到**收到接收端确认**的总时间 | 含往返传播时延 + 中间节点的处理/排队时延 |
| **信道利用率** | $\frac{有数据通过的时间}{总时间}$ | 利用率并非越高越好 |
| **网络利用率** | 全网信道利用率的加权平均 | 同上 |

> **考点**：时延带宽积可形象理解为"**管道容积**"——传播时延是管道长度、带宽是管道截面，乘积就是管道内能装下的比特数；发送方发出一个分组后，至少要经过**一个传播时延**它才到达对端。
> **易错点**：RTT 不等于两倍发送时延；**信道利用率过高 → 排队时延急剧增大**，这是网络接近拥塞的信号。

## 分层结构

网络是一个复杂系统，**分层**把大问题拆成若干**局部问题**逐层解决。**分层原则**：

- 每层实现一种**相对独立**的功能，降低系统复杂度
- 层间界面**自然清晰**，跨层交互的信息尽量少
- **下层为上层提供服务**，上层通过接口使用下层功能，下层细节对上层**透明**

**分层的好处（意义）**：

- **各层相互独立**：上层只需知道通过接口获得哪些服务，无需关心下层如何实现
- **灵活性好**：某一层变化（只要接口不变）不影响其他层
- **易于实现和维护**：复杂系统拆成小模块，便于调试、排错与更新
- **促进标准化**：每层的功能与所提供的服务都有精确定义

> **考点**：**体系结构 = 各层及其协议的集合**，是对网络功能的**抽象**精确定义；**实现**是具体的软硬件。体系结构只规定"做什么"，不规定"怎么做"——体系结构是抽象的，实现是具体的。

### 协议及其三要素

**协议（Protocol）**：控制**对等实体**（同层实体）之间通信的规则的集合，是**水平**的。

| 要素 | 规定内容 | 典型例子 |
|:---|:---|:---|
| **语法** | 数据与控制信息的**格式与结构** | 报文首部各字段的长度、位置 |
| **语义** | 发出何种信息、完成何种**动作与应答** | 收到差错报文时回送差错报告 |
| **同步（时序）** | 事件实现的**顺序**与条件 | 建立连接的**三次握手**次序 |

> **易错点**：三要素中**"同步/时序"最容易漏答**；协议是**水平**的（对等实体间），服务是**垂直**的（相邻层间）。

### 接口、服务与服务原语

![协议、服务与 SAP 的关系（协议水平、服务垂直）](/blog/images/第1章 计算机网络体系结构.assets/sap-协议与服务.png)

**服务访问点 SAP（Service Access Point）**：相邻两层实体交换信息的**逻辑接口**，如传输层的 SAP 是**端口号**。**服务**：下层通过 SAP 为**紧邻的上层**提供的功能；只有**上层看得见的功能**才算服务，实现细节对上层透明。

上层使用下层服务需通过**服务原语**：

| 原语 | 方向 | 作用 |
|:---|:---|:---|
| **请求 Request** | 上 → 下 | 服务用户请求服务（如请求建立连接） |
| **指示 Indication** | 下 → 上 | 通知对端用户发生了某事件 |
| **响应 Response** | 上 → 下 | 收到指示的一方作出回应 |
| **证实 Confirmation** | 下 → 上 | 将请求的结果回告请求方 |

**面向连接 vs 无连接服务**：

| 对比项 | 面向连接服务 | 无连接服务 |
|:---|:---|:---|
| 通信前 | 先**建立连接**，用后**释放**（如三次握手） | **不建连接**，直接发送 |
| 路由 | 分组沿同一路径**按序**到达 | 每个分组**独立选路**，可能失序、丢失 |
| 可靠性 | 可靠，含流量/拥塞控制（**TCP**） | 尽力而为 Best Effort（**UDP**、IP） |
| 开销 | 建连/释放开销大，灵活性差 | 开销小、灵活、快速 |

此外，服务还可按**可靠性**分为可靠/不可靠服务，按**确认机制**分为有确认/无确认服务（对应"有证实/无证实"）。

> **考点**：**同一服务可由不同协议实现，同一协议也可提供不同服务**；"有确认"是机制、"可靠"是效果，两者不是一回事。

### 数据单元：PDU、SDU 与 PCI

| 概念 | 全称 | 含义 |
|:---|:---|:---|
| **PDU** | Protocol Data Unit，协议数据单元 | **对等层**之间传送的数据单元 |
| **SDU** | Service Data Unit，服务数据单元 | 本层交给下层传送的"用户数据" |
| **PCI** | Protocol Control Information，协议控制信息 | 控制信息（首部：地址、序号、校验等） |

**关系**：$本层 PDU = 本层 PCI + 本层 SDU$——上一层的 PDU 到本层就是 SDU，加首部（**封装**）后变成本层 PDU；接收端逐层**去首部（解封装）**。

> **考点**：封装链条——**报文 → 报文段 → 数据报 → 帧 → 比特流**；"上一层 PDU 是下一层 SDU"是选择题常客。

## OSI 参考模型（七层）

![OSI 七层对等通信与各层协议](/blog/images/第1章 计算机网络体系结构.assets/osi-七层模型.png)

**OSI（Open Systems Interconnection）参考模型**是 ISO 提出的**法律上的国际标准**，自底向上为**物理、数据链路、网络、传输、会话、表示、应用**七层（口诀"物链网传会表应"）：

| 层 | 核心功能 | 传输单位 |
|:---|:---|:---|
| **应用层** | 用户与网络的**界面**，提供应用服务（HTTP、FTP、SMTP） | 报文 |
| **表示层** | **数据格式转换**、加密解密、压缩恢复 | 报文 |
| **会话层** | 建立/管理/**终止会话**，设置**校验点**（断点续传） | 报文 |
| **传输层** | **端到端**（进程间）通信，**复用与分用**、可靠传输、流量控制 | 报文段 |
| **网络层** | **路由选择**、流量/拥塞控制、**异构网络互联** | 分组（数据报） |
| **数据链路层** | **成帧**、差错控制、流量控制、MAC 寻址 | 帧 |
| **物理层** | **比特流的透明传输**，规定接口的机械/电气/功能/规程特性 | 比特 |

> **易错点**：**传输层是端到端**（主机**进程**之间），**网络层及以下是点到点**（主机—路由器—路由器等相邻节点之间）；OSI 层次理论完整但**层次多、实现复杂**，最终未成为事实标准。

对等层之间的通信是**逻辑（虚）通信**：数据实际沿本系统逐层向下封装，经物理介质到达对端后再逐层向上解封装，**物理层是唯一真正传输数据的层次**。

## TCP/IP 参考模型（四层）

| 层 | 功能 | 主要协议 |
|:---|:---|:---|
| **应用层** | 面向用户的各种应用服务 | HTTP、FTP、SMTP、DNS |
| **传输层** | 进程间端到端通信 | **TCP**（面向连接、可靠）、**UDP**（无连接、不可靠） |
| **网际层** | 分组转发与路由选择 | **IP**（核心）、ICMP、ARP |
| **网络接口层** | 与各种底层网络对接，**未规定具体内容** | 以太网、PPP 等 |

TCP/IP 的核心设计思想是**沙漏模型**：**网际层只留一个 IP 协议**（最窄处），上层应用可无限扩展、下层可运行于任何网络技术——"**IP over everything, everything over IP**"。

> **考点**：TCP/IP **先有协议、后有模型**（与 OSI 相反）；其**网络层只提供无连接**服务，而 OSI 网络层面向连接与无连接均可；网络接口层不规定具体内容，正体现了 IP 屏蔽底层差异。

## OSI、TCP/IP 与五层教学模型对比

![OSI、TCP/IP 与五层混合模型](/blog/images/第1章 计算机网络体系结构.assets/osi-tcpip-五层对比.png)

| 对比项 | OSI 参考模型 | TCP/IP 参考模型 |
|:---|:---|:---|
| 层次数 | **7 层** | **4 层** |
| 产生顺序 | **先有模型，后有协议** | **先有协议，后有模型** |
| 地位 | 法律上的国际标准，理论完整但未流行 | **事实上的国际标准** |
| 网络层 | 可面向连接，也可无连接 | **仅无连接**（IP 数据报） |
| 传输层 | 以面向连接为主 | **TCP / UDP** 两种并存 |
| 会话层 + 表示层 | 独立成层 | 并入**应用层** |
| 物理层 + 数据链路层 | 两层 | 合并为**网络接口层**（内容未定义） |

**五层教学模型**综合 OSI 的清晰层次与 TCP/IP 的实用性，是 **408 考试默认使用的模型**（无特别说明按五层作答）：

| 层 | 核心功能 | 典型协议 | 典型设备 | PDU |
|:---|:---|:---|:---|:---|
| **应用层** | 用户接口、应用服务 | HTTP、FTP、DNS | 网关（最高可到应用层） | 报文 |
| **传输层** | 进程间端到端、复用分用 | TCP、UDP | — | 报文段 |
| **网络层** | 路由选择、分组转发 | IP、ICMP、ARP | **路由器** | 分组（数据报） |
| **数据链路层** | 成帧、差错/流量控制 | 以太网、PPP | **交换机、网桥** | 帧 |
| **物理层** | 比特流透明传输 | 曼彻斯特编码等 | **中继器、集线器** | 比特 |

> **易错点**：集线器在**物理层**（转发比特、不隔离冲突域），交换机在**数据链路层**（按 MAC 转发帧、隔离冲突域），路由器在**网络层**——"设备工作在哪个层次"是高频选择题；网关是**网络层以上**的设备。

## 高频考点速记

| 考点 | 记忆 |
|:---|:---|
| 网络定义 | **互连的、自治的**计算机集合；最基本功能**数据通信**、最终目的**资源共享** |
| 三要素 | **计算机、通信链路、协议**（协议是核心） |
| 分类 | 按范围 WAN/MAN/LAN/PAN；按交换**电路/报文/分组**——因特网用**分组交换** |
| 速率换算 | bit 以 **$10^3$** 为底、Byte 以 **$2^{10}$** 为底，两者勿混 |
| 发送时延 | $数据长度 \div 发送速率$，由发送端决定，**与距离无关** |
| 传播时延 | $信道长度 \div 传播速率$（铜缆/光纤约 $2\times10^8$ m/s），**与数据长度无关** |
| 时延带宽积 | $传播时延 \times 带宽$，单位 **bit**——"**以比特为单位的链路长度**" |
| RTT 与利用率 | RTT = 发送数据到**收到确认**；**利用率过高 → 时延急剧增大** |
| 协议三要素 | **语法**（格式）、**语义**（动作）、**同步/时序**（顺序） |
| 协议 vs 服务 | 协议**水平**（对等实体）、服务**垂直**（相邻层）；$PDU = PCI + SDU$ |
| 服务原语 | **请求、指示、响应、证实**四类；SAP 如**端口号** |
| 两种服务 | **面向连接**（TCP：先建连、按序可靠）vs **无连接**（UDP/IP：独立选路、尽力而为） |
| OSI 七层 | **物链网传会表应**；传输层**端到端**、网络层及以下**点到点** |
| OSI vs TCP/IP | 先模型后协议 vs 先协议后模型；网际层**仅无连接**；会表应并入应用层、链路物理并入网络接口层 |
| 五层模型与设备 | 应用/传输/网络/链路/物理（408 默认）；集线器—物理层、交换机—链路层、路由器—网络层、网关—网络层以上 |
