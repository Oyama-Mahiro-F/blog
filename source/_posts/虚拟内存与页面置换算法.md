连续分配、基本分页/分段（见姊妹篇《内存管理：连续分配与分页分段》）有一个共同瓶颈：**程序必须一次性全部装入内存，且装入后一直驻留到运行结束**——大程序装不进，多道程序并发度也上不去。**虚拟存储器（Virtual Memory）**利用**局部性原理**突破这一限制：程序只需**部分装入**即可启动，其余部分"用时再调、缺了再换"，让进程在逻辑上拥有比物理内存大得多的存储空间。408 对本章的考查集中在：**虚拟内存的概念与特征、请求分页与缺页中断、页框分配策略、页面置换算法（OPT / FIFO / Clock / LRU）的缺页率演算、抖动与工作集**——其中置换算法的手算快照几乎年年出现。

## 虚拟内存的基本概念

### 局部性原理：虚拟内存的理论基础

程序运行时对存储器的访问是**不均匀、相对集中**的，这一现象称为**局部性原理（Locality）**：

| 局部性 | 含义 | 典型例子 |
|:---|:---|:---|
| **时间局部性** | 刚被访问过的项，**不久后再次被访问** | 循环语句、反复调用的函数、热点变量 |
| **空间局部性** | 刚被访问过的存储单元，其**附近单元即将被访问** | 顺序执行的指令、按行遍历的数组 |

正因局部性存在，程序在任一时间段内真正活跃的只是**一小部分页面**——只把这部分装入内存，缺页率就不会太高，程序便能"部分装入"照常运行。**局部性原理是虚拟存储器能够实现的理论基础**。

> **考点**：题目问"虚拟内存的理论基础是什么"，答**局部性原理**（时间局部性 + 空间局部性）。

### 虚拟存储器的定义与特征

**虚拟存储器**：基于局部性原理，程序装入时**只装入部分页面**即可运行，运行过程中再把它需要的页面（或段）**陆续调入内存**；暂不运行的内容可**换出**到外存。进程按**逻辑地址空间**编址，仿佛拥有一个容量远大于物理内存的"存储器"。

**传统存储管理 vs 虚拟存储管理**：

| 对比项 | 传统存储管理 | 虚拟存储管理 |
|:---|:---|:---|
| 装入方式 | **一次性**：作业必须整体装入才能运行（瓶颈一） | **多次性**：分多次调入，每次只装一部分（**最重要特征**） |
| 驻留方式 | **驻留性**：装入后一直占住内存直到结束（瓶颈二） | **对换性**：运行中可在内存与外存间**换入换出** |
| 逻辑容量 | 逻辑空间 **≤ 物理内存** | **虚拟性**：逻辑上扩充内存，容量可远大于物理内存（**最终目标**） |
| 中断支持 | 无缺页/缺段机制 | 访问未调入的页/段时产生**缺页/缺段中断** |
| 主要代价 | 内存利用率低、大作业无法运行 | 有缺页开销，**依赖好的置换算法**降低缺页率 |

> **考点**：三特征 = **多次性（区别于传统管理的关键、最重要）、对换性、虚拟性（最终目标）**；多次性、对换性是手段，虚拟性是结果。

### 实现方式与容量

虚拟存储器的实现 = **某种基本管理方式 + 请求调入功能 + 置换功能**：

| 实现方式 | 组成 |
|:---|:---|
| **请求分页存储管理**（重点） | 基本分页 + **请求调页** + **页面置换** |
| **请求分段存储管理** | 基本分段 + 请求调段 + 段置换 |
| **请求段页式存储管理** | 基本段页式 + 请求调页/调段 + 置换 |

**虚拟内存容量**受两方面限制——CPU 的**地址结构**（地址位数）与**内外存总容量**：

$$虚拟内存容量 \le \min(2^{地址位数},\ 内存容量 + 外存容量之和)$$

> **易错点**：
> - 32 位系统虚拟地址空间上限为 $2^{32} = 4\text{GB}$，**与物理内存多大无关**；虚存容量也不是"内存容量"本身。
> - 虚拟存储**不能凭空运行**：被访问的信息必须**已存在于外存**，只是不必常驻内存。
> - "扩大内存"只是**逻辑上的**，物理内存容量并未改变。

实现虚拟存储器需要四个支撑：**一定容量的内存 + 相当容量的外存**（物质基础）、**页表/段表机制**（数据结构，记录状态与外存地址）、**缺页中断机构**（请求调入）、**地址变换机构**（逻辑地址到物理地址）。

## 请求分页管理方式

**请求分页** = 基本分页 + **请求调页**（访问到才调入）+ **页面置换**（内存不足时换出）。它是在基本分页基础上加装"缺页中断 + 置换"两套机构而成，是虚拟存储**最常用、最爱考**的实现。

### 请求页表机构：新增四个字段

基本分页的页表项只有**页框号**；请求分页在其基础上**新增四位**：

| 新增字段 | 作用 |
|:---|:---|
| **状态位 P（存在位）** | 该页是否已调入内存：P=1 在内存，正常变换；**P=0 不在内存，触发缺页中断** |
| **访问位 A（访问字段）** | 记录该页近期**是否/何时被访问**，供**置换算法**使用（Clock 扫描、LRU 近似依据） |
| **修改位 M（脏位）** | 该页调入后是否被**写过**：换出时 M=1 必须**先写回外存**；M=0 可**直接丢弃覆盖**（省一次写盘） |
| **外存地址** | 该页在外存（对换区/文件区）的存放位置，缺页调入时按它**找到并读入页面** |

> **考点**：**看状态位 P 判断是否缺页**；**看修改位 M 判断换出时是否写盘**；**访问位 A 是 Clock/LRU 的硬件依据**；外存地址只在缺页调入时用。
> **易错点**：四个字段各司其职，别把"修改位决定是否写回"与"状态位决定是否缺页"混为一谈。

### 缺页中断与处理流程

CPU 访问的页面**状态位 P=0**（尚未调入内存）时，硬件触发**缺页中断（Page Fault）**——它属于**内中断中的"故障"**，由地址变换机构在指令执行过程中检测并发出。完整处理流程共七步：

1. **保留现场**：保存断点与寄存器现场，转入缺页中断处理程序；
2. **找页**：按页表项中的**外存地址**在磁盘上定位缺页；
3. **分配页框**：查空闲页框，若有空闲页框则直接分配；
4. **淘汰换出**：若无空闲页框，执行**页面置换算法**选出一页淘汰；被淘汰页**修改位 M=1 时先写回外存**，M=0 直接覆盖；
5. **调入**：启动磁盘 I/O，把缺页读入所分配的页框；
6. **更新页表与快表**：填入页框号、**状态位置 1**（若淘汰过页面，同步改写对应表项）；
7. **恢复现场，重新执行被中断的那条指令**（是"重做"这条指令，不是执行下一条）。

**缺页中断与普通（外）中断的区别**：

| 对比项 | 缺页中断 | 普通外部中断 |
|:---|:---|:---|
| 中断类别 | **内中断（异常，故障类）** | 外中断（时钟、I/O 等） |
| 产生时机 | **一条指令执行期间**（取指/访存地址变换时）检测并响应 | 一条指令**执行结束后**才检查响应 |
| 发生次数 | **一条指令可能产生多次**（指令跨页、间接寻址、块传送都要多次访存） | 一条指令一般至多响应一次 |
| 处理结果 | 调页后**重新执行原指令** | 处理后接着执行**下一条**指令 |

> **考点**：缺页中断是"故障"——**排除故障（调入页面）后指令可以重新执行成功**；区别于"终止"型异常（如除 0 非法）。
> **易错点**：处理完后**重新执行触发缺页的那条指令**；跨页指令、块传送指令一条可引发**多次**缺页中断。

### 请求分页的地址变换过程

逻辑地址 (页号 P, 页内偏移 W) 的变换路径：**查快表 TLB → 命中则直接拼接物理地址（1 次访存）→ 未命中查内存页表（2 次访存）→ 状态位 P=0 则进入上述缺页中断流程，调页更新页表与快表后重新执行指令**。快表命中 1 次访存、页表命中 2 次；发生缺页时要先完成一次磁盘 I/O（毫秒级），代价远高于前两者——这正是后面"降低缺页率"如此重要的原因。

## 页框分配与回收

### 驻留集：分配多少页框才合适

**驻留集**：操作系统分配给某进程、当前**驻留在内存中的页框（页面）集合**，其大小直接影响缺页率：

| 驻留集大小 | 后果 |
|:---|:---|
| **过小** | 活跃页放不下，**缺页率骤增**，CPU 大量时间耗在换页上（滑向**抖动**） |
| **过大** | 超过一定数目后缺页率改善甚微，**浪费内存**，且能容纳的进程数减少、**多道程序并发度下降** |

> **考点**：驻留集要**折中**——判据是"驻留集 ≥ 该进程的**工作集**"（见后文），既不频繁缺页也不浪费。

### 页框分配的三种算法

系统共有的空闲页框按什么规则分给各进程：

| 分配策略 | 做法 | 特点 |
|:---|:---|:---|
| **平均分配** | 空闲页框**平均**分给各进程 | 简单；小程序浪费、大程序不够 |
| **按比例分配** | 按各进程**大小（页面数）占系统总页面数的比例**分配 | 大小进程各得其所，较公平 |
| **优先级分配** | **优先级高**的进程多分（常与按比例结合） | 保证重要、紧迫进程先运行；分静态与动态两种 |

进程结束或被挂起换出时，它占用的页框由系统**回收**（清位示图、作废相应表项），重新进入空闲池参与下一次分配。

### 固定 vs 可变、全局 vs 局部置换

**固定分配**：进程运行期间页框数**固定不变**；**可变分配**：页框数可随缺页情况动态增减。**局部置换**：缺页时只能淘汰**本进程**的页面；**全局置换**：可淘汰**任何进程**的页面。四种组合：

| 策略组合 | 是否采用 | 说明 |
|:---|:---|:---|
| **固定分配 + 局部置换** | 采用 | 页框数固定，缺页只能**换自己的页**；难点是预先定不准合适的页框数 |
| **可变分配 + 全局置换** | 采用 | 缺页时新页先占空闲页框，不够就**抢占其他进程的页框**；实现最简单、最常用 |
| **可变分配 + 局部置换** | 采用 | 缺页换自己的页；**缺页频繁 → 增加页框**，缺页过少 → **减少页框**（兼顾双方优点） |
| **固定分配 + 全局置换** | **不可行** | 全局置换会增减本进程页框数，与"固定"自相矛盾 |

**全局置换 vs 局部置换**：

| 对比项 | 全局置换 | 局部置换 |
|:---|:---|:---|
| 淘汰范围 | 内存中**任意进程**的页面 | **仅本进程**自己的页面 |
| 驻留集大小 | 随缺页被动变化（可能被抢走） | 固定，或按缺页率**主动调整** |
| 优点 | 灵活，页框自动流向更需要的进程 | 各进程**互不干扰**，缺页率可控 |
| 缺点 | 缺页多的进程"抢"别人的页，**把抖动传染给全系统** | 无法在进程间动态调剂富余页框 |

> **考点**：分析"抖动为什么会蔓延"要抓住**全局置换**——某进程缺页率高时会不断抢占其他进程页框，把别人也拖进抖动；**局部置换**则把缺页隔离在本进程内。
> **易错点**：不存在"固定分配 + 全局置换"这种组合；可变分配通常配合缺页率高低来增减页框。

## 页面置换算法

缺页时若无空闲页框，必须**淘汰**一页腾位置。理想是淘汰"以后最久不再使用"的页，但**未来无法预知**，只能用不同策略近似——评价标准就是**缺页率**。

### 最佳置换算法 OPT

**OPT（Optimal，最佳置换）**：淘汰**从现在起以后最长时间不再被访问**（或永不再用）的页面。

- **缺页率最低，理论最优**；
- 需要**预知未来的访问序列**——**无法实现**；
- 价值在于作为**评价基准**：拿它与实际算法的缺页数对比，衡量后者接近最优的程度。

### 先进先出置换算法 FIFO 与 Belady 异常

**FIFO**：淘汰**最早进入内存**的页面，进程页面排成一个队列，换页时队首出队。

- 实现**最简单**（一个队列即可），但性能通常最差——它只看"来得早晚"，**与是否常用毫无关系**；
- 可能产生 **Belady 异常**：**分配的页框数增加，缺页次数反而增多**。

**Belady 异常例题**：页面访问序列 **1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5**（12 次访问），分别用 **3 个页框**和 **4 个页框**做 FIFO 置换，求缺页次数。

**三个页框**（内存内容为该步结束后的页框状态）：

| 步 | 访问 | 内存内容（3 个页框） | 是否缺页 |
|:---|:---|:---|:---|
| 1 | 1 | 1 | 缺页 |
| 2 | 2 | 1, 2 | 缺页 |
| 3 | 3 | 1, 2, 3 | 缺页 |
| 4 | 4 | 4, 2, 3（淘汰 1） | 缺页 |
| 5 | 1 | 4, 1, 3（淘汰 2） | 缺页 |
| 6 | 2 | 4, 1, 2（淘汰 3） | 缺页 |
| 7 | 5 | 5, 1, 2（淘汰 4） | 缺页 |
| 8 | 1 | 5, 1, 2 | 命中 |
| 9 | 2 | 5, 1, 2 | 命中 |
| 10 | 3 | 5, 3, 2（淘汰 1） | 缺页 |
| 11 | 4 | 5, 3, 4（淘汰 2） | 缺页 |
| 12 | 5 | 5, 3, 4 | 命中 |

**四个页框**：

| 步 | 访问 | 内存内容（4 个页框） | 是否缺页 |
|:---|:---|:---|:---|
| 1 | 1 | 1 | 缺页 |
| 2 | 2 | 1, 2 | 缺页 |
| 3 | 3 | 1, 2, 3 | 缺页 |
| 4 | 4 | 1, 2, 3, 4 | 缺页 |
| 5 | 1 | 1, 2, 3, 4 | 命中 |
| 6 | 2 | 1, 2, 3, 4 | 命中 |
| 7 | 5 | 5, 2, 3, 4（淘汰 1） | 缺页 |
| 8 | 1 | 5, 1, 3, 4（淘汰 2） | 缺页 |
| 9 | 2 | 5, 1, 2, 4（淘汰 3） | 缺页 |
| 10 | 3 | 5, 1, 2, 3（淘汰 4） | 缺页 |
| 11 | 4 | 4, 1, 2, 3（淘汰 5） | 缺页 |
| 12 | 5 | 4, 5, 2, 3（淘汰 1） | 缺页 |

**结果对比**：

| 页框数 | 缺页次数 | 命中次数 | 缺页率 |
|:---|:---|:---|:---|
| 3 个 | **9** | 3 | 9/12 = **75%** |
| 4 个 | **10** | 2 | 10/12 ≈ **83.3%** |

页框多了 1 个，缺页反而从 9 次涨到 10 次——**Belady 异常**实锤。4 框时 1、2 号页在前段命中过，却按"来得早"被 5、1、2、3、4 连续挤出；3 框时 1、2 的命中恰好拖后了它们的淘汰，反而少缺一次。

> **考点**：**只有 FIFO 会产生 Belady 异常**；OPT、LRU、Clock 都不会——页框越多缺页只减不增。
> **易错点**：并非所有序列都会异常。例如访问序列 1, 2, 3, 4 做 FIFO：3 框缺页 4 次，4 框也缺页 4 次（未增多）——Belady 异常只对**特定序列**发生，答题时别写"页框增加缺页必增多"。

### 最近最久未使用置换算法 LRU

**LRU（Least Recently Used）**：淘汰**过去最长时间没有被访问**的页面——用"**过去的访问历史**"预测未来：最近用过的页大概率马上还用。

- **性能最接近 OPT**（OPT 看"未来最久不用"，LRU 看"过去最久未用"，一字之差）；
- 需要硬件支持记录访问时间：**计数器**（每页一个时间戳寄存器，每次访存都更新）或**寄存器栈**（每次访问把页号压到栈顶，栈底即最久未用页）；
- 因为**每条访存指令都要更新记录**，硬件开销大，实际系统常用 **Clock 算法近似**。

> **考点**：LRU **可实现但开销大**；OPT **不可实现**。"淘汰最久未使用的"对应 LRU，"淘汰未来最久不使用的"对应 OPT——选择填空高频混淆点。

### 时钟置换算法 Clock（NRU）与改进型

**Clock 算法**（又称 **NRU，最近未使用**）：给每页配一个**访问位 A**，内存中所有页面排成**循环队列**，扫描指针逐帧轮转。

- 页面**装入内存或被访问（命中）时**，硬件把它的访问位置 1（软件**不清位**，命中不清零）；
- **缺页时**指针从当前位置**循环扫描**：遇到 **A=1 的页，清 0 后继续前进**（给它"第二次机会"）；遇到 **A=0 的页，淘汰**，装入新页，指针停在下一位置；
- 是 **LRU 的低开销近似**：无需精确时间戳，只记"最近用没用过"。

**改进型 Clock**：在访问位之外再引入**修改位 M**——优先淘汰**既没被访问、又不用写回**的页，把换出代价降到最低。页面按 (A, M) 分为四类，淘汰优先级从高到低：

| 类别 (A, M) | 含义 | 淘汰优先级 |
|:---|:---|:---|
| **(0, 0)** | 最近未访问、未修改 | **第一优先**（代价最小：不写盘） |
| **(0, 1)** | 最近未访问、已修改 | 第二优先（需写回外存） |
| **(1, 0)** | 最近被访问、未修改 | 第三优先 |
| **(1, 1)** | 最近被访问、已修改 | **最后**（最不该淘汰） |

扫描过程最多四轮：**第一轮**找 (0,0)；**第二轮**找 (0,1)，扫过的页**顺带把 A 清 0**；**第三轮**再找 (0,0)（原 (1,0) 已被清成 (0,0)）；**第四轮**必能淘汰 (0,1)（原 (1,1) 已变成 (0,1)）。

> **考点**：改进型 Clock **优先淘汰 (0,0)**——既"最近没用"（大概率近期也不会用）又"没改过"（淘汰**不用写回外存**），两项开销同时最小。
> **易错点**：简单 Clock 最坏情形（所有页 A 全为 1）会退化成"扫一整圈全清 0、再淘汰指针处的页"，行为趋近 FIFO。

### 缺页率演算：同一序列跑三种算法（核心例题）

**题目**：页面走向 **7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0, 1, 7, 0, 1**（共 20 次访问），分配 **3 个页框**，分别用 FIFO、LRU、OPT 置换，求各自缺页次数与缺页率。其中

$$缺页率 = \frac{缺页次数}{访问总次数}$$

**FIFO（淘汰最早进入的页）**：

| 步 | 访问 | 内存内容（3 个页框） | 是否缺页 |
|:---|:---|:---|:---|
| 1 | 7 | 7 | 缺页 |
| 2 | 0 | 7, 0 | 缺页 |
| 3 | 1 | 7, 0, 1 | 缺页 |
| 4 | 2 | 2, 0, 1（淘汰 7） | 缺页 |
| 5 | 0 | 2, 0, 1 | 命中 |
| 6 | 3 | 2, 3, 1（淘汰 0） | 缺页 |
| 7 | 0 | 2, 3, 0（淘汰 1） | 缺页 |
| 8 | 4 | 4, 3, 0（淘汰 2） | 缺页 |
| 9 | 2 | 4, 2, 0（淘汰 3） | 缺页 |
| 10 | 3 | 4, 2, 3（淘汰 0） | 缺页 |
| 11 | 0 | 0, 2, 3（淘汰 4） | 缺页 |
| 12 | 3 | 0, 2, 3 | 命中 |
| 13 | 2 | 0, 2, 3 | 命中 |
| 14 | 1 | 0, 1, 3（淘汰 2） | 缺页 |
| 15 | 2 | 0, 1, 2（淘汰 3） | 缺页 |
| 16 | 0 | 0, 1, 2 | 命中 |
| 17 | 1 | 0, 1, 2 | 命中 |
| 18 | 7 | 7, 1, 2（淘汰 0） | 缺页 |
| 19 | 0 | 7, 0, 2（淘汰 1） | 缺页 |
| 20 | 1 | 7, 0, 1（淘汰 2） | 缺页 |

**LRU（淘汰过去最久未使用的页）**：

| 步 | 访问 | 内存内容（3 个页框） | 是否缺页 |
|:---|:---|:---|:---|
| 1 | 7 | 7 | 缺页 |
| 2 | 0 | 7, 0 | 缺页 |
| 3 | 1 | 7, 0, 1 | 缺页 |
| 4 | 2 | 2, 0, 1（淘汰 7） | 缺页 |
| 5 | 0 | 2, 0, 1 | 命中 |
| 6 | 3 | 2, 0, 3（淘汰 1） | 缺页 |
| 7 | 0 | 2, 0, 3 | 命中 |
| 8 | 4 | 4, 0, 3（淘汰 2） | 缺页 |
| 9 | 2 | 4, 0, 2（淘汰 3） | 缺页 |
| 10 | 3 | 4, 3, 2（淘汰 0） | 缺页 |
| 11 | 0 | 0, 3, 2（淘汰 4） | 缺页 |
| 12 | 3 | 0, 3, 2 | 命中 |
| 13 | 2 | 0, 3, 2 | 命中 |
| 14 | 1 | 1, 3, 2（淘汰 0） | 缺页 |
| 15 | 2 | 1, 3, 2 | 命中 |
| 16 | 0 | 1, 0, 2（淘汰 3） | 缺页 |
| 17 | 1 | 1, 0, 2 | 命中 |
| 18 | 7 | 1, 0, 7（淘汰 2） | 缺页 |
| 19 | 0 | 1, 0, 7 | 命中 |
| 20 | 1 | 1, 0, 7 | 命中 |

**OPT（淘汰未来最久不再使用的页）**：

| 步 | 访问 | 内存内容（3 个页框） | 是否缺页 |
|:---|:---|:---|:---|
| 1 | 7 | 7 | 缺页 |
| 2 | 0 | 7, 0 | 缺页 |
| 3 | 1 | 7, 0, 1 | 缺页 |
| 4 | 2 | 2, 0, 1（淘汰 7，之后再也不用） | 缺页 |
| 5 | 0 | 2, 0, 1 | 命中 |
| 6 | 3 | 2, 0, 3（淘汰 1，下一次使用最远） | 缺页 |
| 7 | 0 | 2, 0, 3 | 命中 |
| 8 | 4 | 2, 4, 3（淘汰 0，下一次使用最远） | 缺页 |
| 9 | 2 | 2, 4, 3 | 命中 |
| 10 | 3 | 2, 4, 3 | 命中 |
| 11 | 0 | 2, 0, 3（淘汰 4，之后再也不用） | 缺页 |
| 12 | 3 | 2, 0, 3 | 命中 |
| 13 | 2 | 2, 0, 3 | 命中 |
| 14 | 1 | 2, 0, 1（淘汰 3，之后再也不用） | 缺页 |
| 15 | 2 | 2, 0, 1 | 命中 |
| 16 | 0 | 2, 0, 1 | 命中 |
| 17 | 1 | 2, 0, 1 | 命中 |
| 18 | 7 | 7, 0, 1（淘汰 2，之后再也不用） | 缺页 |
| 19 | 0 | 7, 0, 1 | 命中 |
| 20 | 1 | 7, 0, 1 | 命中 |

**三种算法结果汇总**：

| 算法 | 缺页次数 | 命中次数 | 缺页率 |
|:---|:---|:---|:---|
| OPT | **9** | 11 | 9/20 = **45%** |
| LRU | **12** | 8 | 12/20 = **60%** |
| FIFO | **15** | 5 | 15/20 = **75%** |

**结论**：缺页次数 **OPT(9) < LRU(12) < FIFO(15)**——LRU 用"过去的局部性"很好地逼近了 OPT；FIFO 无视使用情况，最差。

> **考点**：手算大题按"步"列表逐个填，每一步先判**命中/缺页**，缺页再按算法**选定淘汰页**；3 个页框需要 3 步"冷启动"装满，这 3 步必缺页。
> **易错点**：FIFO 的淘汰顺序按**调入时间**而非页号；LRU 在命中后要**更新该页的"最近使用时间"**——第 5 步命中 0 之后，最久未用页就从 7 变成了 1。

### 四种置换算法大对比

| 算法 | 淘汰依据 | 能否实现 | 优点 | 缺点 | Belady 异常 |
|:---|:---|:---|:---|:---|:---|
| **OPT** | **未来**最久不被访问 | **否**（需预知未来） | 缺页率最低，理论最优 | 只能作评价基准 | 不会 |
| **FIFO** | **最早进入内存** | 是 | 实现极简（一个队列） | 与使用频率无关，性能最差 | **可能发生** |
| **Clock** | 访问位 A（最近是否用过） | 是 | 近似 LRU，开销小 | 记录粒度粗，性能略逊 LRU | 不会 |
| **LRU** | **过去**最久未被访问 | 是（需计数器/栈） | 性能最接近 OPT | 每次访存都要更新，**硬件开销大** | 不会 |

> **考点**：题目给"改进性能"的选项时——换用 LRU/Clock、增加页框、预调页都可降低缺页率；而"增加页框"对 FIFO 不一定有效（Belady 异常）。

## 内存映射文件

**内存映射文件（Memory-Mapped File）**：通过 `mmap` 把磁盘上的**文件映射到进程虚拟地址空间**的一段区域，之后像访问内存数组一样读写文件——首次访问某页时经**缺页中断按需从文件调入**，修改后由系统写回文件；**多个进程映射同一文件**即共享同一片物理页框，可作**进程间通信（共享内存）**的实现方式。

> **考点**：内存映射文件 = **请求分页思想在文件访问上的应用**；映射同一文件实现**共享内存**，还省去了 read/write 的系统调用与两次数据拷贝。

## 虚拟存储器性能的影响因素及改进方法

### 抖动（颠簸）

**抖动（Thrashing）**：进程**刚换出的页马上又要用**，系统不停地在内存与外存之间倒腾页面，**CPU 大部分时间忙于换页，利用率急剧下降**。

- **直接原因**：分配给进程的**页框数小于其工作集**（活跃页装不下），或内存中**进程过多**、页框被摊薄；
- **恶性循环**：CPU 利用率低 → 系统误以为进程太少，**继续调入更多进程** → 页框更紧张 → 缺页更凶，抖动加剧；
- 到达"抖动拐点"后，**增加进程数/换入进程只会更糟**。

> **考点**：抖动是**全局性**现象（全系统缺页率高、CPU 利用率骤降），不是单个进程偶尔缺页多；根因是**驻留集 < 工作集**。

### 工作集

**工作集 W(t, Δ)**：进程在时刻 t 之前的 **Δ 次页面访问**中实际访问到的**页面集合**（滑动窗口，随时间变化）。例：访问序列 ... 4, 3, 2, 4, 3, 2, 4, 3, 2, 1, 2, 1, 2, 1, 3，取 Δ=5，则时刻 t 的最近 5 次访问为 [3, 2, 4, 3, 2]，**工作集 = {2, 3, 4}**。

- 工作集大小反映进程当前的**局部性程度**；
- **驻留集 ≥ 工作集** → 缺页少、运行平稳；**驻留集 < 工作集** → 频繁缺页 → 抖动。

### 有效访问时间与缺页率

设缺页率为 $f$，一次访存时间为 $t_m$，一次缺页处理的平均时间为 $t_p$（含缺页中断处理与磁盘 I/O，**毫秒级**，比纳秒级访存慢约 $10^4 \sim 10^5$ 倍）：

$$EAT = (1 - f) \times t_m + f \times t_p$$

**例题**：访存时间 100ns，缺页处理时间 8ms，缺页率 f = 0.0001：

$$EAT = 0.9999 \times 100 + 0.0001 \times 8 \times 10^6 \approx 99.99 + 800 = 900\,\text{ns}$$

缺页率仅万分之一，有效访问时间就涨到原来的约 **9 倍**——**降低缺页率是提升虚拟存储器性能的核心**。

### 影响缺页率的因素与改进方法

| 影响因素 | 对缺页率的影响 | 改进方法 |
|:---|:---|:---|
| **页面大小** | 页大 → 页表小、页内碎片大；页小 → 页表大、缺页次数多 | **折中选取**页面大小 |
| **程序局部性** | 局部性越好缺页越少 | 改写程序：数组**按行遍历**、顺序访问 |
| **驻留集（页框数）** | 页框越多缺页越少，但边际递减 | 保证**驻留集 ≥ 工作集** |
| **置换算法** | LRU/Clock 明显优于 FIFO | 选用**更好的置换算法** |
| **调入策略** | 请求调页一次只调一页 | **预调页**：利用空间局部性一次调入若干相邻页 |
| **写回开销** | M=1 的页换出要先写盘，拖慢缺页处理 | 延迟写/成批写回，减少写盘次数 |

**程序结构经典例题**：128×128 的 int 数组按行连续存放，**每页恰好放一行**，进程只有 1 个页框——行优先遍历（外层 i 内层 j）**每行缺页一次，共 128 次**；列优先遍历（外层 j 内层 i）每次访问都跳到别的页，缺页 **128×128 = 16384 次**。同样的程序与页框数，仅访问顺序不同，缺页相差 **128 倍**。

**预防/消除抖动的措施**：采用**局部置换**（隔离缺页）；按**工作集模型**动态调整驻留集；遵循 **L=S 准则**（缺页间隔 L 与缺页处理时间 S 相当时效率最高）；**挂起（换出）部分进程**腾出页框；选用 LRU/Clock 等好算法。

## 高频考点速记

| 考点 | 记忆 |
|:---|:---|
| 局部性原理 | **时间局部性**（循环、重复调用）+ **空间局部性**（顺序执行、数组）——虚拟内存的理论基础 |
| 虚拟内存三特征 | **多次性**（最重要、区别于传统管理）、**对换性**、**虚拟性**（最终目标） |
| 虚存容量 | $\le \min(2^{地址位数},\ 内外存容量之和)$；32 位系统上限 4GB，**与物理内存大小无关** |
| 实现方式 | 请求分页 / 请求分段 / 请求段页式 = 基本管理 + **请求调入 + 置换** |
| 请求页表新增字段 | **状态位 P**（是否在内存）、**访问位 A**（供置换用）、**修改位 M**（换出是否写回）、**外存地址** |
| 缺页中断 | **内中断（故障）**；**指令执行期间**产生、一条指令可产生**多次**；处理后**重新执行原指令** |
| 缺页处理七步 | 保留现场 → 找页 → 分配页框 →（无空则置换，M=1 先写回）→ 调入 → 更新页表快表 → 重执行指令 |
| 驻留集 | 进程在内存中的页面集合：**过小 → 缺页多 CPU 忙换页；过大 → 浪费内存、并发度下降** |
| 页框分配算法 | **平均分配 / 按比例分配（按进程大小）/ 优先级分配** |
| 置换组合 | 可行：**固定+局部、可变+全局、可变+局部**；不可行：**固定+全局** |
| OPT | 淘汰**未来最久不用**；缺页率最低但**不可实现**，只作评价基准 |
| FIFO | 淘汰**最早进入**；实现最简单、性能最差；**唯一可能 Belady 异常**（3 框 9 次 vs 4 框 10 次） |
| LRU | 淘汰**过去最久未用**；**性能最接近 OPT**；需计数器/栈，**开销大** |
| Clock / 改进 Clock | 访问位循环扫描：A=1 清 0 继续、A=0 淘汰；改进型优先淘汰 **(A=0, M=0)** → (0,1) → (1,0) → (1,1) |
| 抖动与工作集 | 驻留集 **< 工作集** → 抖动（CPU 利用率骤降）；**驻留集 ≥ 工作集**才平稳；措施：局部置换、L=S、挂起进程 |
| EAT 与性能 | $EAT=(1-f)t_m + f\,t_p$；缺页处理毫秒级，缺页率极小也致命；改进：预调页、按行访问、好算法 |
