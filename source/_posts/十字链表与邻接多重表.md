邻接矩阵与邻接表（含逆邻接表）是图最常用的两种存储结构，但各有短板：**邻接矩阵空间 $O(n^2)$，稀疏图太浪费**；**邻接表虽省空间，却有向图难找入边（要另建逆邻接表）、无向图每条边要存两份**。为此考纲引入两种专用链式存储：**十字链表（Orthogonal List）**把邻接表与逆邻接表**合二为一**，专用于**有向图**；**邻接多重表（Adjacency Multilist）**让每条边**只存一个结点**，专用于**无向图**。两者空间复杂度均为 $O(n+e)$，是 408 选择题的高频出题点。

## 十字链表（有向图）

十字链表在邻接表的基础上，再为每个顶点补一条**入弧链表**：每条弧只占**一个结点**，同时挂在**弧尾的出弧链**和**弧头的入弧链**上——相当于把邻接表（沿 `firstout` 找出边）和逆邻接表（沿 `firstin` 找入边）合并存储，出度、入度都能高效求得。

### 结点结构

```text
     顶点结点 (VexNode)                   弧结点 (ArcBox)
┌──────┬─────────┬──────────┐   ┌─────────┬─────────┬───────┬───────┬──────┐
│ data │ firstin │ firstout │   │ tailvex │ headvex │ hlink │ tlink │ info │
└──────┴─────────┴──────────┘   └─────────┴─────────┴───────┴───────┴──────┘
```

| 字段 | 含义 |
|:---|:---|
| `firstin` | 顶点的**第一条入弧**（入弧链入口，相当于逆邻接表的表头指针） |
| `firstout` | 顶点的**第一条出弧**（出弧链入口，相当于邻接表的表头指针） |
| `tailvex` | 弧尾顶点下标（弧从谁发出） |
| `headvex` | 弧头顶点下标（弧指向谁） |
| `hlink` | 指向下一条**弧头相同**的弧（同在该弧头的入弧链上） |
| `tlink` | 指向下一条**弧尾相同**的弧（同在该弧尾的出弧链上） |
| `info` | 弧的权值等信息 |

> **考点**：**hlink 记 head（弧头）→ 入弧链；tlink 记 tail（弧尾）→ 出弧链**。顺 `tlink` 数出边求出度、顺 `hlink` 数入边求入度，**不必再建逆邻接表**。

### 结构定义

```c
typedef struct ArcBox {
    int tailvex, headvex;              // 弧尾、弧头顶点的下标
    struct ArcBox *hlink, *tlink;      // hlink 入弧链、tlink 出弧链
    InfoType info;                     // 弧的权值等信息
} ArcBox;

typedef struct {
    VexType data;
    ArcBox *firstin, *firstout;        // 第一条入弧、第一条出弧
} VexNode;

typedef struct {
    VexNode xlist[MAX_VEX];            // 顶点数组
    int vexnum, arcnum;                // 顶点数、弧数
} OLGraph;
```

### 完整示例：建十字链表并找入边/出边

有向图：顶点 $V_0$、$V_1$、$V_2$、$V_3$；弧集 $\langle V_0,V_1\rangle$、$\langle V_0,V_2\rangle$、$\langle V_1,V_3\rangle$、$\langle V_2,V_1\rangle$，共 4 条弧，对应 4 个弧结点 A0、A1、A2、A3。

```text
弧结点（每条弧只存一份；hlink 连同弧头，tlink 连同弧尾）
┌────┬─────────┬─────────┬──────────┬──────────┐
│ 弧 │ tailvex │ headvex │ hlink    │ tlink    │
├────┼─────────┼─────────┼──────────┼──────────┤
│ A0 │   0     │   1     │ → A3     │ → A1     │   <v0,v1>
│ A1 │   0     │   2     │ → ∧      │ → ∧      │   <v0,v2>
│ A2 │   1     │   3     │ → ∧      │ → ∧      │   <v1,v3>
│ A3 │   2     │   1     │ → ∧      │ → ∧      │   <v2,v1>
└────┴─────────┴─────────┴──────────┴──────────┘

顶点结点（firstin 串入弧链，firstout 串出弧链）
┌────┬───────────┬────────────┐
│顶点│ firstin   │ firstout   │
├────┼───────────┼────────────┤
│ v0 │    ∧      │ → A0       │
│ v1 │ → A0      │ → A2       │
│ v2 │ → A1      │ → A3       │
│ v3 │ → A2      │    ∧       │
└────┴───────────┴────────────┘

出弧链（顺 tlink）：v0 ─firstout→ A0<v0,v1> ─tlink→ A1<v0,v2> ─tlink→ ∧
入弧链（顺 hlink）：v1 ─firstin→ A0<v0,v1> ─hlink→ A3<v2,v1> ─hlink→ ∧
```

**找所有出边（求出度）**：从 `v0.firstout` 出发 → A0（$\langle v_0,v_1\rangle$）→ 顺 `tlink` → A1（$\langle v_0,v_2\rangle$）→ `tlink = ∧` 结束，共 2 条，出度为 2。

**找所有入边（求入度）**：从 `v1.firstin` 出发 → A0（$\langle v_0,v_1\rangle$）→ 顺 `hlink` → A3（$\langle v_2,v_1\rangle$）→ `hlink = ∧` 结束，共 2 条，入度为 2。

![有向图的十字链表示例](/blog/images/第6章 图.assets/1062579-20171110191910653-695287627.png)

> **易错点**：十字链表**只适用于有向图**——无向图的边没有方向，"入弧链/出弧链"无从谈起；无向图的对应结构是邻接多重表。

## 邻接多重表（无向图）

邻接表存无向图时，每条边 $(u,v)$ 在 $u$、$v$ 两个顶点的边表里**各存一个结点**（共 2 份），带来两个麻烦：**删除一条边要改两条单链表**；**给边做标记（如图遍历中标记边已访问）要同步两处**。邻接多重表的对策：**每条边只建一个边结点**，让它同时挂在所依附的两个顶点的边链表中。

### 结点结构

```text
    顶点结点 (VexBox)                        边结点 (EBox)
┌──────┬───────────┐      ┌──────┬──────┬───────┬──────┬───────┬──────┐
│ data │ firstedge │      │ mark │ ivex │ ilink │ jvex │ jlink │ info │
└──────┴───────────┘      └──────┴──────┴───────┴──────┴───────┴──────┘
```

| 字段 | 含义 |
|:---|:---|
| `firstedge` | 指向**第一条依附于该顶点**的边 |
| `mark` | 标志域，标记该边是否被访问过 |
| `ivex` / `jvex` | 该边依附的**两个顶点**的下标 |
| `ilink` | 指向下一条**依附于 ivex** 的边（ivex 侧的边链） |
| `jlink` | 指向下一条**依附于 jvex** 的边（jvex 侧的边链） |
| `info` | 边的权值等信息 |

> **考点**：一条边 $(u,v)$ **只有一个结点**，却同时出现在 $u$ 的边链（沿 `ilink` 走）和 $v$ 的边链（沿 `jlink` 走）中——**一份存储、两条链路**。

### 结构定义

```c
typedef struct EBox {
    int mark;                          // 访问标记
    int ivex, jvex;                    // 边依附的两个顶点下标
    struct EBox *ilink, *jlink;        // ivex 侧、jvex 侧的下一条依附边
    InfoType info;                     // 边的权值等信息
} EBox;

typedef struct {
    VexType data;
    EBox *firstedge;                   // 第一条依附于该顶点的边
} VexBox;

typedef struct {
    VexBox adjmulist[MAX_VEX];         // 顶点数组
    int vexnum, edgenum;               // 顶点数、边数
} AMLGraph;
```

### 完整示例：建邻接多重表

无向图：顶点 $V_0$、$V_1$、$V_2$、$V_3$；边集 $(V_0,V_1)$、$(V_0,V_2)$、$(V_1,V_2)$、$(V_2,V_3)$，共 4 条边，每条只存 1 个边结点 e0、e1、e2、e3（约定小下标作 ivex）。

```text
边结点
┌────┬──────┬───────┬──────┬───────┬──────────┐
│ 边 │ ivex │ ilink │ jvex │ jlink │ 依附顶点 │
├────┼──────┼───────┼──────┼───────┼──────────┤
│ e0 │  0   │ → e1  │  1   │ → e2  │ (v0,v1)  │
│ e1 │  0   │ → ∧   │  2   │ → e2  │ (v0,v2)  │
│ e2 │  1   │ → ∧   │  2   │ → e3  │ (v1,v2)  │
│ e3 │  2   │ → ∧   │  3   │ → ∧   │ (v2,v3)  │
└────┴──────┴───────┴──────┴───────┴──────────┘

顶点表：v0.firstedge→e0   v1.firstedge→e0   v2.firstedge→e1   v3.firstedge→e3

v0 的边链：e0(v0,v1) ─ilink→ e1(v0,v2) ─ilink→ ∧
v1 的边链：e0(v0,v1) ─jlink→ e2(v1,v2) ─ilink→ ∧
v2 的边链：e1(v0,v2) ─jlink→ e2(v1,v2) ─jlink→ e3(v2,v3) ─ilink→ ∧
（从某条边走向下一条时，走 ilink 还是 jlink 取决于该顶点在 ivex 还是 jvex 侧）
```

### 删边对比演示：只改一处 vs 改两处

删除边 $(V_1,V_2)$，即边结点 e2：

- **邻接多重表**：e2 只是**一个**结点。把 v1 边链上的前驱 e0 的 `jlink` 改为 `e2.ilink`（∧），把 v2 边链上的前驱 e1 的 `jlink` 改为 `e2.jlink`（e3），再释放 e2。两个链域的值都从 e2 自身出发即可取得，**释放的边结点只有 1 个**。
- **邻接表**：同一条边被复制成**两个**结点，分别在 v1、v2 的边表里；必须**在两条单链表中各找前驱、各删一个结点**，释放 2 个结点。

| 操作 | 邻接表（无向图） | 邻接多重表 |
|:---|:---|:---|
| 删除一条边 | 在两个顶点的边表**各删一个结点**（改 2 处） | 只删 **1 个**边结点（改其两个前驱的链域） |
| 标记边已访问 | 同一条边的两个结点要**同步标记**（或另设辅助数组） | 改该边结点自己的 `mark`，**一处即可** |
| 边结点个数 | $2e$ | $e$（省约一半） |
| 空间复杂度 | $O(n+2e)$ | $O(n+e)$ |

> **考点**：邻接多重表专为**无向图中边操作频繁**（删边、标记边）的场景设计；若只做"找邻接点、图遍历"，普通邻接表同样够用。

## 五种图存储结构总对比

结合前两篇的邻接矩阵、邻接表（含逆邻接表），五种结构对比如下（收官大表）：

| 存储结构 | 适用图 | 空间复杂度 | 找邻接点/出边 | 找入边（入度） | 判边是否方便 | 特点 |
|:---|:---|:---|:---|:---|:---|:---|
| 邻接矩阵 | 有向/无向，**稠密图** | $O(n^2)$ | 遍历该行，$O(n)$ | 遍历该列，$O(n)$ | **$O(1)$ 最方便** | 简单直观，稀疏图浪费 |
| 邻接表 | 有向/无向，**稀疏图** | $O(n+e)$（无向 $O(n+2e)$） | 顺边链，$O(\deg)$ | 需**另建逆邻接表** | $O(\deg)$ | 无向图每边存 2 份 |
| 逆邻接表 | 有向图 | $O(n+e)$ | 不便（存的全是入边） | 顺入边链，$O(\text{in})$ | $O(\text{in})$ | 与邻接表二选一，难两全 |
| **十字链表** | **有向图** | $O(n+e)$ | 顺 `tlink`，$O(\text{out})$ | 顺 `hlink`，$O(\text{in})$ | $O(\text{out})$ | 邻接表 + 逆邻接表**合体** |
| **邻接多重表** | **无向图** | $O(n+e)$ | 顺边链，$O(\deg)$ | —（边链长度即度） | $O(\deg)$ | 每边 **1** 个结点，边操作高效 |

> **考点**：按操作场景选结构——"**既方便找出边又方便找入边**"选**十字链表**；"**对边删除/标记操作多**"选**邻接多重表**；"**判断两顶点间是否有边**"选**邻接矩阵**（$O(1)$）；"**稀疏图省空间 + 方便遍历邻接点**"选**邻接表**。

## 高频考点速记

| 考点 | 记忆 |
|:---|:---|
| 十字链表适用 | **有向图**专用；邻接表 + 逆邻接表**合二为一** |
| 十字链表顶点结点 | data + **firstin**（入弧链入口）+ **firstout**（出弧链入口） |
| 弧结点信息域 | tailvex（弧尾）+ headvex（弧头）+ **hlink**（同弧头的下一条弧）+ **tlink**（同弧尾的下一条弧） |
| 记忆口诀 | **h = head 弧头 → 入弧链求入度；t = tail 弧尾 → 出弧链求出度** |
| 邻接多重表适用 | **无向图**专用；每条边**只存 1 个结点** |
| 边结点信息域 | mark（访问标记）+ ivex/jvex（两端下标）+ **ilink**（下一条依附 ivex）+ jlink（下一条依附 jvex）+ info |
| 核心优点 | 删边、标记边**只动 1 个结点**；邻接表同一条边存 2 份、要改 2 处 |
| 空间复杂度 | 十字链表、邻接多重表均 $O(n+e)$；无向图邻接表 $O(n+2e)$；邻接矩阵 $O(n^2)$ |
| 不可混用 | 十字链表不能存无向图，邻接多重表不能存有向图 |
| 结构选择 | 判边快→邻接矩阵；省空间→邻接表；出入边都要→十字链表；边操作多→邻接多重表 |
