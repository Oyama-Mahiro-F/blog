**万维网 WWW（World Wide Web）**是一个基于**超文本**的、分布式的全球信息服务系统；**HTTP（HyperText Transfer Protocol，超文本传输协议）**则是支撑它的核心应用层协议，也是 408 应用层分值最高的考点。408 对这部分考查集中在：**WWW 三要素与 URL 格式、HTTP 报文结构、请求方法与状态码、持续/非持续连接的 RTT 时延计算、Cookie**。

## WWW 概念与组成结构

**WWW** 以**超文本标记语言 HTML** 编写网页文档，每个资源用 **URL** 唯一定位，文档之间以**超链接（Hyperlink）**相互引用，通过 **HTTP 协议**传输。WWW 的三大核心是：**URL（定位资源）、HTML（编写文档）、HTTP（传输协议）**。

- 工作模式：**C/S（客户/服务器）**——**浏览器**是客户程序，主动向 Web 服务器发出请求；服务器存储文档并返回响应

### 万维网文档

万维网上的文档按**生成方式**分为三类：

| 文档类型 | 生成方式 | 例子 |
|:---|:---|:---|
| **静态文档** | HTML **事先写好**，内容固定不变 | 纯 HTML 介绍页 |
| **动态文档** | 服务器收到请求后**临时生成**，服务器端接口是 **CGI（通用网关接口）** | 查询结果页、留言板 |
| **活动文档** | 服务器把**程序**发给浏览器，在**本地执行**后展现 | JavaScript 页面 |

> **考点**：动态文档在**服务器端**生成（CGI），活动文档在**浏览器端**执行——"谁生成"是区分点。

### URL：统一资源定位符

```text
协议 :// 主机名[:端口] / 路径
例：http://www.example.com:80/cs/index.html
```

| 组成 | 本例取值 | 说明 |
|:---|:---|:---|
| **协议** | http | 也可以是 https、ftp 等 |
| **主机名** | www.example.com | 域名（或 IP 地址） |
| **端口** | :80 | **HTTP 默认 80、HTTPS 默认 443**，取默认值时可省略 |
| **路径** | /cs/index.html | 省略时服务器返回**默认首页**（如 index.html） |

**在浏览器输入网址到看到页面的完整过程**（每一层协议都要能答出来）：

```text
① 浏览器分析 URL，取出域名
② DNS 解析域名得到 IP 地址（UDP 53，递归 + 迭代）
③ 浏览器与 Web 服务器建立 TCP 连接（三次握手，端口 80）
④ 浏览器发送 HTTP 请求报文（GET /index.html）
⑤ 服务器返回 HTTP 响应报文（含 HTML 文档）
⑥ 释放 TCP 连接（非持续连接时）
⑦ 浏览器解释 HTML 并渲染显示
```

> **考点**：一句话口诀——**"域名用 DNS（UDP 53）、传输靠 TCP（80）、网页走 HTTP"**；URL 四要素 = **协议 + 主机 + 端口 + 路径**。

**一次网页访问涉及的协议汇总**：

| 环节 | 协议 | 传输层 / 端口 |
|:---|:---|:---|
| 域名解析 | DNS | **UDP 53**（区域传送用 TCP 53） |
| 建立 / 释放连接 | TCP 三次握手 / 四次挥手 | **端口 80** |
| 传输网页文档与对象 | HTTP | TCP 80 |

## HTTP 协议

### HTTP 的特点

| 特点 | 说明 |
|:---|:---|
| 传输层用 **TCP** | 默认端口 **80**（HTTPS 用 443），保证可靠传输 |
| **无状态（Stateless）** | 服务器**不记忆**客户及其历史请求，每个请求独立处理——实现简单、便于做集群；需要"记住用户"时靠 **Cookie** 弥补 |
| **灵活** | 可传输**任意类型**的数据（文本、图片、视频…），由首部 **Content-Type** 标明类型 |
| 请求-响应模式 | 一次请求 + 一次响应构成一个事务；通信**始终由客户（浏览器）发起** |
| 明文传输 | HTTP 本身不加密；**HTTPS = HTTP + SSL/TLS**（端口 443）提供加密与身份认证 |

### Cookie：弥补无状态

- 用户首次访问网站时，服务器生成一个唯一的**识别码（session ID）**，在响应报文的 **Set-cookie 首部行**中下发
- 浏览器把识别码存为**本地 Cookie 文件**；之后每次请求该网站，都在请求报文的 **Cookie 首部行**中把识别码**带回**
- 服务器凭识别码认出"这是同一个用户"，从而实现**会话跟踪**（购物车、登录状态等）

> **考点**：HTTP **无状态**，靠 **Cookie** 弥补；**Cookie 保存在客户端、Session 保存在服务器端**，两者用 session ID 关联。

### HTTP 报文结构

**请求报文**（客户端 → 服务器）：

```text
GET /cs/index.html HTTP/1.1        ← 请求行：方法 URL HTTP版本
Host: www.example.com              ← 首部行
Connection: keep-alive             ← 首部行
User-Agent: Mozilla/5.0            ← 首部行
                                   ← 空行（CRLF，分隔首部与主体）
（实体主体：GET 请求一般为空）      ← 实体主体
```

**响应报文**（服务器 → 客户端）：

```text
HTTP/1.1 200 OK                    ← 状态行：HTTP版本 状态码 短语
Server: nginx                      ← 首部行
Content-Type: text/html            ← 首部行
Content-Length: 1024               ← 首部行
                                   ← 空行
<html>...</html>                   ← 实体主体
```

| 报文 | 结构 |
|:---|:---|
| **请求报文** | **请求行（方法 URL 版本）** + 首部行 + 空行 + 实体主体 |
| **响应报文** | **状态行（版本 状态码 短语）** + 首部行 + 空行 + 实体主体 |

> **易错点**：请求行和状态行都**没有"首部"二字**却最容易混——请求行以**方法**开头，状态行以**版本**开头、状态码在中间；首部行之后必须有**空行**。

### 请求方法

| 方法 | 作用 | 说明 |
|:---|:---|:---|
| **GET** | **读取**指定资源 | 最常用；参数拼接在 URL 之后 |
| **POST** | 向服务器**提交**数据（如表单） | 数据放在**实体主体**中 |
| **HEAD** | 只要**首部**、不要正文 | 用于检查资源是否存在、是否被修改 |
| **PUT** | **上传/替换**资源 | 把实体主体存放到指定 URL |
| **DELETE** | **删除**指定资源 | — |

**GET vs POST 对比**：

| 对比项 | GET | POST |
|:---|:---|:---|
| 语义 | **获取**资源 | **提交**数据、请求处理 |
| 参数位置 | 拼在 **URL** 后（?a=1&b=2），**可见** | 放在**实体主体**中，**不可见** |
| 长度 | URL 长度有限，参数**有上限** | 主体可以很大 |
| 后果 | 幂等（多次请求无副作用）、可缓存/收藏 | 通常有副作用、不被缓存 |

### 状态码

状态码是三位数字，**首位（1&#126;5）表示类别**：

| 类别 | 含义 | 典型例子 |
|:---|:---|:---|
| **1xx** | 信息提示（请求已收到，继续处理） | 100 Continue |
| **2xx** | **成功** | **200 OK** |
| **3xx** | **重定向**（需进一步操作才能完成） | **301** 永久移动、**302** 临时移动 |
| **4xx** | **客户端错误** | **404 Not Found**、403 Forbidden |
| **5xx** | **服务器错误** | **500** 服务器内部错误 |

> **考点**：**2 成功（200）、3 重定向（301/302）、4 客户端错（404）、5 服务器错（500）**。
> **易错点**：**404 属于客户端错误**（请求的资源在服务器上不存在），不是服务器故障；服务器内部出错才是 **500**。

### 非持续连接与持续连接

| 对比项 | 非持续连接（HTTP/1.0） | 持续连接（HTTP/1.1，**默认**） |
|:---|:---|:---|
| TCP 连接数 | **每个对象都新建一条** TCP 连接，传完即断 | **一条** TCP 连接上先后传完多个对象 |
| 每对象开销 | **2 RTT**（1 RTT 建连 + 1 RTT 请求/响应） | 建连只花 **1 次** RTT，此后每对象 **1 RTT** |
| 总时延 | 对象越多时延越大（反复握手/挥手） | 明显更小 |
| 非流水线方式 | — | 发一个请求、等一个响应，再发下一个（串行） |
| 流水线方式 | — | **一次连续发出多个请求**，响应陆续全部返回（更快） |

**例题：页面加载时延计算**——某页面由 **1 个基本 HTML 文档 + 3 个图片对象**组成，往返时延 **RTT = 10 ms**，忽略传输时延与服务器处理时间。求四种方式下从发起建连到收完所有对象的总时延。

- **方式一：非持续连接（HTTP/1.0），串行请求**
  - 每个对象都要"建连 1 RTT + 请求响应 1 RTT" = **2 RTT**
  - 总时延 = $2 + 2 \times 3 = 8$ RTT = **80 ms**（HTML 2 RTT，3 张图片各 2 RTT）
- **方式二：非持续连接 + 并行连接**（浏览器同时开 3 条 TCP 连接）
  - 3 张图片的建连与请求**并行完成**，只耗 2 RTT
  - 总时延 = $2 + 2 = 4$ RTT = **40 ms**
- **方式三：持续连接，非流水线（HTTP/1.1）**
  - 建连 **1 RTT**（只花一次），之后每个对象各 1 RTT
  - 总时延 = $1 + 1 + 3 = 5$ RTT = **50 ms**（1 建连 + HTML 1 + 图片各 1）
- **方式四：持续连接 + 流水线**
  - 3 个图片请求**一次连发**，共 1 RTT 收回
  - 总时延 = $1 + 1 + 1 = 3$ RTT = **30 ms**

**验算**：流水线比非流水线节省的是图片请求之间的串行等待（$5 - 3 = 2$ RTT）；非持续串行最慢（8 RTT），持续流水线最快（3 RTT）。

| 方式 | 时延（RTT） | 实际时间 |
|:---|:---|:---|
| 非持续，串行 | $2 + 2 \times 3 = 8$ | 80 ms |
| 非持续，3 条并行 | $2 + 2 = 4$ | 40 ms |
| 持续，非流水线 | $1 + 1 + 3 = 5$ | 50 ms |
| 持续，流水线 | $1 + 1 + 1 = 3$ | 30 ms |

> **考点**：非持续连接**每个对象需 2 RTT**；**HTTP/1.1 默认持续连接**，流水线把多个请求连发、每批只需 1 RTT。
> **易错点**：持续连接的**建连 RTT 只计一次**；总时延别忘了 HTML 本身也要 1 个请求 RTT；并行连接是浏览器的优化手段，不改变 HTTP/1.0"每对象一连接"的本质。
> **补充**：流水线方式下服务器仍须**按请求顺序**返回响应；HTTP/2 在持续连接基础上进一步实现**多路复用**，可并行传输多个请求与响应。

## 高频考点速记

| 考点 | 记忆 |
|:---|:---|
| WWW 三要素 | **URL 定位、HTML 写文档、HTTP 传输**；C/S 模式，客户是浏览器 |
| URL 格式 | 协议://主机[:端口]/路径；**HTTP 80、HTTPS 443**，默认端口可省略 |
| HTTP 传输层 | **TCP 80**；通信由客户（浏览器）发起 |
| 无状态 | 服务器不记忆客户；**Cookie 弥补**（Set-cookie 下发、Cookie 首部带回） |
| Cookie vs Session | Cookie 存**客户端**，Session 存**服务器端**，用 session ID 关联 |
| 请求报文 | **请求行（方法 URL 版本）** + 首部行 + 空行 + 实体主体 |
| 响应报文 | **状态行（版本 状态码 短语）** + 首部行 + 空行 + 实体主体 |
| 请求方法 | **GET** 读、**POST** 提交（主体传参）、**HEAD** 只要首部、PUT 上传、DELETE 删除 |
| GET vs POST | GET 参数在 **URL**（可见、有限、幂等）；POST 参数在**主体**（不可见、可大） |
| 状态码 | 1&#126;5 开头：信息 / **2 成功(200)** / **3 重定向(301/302)** / **4 客户端错(404)** / **5 服务器错(500)** |
| 非持续连接 | 每对象一条 TCP 连接，**2 RTT/对象**（1 建连 + 1 请求响应） |
| 持续连接 | **HTTP/1.1 默认**；建连 1 RTT + 每对象 1 RTT；流水线每批 1 RTT |
| 万维网文档 | 静态（HTML 固定）/ 动态（服务器生成，**CGI** 接口）/ 活动文档（浏览器本地执行） |
