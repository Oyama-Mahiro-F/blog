二叉排序树（BST）的查找效率取决于树高：理想情况 $h = \lceil\log_2(n+1)\rceil$，查找 $O(\log n)$；但若按有序序列插入，BST 会**退化为单链表**（$h=n$），查找降为 $O(n)$。**平衡**就是给 BST 加约束、把树高强行压回 $O(\log n)$ 的手段，主流有两条路线：

| 路线 | 平衡手段 | 树高上界 | 代价 |
|:---|:---|:---|:---|
| **AVL 树** | 严格：任意结点左右子树高度差 $\leq 1$ | $\approx 1.44\log_2(n+1)$ | 树最矮、查找最快，但**插入/删除旋转频繁** |
| **红黑树** | 宽松：红/黑着色的 5 条规则 | $\leq 2\log_2(n+1)$ | 树略高，但**插入最多 2 次、删除最多 3 次旋转** |

> **考点**：两者**查找、插入、删除都是 $O(\log n)$**，区别不在数量级而在**常数与旋转次数**——查询为主选 AVL，增删频繁选红黑树。

## AVL 树的定义与平衡因子

AVL 在 BST 基础上添加**平衡约束**：任意结点左右子树高度差不超过 1，从而将树高控制在 $O(\log n)$。

### 结点类型定义

```c
typedef struct BSTNode {
    KeyType key;                             // 关键字域
    int Bfactor;                             // 平衡因子域（hL - hR）
    struct BSTNode *Lchild, *Rchild;         // 左、右孩子指针
} BSTNode;
```

> AVL 结点比普通 BST 结点多一个 `Bfactor` 字段。

### 定义与术语

| 术语 | 定义 |
|:---|:---|
| **平衡因子（BF）** | $BF = h_L - h_R$，取值为 $\{-1, 0, 1\}$ |
| AVL 条件 | 所有结点的 $\|BF\| \leq 1$ |
| 最小不平衡子树 | 离插入点最近的、$\|BF\| > 1$ 的结点为根的子树 |

> **易错点**：平衡因子是**左高减右高**，且**空树高度记为 0**。$\|BF\| = 2$ 就已失衡，不存在 $\|BF\| \geq 3$ 的情形——因为每插入一个结点最多让某条路径长 1，发现失衡时立即调整。

## 平衡化旋转：四种失衡类型

插入/删除后：

1. 沿路径向上更新平衡因子
2. 找到第一个 $\|BF\| > 1$ 的结点 A（最小不平衡子树的根）
   - 删除时：站在失衡节点 A 上，看左右子树谁更高——**较高的孩子就是 B**；再看 B 的左右子树谁更高——**较高的孩子就是 C**；若 B 两个孩子一样高，选**和 A 到 B 同方向的那个**
3. 根据插入位置选择旋转类型（LL / RR / LR / RL）
4. 旋转后 A 的 BF 恢复为 -1/0/1，整个树恢复平衡

| 情况 | 插入位置 | 旋转方式 | 核心操作 |
|:---|:---|:---|:---|
| **LL** | 左子树的左子树 | 右单旋 | 树的左边太重，顺时针向右"掰" |
| **RR** | 右子树的右子树 | 左单旋 | 树的右边太重，逆时针向左"掰" |
| **LR** | 左子树的右子树 | 先左后右双旋 | 先左旋捋直（变 LL 型），再整体右旋 |
| **RL** | 右子树的左子树 | 先右后左双旋 | 先右旋捋直（变 RR 型），再整体左旋 |

> **旋转法则**：被挤掉的节点，直接挂到降级节点的空缺位置上。

![AVL 四种旋转图解](/blog/images/第7章 查找.assets/1a4e065af5d8655cf23bbb45657b3be5.webp)

**LL 旋转图解（右单旋）**：

```
旋转前（A的BF=2）:          右旋 →          旋转后（B的BF=0）:
        A                                      B
       / \                                    / \
      B   Ar                                Bl   A
     / \                                        / \
    Bl  Br                                     Br  Ar
插入Bl导致失衡
```

**LR 旋转图解（先左后右双旋）**：

```
旋转前（A的BF=2）:    先左旋B子树（→LL）    再右旋A:
        A                  A                    C
       / \                / \                  / \
      B   Ar      →      C   Ar       →      B   A
     / \                / \                  / \ / \
    Bl  C              B  Cr               Bl Cl Cr Ar
       / \            / \
      Cl  Cr        Bl  Cl(?)
插入C的子树导致失衡
```

**RR 与 RL 完全对称**：把上面两张图左右镜像即可——RR 做左单旋（B 上升为根，A 变成 B 的左孩子，B 原左子树 Bl 挂到 A 的右侧）；RL 先对 B 做右旋变成 RR 型，再对 A 做左旋。

> **考点**：判断旋转类型只看**从失衡结点 A 出发到新插入结点的前两步方向**（左左 / 右右 / 左右 / 右左），**不看后面的路径**。

## AVL 树的插入调整

插入一个结点的完整流程：

1. **按 BST 规则插入**新结点（小于走左、大于走右，插为叶子）
2. **回溯更新** BF：从新结点的父结点开始向根方向更新
3. **首个 $\|BF\|>1$ 的结点即 A**，取 A 到插入点方向的前两步定型（LL/RR/LR/RL）
4. **旋转一次**（单旋算 1 次、双旋算 1 次调整）后子树高度恢复为插入前的高度，**上层 BF 自动全部复原**——所以**插入最多只需一次旋转**

### 例题：依次插入 16, 3, 7, 11, 9, 26, 18, 14, 15 构造 AVL 树

**题目**：从空树开始依次插入上述 9 个关键字，写出每步是否失衡、失衡类型与旋转结果，并画出最终 AVL 树。

**过程**：

| 步骤 | 插入 | 失衡结点 A | 类型 | 旋转后子树 |
|:---|:---:|:---:|:---:|:---|
| 1 | 16 | — | — | 根为 16 |
| 2 | 3 | — | — | 16 的左孩子为 3，$BF(16)=1$ |
| 3 | 7 | 16 | **LR** | 先左旋 3、再右旋 16 → 7(3, 16) |
| 4 | 11 | — | — | 挂到 16 的左孩子，$BF(7)=-1$ |
| 5 | 9 | 16 | **LL** | 右旋 16 → 11(9, 16)，树成 7(3, 11(9,16)) |
| 6 | 26 | 7 | **RR** | 左旋 7 → 11(7(3,9), 16(-,26)) |
| 7 | 18 | 16 | **RL** | 先右旋 26、再左旋 16 → 18(16, 26) |
| 8 | 14 | — | — | 挂到 16 的左孩子，$BF(16)=1$ |
| 9 | 15 | 16 | **LR** | 先左旋 14、再右旋 16 → 15(14, 16) |

**结果**：最终 AVL 树（高度 4）：

```
              11
            /    \
          7        18
         / \      /   \
        3   9   15     26
                / \
              14   16
```

**验算**：逐结点核对平衡因子——$BF(3)=BF(9)=BF(14)=BF(16)=BF(26)=0$，$BF(7)=0$，$BF(15)=0$，$BF(18)=2-1=1$，$BF(11)=2-3=-1$，全部落在 $\{-1,0,1\}$ ✓。高度校验：$n=9$ 时上界 $1.44\log_2(n+1) = 1.44\times\log_2 10 \approx 4.78 \geq 4$ ✓。中序遍历得 3, 7, 9, 11, 14, 15, 16, 18, 26，严格递增，仍是 BST ✓。

> **考点**：本题一次覆盖了 **LR、LL、RR、RL 四种旋转**，是 408 最典型的手工构造题型。每次插入后**只调整最小不平衡子树**，其余部分不动。

## AVL 树的查找

查找过程与普通 BST **完全一样**——从根开始，小于走左、大于走右。

- 和给定关键字比较的次数**不超过树的深度**
- 含有 $n$ 个结点的 AVL 树最大深度为 $\approx 1.44\log_2(n+1)$
- 平均查找长度和 $\log_2 n$ 一个数量级

## AVL 树的性能分析

| 项目 | 值 |
|:---|:---|
| 含有 $n$ 个结点的 AVL 最大高度 | $\approx 1.44\log_2(n+1)$ |
| 查找 | $O(\log_2 n)$ |
| 插入 | $O(\log_2 n)$（最多一次旋转，发生在最小不平衡子树根处） |
| 删除 | $O(\log_2 n)$（可能多次旋转直到根） |

> **408 高频考点**：给一组关键字，按顺序插入画出 AVL 构造过程（标注每次旋转的 BF 变化）。

> **易错点**：**插入最多 1 次旋转，删除可能 $O(\log n)$ 次**——删除会让子树变矮，矮 1 层会把失衡向上传播，必须一路回溯到根。

## 红黑树的定义：5 条性质（必背）

AVL 通过严格的平衡因子（$\|BF\| \leq 1$）保持平衡，但插入/删除可能需要多次旋转。红黑树采用**较为宽松的平衡条件**——通过给结点着色（红/黑）和一组规则约束树的结构，插入最多 2 次旋转即可恢复，删除最多 3 次，实际效率通常高于 AVL。

**红黑树**是一棵满足以下 5 条性质的二叉排序树（BST）：

| # | 性质 | 说明 |
|:---|:---|:---|
| ① | 每个结点是**红色**或**黑色** | 结点增加一个 `color` 字段 |
| ② | **根结点**是黑色 | 根必须为黑 |
| ③ | 每个**叶结点（NIL）**是黑色 | 外部结点统一视为黑 |
| ④ | **红结点不相邻** | 红色结点的父结点和子结点必须是黑色 |
| ⑤ | 对每个结点，从该结点到其所有后代叶结点的路径上，**黑色结点数相同** | 即黑高（Black-Height）相等 |

![红黑树示例](/blog/images/第7章 查找.assets/251730074203156.jpg)

### 结点类型定义

```c
typedef enum { RED, BLACK } ColorType;

typedef struct RBNode {
    KeyType key;                             // 关键字
    ColorType color;                         // 结点颜色
    struct RBNode *Lchild, *Rchild;          // 左、右孩子
    struct RBNode *parent;                   // 父结点（旋转时需回溯）
} RBNode;
```

### 核心性质

| 性质 | 结论 |
|:---|:---|
| 从根到叶的最长路径 ≤ 2 × 最短路径 | 最长：红黑交替；最短：全黑 |
| 含有 $n$ 个结点的红黑树最大高度 | $\leq 2\log_2(n+1)$ |
| 查找时间复杂度 | $O(\log n)$ |
| 插入/删除 | $O(\log n)$，旋转次数**少于 AVL** |

> **考点**：性质 ④ + ⑤ 联合起来才是"宽松平衡"的本质——黑高处处相等保证了下界，红结点不相邻保证红结点最多占一半路径长度，于是最长路径不超过最短路径的 2 倍，树高被限制在 $2\log_2(n+1)$ 内。

## 红黑树的插入调整（三类情况）

插入新结点初始为**红色**（染红只可能破坏性质 ④，染黑必然破坏性质 ⑤，代价更大），然后根据父结点颜色判断是否需要调整：

| 情况 | 父结点 | 叔结点 | 处理 |
|:---|:---|:---|:---|
| ① | 黑色 | — | 不需调整（直接插入红色结点即可） |
| ② | 红色 | **红色** | 父和叔变黑，祖父变红 → 向上递归检查 |
| ③ | 红色 | **黑色** | 旋转 + 变色（LL/RR/LR/RL，类 AVL） |

情况 ③ 的旋转与 AVL 同名同形，只是旋转后要补一次变色：

| 子情况 | 新结点位置 | 操作 |
|:---|:---|:---|
| LL | 祖父的左孩子的左孩子 | 右单旋祖父 + 父变黑、祖父变红 |
| RR | 祖父的右孩子的右孩子 | 左单旋祖父 + 父变黑、祖父变红 |
| LR | 祖父的左孩子的右孩子 | 先左旋父转成 LL，再按 LL 处理 |
| RL | 祖父的右孩子的左孩子 | 先右旋父转成 RR，再按 RR 处理 |

> 插入最多进行 **2 次旋转**（情况 ③ 的双旋场景）即可恢复所有性质。

> **易错点**：情况 ② 只变色不旋转，但把"红红冲突"向上推给了祖父，可能一路递归到根；**根被染红时直接改回黑色**，此时整棵树黑高 +1（唯一会让黑高变化的操作）。

## 红黑树的删除调整

删除先按 BST 规则化简：若待删结点有两个孩子，用其**中序后继（或前驱）**的值顶替，转为删除那个后继结点——后继最多只有一个孩子。于是只需处理"待删结点孩子数 $\leq 1$"：

| 情形 | 处理 |
|:---|:---|
| 待删结点是**红色** | 直接删除，不影响任何性质（红结点不参与黑高） |
| 待删结点是黑色、但有**一个红孩子** | 红孩子顶替其位置并**染黑**，黑高复原 |
| 待删结点是**黑叶子** | 删除后该路径黑高少 1，形成"**双黑**"缺陷，需按**兄弟结点**颜色分情况调整 |

"双黑"的调整（设缺陷结点为 x、其兄弟为 w）：

| 兄弟 w 的情况 | 操作 | 是否结束 |
|:---|:---|:---|
| w 为**红** | 旋转父结点 + w 与父换色 → 转化为下面两种情况 | 否（转情况） |
| w 为**黑**，且有**红侄子** | 旋转 + 变色（同 LL/RR/LR/RL 型），黑高立即补回 | **是** |
| w 为**黑**，两侄子**全黑** | w 染红，把一层黑"上交"父结点：父为红则父染黑结束；父为黑则缺陷上移到父，向上递归 | 父红则是，父黑则继续 |

> 删除最多进行 **3 次旋转**；变色可能沿路径向上传播 $O(\log n)$ 次，但**旋转次数是常数**——这正是红黑树优于 AVL 的地方。

> **考点**：408 一般只考"删除红结点无影响、删除黑结点破坏黑高、删除最多 3 次旋转"这几个结论，不要求手工推完整删除过程；**先记结论，再理解双黑上移**。

## AVL vs 红黑树

| 维度 | AVL | 红黑树 |
|:---|:---|:---|
| 平衡条件 | $\|BF\| \leq 1$（严格） | 5 条颜色规则（宽松） |
| 结点额外字段 | `Bfactor`（整型） | `color`（1 bit）+ `parent` |
| 树高 | $\approx 1.44\log_2 n$（更低） | $\leq 2\log_2 n$（略高） |
| 查找 | $O(\log n)$（更快，树更矮） | $O(\log n)$ |
| 插入旋转 | 最多 **1** 次 | 最多 **2** 次 |
| 删除旋转 | 最多 $O(\log n)$ 次 | 最多 **3** 次 |
| 平衡维护开销 | 大（删除要一路回溯旋转） | 小（旋转次数常数，主要靠变色） |
| 适用场景 | 查询频繁 | **插入/删除频繁**（如 STL `map`、Java `TreeMap`） |

> **408 考点**：红黑树 5 条性质记忆、根必黑/红不相邻/黑高等高、与 AVL 的适用场景对比。

## 高频考点速记

| 考点 | 记忆 |
|:---|:---|
| 为什么要平衡 | BST 按有序序列插入会退化成单链表，查找 $O(n)$ |
| AVL 平衡因子 | $BF=h_L-h_R\in\{-1,0,1\}$；$\vert BF\vert>1$ 处为最小不平衡子树根 |
| AVL 四旋转 | **LL 右单旋、RR 左单旋、LR 先左后右、RL 先右后左** |
| 旋转定型 | 只看 A 到插入点的**前两步方向**，与后续路径无关 |
| AVL 旋转法则 | 被挤掉的结点挂到**降级结点的空缺位置** |
| AVL 复杂度 | 高 $\approx1.44\log_2(n+1)$；插入最多 **1** 次旋转、删除可 $O(\log n)$ 次 |
| 红黑树 5 性质 | 红黑着色、**根黑**、NIL 黑、**红不相邻**、**黑高相等** |
| 红黑树高度 | $\le 2\log_2(n+1)$；最长路径 $\le 2\times$ 最短路径；查找 $O(\log n)$ |
| 红黑树插入 | 新结点**染红**；父黑免调；父叔红→变色上递；父红叔黑→旋转+变色；最多 **2** 次旋转 |
| 红黑树删除 | 删红无影响；删黑破坏黑高→"双黑"按兄弟颜色调整；最多 **3** 次旋转 |
| 红黑树 vs AVL | AVL 树矮查询快；红黑树插入/删除旋转少，适用 STL `map`/`TreeMap` |
