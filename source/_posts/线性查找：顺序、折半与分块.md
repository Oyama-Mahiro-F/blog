查找（Searching）是在数据集合中找出关键字等于给定值的记录。衡量查找算法优劣的核心指标是**平均查找长度 ASL（Average Search Length）**——查找过程中与关键字比较次数的期望：

$$ASL = \sum_{i=1}^{n} p_i c_i$$

其中 $p_i$ 是查找第 $i$ 个记录的概率（通常假设**等概率** $p_i = 1/n$），$c_i$ 是找到第 $i$ 个记录所需的比较次数。

本文三种方法都建立在**线性表**上，区别只在于"要不要求有序""要不要额外索引"：

| 方法 | 表结构要求 | 有序性 | 额外空间 | $ASL_{succ}$（等概率） | 时间复杂度 |
|:---|:---|:---|:---|:---|:---|
| 顺序查找 | 顺序 / 链式均可 | 不要求 | 无 | $(n+1)/2$ | $O(n)$ |
| 折半查找 | **必须顺序存储** | **必须有序** | 无 | $\approx\log_2(n+1)-1$ | $O(\log_2 n)$ |
| 分块查找 | 索引表 + 数据表 | **块间有序、块内无序** | 索引表 | $\log_2(b+1)+\frac{s+1}{2}$ | $O(\sqrt{n})$ |

> **考点**：三者的选择依据是**表的有序性与增删频率**——无序表或链表只能顺序查找；有序且顺序存储用折半；既要频繁插入删除又想比顺序快，用分块。

## 顺序查找

从头到尾依次扫描，逐个比较关键字——最朴素的查找方法，**对表的结构不做任何要求**（顺序存储和链式存储均可）。

### 算法实现

**不带哨兵版本**：

```c++
int SeqSearch(int a[], int n, int key) {
    for (int i = 0; i < n; i++) {
        if (a[i] == key) {
            return i;                // 查找成功，返回下标
        }
    }
    return -1;                       // 查找失败
}
```

**带哨兵版本**（把 key 放在 a[0]，从末尾向前找，省去边界判断）：

```c++
int SeqSearch_Sentinel(int a[], int n, int key) {
    a[0] = key;                      // 哨兵
    int i = n;
    while (a[i] != key) {
        i--;                         // 无需判断 i >= 0
    }
    return i;                        // i=0 表示未找到
}
```

> 哨兵法把目标放在 a[0]，从后往前找，循环内省去 `i >= 0` 的边界判断，查找失败时停在 a[0] 上。

### 性能分析

| 情况 | 比较次数 | 说明 |
|:---|:---|:---|
| 最好 | $1$ | 第一个元素就是目标 |
| 最坏 | $n$ | 最后一个才是目标或不存在 |
| 平均 | $(n+1)/2$ | 等概率下每次比较均分布 |

**ASL 计算**（等概率 $p_i = 1/n$）：

$$ASL_{succ} = \sum_{i=1}^{n} \frac{1}{n} \cdot i = \frac{n+1}{2}$$

$$ASL_{fail} = n+1$$

**考虑查找成功/失败概率的 ASL**（成败各 $1/2$）：

$$ASL = \frac{1}{2} \cdot ASL_{succ} + \frac{1}{2} \cdot ASL_{fail} = \frac{3(n+1)}{4}$$

| 项目 | 结论 |
|:---|:---|
| 时间复杂度 | $O(n)$ |
| 空间复杂度 | $O(1)$ |
| 优点 | 对表无结构要求，顺序存储和链式存储均可 |
| 缺点 | 慢——表中即使有序也需逐个比较 |

### 例题：n=6 的顺序查找 ASL

**题目**：长度 $n=6$ 的表，等概率查找，求 $ASL_{succ}$、$ASL_{fail}$，以及成败各占一半时的 $ASL$。

**过程**：查找第 $i$ 个元素恰需 $i$ 次比较（$i=1,2,\dots,6$），失败需比完全部 $6$ 个再判越界，共 $n+1=7$ 次。

$$ASL_{succ} = \frac{1+2+3+4+5+6}{6} = \frac{21}{6} = 3.5$$

**结果**：$ASL_{succ} = 3.5$，$ASL_{fail} = 7$，成败各半时

$$ASL = \frac{1}{2}\times 3.5 + \frac{1}{2}\times 7 = 5.25$$

**验算**：代入通式，$\frac{n+1}{2} = \frac{7}{2} = 3.5$ ✓；$\frac{3(n+1)}{4} = \frac{21}{4} = 5.25$ ✓。

> **考点**：顺序查找的 $ASL_{fail} = n+1$（**不是 $n$**）——失败时还要多一次"下标越界/哨兵命中"的判断。

## 折半查找

每次取**中间位置**元素与关键字比较，每次将查找范围**缩小一半**，直到找到或区间为空。

> **前提**：查找表必须**有序**，且采用**顺序存储**（随机访问）。

### 算法实现

```c++
int BinarySearch(int a[], int n, int key) {
    int low = 0, high = n - 1, mid;
    while (low <= high) {
        mid = (low + high) / 2;           // 折半
        if (a[mid] == key) {
            return mid;                   // 查找成功
        } else if (a[mid] > key) {
            high = mid - 1;               // 去左半区
        } else {
            low = mid + 1;                // 去右半区
        }
    }
    return -1;                            // 查找失败
}
```

> `mid = low + (high - low) / 2` 可防溢出；`mid = (low + high) / 2` 当 $n$ 较小时等价。

### 执行过程示例

```
sorted list: [10, 20, 30, 40, 50, 60, 70]    search key = 40

round 1: low=0   mid=3(40)   high=6   → mid=40 == key → success!（1 次比较成功）
```

```
查找 key = 25（失败）

第1轮: low=0   mid=3(40)   high=6     25 < 40, high = 2
第2轮: low=0   mid=1(20)   high=2     25 > 20, low = 2
第3轮: low=2   mid=2(30)   high=2     25 < 30, high = 1
第4轮: low=2 > high=1 → 查找失败
```

> **易错点**：循环条件是 `low <= high`（不是 `<`）——当区间只剩一个元素时 `low == high`，仍需比较一次。

### 判定树（二叉判定树）

折半查找过程可描述为一棵**平衡二叉树**——每个结点对应一次比较，根据比较结果走向左子树或右子树。

```
有序表 [10,20,30,40,50,60,70] 的二叉判定树：

                  40
                /    \
              20      60
             /  \    /  \
           10   30  50   70
```

- 查找成功的比较次数 = 从根到该结点的路径长度
- 查找失败的比较次数 = 从根到失败结点（空子树）的路径长度
- 判定树是一棵**平衡二叉排序树**，高度为 $\lceil \log_2(n+1) \rceil$

### 性能分析

**等概率下的 ASL**（判定树有 $n$ 个内部结点，深度 $h = \lceil \log_2(n+1) \rceil$）：

$$ASL_{succ} = \frac{1}{n} \sum_{i=1}^{n} level_i \approx \log_2(n+1) - 1$$

$$ASL_{fail} \leq \lceil \log_2(n+1) \rceil$$

| 项目 | 结论 |
|:---|:---|
| 时间复杂度 | $O(\lceil \log_2(n+1) \rceil)$ |
| 空间复杂度 | $O(1)$（非递归） |
| 优点 | 比顺序查找快得多 |
| 缺点 | **必须有序** + **必须顺序存储**（需要随机访问 `mid`） |

### 例题：由判定树计算折半查找的 ASL

**题目**：对有序表 $[10,20,30,40,50,60,70]$（$n=7$）作折半查找，求等概率下的 $ASL_{succ}$ 与 $ASL_{fail}$。

**过程**：先画判定树（见上），按层统计各结点的比较次数：

| 层次 | 结点 | 结点数 | 每个的比较次数 |
|:---|:---|:---:|:---:|
| 第 1 层 | 40 | 1 | 1 |
| 第 2 层 | 20、60 | 2 | 2 |
| 第 3 层 | 10、30、50、70 | 4 | 3 |

$$ASL_{succ} = \frac{1\times 1 + 2\times 2 + 4\times 3}{7} = \frac{17}{7} \approx 2.43$$

失败结点共 $n+1 = 8$ 个，全部挂在第 3 层结点之下，每个失败路径经过 $3$ 个内部结点：

$$ASL_{fail} = \frac{8 \times 3}{8} = 3$$

**结果**：$ASL_{succ} = 17/7 \approx 2.43$，$ASL_{fail} = 3$。

**验算**：通式 $\log_2(n+1)-1 = \log_2 8 - 1 = 2$，与 $2.43$ 同数量级 ✓；$ASL_{fail} \leq \lceil\log_2(n+1)\rceil = 3$，取到等号 ✓。对比顺序查找 $n=7$ 时 $ASL_{succ} = 4$，折半明显更优。

> **考点**：折半查找题**必须先画判定树**——ASL、最大比较次数、失败结点位置全部从树上读，硬套公式容易在 $n$ 非 $2^k-1$ 时算错。

### 顺序查找 vs 折半查找对比

| 维度 | 顺序查找 | 折半查找 |
|:---|:---|:---|
| 表结构要求 | **无要求**（顺序/链式均可） | 必须**有序** + **顺序存储** |
| 时间复杂度 | $O(n)$ | $O(\log n)$ |
| 插入/删除 | 方便 | 困难（需保持有序，移动元素） |

> **选择依据**：表小或无序 → 顺序查找；表大且有序且顺序存储 → 折半查找；需要频繁插入删除 → 分块查找或 BST。

## 分块查找（索引顺序查找）

将数据**分块**，块间有序但块内无序。建立**索引表**记录每块的最大关键字和起始地址。查找分两步：**① 在索引表中折半（或顺序）确定所在块 → ② 在块内顺序查找**。

### 结构示意

```
index table:           data table (3 blocks, 3 elems each):
┌────┬──────┐          ┌───┬───┬───┬───┬───┬───┬───┬───┬───┐
│max │ addr │          │30 │20 │10 │50 │40 │60 │90 │70 │80 │
├────┼──────┤          └───┴───┴───┴───┴───┴───┴───┴───┴───┘
│30  │  0   │           ← block 1 (10~30)  ← block 2 (40~60) ← block 3 (70~90)
│60  │  3   │
│90  │  6   │
└────┴──────┘

search key = 40:
  ① index table: 30<40≤60 → block 2, addr=3
  ② from a[3] search in order → found at a[4]=40
```

上例中数据表被切成 3 块：块 1 为 10&#126;30、块 2 为 40&#126;60、块 3 为 70&#126;90。**块内元素无序**（如块 1 是 30、20、10），但**任一块内所有关键字都小于后一块的全部关键字**——这正是索引表能用折半的原因。

### 性能分析

| 查找阶段 | 方法 | 平均比较次数 |
|:---|:---|:---|
| ① 确定块 | 折半查找 | $\log_2(b+1)$（$b$ 为块数） |
| ② 块内查找 | 顺序查找 | $(s+1)/2$（$s$ 为块大小） |

$$ASL = \underbrace{\log_2(b+1)}_{\text{索引查找}} + \underbrace{\frac{s+1}{2}}_{\text{块内查找}}$$

若索引表也用**顺序查找**，则 $ASL = \frac{b+1}{2} + \frac{s+1}{2}$。将 $n = b \cdot s$ 代入并对 $s$ 求极小，得 $s = \sqrt{n}$ 时取到最小值 $\sqrt{n} + 1$。

| 项目 | 结论 |
|:---|:---|
| 时间复杂度 | $O(\sqrt{n})$（当 $s \approx \sqrt{n}$ 时最优） |
| 优点 | 兼具顺序查找简单 + 折半查找快速，**适合插入/删除**（块内无序） |
| 缺点 | 需要额外的索引表空间 |

### 例题：n=9 分块查找的 ASL

**题目**：$n=9$ 个记录分成 $b=3$ 块、每块 $s=3$ 个（即上图结构），索引表用折半查找、块内用顺序查找，求 $ASL$，并与顺序、折半查找比较。

**过程**：

$$ASL = \log_2(b+1) + \frac{s+1}{2} = \log_2 4 + \frac{3+1}{2} = 2 + 2 = 4$$

**结果**：$ASL = 4$。三者对比（$n=9$）：

| 方法 | $ASL_{succ}$ | 说明 |
|:---|:---|:---|
| 顺序查找 | $(9+1)/2 = 5$ | 最慢，但无任何前提 |
| 分块查找 | $4$ | 居中，且**支持高效增删** |
| 折半查找 | $\approx\log_2 10 - 1 \approx 2.32$ | 最快，但要求全表有序 |

**验算**：$s = 3 = \sqrt{9}$，正好是最优分块，用顺序索引验算 $\frac{b+1}{2} + \frac{s+1}{2} = 2 + 2 = 4$，与折半索引结果一致（$b$ 很小时两种索引查找差别不大）✓。

> **考点**：分块查找的价值不在"最快"，而在**兼顾增删**——插入只需扔进对应块的末尾并更新索引表最大值，无需像折半那样整体搬移元素保持有序。

## 三种查找方法对比

| 维度 | 顺序查找 | 折半查找 | 分块查找 |
|:---|:---|:---|:---|
| 有序性要求 | 无 | **全表有序** | **块间有序、块内无序** |
| 存储要求 | 顺序 / 链式 | **必须顺序存储** | 数据表 + 索引表 |
| $ASL_{succ}$ | $\frac{n+1}{2}$ | $\approx\log_2(n+1)-1$ | $\log_2(b+1)+\frac{s+1}{2}$ |
| $ASL_{fail}$ | $n+1$ | $\leq\lceil\log_2(n+1)\rceil$ | 索引定位 + 整块扫完 |
| 时间复杂度 | $O(n)$ | $O(\log_2 n)$ | $O(\sqrt{n})$ |
| 空间复杂度 | $O(1)$ | $O(1)$ | $O(b)$（索引表） |
| 插入 / 删除 | 方便 | **困难**（要维持有序） | **方便**（块内无序） |
| 适用场景 | 小表 / 链表 / 无序表 | 大表、有序、静态查找 | 增删频繁又要速度 |

> **考点**：三种方法的**核心区别是"用什么换速度"**——折半用"有序 + 随机访问"这两个约束换来 $O(\log n)$；分块用"额外索引表空间"换来 $O(\sqrt{n})$ 且不牺牲增删；顺序查找什么都不要求，所以最慢。

## 高频考点速记

| 考点 | 记忆 |
|:---|:---|
| ASL 定义 | $ASL=\sum p_i c_i$，等概率时 $p_i = 1/n$；分**成功**与**失败**两个 ASL |
| 顺序查找 | 哨兵放 $a[0]$ 省边界判断；$ASL_{succ}=(n+1)/2$、$ASL_{fail}=n+1$、$O(n)$ |
| 成败概率各半 | $ASL=\frac{3(n+1)}{4}$ |
| 顺序查找适用 | 小数据量 / 链表 / 无序表 |
| 折半查找前提 | 必须**有序** + **顺序存储**（随机访问 mid） |
| 折半循环条件 | `while (low <= high)`，失败出口是 `low > high` |
| 折半判定树 | 平衡二叉排序树，高度 $\lceil\log_2(n+1)\rceil$；**先画树再算 ASL** |
| 折半 ASL | $ASL_{succ}\approx\log_2(n+1)-1$，$ASL_{fail}\le\lceil\log_2(n+1)\rceil$，$O(\log n)$ |
| 分块查找 | 索引折半 $\log_2(b+1)$ + 块内顺序 $(s+1)/2$；顺序索引则为 $\frac{b+1}{2}+\frac{s+1}{2}$ |
| 最优分块 | $s\approx\sqrt{n}\to O(\sqrt{n})$，最小 $ASL=\sqrt{n}+1$ |
| 分块结构要求 | 块间有序、块内无序；需要索引表（存每块最大关键字 + 起始地址） |
| 分块适用场景 | 兼顾增删与速度 |
| 三者取舍 | 无序/链式→顺序；有序静态→折半；增删频繁→分块或 BST |
