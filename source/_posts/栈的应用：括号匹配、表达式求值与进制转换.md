栈的 LIFO 特性决定了它天生适合处理**"需要回头看最近一次、或需要逆序输出"**的问题。408 考纲里栈有三个经典应用，它们的共同点都是**用一个栈暂存"暂时用不上但迟早要用"的信息**。

| 应用 | 栈里存什么 | 利用的特性 |
|:---|:---|:---|
| 括号匹配 | 未配对的**左括号** | 最后出现的左括号最先配对（LIFO） |
| 表达式求值 | 未确定时机的**运算符** / 待运算的**操作数** | 优先级高的后入先出 |
| 进制转换 | 除基取余得到的**余数** | 先算出的低位最后输出（逆序） |

## 括号匹配

括号匹配（Bracket Matching）是栈最经典、最基础的应用。编译器在词法分析时检查代码里的括号是否成对、正确嵌套，底层靠的就是这个算法。

### 算法核心思想

完美利用栈 **LIFO（后进先出）** 的特性——**最后出现的左括号，必须最先遇到与其配对的右括号**。

算法流程浓缩为四步：

1. **遍历字符串**：从左到右依次读取字符。
2. **遇左则入**：遇到左括号 `(`、`[`、`{`，直接压入栈中。
3. **遇右则弹**：遇到右括号 `)`、`]`、`}`，弹出当前栈顶元素比对：
   - 能配对（如栈顶是 `[`，当前是 `]`），继续扫描。
   - **[失败情况 A]** 类型不匹配（如栈顶是 `(`，当前是 `]`），判定非法！
   - **[失败情况 B]** 栈已空，说明右括号多余（如 `())`），判定非法！
4. **终局判定**：遍历结束后检查栈：
   - 栈为空，所有括号完美配对，**匹配成功**。
   - **[失败情况 C]** 栈不空，说明左括号多余（如 `(()`），判定非法！

### 算法实现

```c++
#include <stdlib.h>
#include <stdbool.h>

// 假设 SqStack 以及 Push, Pop, StackEmpty 函数已正确实现
bool MatchBrackets(SqStack &S) {
    char ch, x;

    // 持续读取字符，直到遇到回车符（'\n'）
    while (scanf("%c", &ch) != EOF && ch != '\n') {

        // 1. 遇左括号压栈
        if (ch == '(' || ch == '[') {
            Push(S, ch);
        }
        // 2. 遇右括号弹栈比对
        else if (ch == ')' || ch == ']') {

            // 【防御核心】出栈前必须判空！防止右括号多余
            if (StackEmpty(S)) {
                printf("匹配失败：右括号多余！\n");
                return false;
            }

            // 弹出栈顶元素到 x 中
            Pop(S, x);

            // 检查括号类型是否匹配
            if ((ch == ')' && x != '(') || (ch == ']' && x != '[')) {
                printf("匹配失败：括号类型不匹配！\n");
                return false;
            }
        }
    }

    // 3. 终局判断：字符串读取完毕后，栈必须为空
    if (!StackEmpty(S)) {
        printf("匹配失败：左括号多余！\n");
        return false;
    }

    printf("匹配成功！\n");
    return true;
}
```

### 匹配示例

匹配 `[ ( ) { } ]`：

```
Step 1: 读 '[' → 遇左括号压栈 → 栈: [ [ ]
Step 2: 读 '(' → 遇左括号压栈 → 栈: [ (, [ ]
Step 3: 读 ')' → 弹栈比对 '(' 匹配 ')' ✓ → 栈: [ [ ]
Step 4: 读 '{' → 压栈 → 栈: [ {, [ ]
Step 5: 读 '}' → 弹栈比对 '{' 匹配 '}' ✓ → 栈: [ [ ]
Step 6: 读 ']' → 弹栈比对 '[' 匹配 ']' ✓ → 栈空，匹配成功！
```

### 三种失败情况总结

| 失败情况 | 现象 | 例子 |
|:---|:---|:---|
| A：类型不匹配 | 栈顶左括号与当前右括号类型不同 | `( ]` |
| B：右括号多余 | 遇到右括号时栈已空 | `())` |
| C：左括号多余 | 遍历结束栈不空 | `(()` |

## 表达式求值

人类习惯阅读**中缀表达式**（如 `3 + 4 * 2`），但计算机扫描代码只能从左到右读字符，遇到 `+` 时不知道后面还藏着 `*` 或括号。图灵奖得主 Dijkstra 发明了**调度场算法 (Shunting-yard algorithm)**，利用栈将中缀表达式转化为计算机极易处理的**后缀表达式（逆波兰表达式）**，然后再计算。

整个过程分两大阶段：

### 阶段一：中缀表达式转后缀表达式（核心难点）

借助一个**操作符栈**暂存还未确定执行时机的运算符。

**核心运算铁律：**

1. **遇到操作数（数字或字母）**：直接输出到结果序列。
2. **遇到左括号 `(`**：优先级最高，直接压入操作符栈。
3. **遇到右括号 `)`**：疯狂弹栈并输出，直到弹出对应的左括号 `(` 为止（括号对互相抵消，不输出）。
4. **遇到运算符（`+`、`-`、`*`、`/`）**（最容易错）：
   - 与当前栈顶运算符比较优先级。
   - **如果栈顶优先级 ≥ 当前运算符优先级**，把栈顶弹出并输出；继续比较，直到栈顶优先级更低或栈空。
   - 最后，将当前运算符压入栈中。
5. **处理尾声**：表达式扫描结束后，操作符栈里还有东西则全部弹栈并输出。

> 原理隐喻：优先级高的运算符像急脾气，不能被优先级低的压在下面；一旦遇到优先级更低的压过来，急脾气就必须立刻出栈执行。

### 阶段二：后缀表达式求值

后缀表达式（如 `3 4 2 * +`）没有括号、不需要考虑优先级，极其适合计算机无脑执行。

借助一个**操作数栈**：

1. 遇到数字：直接压栈。
2. 遇到运算符：从栈顶弹出**两个**操作数计算（**注意顺序**：次栈顶元素 运算 栈顶元素），结果压回栈中。
3. 扫描结束，栈中最后剩下的数字就是最终答案。

### 完整示例：`b - (a + 5) * 3`（代入 $a = 2, b = 30$）

**第一阶段：中缀转后缀（调度场算法）**

| 步骤 | 读入 | 操作符栈 (底→顶) | 输出区 | 判定逻辑 |
|:---:|:---|:---|:---|:---|
| 1 | `b` | `[ ]` | `b` | 操作数，直接输出 |
| 2 | `-` | `[ - ]` | `b` | 栈空，直接压入 |
| 3 | `(` | `[ -, ( ]` | `b` | 左括号，直接压入 |
| 4 | `a` | `[ -, ( ]` | `b a` | 操作数，直接输出 |
| 5 | `+` | `[ -, (, + ]` | `b a` | 栈顶是 `(`，直接压入 |
| 6 | `5` | `[ -, (, + ]` | `b a 5` | 操作数，直接输出 |
| 7 | `)` | `[ - ]` | `b a 5 +` | **弹栈!** 弹出 `+` 直到遇 `(` 抵消 |
| 8 | `*` | `[ -, * ]` | `b a 5 +` | `*` 优先级 > 栈顶 `-`，压入 |
| 9 | `3` | `[ -, * ]` | `b a 5 + 3` | 操作数，直接输出 |
| 10 | 结束 | `[ ]` | `b a 5 + 3 * -` | 弹空栈中剩余 `*` `-` |

**第二阶段：后缀表达式求值（代入 $b=30, a=2$）**

扫描：`30 2 5 + 3 * -`

| 步骤 | 读入 | 操作数栈 (底→顶) | 计算动作 |
|:---:|:---|:---|:---|
| 1 | `30` | `[ 30 ]` | 数字，压栈 |
| 2 | `2` | `[ 30, 2 ]` | 数字，压栈 |
| 3 | `5` | `[ 30, 2, 5 ]` | 数字，压栈 |
| 4 | `+` | `[ 30, 7 ]` | 弹出 5,2 → **2+5=7**，7 压栈 |
| 5 | `3` | `[ 30, 7, 3 ]` | 数字，压栈 |
| 6 | `*` | `[ 30, 21 ]` | 弹出 3,7 → **7×3=21**，21 压栈 |
| 7 | `-` | `[ 9 ]` | 弹出 21,30 → **30−21=9**，9 压栈 |
| 8 | 结束 | `[ 9 ]` | 栈中唯一数字 **9** = 最终答案! |

## 进制转换

利用栈将十进制整数转换为 2 进制或 8 进制等目标进制。**除基取余，逆序输出**——先算出的低位余数压在栈底最后输出，完美利用栈的 LIFO 特性实现逆序。

### 算法过程

**第一步：环境初始化**

1. 构造一个空的顺序栈（或链栈）`S`，暂时存储计算产生的余数。
2. 准备一个普通整型变量 `e`，用于最后阶段接收出栈的数据。

**第二步：除基取余，顺序入栈（核心计算层）**

当被转换的十进制数 $n > 0$ 时，持续循环：

1. **求余**：计算当前 $n$ 除以目标进制 $d$ 的余数 $k = n \bmod d$。
2. **压栈**：将余数 $k$ 压入栈 `S` 的栈顶。
3. **降维**：更新 $n = n / d$（整数除法，向下取整）。

**第三步：逆序出栈，完成转换（核心输出层）**

当循环结束（$n = 0$）时，所有余数已按"从低位到高位"的顺序堆叠在栈中。当栈 `S` 不为空时持续循环：

1. **弹栈**：将栈顶元素弹出赋值给 `e`。
2. **输出**：打印变量 `e` 的值。

### 算法实现

```c++
#include <stdlib.h>
#include <stdbool.h>

void Conversion(int n, int d) {
    /* 将十进制整数 n 转换为 d (2或8) 进制数 */
    SqStack S;
    int k, e;

    // 1. 初始化栈
    InitStack(S);

    // 2. 除基取余，压入栈中
    while (n > 0) {
        k = n % d;
        Push(S, k);
        n = n / d;
    }

    // 3. 栈不空时出栈，逆序输出
    while (!StackEmpty(S)) {
        Pop(S, e);
        printf("%d", e);
    }

    printf("\n");
}
```

### 实例：十进制 13 → 二进制 1101

```
【"除基取余，顺序入栈"】         【"逆序出栈"】
n=13: 13%2=1 → Push(1)          Pop → 1 (最高位)
n=6 :  6%2=0 → Push(0)          Pop → 1
n=3 :  3%2=1 → Push(1)          Pop → 0
n=1 :  1%2=1 → Push(1)          Pop → 1 (最低位)
n=0 : 结束

入栈后栈底→顶: [1][0][1][1]     出栈顺序: 1→1→0→1 → 结果 1101 ✓
```

## 三个应用的共性与辨析

| 应用 | 栈的角色 | 关键易错点 |
|:---|:---|:---|
| 括号匹配 | 暂存**待配对的左括号** | 出栈前**必须判空**（右括号多余）；遍历完**必须查栈空**（左括号多余） |
| 表达式求值 | 暂存**未到时机的运算符** + **待运算操作数** | 栈顶优先级 **≥** 当前才弹（不是 `>`）；后缀求值弹出两数时**顺序是「次栈顶 运算 栈顶」** |
| 进制转换 | 暂存**余数**以逆序输出 | 循环条件是 `n > 0`；`n = 0` 时结果为空 |

> **一句话串起来**：括号匹配用栈**保存"未完成的期待"**，表达式求值用栈**保存"未定的执行顺序"**，进制转换用栈**保存"待逆序的输出"**。本质都是 LIFO 对"最近相关"的天然表达。

## 高频考点速记

| 考点 | 记忆 |
|:---|:---|
| 括号匹配 | 遇左压栈、遇右弹栈比对；三种失败：类型不匹配 / 右括号多余 / 左括号多余 |
| 括号匹配-防御 | 出栈前**必须判空**，否则 `())` 会崩溃 |
| 中缀转后缀 | 操作数直接输出；左括号入栈；右括号弹栈至 `(`；运算符"栈顶 ≥ 当前则弹栈"后入栈 |
| 后缀求值 | 数字压栈；遇运算符弹两操作数（**次栈顶 运算 栈顶**）后压回 |
| 表达式求值-为什么用栈 | 操作符栈暂存"未到时机"的运算符；操作数栈暂存"待运算"的数 |
| 进制转换 | **除基取余，逆序出栈**；时间/空间均 $O(\log_d n)$ |
| 进制转换-为什么用栈 | 余数先算出来的是低位，利用 LIFO 自动逆序输出 |
| 栈的复杂度 | 三应用均为 $O(n)$ 时间、$O(n)$ 空间 |
