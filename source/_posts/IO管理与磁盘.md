**I/O 管理**是操作系统中负责管理外部设备的子系统，核心目标是**方便用户使用设备、提高设备与 CPU 的利用率、让两者充分并行**。本章横跨两大块：**I/O 管理基础**（设备分类、I/O 控制方式、软件层次、缓冲区、设备分配与 SPOOLing）和**外存管理**（磁盘结构、访问时间、磁盘调度算法、固态硬盘）。408 对本章的考查非常固定：**三种 I/O 控制方式的 CPU 干预程度对比、缓冲区时间计算（单/双缓冲流水推演）、磁盘调度六算法的完整演算、磁盘访问时间三段式计算**，几乎每年必占分。

## I/O 设备及其分类

**I/O 设备**是 CPU 与外部世界交换信息的载体。同一个设备可以从**三个维度**归类，考试常考"某设备属于哪类"：

| 分类维度 | 类别 | 特点 | 典型设备 |
|:---|:---|:---|:---|
| **按信息交换单位** | **块设备** | 以**数据块**为单位、**可寻址**、可随机访问，速率高 | 磁盘、SSD |
| | **字符设备** | 以**字符**为单位、**不可寻址**、只能顺序访问 | 键盘、鼠标、打印机 |
| **按传输速率** | 低速设备 | 每秒几&#126;几百字节 | 键盘、鼠标 |
| | 中速设备 | 每秒数千&#126;数万字节 | 行式打印机 |
| | 高速设备 | 每秒几十万&#126;数兆字节 | 磁盘、光盘机、网卡 |
| **按共享属性** | **独占设备** | 一次仅允许一个进程使用，使用期**独占** | 打印机、磁带机 |
| | **共享设备** | 可由多个进程**交替（宏观同时）**使用 | 磁盘 |
| | **虚拟设备** | 用 SPOOLing 把独占设备改造成的"共享"设备 | 虚拟打印机 |

> **考点**：**磁盘同时是块设备、共享设备、高速设备**；打印机是**字符设备、独占设备**，经 SPOOLing 改造后成为**虚拟设备**——这是选择题最爱考的组合。

### I/O 接口（设备控制器）与 I/O 端口

**设备控制器（I/O 接口）**是 CPU 与设备之间的**中间硬件**，负责接收并识别 CPU 的命令、控制设备完成数据交换。其组成分三部分：

| 组成 | 说明 |
|:---|:---|
| **与 CPU 的接口** | 三类信号线：**数据线**（传数据、控制与状态信息）、**地址线**（传要访问的**寄存器编号**）、**控制线**（传读/写控制信号） |
| **与设备的接口** | 一个控制器可接一个或多个设备，每个接口传**数据、控制、状态**三类信号 |
| **I/O 逻辑** | 对 CPU 收到的 **I/O 命令进行译码**，据此选中设备并发控制信号 |

**I/O 端口**指控制器中**可被 CPU 直接访问的寄存器**，共三类：

| 寄存器 | 作用 |
|:---|:---|
| **数据寄存器** | 暂存设备输入或 CPU 输出的数据 |
| **控制寄存器** | 由 **CPU 写入**，启动命令或改变设备模式 |
| **状态寄存器** | 保存设备状态/执行结果，供 CPU **读取** |

端口编址方式一句话：**独立编址**——I/O 端口单独编号，用**专用 I/O 指令**访问；**统一编址（内存映射 I/O）**——端口占用内存地址空间，用**普通访存指令**访问。

> **易错点**：地址线上传的是**寄存器（端口）编号**而非设备号；数据线上既传数据也传控制/状态信息。

## I/O 控制方式（重点）

演进主线：**CPU 的介入越来越少，CPU 与设备的并行程度越来越高**。

### 轮询方式（程序直接控制）

CPU 发出 I/O 命令后，**不断读取状态寄存器**测试设备是否就绪（**忙等**），就绪后传**一个字**，反复直到数据全部传完。CPU **全程参与、全程忙等**，利用率最低，但实现最简单、无需额外硬件。

### 中断驱动方式

设备准备数据期间 **CPU 可执行其他进程**；设备就绪后**主动发中断**，CPU 响应中断传送**一个字**，然后继续。特点：**每传输一个字（字节）就打断 CPU 一次**，传一块 n 字需 **n 次中断**；且数据仍要**经过 CPU**（在控制器与内存之间由 CPU 搬运）。

### DMA 方式（直接存储器存取）

**DMA** 在**外设与内存之间直接传输数据块**，数据**不经过 CPU**。CPU 只在**传送开始（初始化 DMA 控制器）与结束（接收完成中断）时干预**，一块数据**共干预 2 次**。DMA 控制器由四个部件组成：**CR 命令/状态寄存器、MAR 内存地址寄存器、DR 数据寄存器、DC 数据计数器**，传输中由 DMA 控制器自动修改地址与计数。

### 通道方式

**通道**是能执行**通道程序**的专用 I/O 处理机：CPU 只需发**一条启动指令**，通道即自行控制**一组（多块）数据**的传输，完毕后向 CPU 发一次中断，还可控制**多台设备**并行工作——**CPU 干预程度最低**。

### 各方式对比（必考）

| 对比项 | 轮询 | 中断驱动 | DMA | 通道 |
|:---|:---|:---|:---|:---|
| 数据传输单位 | 一个字 | 一个字（字节） | **一个数据块** | **一批数据块** |
| 数据是否经 CPU | 经过 CPU | 经过 CPU | **不经过 CPU**（内存与设备直接） | 不经过 |
| CPU 干预程度 | **最高**（全程忙等参与） | 较高（每字中断一次，一块 n 次） | 低（开始+结束**共 2 次**） | **最低**（一条指令+一次中断） |
| CPU 是否全程参与 | **是（忙等轮询）** | 否（等待时可做别事） | 否（仅首尾介入） | 否 |
| 并行程度 | 无并行 | 设备与 CPU 部分并行 | 较高 | 最好（多设备并行） |
| 适用场景 | 简单低速设备 | 中低速设备 | 高速块设备（磁盘） | 大规模高速 I/O |

> **考点**：DMA 与中断驱动的本质区别——**中断驱动每字中断一次且数据经 CPU 搬运；DMA 每块只中断一次且数据不经过 CPU**。
> **易错点**：DMA 传输中"数据不经 CPU"≠"不需要 CPU"，开始时 CPU 仍要**初始化**（内存地址、计数、方向），结束时 CPU 要**处理中断**。

## I/O 软件层次结构

I/O 软件采用**分层结构**，请求自上而下传递、结果自下而上返回，**每层只调用紧邻的下一层**：

| 层次 | 职责 | 典型内容 |
|:---|:---|:---|
| **用户层 I/O 软件** | 封装系统调用的**库函数**，为用户提供 I/O 接口 | printf、scanf、fread |
| **设备独立性软件** | 与设备无关的**公有操作**：命名与映射、设备保护、**缓冲管理**、**设备分配与回收**、差错报告、**SPOOLing** | 逻辑设备名 → 物理设备 |
| **设备驱动程序** | 把抽象请求翻译成**具体设备命令**，向设备控制器的**寄存器**写入命令/参数并启动设备 | 设寄存器、启动磁盘 |
| **中断处理程序** | 响应设备中断：保存现场、判断中断原因、善后处理、恢复现场 | 传输完成/出错处理 |

设备驱动程序向上层提供**统一接口**（open/close/read/write），因此**换设备只需换驱动程序**，应用程序与系统其余部分不变。

> **考点**：**设备驱动程序是唯一直接控制硬件的软件层**，与具体设备一一对应、属于内核；设备独立性软件与驱动程序的分界——**前者与设备无关（做公有操作），后者与具体设备相关**。
> **易错点**：层次次序常考排序题——用户层 → 设备独立性软件 → 驱动程序 → 中断处理程序 → 硬件，**中断处理在驱动的下面**。

## 高速缓存与缓冲区

**I/O 调度**：确定一个良好的顺序来执行等待中的 I/O 请求（最典型就是**磁盘请求调度**，见后文），以改善整体性能。**磁盘高速缓存**则是在**内存**中保存最近访问过的磁盘数据副本，利用**时间局部性**减少实际访盘次数——注意它存的是"**已用数据的副本**"，与缓冲区"暂存**待传输**的数据"不同。

引入缓冲区（Buffer）的四个目的：

| 目的 | 说明 |
|:---|:---|
| 缓和 **CPU 与设备速度不匹配** | 慢设备先攒入缓冲区，快方不必空等 |
| **减少中断频率** | 数据攒够一批才中断 CPU 一次 |
| 解决**数据粒度不匹配** | 如按字符输入、按块处理 |
| 提高 **CPU 与设备的并行性** | CPU 处理上一批时，设备输入下一批 |

### 缓冲区方案对比（必考）

记号：**T** = 设备把一块数据输入缓冲区的时间，**M** = 缓冲区数据传送到用户工作区的时间，**C** = CPU 处理（计算）一块的时间。

| 方案 | 结构 | 每块稳态耗时 | 说明 |
|:---|:---|:---|:---|
| **单缓冲** | 1 个缓冲区，设备与用户区**互斥**使用 | $\max(C, T) + M$ | 输入与处理可重叠，**M 必须串行** |
| **双缓冲** | 2 个缓冲区轮流装填 | $\max(C + M, T)$ | 输入与"移送+处理"流水并行 |
| **循环缓冲** | n 个缓冲区组成环，多个指针 | 适合**生产者—消费者**模式 | 读指针/写指针沿环推进 |
| **缓冲池** | 系统公用缓冲区集合 | **空缓冲队列、装满输入队列、装满输出队列** | **全系统共享**，利用率最高 |

### 缓冲区时间计算例题（必考）

某设备输入一块数据 $T = 100\mu s$，缓冲区传送至用户区 $M = 10\mu s$，CPU 处理一块 $C = 50\mu s$，连续输入并处理 n 块，求单缓冲、双缓冲下第 2 块完成时刻与稳态每块耗时。

**单缓冲流水推演**：

- 第 1 块：输入 $0&#126;100$（缓冲区满）→ 移送 $100&#126;110$ → 处理 $110&#126;160$，完成时刻 **160μs**
- 缓冲区在 $t = 110$ 移送完即空出，设备随即输入第 2 块：$110&#126;210$；第 2 块的移送须等**缓冲区满（210）**且**用户区空闲（160）**，两者取大 → 移送 $210&#126;220$、处理 $220&#126;270$，第 2 块完成时刻 **270μs**
- 稳态每块耗时 = $270 - 160 = 110\mu s$，恰为 $\max(C, T) + M = \max(50, 100) + 10 = 110$ ✓
- n 块总时间 = $(T + M + C) + (n-1)\times[\max(C,T)+M] = 160 + 110(n-1)$ μs

**双缓冲流水推演**：

- 第 1 块：输入 $0&#126;100$（缓冲区1）→ 移送 $100&#126;110$ → 处理 $110&#126;160$，完成时刻 **160μs**
- 设备在 $t = 100$ 起改填缓冲区2：$100&#126;200$；第 2 块移送等缓冲区2满（200）即可（用户区 160 已空闲）→ 移送 $200&#126;210$、处理 $210&#126;260$，第 2 块完成时刻 **260μs**
- 第 3 块验证稳态：输入 $200&#126;300$ → 移送 $300&#126;310$ → 处理 $310&#126;360$，完成 360μs，稳态每块 = $360 - 260 = 100\mu s$，恰为 $\max(C+M, T) = \max(60, 100) = 100$ ✓
- n 块总时间 = $160 + 100(n-1)$ μs

> **考点**：单缓冲 $\max(C,T)+M$、双缓冲 $\max(C+M,T)$；求 n 块总时间 = **第一块 $(T+M+C)$ + $(n-1)\times$ 每块稳态耗时**。
> **易错点**：单缓冲中 T 与 C 可重叠，但 **M 必须串行**（缓冲区同一时刻只能被输入方或用户区一方使用）；双缓冲中与 T 重叠的是 **M+C 整段**，不是 C。

## 设备分配与回收

### 分配用数据结构

| 数据结构 | 数量 | 记录内容 |
|:---|:---|:---|
| **系统设备表 SDT** | 全系统 1 张 | 系统全部设备表目，每项指向对应 DCT |
| **设备控制表 DCT** | 每设备 1 张 | 类型、标识符、忙/闲状态、**设备等待队列指针** |
| **控制器控制表 COCT** | 每控制器 1 张 | 控制器状态、与通道的连接指针、等待队列指针 |
| **通道控制表 CHCT** | 每通道 1 张 | 通道状态、通道等待队列指针 |

分配顺序固定为**设备 → 控制器 → 通道**三步：以物理设备名查 SDT 找到 DCT → 由 DCT 找 COCT → 由 COCT 找 CHCT；**任一层忙**，就把进程 PCB 挂到**该层的等待队列**；**三者全部到手**才能启动 I/O。回收时删除各表分配记录并**唤醒等待队列的下一个进程**。

### 安全分配与不安全分配

| 方式 | 做法 | 后果 |
|:---|:---|:---|
| **安全分配** | 进程发出 I/O 请求后**立即阻塞**，设备用完释放才继续运行 | **不会死锁**；但 CPU 与设备**串行工作**，进程推进慢 |
| **不安全分配** | 发出 I/O 请求后**继续运行**，需要时可再请求其他设备 | 推进快、可同时操作多个设备；但**可能死锁**（需配合银行家算法等避免） |

> **易错点**：会死锁的是**不安全分配**方式；安全分配"请求即阻塞"，不持有设备等待设备，**不会死锁**。

### 设备独立性（逻辑设备名映射）

用户程序用**逻辑设备名**（如 printer）提出请求，系统查**逻辑设备表 LUT** 映射为物理设备名再分配——**换设备只需改映射表，程序不用改**，这就是**设备独立性**。LUT 表项含**逻辑设备名、物理设备名（或系统设备表指针）、驱动程序入口地址**三项，可**整个系统一张**（所有用户共用）或**每用户一张**（各用户逻辑名互不干扰）；同类设备有多台时，系统从 SDT 起**逐台寻找空闲设备**，全部忙才挂该类设备的等待队列。

## SPOOLing（假脱机技术）

**脱机技术**：用外围控制机把输入预先读入磁带、输出先写到磁带，主机不直接操作慢速设备。**SPOOLing** 用**软件 + 磁盘**模拟这一过程，把**独占设备改造成共享的虚拟设备**。

![SPOOLing 系统组成](/blog/images/OS第5章 输入输出管理.assets/spooling-structure.png)

| 组成 | 位置 | 作用 |
|:---|:---|:---|
| **输入井 / 输出井** | **磁盘（外存）** | 模拟脱机的磁带：收容输入数据 / 用户输出数据 |
| 输入/输出缓冲区 | **内存** | 设备与井之间的中转 |
| **输入进程 / 输出进程** | 内存 | 模拟脱机时的**外围控制机**，负责设备与井间搬运 |
| 井管理程序 | 内存 | 控制作业与磁盘井之间的信息交换 |

**共享打印机流程**（文字演示）：

1. 用户进程请求打印时，SPOOLing 系统在**输出井**为其申请空闲盘块，把打印数据写入；
2. 再申请一张空白**打印请求表**，挂到打印队列上，随即返回——用户进程认为"打印已完成"；
3. **输出进程**空闲时从队列逐个取任务，把井中数据经输出缓冲区送打印机打印。

![共享打印机原理](/blog/images/OS第5章 输入输出管理.assets/spooling-printer.png)

效果：多个进程可"同时"提交打印任务（各自拿到一台**虚拟打印机**），物理上打印机仍逐个任务排队执行——**逻辑共享、物理排队**。

> **考点**：SPOOLing 的井开在**磁盘**上；它是"独占设备 → 共享（虚拟）设备"的典型实现，打印机问题必考；输入/输出进程扮演**外围控制机**角色。

## 磁盘的结构与管理

![磁盘结构与磁盘地址](/blog/images/OS第5章 输入输出管理.assets/disk-structure.png)

| 概念 | 说明 |
|:---|:---|
| **盘面** | 盘片的磁记录表面，一个盘片上下两面各算一个盘面，**每面一个磁头** |
| **磁道** | 盘面上的同心圆，**由外向内编号** |
| **扇区** | 磁道分成的弧段，**磁盘读写的最小单位**（通常 512B） |
| **柱面** | 所有盘面上**相同半径磁道**的集合 |

**磁盘地址 =（柱面号，盘面号，扇区号）**。读取一个磁盘块的动作：**按柱面号移动磁臂**到目标柱面 → **激活目标盘面对应的磁头** → 磁盘旋转使目标扇区**从磁头下划过**完成读写。

管理三步：**低级格式化（物理格式化）**——划分磁道、扇区，写入扇区头尾与校验信息 → **分区**——把磁盘划成若干分区（卷）→ **高级格式化（逻辑格式化）**——在各分区上**建立文件系统**（引导块、超级块、空闲空间管理等）。磁盘 0 号扇区存放**引导块**（自举程序）；坏块在格式化时标记或用备用块替换。

### 磁盘访问时间（必考三段式）

$$T_{\text{访问}} = T_{\text{寻道}} + T_{\text{旋转延迟}} + T_{\text{传输}}$$

| 组成 | 含义 | 量级 |
|:---|:---|:---|
| **寻道时间** | 磁臂移动到目标磁道的时间 | **毫秒级，占大头** |
| **旋转延迟** | 目标扇区转到磁头下方的时间，**平均 = 转半圈** | 毫秒级 |
| **传输时间** | 读/写数据本身的时间 | 最小 |

**例题**：磁盘转速 7200 r/min，平均寻道时间 8 ms，每磁道 100 个扇区，读 1 个扇区共需多少时间？

1. 转一圈的时间：$\dfrac{60\text{ s}}{7200} = 8.33\text{ ms}$
2. 平均旋转延迟 = 转半圈：$\dfrac{1}{2} \times 8.33 = 4.17\text{ ms}$
3. 传输 1 个扇区：$\dfrac{8.33}{100} = 0.083\text{ ms}$
4. 总时间 = $8 + 4.17 + 0.083 \approx \mathbf{12.25\text{ ms}}$

> **考点**：**平均旋转延迟 = 半圈时间**，7200rpm 即 4.17ms（不是 8.33ms）；三段中**寻道时间占主导**——磁盘调度算法优化的正是寻道。

## 磁盘调度算法（必考）

调度目标：**减少平均寻道时间**。六个算法的含义：

- **FCFS（先来先服务）**：按请求到达顺序服务，公平简单，但寻道距离长；
- **SSTF（最短寻道时间优先）**：每次选**离当前磁头最近**的请求，平均寻道短，但**远处请求可能饥饿**；
- **SCAN（电梯算法）**：沿一个方向扫到**端点**才转向，途中依次服务；**不会饥饿**，但两端等待不均；
- **LOOK**：SCAN 的改进，扫到**该方向最远请求**即折返，少走空道；
- **C-SCAN**：只**单向服务**，到端点后**快速回卷到另一端**再扫，各磁道等待时间更均匀；
- **C-LOOK**：C-SCAN 的改进，到最远请求后**直接回到最小请求**处继续单向服务。

### 磁盘调度公共例题（六算法完整演算）

磁道号范围 0&#126;199，磁头初始位于 **53**，当前沿磁道号**增大方向**移动，请求队列：**98, 183, 37, 122, 14, 124, 65, 67**。求各算法的磁头移动道数。

**FCFS**：按到达顺序
53→98→183→37→122→14→124→65→67
$= 45+85+146+85+108+110+59+2 = \mathbf{640}$

**SSTF**：每次取最近者（65, 67, 37, 14, 98, 122, 124, 183）
53→65→67→37→14→98→122→124→183
$= 12+2+30+23+84+24+2+59 = \mathbf{236}$

**SCAN**（增大方向，扫到端点 **199** 才转向）
53→65→67→98→122→124→183→**199**→37→14
$= 12+2+31+24+2+59+16+162+23 = \mathbf{331}$

**LOOK**（增大方向，到最远请求 **183** 即折返）
53→65→67→98→122→124→183→37→14
$= 12+2+31+24+2+59+146+23 = \mathbf{299}$

**C-SCAN**（单向服务，到 **199** 后回卷到 **0** 再扫）
53→65→67→98→122→124→183→**199**（共 146）→**0**（回程 199）→14→37（共 37）
$= 146 + 199 + 37 = \mathbf{382}$（若题目规定不计回程空走，则为 $146+14+23 = 183$）

**C-LOOK**（到 **183** 后直接回到最小请求 **14**）
53→65→67→98→122→124→183（共 130）→14（169）→37（23）
$= 130 + 169 + 23 = \mathbf{322}$

### 磁盘调度算法大对比

| 算法 | 规则 | 方向 | 是否饥饿 | 特点 |
|:---|:---|:---|:---|:---|
| **FCFS** | 按到达顺序 | 无 | 不饥饿 | 公平、简单、寻道距离最长 |
| **SSTF** | 每次选最近请求 | 任意 | **可能饥饿** | 贪心策略，总寻道通常最短 |
| **SCAN** | 单向扫到**端点**再反向 | 双向来回 | 不会 | 电梯算法，实际系统**最常用**；端点附近等待不均 |
| **LOOK** | 到**最远请求**即折返 | 双向来回 | 不会 | SCAN 改进，少走"空道" |
| **C-SCAN** | 单向服务，到端点**回卷到另一端** | 单向 | 不会 | 各磁道等待时间**最均匀** |
| **C-LOOK** | 到最远请求后**回到最小请求** | 单向 | 不会 | C-SCAN 改进，回程空走更少 |

> **考点**：SCAN 与 LOOK 的区别——SCAN **必须到端点（199）**才转向，LOOK 到**最远请求（183）**就折返，所以 LOOK 寻道更短；SCAN 与 C-SCAN 的区别——SCAN 双向都服务、C-SCAN **只单向服务**。
> **易错点**：SCAN 沿当前方向**先服务途中请求、到端点才转向**，不能半路折返；C-SCAN 回程（端点→另一端）**不服务任何请求**。

## 固态硬盘（SSD）

**SSD** 由**闪存（Flash）芯片**构成，**没有机械部件**，因此**没有寻道时间和旋转延迟**，随机读性能接近顺序读。

| 对比项 | 机械硬盘 HDD | 固态硬盘 SSD |
|:---|:---|:---|
| 机械部件 | 有（盘片旋转、磁头移动） | **无** |
| 寻道/旋转延迟 | 毫秒级 | **没有** |
| 随机访问 | 慢（需寻道+旋转） | **快**（接近顺序访问） |
| 写入方式 | 可**原地覆盖写** | **不能原地写**：先**擦除**（以**块**为单位）再**写入**（以**页**为单位） |
| 寿命 | 长 | 块擦写次数有限，需**磨损均衡** |
| 其他 | 怕震动 | 抗震、低功耗、静音 |

SSD 的读写以**页**为单位；若目标页已有数据，必须先擦除其所在**整块**（"**先擦后写**"）——由此带来**写入放大**：实际写入闪存的量大于主机请求的写入量。**FTL（闪存转换层）**负责逻辑块地址到物理页的映射、垃圾回收与磨损均衡。存储单元按每单元存储位数分 **SLC（1bit）/ MLC（2bit）/ TLC（3bit）**——位数越多容量越大，但速度越慢、寿命越短。

**磨损均衡（wear leveling）**：把擦写次数**均摊**到所有块，避免个别块提前损坏：

| 方式 | 做法 | 特点 |
|:---|:---|:---|
| **动态磨损均衡** | 写入新数据时优先选**累计擦写次数少**的块 | 实现简单，但不动旧数据 |
| **静态磨损均衡** | 把长期不变化的**冷数据**搬到擦写次数多的块，腾出好块 | 更均衡、寿命更长，但搬移数据**写入放大明显** |

> **考点**：SSD 相对磁盘的最大优势是**无寻道与旋转延迟、随机读快**；最大限制是**不能原地覆盖写（先擦后写）与擦写寿命**，靠**磨损均衡**缓解。

## 高频考点速记

| 考点 | 记忆 |
|:---|:---|
| 设备分类 | 三维度：块/字符（可否寻址）、低/中/高速、独占/共享/虚拟；**磁盘=块+共享+高速**，打印机=字符+独占 |
| I/O 端口 | 数据/控制/状态三类寄存器；独立编址（专用 I/O 指令）或统一编址（内存映射） |
| 三种控制方式 | 轮询忙等全程参与 → 中断每字打断 CPU、数据经 CPU → DMA 块直传不经 CPU（干预 2 次）→ 通道干预最少 |
| 软件四层 | 用户层（库函数）→ 设备独立软件（命名/保护/缓冲/分配/SPOOLing）→ 驱动（写寄存器，唯一直接控硬件）→ 中断处理；**每层只调下一层** |
| 缓冲目的 | 缓和速度矛盾、减少中断频率、提高并行性、数据粒度匹配 |
| 单缓冲 | 每块稳态 $\max(C,T)+M$（M 串行不可重叠） |
| 双缓冲 | 每块稳态 $\max(C+M,T)$；n 块总时间 = 第一块 $(T+M+C)+(n-1)\times$ 每块 |
| 设备分配 | SDT→DCT→COCT→CHCT，设备→控制器→通道三步，忙则 PCB 挂该层等待队列 |
| 分配安全性 | 安全分配请求即阻塞**不死锁**；不安全分配可推进但**可能死锁** |
| 设备独立性 | 逻辑设备名 + LUT 映射，换设备不改程序 |
| SPOOLing | 井（磁盘）+ 缓冲区 + 输入/输出进程；独占设备 → **虚拟共享设备**，逻辑并行、物理排队 |
| 磁盘地址 | 柱面号+盘面号+扇区号；读取三步：移臂→选磁头→旋转到扇区 |
| 访问时间 | 寻道 + 旋转延迟（**平均半圈**）+ 传输；寻道占主导；7200rpm → 4.17ms |
| 格式化 | 低级格式化划分扇区写校验；高级格式化建文件系统 |
| 磁盘调度 | SSTF 会饥饿；SCAN 到端点转向；LOOK 到最远请求折返；C-SCAN/C-LOOK 单向回卷；例题 640/236/331/299/382/322 |
| SSD | 读写按**页**、擦除按**块**（先擦后写）；无寻道随机读快；磨损均衡分动态/静态（静态写入放大明显） |
