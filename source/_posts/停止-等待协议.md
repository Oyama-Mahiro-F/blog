**停止-等待协议（Stop-and-Wait）**是最简单的可靠传输协议：发送方每发送一帧就**停下来等待确认**，收到 ACK 后才发送下一帧；超时未收到确认则重传该帧。它一帧一个往返，信道利用率极低，但却是理解**可靠传输三要素**和**滑动窗口**的起点，也是 408 信道利用率计算的经典考点。

## 可靠传输三要素

链路层要实现可靠传输，三个要素**缺一不可**：

![可靠传输三要素](/blog/images/第3章 数据链路层.assets/stopping-waiting-reliable-transmission.png)

| 要素 | 作用 |
|:---|:---|
| **确认（ACK）** | 接收方告知发送方哪些帧已正确收到 |
| **超时重传** | 发送方启动计时器，超时未收到确认就重传（可靠性的最终保障） |
| **序号（编号）** | 区分新旧帧，判断重复/乱序 |

> **考点**：可靠传输 = 确认 + 超时重传 + 序号，三者缺一不可；TCP 的可靠传输同样基于这三要素。

## 工作过程

```
发送方 A                           接收方 B
   │── 数据帧 0 ────────────────────►│
   │◄──────────── 确认 ACK0 ────────│
   │── 数据帧 1 ────────────────────►│
   │◄──────────── 确认 ACK1 ────────│
   │── 数据帧 2 ┄┄┄┄┄┄┄┄ 丢失 ┄┄┄┄┄►│
   │   (计时器超时 → 重传帧 2)        │
   │── 数据帧 2 ────────────────────►│
   │◄──────────── 确认 ACK2 ────────│
```

> 图：停止-等待协议——发一帧、等确认、再发下一帧，一帧一个往返。

## 三种异常情况

| 情况 | 发送方行为 | 接收方行为 |
|:---|:---|:---|
| 数据帧丢失 | 计时器超时后**重传**该帧 | 一直等待，收到重传帧后正常确认 |
| 确认帧丢失 | 计时器超时后**重传**该帧 | 收到**重复帧**，**丢弃**并**再次发送确认** |
| 确认帧迟到 | 可能超时重传 | 靠**序号**识别重复帧并丢弃 |

由于发送方一次最多只有一帧在途，序号只需 **1 位**（0、1 交替）即可区分新旧帧。

## 信道利用率（重点考点）

停止-等待的每个周期只发送一帧，其余时间都在等待往返传播：

$$U = \frac{T_{发送}}{T_{发送} + RTT + T_{确认}}$$

- $T_{发送}$ = 帧长 / 数据率（发送时延）
- **RTT** = 往返传播时延 = 2τ（τ 为单程传播时延）
- 帧长注意单位换算：1KB = 1024B = 8192 bit

**例题（王道经典）**：主机 A 向 B 发送 **1KB** 的帧，数据率 **100Mbps**，RTT = **20ms**，确认帧发送时延与数据帧相同，求停止-等待的信道利用率。

| 项目 | 计算 |
|:---|:---|
| 帧长 | 1KB = 1024 B = 8 × 1024 = **8192 bit** |
| $T_{发送}$ | $\frac{8192}{100 \times 10^6} = 8.192 \times 10^{-5}$ s = **0.08192 ms** |
| RTT | **20 ms** |
| $T_{确认}$ | 与数据帧相同 = **0.08192 ms** |
| 利用率 U | $\frac{0.08192}{0.08192 + 20 + 0.08192} = \frac{0.08192}{20.16384}$ ≈ **0.00406 ≈ 0.41%** |

**结论**：发送一帧只需 0.08ms，却要等 20ms 的往返——**利用率仅约 0.4%**，信道几乎全程空闲。这是停止-等待协议的最大缺点；**滑动窗口协议（GBN / SR）连续发送**正是为解决这个问题而生。

> **易错点**：① RTT 本身就是往返时间（RTT = 2τ），分母**直接用 RTT，不要再乘 2**；若题给的是**单程**传播时延 τ，则等待时间为 2τ；② 确认帧发送时间有时给"忽略"，有时按帧长算——按题目条件代入。

## 高频考点速记

| 考点 | 记忆 |
|:---|:---|
| 停止-等待 | 发一帧、等确认、再发下一帧；一帧一个往返 |
| 可靠传输三要素 | **确认 + 超时重传 + 序号**，三者缺一不可 |
| 序号位数 | 1 位（0/1 交替）即可区分新旧帧 |
| 确认丢失/迟到 | 重传后接收方**丢弃重复帧**并重复确认 |
| 信道利用率 | $U = \frac{T_{发送}}{T_{发送} + RTT + T_{确认}}$；例题 ≈ **0.41%** |
| 致命缺点 | 等待 RTT 时间占比大 → **利用率极低**（→ GBN/SR 滑动窗口） |
