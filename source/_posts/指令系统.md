**指令系统（Instruction Set Architecture，ISA）**是一台计算机中**所有机器指令的集合**，处于软件与硬件的**分界面**：上层软件按 ISA 编译，下层硬件按 ISA 实现，同一 ISA 可以有不同的微架构（如 Intel 与 AMD 都实现 x86）。本章 408 考查三大块：**指令格式（操作码 + 地址码，扩展操作码计算必考）、寻址方式（十种寻址方式的 EA 与访存次数是绝对核心）、CISC 与 RISC（对比表）**。

约定记号：**(X)** 表示寄存器 X 的内容，**M[a]** 表示主存地址 a 的单元内容，**A** 为指令中给出的**形式地址**，**EA（Effective Address）** 为操作数的**有效地址**（最终访问主存的真实地址）。

## 指令格式：操作码与地址码

一条机器指令由**操作码**和**地址码**两部分组成：

```text
+-------------+--------------------------+
|   操作码 OP  |         地址码 A          |
+-------------+--------------------------+
```

- **操作码**：指明指令"做什么"（加/减/传送/跳转……），是指令中**必须**有的字段
- **地址码**：指明操作数（及结果）"在哪里"——可以是**主存地址**，也可以是**寄存器编号**，还可以是**立即数**本身

> **考点**：地址码字段给出的不一定都是主存地址。给出**寄存器编号**时操作数在 CPU 内部，执行阶段**无需访存**；给出**立即数**时操作数直接藏在指令里，连主存都不用碰。

### 四地址、三地址、二地址、一地址与零地址

| 指令格式 | 字段形式 | 操作语义 | 特点与适用场景 |
|:---|:---|:---|:---|
| **四地址** | OP A1 A2 A3 A4 | (A1) OP (A2) → A3；A4 = 下一条指令地址 | 早期机器用；地址字段太多、字长压力大，已被 PC 取代 |
| **三地址** | OP A1 A2 A3 | (A1) OP (A2) → A3 | 最直观，源操作数不被破坏；RISC 常用（结果写独立寄存器） |
| **二地址** | OP A1 A2 | (A1) OP (A2) → A1 | **最常用**（x86 风格）；结果**覆盖**源操作数 A1；按操作数物理位置分 SS（存-存）/RS（寄-存）/RR（寄-寄） |
| **一地址** | OP A | 隐含累加器：ACC OP (A) → ACC；或单目：(A) OP → A | 单操作数指令（INC、NOT）；隐含 ACC 可省一个地址字段 |
| **零地址** | OP | 无操作数或操作数**隐含** | NOP、HALT 等无操作数指令；**堆栈计算机**的 PUSH/POP（操作数隐含在栈顶） |

> **考点**：零地址指令 ≠ 没有操作数——要么真的**不需要操作数**（空操作、停机），要么操作数**隐含约定**（堆栈操作隐含 SP 指向的栈顶）。
> **易错点**：二地址指令 `ADD A1, A2` 执行后 **A1 原内容被结果覆盖**；三地址指令的源操作数则保持不变。

计算 C = A + B 的对比（二地址需 3 条，三地址 1 条）：

```text
二地址（x86 风格）            三地址（MIPS 风格）
MOV  C, A                    ADD  C, A, B     ; C ← A + B，一条完成
ADD  C, B                    （前提：地址字段/寄存器足够多）
```

### 定长操作码

所有指令的操作码**位数相同、位置固定**：$n$ 位操作码最多表示 $2^n$ 条指令。

| 优点 | 缺点 |
|:---|:---|
| 译码简单、速度快；格式规整，**利于流水线**（RISC 采用，如 MIPS 固定 6 位操作码） | 操作码占位多了地址码就少；指令数不足 $2^n$ 时编码空间浪费 |

### 扩展操作码（变长操作码）

操作码位数**可变**：**短操作码留给高频指令，长操作码留给低频指令**——这是**哈夫曼编码**"高频短码、低频长码"思想的应用，可在有限指令字长内容纳更多指令种类。

- **前缀编码原则**：任一短操作码都**不能**是更长操作码的**前缀**，否则译码时产生二义性（无法判断这条指令的操作码到底多长）
- 常用扩展手法：**每级留下"全 1"码点不用**，把它作为下一级扩展的公共前缀，"借"地址码字段继续当操作码用
- 代价：硬件需逐级判断，译码复杂，不利于流水线

> **考点**：判断一组操作码是否合法，就看**短码是否为长码的前缀**。例如 4 位码 1111 已用作扩展前缀，就绝不能再定义成一条 4 位操作码的指令。
> **易错点**：扩展不是随意留码点——某一级**剩余码点数 × $2^{借位位数}$** 才是下一级可用的总码点数，做题必须**逐级清算剩余空间**。

### 扩展操作码例题（计算必考）

**题目（正向）**：指令字长 16 位，每个地址码字段 4 位。若三地址指令 15 条、二地址指令 8 条、一地址指令 127 条，其余编码全部留给零地址指令，问各级操作码位数各是多少？零地址指令最多有多少条？

**解**（逐级扩展、逐级清算剩余空间）：

**第一级（三地址，操作码 4 位）**：4 位操作码共 $2^4 = 16$ 个码点，三地址指令用 15 条，编号 $0000 \sim 1110$；剩 **1 个码点 1111** 作扩展前缀。

**第二级（二地址，操作码 8 位）**：前缀 1111 借地址码 A1 的 4 位，得 $1 \times 2^4 = 16$ 个 8 位码点；二地址指令用 8 条，编号 $1111\ 0000 \sim 1111\ 0111$；剩 $16 - 8 = 8$ 个码点（$1111\ 1000 \sim 1111\ 1111$）继续扩展。

**第三级（一地址，操作码 12 位）**：8 个前缀各借 A2 的 4 位，得 $8 \times 2^4 = 128$ 个 12 位码点；一地址指令用 127 条，编号 $1111\ 1000\ 0000 \sim 1111\ 1111\ 1110$；剩 $128 - 127 = 1$ 个码点（$1111\ 1111\ 1111$）继续扩展。

**第四级（零地址，操作码 16 位）**：1 个前缀借 A3 的 4 位，得 $1 \times 2^4 = 16$ 个 16 位码点，全部给零地址指令。

| 指令类型 | 操作码位数 | 已用条数（本级共） | 剩余码点 | 扩展去向 |
|:---|:---:|:---:|:---:|:---|
| 三地址 | 4 | 15（共 16） | 1（1111） | 借 4 位 → 8 位级 16 码点 |
| 二地址 | 8 | 8（共 16） | 8 | 借 4 位 → 12 位级 128 码点 |
| 一地址 | 12 | 127（共 128） | 1（全 1） | 借 4 位 → 16 位级 16 码点 |
| 零地址 | 16 | 最多 **16**（共 16） | 0 | 末级可用满 |

**答**：操作码依次为 **4 / 8 / 12 / 16 位**，零地址指令最多 **16 条**。所有指令的操作码互不为前缀，可唯一译码 ✓

**题目（反向）**：同为 16 位指令字长、每个地址字段 4 位。若三地址 15 条、二地址 15 条、一地址 12 条，求零地址指令最多多少条？

**解**：4 位级剩 1 个前缀 1111 → 8 位级共 $1 \times 2^4 = 16$ 个码点，用 15 条剩 1 个前缀 1111 1111 → 12 位级共 $1 \times 2^4 = 16$ 个码点，用 12 条**剩 4 个前缀**（$1111\ 1111\ 1100 \sim 1111\ 1111\ 1111$）→ 16 位级码点 = $4 \times 2^4 = \mathbf{64}$，零地址指令最多 **64 条**。

> **考点**：反向题的关键是算出中间某一级**剩下几个前缀**——每个剩余前缀都能再分裂出 $2^{地址字段位数}$ 个下一级码点。若反过来"给零地址条数求一地址最多几条"，思路相同、自底向上逐级回推即可。

## 指令寻址：下一条指令在哪

**指令寻址**解决"下一条指令的地址如何形成"，只有两种方式：

| 方式 | 机制 | 说明 |
|:---|:---|:---|
| **顺序寻址** | $(PC) + 1 \to PC$ | 这里的"1"指**一条指令的长度**：按字编址时 +1；按字节编址且指令变长时，取指后 PC 自动加**该指令的实际字节数** |
| **跳跃寻址** | 转移指令直接修改 PC | 由转移指令（JMP、条件转移、CALL、RET 等）给出目标地址，PC 被赋值为跳转目标而非递增 |

> **易错点**："PC+1"的 1 不是恒等于 1 字节。定长指令按字编址时 +1 即可；x86 这类变长指令集，取指后 PC 要加**本条指令的实际长度**。
> **考点**：转移指令的目标地址常用**相对寻址**给出（目标 = 取指后的 PC + 偏移量 A），程序整体搬到内存任何位置都能正确跳转——这就是**位置无关代码（PIC）**的基础。

## 数据寻址：十种寻址方式

**数据寻址**解决"操作数在哪里"。指令中给出的地址叫**形式地址 A**，经寻址方式变换后得到**有效地址 EA**；指令中通常设**寻址特征字段**指明本操作数采用哪种寻址方式。

### 隐含寻址

操作数地址由操作码**隐含约定**（不显式给出），最常见的是隐含**累加器 ACC**：`ADD A` 实为 $ACC \leftarrow ACC + M[A]$。优点是**缩短指令字长**，缺点是不够灵活。堆栈类指令隐含 SP、单地址指令隐含 ACC，都是典型。

### 立即寻址

操作数本身就在指令的地址码字段（**立即数**），取指后立即可用，执行阶段 **0 次访存、速度最快**。用途：给变量赋**初值、常量**（如 `MOV AX, 5`）。缺点：立即数位数 = A 的位数，表示范围受限；补码立即数还需符号扩展。

> **考点**：立即寻址中地址码是**操作数本身**而非地址——它是"没有有效地址 EA"的唯一常见情形。

### 直接寻址

$$EA = A$$

形式地址就是有效地址，执行阶段**访存 1 次**取操作数。优点：简单直观，无需计算；缺点：寻址范围受 A 位数限制（A 有 $n$ 位只能访问 $2^n$ 个单元），且地址写死在指令里，不便于程序浮动。

### 间接寻址

$$EA = (A)$$

形式地址指向的**主存单元里存的才是有效地址**——"地址的地址"。

- **一次间接**：先访存读 $M[A]$ 得 EA，再访存取操作数 → 执行阶段共 **2 次访存**
- **多次间接**：主存单元的最高位作**间址特征位**，为 1 继续间接、为 0 则该单元内容即 EA；$n$ 次间接执行阶段访存 $n + 1$ 次
- 优点：**扩大寻址范围**（短 A 经中转可覆盖全地址空间）、便于实现指针与子程序跳转；缺点：多次访存，速度最慢

### 寄存器寻址与寄存器间接寻址

- **寄存器（直接）寻址**：地址码给出**寄存器编号 R**，操作数就在寄存器中：操作数 $= (R)$，**0 次访存**，速度最快；寄存器编号位数远小于主存地址位数，**指令更短**；受限于寄存器个数
- **寄存器间接寻址**：寄存器里存的**是地址**：$EA = (R)$，执行阶段**访存 1 次**；寻址范围取决于寄存器位宽（位宽足够即可覆盖全部主存）；比间接寻址少访存一次，是指针的常用实现

> **易错点**：两者只差"一层括号"——寄存器寻址的寄存器里是**操作数**（0 次访存），寄存器间接寻址的寄存器里是**操作数的地址**（1 次访存）。

### 相对寻址

$$EA = (PC) + A$$

以 **PC 的内容为基准、A 为偏移量**（补码，可正可负）。注意计算时 PC 已完成取指后的自增，即基准是**下一条指令的地址**，不是本条指令的地址。用途：**转移指令**给定跳转距离；程序整体**浮动**（搬到内存任意处）后仍能正确转移——**位置无关**。

### 基址寻址

$$EA = (BR) + A$$

以**基址寄存器 BR 的内容为基准**、A 为位移量。BR 由**操作系统**设置（专用寄存器或指定的通用寄存器），**用户程序不能修改**其内容。用途：**多道程序环境下的程序重定位**——程序装入哪里，OS 就把基址设成哪里，程序内地址不变；BR 位数可大于 A，从而**扩大寻址范围**。**面向系统**，对用户透明。

### 变址寻址

$$EA = (IX) + A$$

以**形式地址 A 为基准**、**变址寄存器 IX 的内容为位移量**——与基址正好"反过来"。**IX 由用户设定和修改**，对用户可见，执行中还可自增（自动变址）；A 指向数组**首元素**。用途：**数组、循环**处理——循环体不变，每轮 IX 加 1 即可依次访问各元素。**面向用户**。

### 堆栈寻址

操作数隐含在**堆栈栈顶**，由**堆栈指针 SP** 指示：

$$EA = (SP)$$

- **软堆栈**（主存中划出栈区）：执行阶段访存 1 次；**硬堆栈**（寄存器堆实现）：0 次访存
- 压栈 `PUSH`：先 $(SP) - 1 \to SP$（按字节编址存 16 位数则 -2），再存数；出栈 `POP`：先取数，再 $(SP) + 1 \to SP$——**先进后出（LIFO）**，栈通常向低地址生长
- 用途：**函数调用的参数传递与返回地址保存、表达式求值**（零地址计算机的基础）

### 十种寻址方式大对比

| 寻址方式 | 有效地址 EA | 访存次数（取指令之外） | 特点 / 用途 |
|:---|:---|:---:|:---|
| 隐含寻址 | 操作数隐含在约定位置（ACC、栈顶） | 0 | 缩短指令字长；不够灵活 |
| 立即寻址 | 无（A 即操作数） | **0** | 最快；装常量/初值；范围受 A 位数限制 |
| 直接寻址 | $EA = A$ | **1** | 简单；寻址范围受 A 位数限制 |
| 间接寻址 | $EA = (A)$ | **2**（n 次间接 n+1） | 扩大寻址范围、指针；最慢 |
| 寄存器寻址 | 无（操作数 = (R)） | **0** | 最快、指令短；寄存器个数有限 |
| 寄存器间接寻址 | $EA = (R)$ | **1** | 寄存器给地址；范围 = 寄存器位宽 |
| 相对寻址 | $EA = (PC) + A$ | **1** | 转移指令、程序浮动、位置无关 |
| 基址寻址 | $EA = (BR) + A$ | **1** | 重定位、多道程序；面向 OS；扩大寻址范围 |
| 变址寻址 | $EA = (IX) + A$ | **1** | 数组/循环；面向用户；IX 可变 |
| 堆栈寻址 | $EA = (SP)$ | **1**（软堆栈） | LIFO；函数调用、参数传递、表达式求值 |

> **考点**：访存次数速记——**立即、寄存器（含隐含 ACC）0 次；直接、寄存器间接、相对、基址、变址、堆栈各 1 次；一次间接 2 次**（均不含取指令本身的访存）。

### 相对、基址、变址：一张表辨析

三者都是"两量相加"，区别在**谁作基准、谁作偏移、面向谁**：

| 对比项 | 相对寻址 | 基址寻址 | 变址寻址 |
|:---|:---|:---|:---|
| 有效地址 | $(PC) + A$ | $(BR) + A$ | $(IX) + A$ |
| 作**基准**的量 | PC 内容（自动指向下一条指令） | **基址寄存器内容**（OS 装入，用户不可改） | **形式地址 A**（程序员/编译器给出） |
| 作**偏移**的量 | 形式地址 A（补码，可正可负） | 形式地址 A | **变址寄存器内容 (IX)**（用户可改、可自增） |
| 面向对象 | 用户（转移指令） | **系统**（对用户透明） | **用户**（IX 对用户可见） |
| 典型用途 | 转移指令、程序浮动、位置无关代码 | 多道程序**重定位**、扩大寻址范围 | **数组遍历、循环**处理 |
| 一句话记忆 | PC 基准、A 偏移 | BR 基准、A 偏移 | A 基准、IX 偏移 |

> **易错点**：基址与变址公式形如孪生，判别口诀——**"基址锁基准（BR 是基准、系统管），变址锁偏移（IX 是偏移、用户管）"**；相对寻址的基准 PC 会**自动加 1**，算转移目标时基准是取指后的 PC。

## 寻址方式有效地址例题

**题目**：某机主存按字编址，指令字长 16 位，地址码字段 A = 1234H。执行某条操作数访问指令时，有关寄存器与主存内容如下，求各寻址方式下的 EA 与操作数（访存次数不含取指令）。

| 寄存器 | PC | BR（基址） | IX（变址） | SP | R0 | R1 |
|:---|:---:|:---:|:---:|:---:|:---:|:---:|
| 内容 | 2000H | 3000H | 1000H | 5F00H | 1234H | 0088H |

| 主存地址 | 1234H | 5678H | 3234H | 4234H | 5F00H |
|:---|:---:|:---:|:---:|:---:|:---:|
| 内容 | 5678H | 1234H | 7FF0H | 0C00H | 1234H |

**逐个推演**：

| 寻址方式 | EA 计算 | EA | 操作数 | 访存 |
|:---|:---|:---:|:---|:---:|
| 立即 | A 即操作数 | — | **1234H** | 0 |
| 直接 | $EA = A = 1234H$ | **1234H** | M[1234H] = **5678H** | 1 |
| 一次间接 | $EA = (A) = M[1234H] = 5678H$ | **5678H** | M[5678H] = **1234H** | 2 |
| 寄存器 | 操作数 = (R1) = 0088H | — | **0088H** | 0 |
| 寄存器间接 | $EA = (R0) = 1234H$ | **1234H** | M[1234H] = **5678H** | 1 |
| 相对 | $EA = (PC) + A = 2000H + 1234H$ | **3234H** | M[3234H] = **7FF0H** | 1 |
| 基址 | $EA = (BR) + A = 3000H + 1234H$ | **4234H** | M[4234H] = **0C00H** | 1 |
| 变址 | $EA = (IX) + A = 1000H + 1234H$ | **2234H** | M[2234H]（表中未列出） | 1 |
| 堆栈 | $EA = (SP) = 5F00H$ | **5F00H** | M[5F00H] = **1234H** | 1 |

**验算（十六进制加法，逢十六进一）**：$2000H + 1234H = 3234H$，$3000H + 1234H = 4234H$，$1000H + 1234H = 2234H$ ✓

> **易错点**：间接寻址 $EA = (A)$ 要**先访存一次**拿地址，不能直接写 $EA = A$；相对寻址的基准是**取指后的 PC**（本例指令为单字长，取指后 PC 已指向下一条）；直接与寄存器间接结果虽同（都到 1234H），但前者地址来自**指令字段**、后者来自**寄存器**。

**相对寻址转移范围小例**：转移指令存放在主存 **2000H** 单元（按字编址），取出该指令后 $(PC) = 2001H$。若偏移量 $A = -3$（补码），转移目标 $= 2001H + (-3) = \mathbf{1FFEH}$（**向后**跳 3 个单元）；若 $A = +5$，目标 $= 2006H$（向前跳 5 个单元）。A 为 8 位补码时偏移范围 $-128 \sim +127$，即相对取指后的 PC **最多向后 128、向前 127 个单元**。

## CISC 和 RISC

| 对比项 | CISC（复杂指令集计算机） | RISC（精简指令集计算机） |
|:---|:---|:---|
| 指令系统规模 | **多**（一般 200 条以上） | **少**（一般少于 100 条） |
| 指令长度 | **可变**（x86 为 1&#126;15 字节） | **定长**（如 MIPS 固定 32 位） |
| 指令使用频率 | 差别大（少数指令占绝大多数执行时间） | 精简后使用频率较均衡 |
| 指令执行时间 | 相差悬殊（多数指令多个周期） | **绝大多数一个时钟周期** |
| 寻址方式 | 多（可达十种以上） | **少**（通常仅两三种） |
| 通用寄存器数量 | 少 | **多**（32 个以上） |
| 访存限制 | **多数指令都能访存** | **仅 Load / Store 指令访存**，运算只在寄存器间进行 |
| 控制方式 | **微程序控制**为主（便于实现复杂指令） | **组合逻辑（硬布线）**为主（速度快） |
| 流水线 | 指令长短、周期不一，难以流水优化 | 指令规整、单周期，**便于流水线** |
| 编译与代码密度 | 编译简单、目标程序短（省空间）；难以做指令级优化 | **必须优化编译**、目标程序较长；时间与指令执行效率高 |
| 代表 | x86 / x86-64 | MIPS、ARM、RISC-V、PowerPC |

**RISC 的核心特征**：指令**定长**、种类少、格式规整；**Load/Store 体系**——只有取数/存数指令访问主存，ALU 运算一律在寄存器间进行；设置**大量通用寄存器**减少访存；控制器以**组合逻辑**实现；高度依赖**优化编译**；天然适配**流水线**。从**时间**看，RISC 用多条简单指令替换 CISC 的一条复杂指令，单条更快、总周期数可更少；从**空间**看，CISC 代码密度更高；从**指令效率**看，RISC 把高频简单指令做到极致。

```text
CISC:  ADD [1000H], AX        ; 一条指令：读内存 + 加法 + 写回内存
RISC:  LOAD R1, [1000H]       ; 取数：主存 → 寄存器
       ADD  R2, R2, R1        ; 运算：寄存器之间
       STORE [1000H], R2      ; 存数：寄存器 → 主存
```

> **考点**：RISC 便于流水线的根源是**指令定长 + 执行单周期 + 仅 Load/Store 访存**；CISC 用**微程序**控制，RISC 用**组合逻辑（硬布线）**控制。现代 CPU 走向融合：x86 内部把复杂指令翻译成类 RISC 微操作执行。

## 高频考点速记

| 考点 | 记忆 |
|:---|:---|
| 指令基本格式 | **操作码**（做什么）+ **地址码**（在哪）；地址码可以是主存地址、寄存器编号或立即数 |
| 零地址指令 | 无操作数（NOP、HALT）或操作数隐含（**堆栈 PUSH/POP 隐含 SP**） |
| 二地址 vs 三地址 | 二地址**结果覆盖源操作数**（x86 风格）；三地址结果独立（RISC 常用） |
| 定长操作码 | $n$ 位 → 最多 $2^n$ 条指令；规整、译码快、利于流水线（MIPS 6 位） |
| 扩展操作码 | **短码给高频、长码给低频**（哈夫曼思想）；**短码不能是长码的前缀** |
| 扩展计算口诀 | 逐级清算：剩余码点 × $2^{借位位数}$ = 下一级码点；全 1 常作扩展前缀 |
| 经典数字 | 16 位指令：15 三 + 8 二 + 127 一 → 零地址最多 **16 条**；15/15/12 → **64 条** |
| 指令寻址 | 顺序 $(PC) + 1$（1 = 一条指令长度）；**跳跃**由转移指令直接改 PC |
| 访存次数 | 立即/寄存器/隐含 **0**；直接/寄存器间接/相对/基址/变址/堆栈 **1**；一次间接 **2** |
| 立即寻址 | 地址码即操作数，0 次访存最快，装常量；范围受字段位数限制 |
| 间接寻址 | $EA = (A)$"地址的地址"，扩大寻址范围，2 次访存最慢 |
| 基址 vs 变址 | 基址 $(BR)+A$：**BR 基准、系统管**、重定位；变址 $(IX)+A$：**A 基准、用户管**、数组循环 |
| 相对寻址 | $EA = (PC) + A$，基准是**取指后的 PC**；转移指令、位置无关代码 |
| 转移范围 | 8 位补码偏移 $-128 \sim +127$：向后最多 128、向前最多 127 个单元 |
| 堆栈寻址 | $EA = (SP)$，LIFO；PUSH 先减 SP 再存、POP 先取再加；函数调用传参 |
| CISC vs RISC | 多/变长/微程序/多数指令可访存 vs 少/定长/**硬布线**/**仅 Load/Store 访存**；RISC 利于流水线 |
