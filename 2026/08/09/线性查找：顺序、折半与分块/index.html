线性查找：顺序、折半与分块

2026-08-09
  • 数据结构&算法

查找（Searching）是在数据集合中找出关键字等于给定值的记录。衡量查找算法优劣的核心指标是平均查找长度 ASL（Average Search Length）——查找过程中与关键字比较次数的期望：

ASL=i=1∑n​pi​ci​

其中 pi​ 是查找第 i 个记录的概率（通常假设等概率 pi​=1/n），ci​ 是找到第 i 个记录所需的比较次数。

本文三种方法都建立在线性表上，区别只在于”要不要求有序””要不要额外索引”：

方法 表结构要求 有序性 额外空间 ASLsucc​（等概率） 时间复杂度
顺序查找 顺序 / 链式均可 不要求 无 (n+1)/2 O(n)
折半查找 必须顺序存储 必须有序 无 ≈log2​(n+1)−1 O(log2​n)
分块查找 索引表 + 数据表 块间有序、块内无序 索引表 log2​(b+1)+2s+1​ O(n​)

考点：三者的选择依据是表的有序性与增删频率——无序表或链表只能顺序查找；有序且顺序存储用折半；既要频繁插入删除又想比顺序快，用分块。

顺序查找

从头到尾依次扫描，逐个比较关键字——最朴素的查找方法，对表的结构不做任何要求（顺序存储和链式存储均可）。

算法实现

不带哨兵版本：

带哨兵版本（把 key 放在 a[0]，从末尾向前找，省去边界判断）：

哨兵法把目标放在 a[0]，从后往前找，循环内省去 i >= 0 的边界判断，查找失败时停在 a[0] 上。

性能分析

情况 比较次数 说明
最好 1 第一个元素就是目标
最坏 n 最后一个才是目标或不存在
平均 (n+1)/2 等概率下每次比较均分布

ASL 计算（等概率 pi​=1/n）：

ASLsucc​=i=1∑n​n1​⋅i=2n+1​ ASLfail​=n+1

考虑查找成功/失败概率的 ASL（成败各 1/2）：

ASL=21​⋅ASLsucc​+21​⋅ASLfail​=43(n+1)​
项目 结论
时间复杂度 O(n)
空间复杂度 O(1)
优点 对表无结构要求，顺序存储和链式存储均可
缺点 慢——表中即使有序也需逐个比较

例题：n=6 的顺序查找 ASL

题目：长度 n=6 的表，等概率查找，求 ASLsucc​、ASLfail​，以及成败各占一半时的 ASL。

过程：查找第 i 个元素恰需 i 次比较（i=1,2,…,6），失败需比完全部 6 个再判越界，共 n+1=7 次。

ASLsucc​=61+2+3+4+5+6​=621​=3.5

结果：ASLsucc​=3.5，ASLfail​=7，成败各半时

ASL=21​×3.5+21​×7=5.25

验算：代入通式，2n+1​=27​=3.5 ✓；43(n+1)​=421​=5.25 ✓。

考点：顺序查找的 ASLfail​=n+1（不是 n）——失败时还要多一次”下标越界/哨兵命中”的判断。

折半查找

每次取中间位置元素与关键字比较，每次将查找范围缩小一半，直到找到或区间为空。

前提：查找表必须有序，且采用顺序存储（随机访问）。

算法实现

mid = low + (high - low) / 2 可防溢出；mid = (low + high) / 2 当 n 较小时等价。

执行过程示例

易错点：循环条件是 low <= high（不是 <）——当区间只剩一个元素时 low == high，仍需比较一次。

判定树（二叉判定树）

折半查找过程可描述为一棵平衡二叉树——每个结点对应一次比较，根据比较结果走向左子树或右子树。

  • 查找成功的比较次数 = 从根到该结点的路径长度
  • 查找失败的比较次数 = 从根到失败结点（空子树）的路径长度
  • 判定树是一棵平衡二叉排序树，高度为 ⌈log2​(n+1)⌉

性能分析

等概率下的 ASL（判定树有 n 个内部结点，深度 h=⌈log2​(n+1)⌉）：

ASLsucc​=n1​i=1∑n​leveli​≈log2​(n+1)−1 ASLfail​≤⌈log2​(n+1)⌉
项目 结论
时间复杂度 O(⌈log2​(n+1)⌉)
空间复杂度 O(1)（非递归）
优点 比顺序查找快得多
缺点 必须有序 + 必须顺序存储（需要随机访问 mid）

例题：由判定树计算折半查找的 ASL

题目：对有序表 [10,20,30,40,50,60,70]（n=7）作折半查找，求等概率下的 ASLsucc​ 与 ASLfail​。

过程：先画判定树（见上），按层统计各结点的比较次数：

层次 结点 结点数 每个的比较次数
第 1 层 40 1 1
第 2 层 20、60 2 2
第 3 层 10、30、50、70 4 3
ASLsucc​=71×1+2×2+4×3​=717​≈2.43

失败结点共 n+1=8 个，全部挂在第 3 层结点之下，每个失败路径经过 3 个内部结点：

ASLfail​=88×3​=3

结果：ASLsucc​=17/7≈2.43，ASLfail​=3。

验算：通式 log2​(n+1)−1=log2​8−1=2，与 2.43 同数量级 ✓；ASLfail​≤⌈log2​(n+1)⌉=3，取到等号 ✓。对比顺序查找 n=7 时 ASLsucc​=4，折半明显更优。

考点：折半查找题必须先画判定树——ASL、最大比较次数、失败结点位置全部从树上读，硬套公式容易在 n 非 2k−1 时算错。

顺序查找 vs 折半查找对比

维度 顺序查找 折半查找
表结构要求 无要求（顺序/链式均可） 必须有序 + 顺序存储
时间复杂度 O(n) O(logn)
插入/删除 方便 困难（需保持有序，移动元素）

选择依据：表小或无序 → 顺序查找；表大且有序且顺序存储 → 折半查找；需要频繁插入删除 → 分块查找或 BST。

分块查找（索引顺序查找）

将数据分块，块间有序但块内无序。建立索引表记录每块的最大关键字和起始地址。查找分两步：① 在索引表中折半（或顺序）确定所在块 → ② 在块内顺序查找。

结构示意

上例中数据表被切成 3 块：块 1 为 10~30、块 2 为 40~60、块 3 为 70~90。块内元素无序（如块 1 是 30、20、10），但任一块内所有关键字都小于后一块的全部关键字——这正是索引表能用折半的原因。

性能分析

查找阶段 方法 平均比较次数
① 确定块 折半查找 log2​(b+1)（b 为块数）
② 块内查找 顺序查找 (s+1)/2（s 为块大小）
ASL=索引查找log2​(b+1)​​+块内查找2s+1​​​

若索引表也用顺序查找，则 ASL=2b+1​+2s+1​。将 n=b⋅s 代入并对 s 求极小，得 s=n​ 时取到最小值 n​+1。

项目 结论
时间复杂度 O(n​)（当 s≈n​ 时最优）
优点 兼具顺序查找简单 + 折半查找快速，适合插入/删除（块内无序）
缺点 需要额外的索引表空间

例题：n=9 分块查找的 ASL

题目：n=9 个记录分成 b=3 块、每块 s=3 个（即上图结构），索引表用折半查找、块内用顺序查找，求 ASL，并与顺序、折半查找比较。

过程：

ASL=log2​(b+1)+2s+1​=log2​4+23+1​=2+2=4

结果：ASL=4。三者对比（n=9）：

方法 ASLsucc​ 说明
顺序查找 (9+1)/2=5 最慢，但无任何前提
分块查找 4 居中，且支持高效增删
折半查找 ≈log2​10−1≈2.32 最快，但要求全表有序

验算：s=3=9​，正好是最优分块，用顺序索引验算 2b+1​+2s+1​=2+2=4，与折半索引结果一致（b 很小时两种索引查找差别不大）✓。

考点：分块查找的价值不在”最快”，而在兼顾增删——插入只需扔进对应块的末尾并更新索引表最大值，无需像折半那样整体搬移元素保持有序。

三种查找方法对比

维度 顺序查找 折半查找 分块查找
有序性要求 无 全表有序 块间有序、块内无序
存储要求 顺序 / 链式 必须顺序存储 数据表 + 索引表
ASLsucc​ 2n+1​ ≈log2​(n+1)−1 log2​(b+1)+2s+1​
ASLfail​ n+1 ≤⌈log2​(n+1)⌉ 索引定位 + 整块扫完
时间复杂度 O(n) O(log2​n) O(n​)
空间复杂度 O(1) O(1) O(b)（索引表）
插入 / 删除 方便 困难（要维持有序） 方便（块内无序）
适用场景 小表 / 链表 / 无序表 大表、有序、静态查找 增删频繁又要速度

考点：三种方法的核心区别是”用什么换速度”——折半用”有序 + 随机访问”这两个约束换来 O(logn)；分块用”额外索引表空间”换来 O(n​) 且不牺牲增删；顺序查找什么都不要求，所以最慢。

高频考点速记

考点 记忆
ASL 定义 ASL=∑pi​ci​，等概率时 pi​=1/n；分成功与失败两个 ASL
顺序查找 哨兵放 a[0] 省边界判断；ASLsucc​=(n+1)/2、ASLfail​=n+1、O(n)
成败概率各半 ASL=43(n+1)​
顺序查找适用 小数据量 / 链表 / 无序表
折半查找前提 必须有序 + 顺序存储（随机访问 mid）
折半循环条件 while (low <= high)，失败出口是 low > high
折半判定树 平衡二叉排序树，高度 ⌈log2​(n+1)⌉；先画树再算 ASL
折半 ASL ASLsucc​≈log2​(n+1)−1，ASLfail​≤⌈log2​(n+1)⌉，O(logn)
分块查找 索引折半 log2​(b+1) + 块内顺序 (s+1)/2；顺序索引则为 2b+1​+2s+1​
最优分块 s≈n​→O(n​)，最小 ASL=n​+1
分块结构要求 块间有序、块内无序；需要索引表（存每块最大关键字 + 起始地址）
分块适用场景 兼顾增删与速度
三者取舍 无序/链式→顺序；有序静态→折半；增删频繁→分块或 BST
