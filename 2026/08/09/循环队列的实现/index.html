循环队列的实现

2026-08-09
  • 数据结构&算法

顺序队列用数组存储，rear 只会单调递增，导致 front 之前腾出的空间无法被利用——这就是假溢出 (False Overflow) 问题。解决办法：循环队列——将数组逻辑上视为环形，当指针到达数组末尾时通过取模运算绕回头部：

rear=(rear+1)modMAXSIZE
front=(front+1)modMAXSIZE

核心难点：判空 vs 判满

循环队列中 front == rear 既是空队条件也是满队条件，必须区分！三种经典方案：

方案 判空条件 判满条件 元素个数 特点
牺牲一个单元 Q.front == Q.rear (Q.rear + 1) % MAXSIZE == Q.front (Q.rear - Q.front + MAXSIZE) % MAXSIZE 408 最常考，默认方案
增设 size 变量 Q.size == 0 Q.size == MAXSIZE Q.size 直观，需增加 size 字段
增设 tag 标记 front==rear && tag==0 front==rear && tag==1 取决于 tag tag=0 上次出队，tag=1 上次入队

考研默认采用牺牲一个单元方案。最大容纳元素数 = MAXSIZE - 1。

核心操作（牺牲一个单元方案，408 默认）

front = rear = 0 为初始值，rear 指向下一个空位。

操作 核心步骤
入队 Q.data[Q.rear] = x; Q.rear = (Q.rear + 1) % MAXSIZE（先存再移），O(1)
出队 x = Q.data[Q.front]; Q.front = (Q.front + 1) % MAXSIZE（先取再移），O(1)
读队头 x = Q.data[Q.front]，不修改 front，O(1)

front 和 rear 的初始化方式（考研必背）

特性 方式一 f=r=0 方式二 f=0,r=-1
rear 含义 下一个空位 当前队尾元素
初始值 front = 0, rear = 0 front = 0, rear = -1
判空 Q.front == Q.rear Q.front > Q.rear
判满（牺牲单元） (Q.rear + 1) % MAXSIZE == Q.front 不适用于循环队列
入队 先存再移 rear 先移 rear 再存
出队 先取再移 front 先取再移 front
元素个数 (Q.rear - Q.front + MAXSIZE) % MAXSIZE Q.rear - Q.front + 1

考研提醒：408 默认采用方式一（front = rear = 0，rear 指向队尾下一位置，牺牲一个单元判满）。审题时先看清初始化值，再推导对应代码！

考点 记忆
