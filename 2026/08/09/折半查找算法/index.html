折半查找算法

2026-08-09
  • 数据结构&算法

每次取中间位置元素与关键字比较，每次将查找范围缩小一半，直到找到或区间为空。

前提：查找表必须有序，且采用顺序存储（随机访问）。

算法实现

mid = low + (high - low) / 2 可防溢出；mid = (low + high) / 2 当 n 较小时等价。

执行过程示例

判定树（二叉判定树）

折半查找过程可描述为一棵平衡二叉树——每个结点对应一次比较，根据比较结果走向左子树或右子树。

  • 查找成功的比较次数 = 从根到该结点的路径长度
  • 查找失败的比较次数 = 从根到失败结点（空子树）的路径长度
  • 判定树是一棵平衡二叉排序树，高度为 ⌈log2​(n+1)⌉

性能分析

等概率下的 ASL（判定树有 n 个内部结点，深度 h=⌈log2​(n+1)⌉）：

ASLsucc​=n1​i=1∑n​leveli​≈log2​(n+1)−1 ASLfail​≤⌈log2​(n+1)⌉
时间复杂度 O(⌈log2​(n+1)⌉)
空间复杂度 O(1)（非递归）
优点 比顺序查找快得多
缺点 必须有序 + 必须顺序存储（需要随机访问 mid）

顺序查找 vs 折半查找对比

维度 顺序查找 折半查找
表结构要求 无要求（顺序/链式均可） 必须有序 + 顺序存储
时间复杂度 O(n) O(logn)
插入/删除 方便 困难（需保持有序，移动元素）

选择依据：表小或无序 → 顺序查找；表大且有序且顺序存储 → 折半查找；需要频繁插入删除 → 分块查找或 BST。
