回退N帧协议（GBN）

2026-08-25
  • 计算机网络

回退N帧协议（GBN, Go-Back-N）让发送方在发送窗口内连续发送多帧，不必一帧一帧地等确认，从而大幅提高信道利用率；代价是一旦出错，就要回退重传出错帧及其后续所有帧（即使其中部分已正确到达）。它是滑动窗口协议中最简单的一种。

协议要点

特性 GBN
发送窗口 WT​ 1≤WT​≤2n−1（n 为序号位数）
接收窗口 WR​ = 1（只能接收按序到达的下一帧）
确认方式 累计确认：对 n 号帧的确认 = n 号及以前所有帧全部正确收到
出错处理 出错/乱序帧全部丢弃；发送方超时重传该帧及后续所有帧（回退 N）
帧缓存 接收方不缓存乱序帧（只需 1 帧缓存，实现简单）

工作过程

图：GBN——第 2 号帧丢失后，接收方丢弃全部乱序帧，发送方超时后回退重传 2、3、4、5、6 共 5 帧。

为什么 WT​≤2n−1

若 WT​=2n：发送方连续发完序号 0∼2n−1 后，若所有确认都丢失，超时后重发 0 号帧——此时接收方已进入新一轮，会把重发的 0 号帧误认为”新一组的第一个帧”（新旧序号重叠，无法区分）。留出一个序号位置（窗口最多 2n−1 个）才能区分新旧。

考点：GBN 窗口上限 WT​=2n−1；接收窗口恒为 1；累计确认；超时重传”该帧 + 后续所有帧”（浪费带宽但简单）。

例题（王道）

GBN 协议，序号 3 位（n = 3），则 WT​≤23−1=7：

  • 发送方发出 0~6 共 7 帧，第 2 号帧丢失
  • 接收方收到 3、4、5、6 号（乱序）→ 全部丢弃，可能回送对 1 号的重复确认
  • 发送方超时后回退重传 2、3、4、5、6 共 5 帧（即使其中部分已正确到达）

提高信道利用率

U=T发送​+RTT+T确认​WT​×T发送​​

窗口内连续发送 WT​ 帧，把 20ms 的等待时间分摊到多帧上；WT​ 越大利用率越高（受 WT​≤2n−1 约束）。

仍用停止-等待例题的数据（n 足够大，WT​=100）：

U = \frac{100 \times 0.08192}{20.16384} \approx \textbf{40.6%}

比停止-等待（0.41%）提高约 100 倍。

考点：利用率公式的分子是”发送时间”，分母是”发送 + 往返传播 + 确认”；窗口协议把等待时间分摊到多帧上。

优缺点

说明
优点 窗口大、连续发送利用率高；接收窗口 = 1、无需缓存，实现简单
缺点 出错时回退重传大量可能已正确到达的帧，浪费带宽（信道质量差时严重）

高频考点速记

考点 记忆
GBN 发送窗口 WT​≤2n−1（n=3 → 7；留一个序号区分新旧）
GBN 接收窗口 恒为 1，只收按序到达的下一帧
确认方式 累计确认：对 n 号确认 = n 号及以前全部正确收到
出错处理 乱序帧全丢；超时回退重传该帧 + 后续所有帧
帧缓存 接收方不缓存（只需 1 帧缓存）
利用率 U=T发送​+RTT+T确认​WT​×T发送​​；例题 0.41% → 40.6%
代价 重传浪费大（→ SR 只重传出错帧改善）
