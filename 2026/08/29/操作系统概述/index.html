操作系统概述

2026-08-29
  • 操作系统

操作系统（Operating System, OS）是指控制和管理整个计算机系统的硬件与软件资源、合理地组织调度计算机的工作与资源分配、为用户和其他软件提供方便的接口与环境的程序集合，是计算机系统中最基本、最重要的系统软件。它位于硬件之上、应用程序之下，是两者的”中间人”。408 对本章的考查以选择题为主，集中在：四大特征（并发与共享互为存在条件）、发展历程各阶段解决了什么问题、内核态/用户态与中断异常、系统调用过程、程序的装入与链接、体系结构（宏内核/微内核/外核）、引导流程与虚拟机。

什么是操作系统

可以从三个角度理解操作系统：系统资源的管理者、用户与计算机硬件之间的接口、最接近硬件的扩充机器。

资源管理者视角：四大管理职能

管理职能 管理对象 主要工作
处理机管理 CPU（进程） 进程控制、进程同步、进程通信、处理机调度
存储器管理 内存 内存分配与回收、地址映射、内存保护与共享、内存扩充
文件管理 外存中的文件 文件存储空间管理、目录管理、文件读/写管理、文件保护
设备管理 各类 I/O 设备 设备分配与回收、缓冲管理、设备驱动，屏蔽 I/O 设备的差异

考点：处理机管理的本质是进程管理；OS 管理资源的目标是安全、高效。多道程序并发带来的”分配 CPU、分配内存、管理文件、管理共享设备”四大问题，正是这四大管理职能的来源。

向上层提供的三种接口

接口 使用者 形式
命令接口 普通用户 联机命令接口（交互式，”说一句做一句”，如 cmd）；脱机命令接口（批处理，”说一堆做一堆”，如 .bat 脚本）
程序接口 程序员/应用程序 由一组系统调用组成，程序通过它请求内核服务
GUI 普通用户 图形化界面；严格说不属于操作系统本身（借助命令接口与图形库实现的程序）

操作系统的目标可概括为：方便性（易于使用）、有效性（提高资源利用率与吞吐量）、可扩充性（便于增加新功能）、开放性（遵循标准互联互通）。

易错点：GUI 通常不算操作系统的一部分；OS 直接提供的是命令接口与程序接口（系统调用）。

四个基本特征：并发、共享、虚拟、异步

其中并发与共享是两个最基本的特征，且互为存在条件。

并发与并行

对比项 并发 并行
时间 同一时间间隔内发生 同一时刻发生
微观 交替执行（轮流使用 CPU） 同时执行
硬件要求 单核即可 需要多核/多处理器

考点：单核 CPU 上多个进程只能并发、不可能并行；只有多核才能真正并行。

共享的两种方式

共享方式 含义 例子
互斥共享 一个时间段内只允许一个进程访问（临界资源） 打印机、磁带机
同时共享 一个时间段内允许多个进程”同时”访问（宏观同时、微观交替） 磁盘、可重入代码

并发与共享互为存在条件（高频辨析）：

  • 共享以并发为前提：若系统不允许并发（单道环境），资源就不存在被多个进程”同时”使用的问题；
  • 并发以共享为条件：若资源不能被有效共享（如都独占），多道程序便无法并发执行。

虚拟：一个物理实体变成若干逻辑对应物

虚拟技术 原理 例子
时分复用 把物理时间分片，轮流服务 虚拟处理器：一个 CPU 虚拟为多个”逻辑 CPU”
空分复用 把物理空间划分使用 虚拟存储器：以外存扩充内存，程序感觉内存很大

易错点：虚拟处理器 = 时分复用，虚拟内存 = 空分复用（选择题常考）；虚拟以并发为前提——没有多个程序并发运行，一个 CPU 何须虚拟成多个。

异步

多道程序环境下资源有限，进程的执行走走停停，以不可预知的速度向前推进；只有系统拥有并发性，才可能导致异步性。

操作系统的发展历程

发展主线是”为了解决上一个阶段的问题“：

手工操作与脱机输入输出

  • 手工操作（无 OS）：用户独占全机，人机速度矛盾突出（人的操作秒级，CPU 运算毫秒/微秒级），CPU 大量时间空闲，资源利用率极低。
  • 脱机输入/输出：引入一台外围机（卫星机），先把纸带上的作业读入高速磁带，主机从磁带取作业、结果也经磁带输出——主机与慢速 I/O 设备脱离，缓解人机速度矛盾。

单道批处理：自动性

监督程序（操作系统的雏形）+ 脱机 I/O：作业成批装入磁带，监督程序逐个自动调入内存运行。三大特点：自动性、顺序性、单道性（内存中只有一道用户程序）。缺点：程序计算时 I/O 空闲、I/O 工作时 CPU 空闲，CPU 大量时间在等待 I/O，利用率仍然很低。

多道批处理：提高利用率，OS 正式诞生

多道程序设计：内存中同时存放多道相互独立的程序，并发执行并共享资源。两个技术前提：中断技术（设备完成/出错时打断 CPU）+ 通道技术（独立于 CPU 的 I/O 控制部件）。

  • 特征：多道性、无序性（作业先提交未必先完成）、调度性（作业调度选作业入内存 + 进程调度分配 CPU，两级调度）。
  • 优点：CPU 与 I/O 设备并行工作，资源利用率大幅提升、系统吞吐量大。
  • 缺点：没有交互性（提交后无法干预）、作业平均周转时间长。
对比项 单道批处理 多道批处理
内存中的程序数 一道 多道
是否并发 否（顺序执行） 是（并发执行）
操作系统 监督程序（雏形） 正式操作系统
人机交互 无 无
资源利用率 低（CPU 等 I/O） 高（CPU 与 I/O 并行）

考点：多道批处理系统标志着操作系统的正式诞生；其两大前提是中断与通道；多道的”无序性”指完成顺序与提交顺序可以不一致。

多道并发利用率例题（甘特图）

例题：内存中同时驻留 Job1、Job2 两道作业，单 CPU，CPU 与 I/O 设备可以并行，CPU 调度从 Job1 开始，作业的执行序列如下（单位 ms）：

  • Job1：CPU 计算 20 → I/O 30 → CPU 计算 10，完成
  • Job2：CPU 计算 30 → I/O 20 → CPU 计算 10，完成

求：并发执行的总时间与 CPU 利用率，并与单道顺序执行比较。

第一步：画甘特图（Job1 在 t=20 转 I/O 后 Job2 立即上 CPU；t=50 时 Job2 转 I/O、Job1 的 I/O 恰好完成拿回 CPU）：

第二步：算总时间。以最后完成的 Job2 为准：总时间 = 80ms。而单道顺序执行时 Job1 单独需 20+30+10=60ms、Job2 单独需 30+20+10=60ms，合计 60+60=120ms。

第三步：算 CPU 利用率（利用率 = CPU 忙碌时间 ÷ 总时间）：

  • 多道并发：CPU 忙碌 20+30+10+10=70ms，利用率 = 8070​×100%=87.5%
  • 单道顺序：CPU 忙碌仍为 30+40=70ms，利用率 = 12070​×100%≈58.3%

验算：80ms 内 CPU 各段无冲突（0~20 Job1、20~50 Job2、50~60 Job1、70~80 Job2）；Job1 的 I/O（20~50）与 Job2 的 CPU 并行、Job2 的 I/O（50~70）与 Job1 的 CPU（50~60）并行，设备段与 CPU 段互不重叠 ✓

考点：多道批处理总时间以最后完成的作业为准；收益来自 CPU 与 I/O 设备并行——idle 段（60~70ms）正是因为 Job1 已完成而 Job2 还在做 I/O，此时 CPU 无活可干。

分时系统：时间片轮转解决人机交互

背景：多道批处理无人机交互，用户提交作业后无法干预。核心思想——时间片轮转：把 CPU 时间划分为时间片，按时间片轮流为各终端用户服务，时间片用完立即切换。四大特征：同时性（多路性）、独立性、及时性、交互性。缺点：不能优先处理紧急任务（再紧急也得排队等时间片）。

实时系统：截止时间

系统能在规定的时间（截止时间）内完成对外部事件的处理。按严格程度分：硬实时（必须绝对准时，如导弹制导、工业过程控制、自动驾驶）与软实时（偶尔超时可接受，如多媒体播放、信息查询）。

对比项 分时系统 实时系统
服务对象 多个用户（人） 外部事件/实时任务
核心目标 交互性、公平性 及时性、高可靠性
响应要求 尽快响应（时间片轮流） 必须在截止时间内完成
紧急任务 不能优先 可优先处理

网络与分布式等其他操作系统

类型 一句话特点
网络操作系统 各结点自治、各管各的，提供网络通信与资源共享
分布式操作系统 多机协同如一台机器，统一管理、对用户透明
个人计算机 OS 单用户多任务、简单易用（Windows/macOS 桌面版）
嵌入式 OS 微型化、实时性、可裁剪（VxWorks、FreeRTOS）

考点：网络 OS 与分布式 OS 的区别——网络 OS 各计算机自治；分布式 OS 由统一的操作系统管理，用户感觉像一台虚拟的整体计算机。

程序的运行环境

CPU 的两种状态与两类指令

指令 例子 谁能执行
特权指令 I/O 指令（启动外设）、置时钟、清内存（内存清零）、置中断屏蔽/关中断、切换 CPU 状态（修改 PSW） 仅内核态
非特权指令 算术运算、逻辑运算、移位、取数/存数、数据传送 用户态、内核态均可
对比项 用户态（目态） 内核态（管态/核心态/特权态）
运行的程序 应用程序 操作系统内核程序
指令权限 只能执行非特权指令 可执行特权指令 + 非特权指令
状态记录 **PSW（程序状态字寄存器）**中的标志位 同左
进入方式 经中断/异常（含系统调用的陷入）进入内核态，由硬件自动完成 —
退出方式 — 内核执行特权指令修改 PSW（如中断返回指令），OS 主动让出 CPU

考点：用户态→内核态唯一的途径是中断/异常，由硬件自动切换；内核态→用户态是 OS 主动执行特权指令。用户态程序执行特权指令会触发异常（非法指令/保护违例）。内核的组成：时钟管理（时间片轮转的基础）、中断机制、原语（原子操作、最底层）、系统控制的数据结构（PCB 等）。

例题（状态切换判断）：判断下列事件是否引起”用户态→内核态”的切换：

事件 是否切换 原因
执行 a=b+c 否 算术运算是非特权指令，用户态完成
除零 是 内中断（故障），硬件转入内核处理程序
调用 read() 读文件 是 陷入指令引发内中断，进入内核执行系统调用
时钟中断到达 是 外中断，硬件自动进入内核处理时间片
内核处理完毕返回 否（方向相反） 执行特权指令修改 PSW：内核态→用户态

易错点：一次系统调用包含两次状态切换（陷入进入 + 返回退出），加上保存/恢复现场，开销比普通函数调用高出几个数量级，所以频繁的系统调用会显著拖慢程序。

中断与异常

中断的定义：程序执行过程中发生某事件时，中止 CPU 上现行程序、引出处理该事件的程序执行的过程。作用：让内核强行夺回 CPU 的使用权，是实现多道程序并发的前提——没有中断，用户程序一旦运行就永远不会把 CPU 交还给操作系统。

类别 信号来源 与现行指令 典型例子
内中断（异常 exception） CPU 内部 有关（同步） 陷阱 trap、故障 fault、终止 abort
外中断（狭义中断 interrupt） CPU 外部 无关（异步） 时钟中断、I/O 中断、键盘输入

内中断（异常）的三种类型：

类型 成因 例子
陷阱（trap，陷入） 程序有意引发 系统调用（访管指令）、断点调试
故障（fault） 错误条件引起，可修复 缺页、除零、溢出、非法指令
终止（abort） 致命硬件错误，不可恢复 控制器故障、内存校验错、总线错误

外中断再分为可屏蔽中断（INTR）与不可屏蔽中断（NMI，如电源掉电、内存校验错）。

考点：外中断是异步的，只能在两条指令之间响应；内中断是同步的，一条指令执行期间即可响应（如缺页、除零）。

中断处理流程：关中断 → 保存断点（PC 压栈）→ 查中断向量表引出中断服务程序（中断向量 = 服务程序入口地址）→ 保存现场（寄存器、PSW）→ 开中断 → 执行中断服务程序 → 恢复现场 → 中断返回。中断处理程序的四项工作：保护状态、识别中断源、处理事件、恢复正常操作。

易错点：系统调用 ≠ 陷入指令——系统调用是目的，陷入（访管）指令是引发内中断的手段；陷入指令在用户态执行，且不是特权指令（否则用户程序根本无法执行它）。

系统调用

系统调用是 OS 提供给应用程序（程序员）的接口。凡涉及共享资源（文件、设备、内存）的操作都必须由内核在内核态代做，以保证系统的稳定与安全。

执行过程（见下图）：

  1. 用户程序传递系统调用号与参数（方式：寄存器 / 参数放内存块、寄存器传块地址 / 堆栈）
  2. 执行陷入指令（访管指令，在用户态执行）→ 引发内中断
  3. CPU 硬件自动切换到内核态，按调用号查系统调用表，转入对应内核处理程序
  4. 内核处理完毕，返回用户态，继续执行用户程序的下一条指令
对比项 系统调用 库函数
执行位置 内核（内核态） 用户态
状态切换 是（陷入 + 返回） 否
开销 大 小
例子 read()、write()、fork() printf()、malloc()

考点：printf 是库函数（用户态完成格式转换），内部封装 write() 系统调用把结果写到屏幕；malloc 内部调用 brk()/mmap() 向内核申请内存。

程序的链接与装入

装入方式 地址转换时机 特点与应用
绝对装入 编译时即确定绝对地址 仅适用于单道批处理环境下的单目标程序
可重定位装入（静态重定位） 装入内存时一次性把逻辑地址全部转为物理地址 装入后不能再移动，无法实现内存扩充；早期多道系统使用
动态运行时装入（动态重定位） 装入时不转换，运行时借助重定位寄存器转换 现代 OS 采用；程序可移动、可部分装入（配合页表），便于共享与虚拟存储
链接方式 时机 特点
静态链接 运行前把各目标模块 + 库拼成一个完整装配模块 之后不再拆开；模块更新需整体重新链接
动态链接 装入时边装入边链接，或运行时用到该模块才链接 便于多个进程共享同一库的副本、便于模块单独更新；运行时动态链接还能”不用不装入”

考点：动态重定位允许程序在内存中浮动（移动），是实现虚拟存储（部分装入、对换）的基础；静态重定位一旦装入，地址就”焊死”了。

程序运行时的内存映像与地址空间

区域 内容 说明
代码段 程序指令 只读，多个进程可共享同一份代码
数据段 已初始化的全局/静态变量 装入时确定
堆 动态分配的内存（malloc/new） 向高地址增长，程序员手动/垃圾回收释放
栈 函数调用帧、局部变量、返回地址 向低地址增长，随函数调用/返回伸缩
PCB 进程控制块 位于内核空间，由 OS 管理，不在用户地址空间
共享库 动态链接库的映射 对应动态链接，多个进程映射同一份

编译链接后程序使用逻辑地址（虚拟地址），运行时由 OS + 硬件（MMU、重定位寄存器/页表）转换为物理地址；每个进程拥有独立的虚拟地址空间。

操作系统的体系结构

分层法与模块化

  • 分层法：OS 分为若干层，层 0 为硬件、层 N 为用户接口，每层只能调用紧邻它的低层（单向依赖）。优点：结构清晰、便于调试与维护（自底向上逐层测试）；缺点：一个功能要层层穿越，层间通信开销大。
  • 模块化：按功能划分为具有一定独立性的模块，规定好模块间接口进行通信（如 Linux 的可加载内核模块 LKM）。优点：灵活、可加载、可维护性好；缺点：接口定义复杂，模块依赖多时难以调试。

宏内核 vs 微内核（重点对比）

宏内核（大内核/单内核）：进程管理、内存管理、文件系统、设备驱动等主要功能模块全部放在内核态，模块间直接函数调用。微内核：内核只保留与硬件紧密相关的处理、中断处理、进程间通信（IPC）、基本调度等最基本功能，文件系统、驱动等作为用户态服务进程（客户/服务器模式），微内核常驻内存、并非一个完整的 OS。

对比项 宏内核（大内核） 微内核
内核规模 大（功能全在内核） 小（只留核心功能）
状态切换次数 少（函数直接调用） 多（服务请求需频繁切换）
性能 高 低（切换 + IPC 消息传递开销）
可靠性 低（一处崩溃全系统崩溃） 高（服务进程崩溃可重启）
扩展性/可维护性 差（代码庞大、结构混乱） 好（结构清晰，可动态添加服务）
典型系统 Linux、Windows Mach、Minix、QNX、L4

考点：微内核性能低的根源 = 频繁的用户态/内核态切换 + 进程间通信（消息传递）开销；客户/服务器模式下所有请求都经过内核转发。

外核（exokernel）

外核（exokernel）是考纲新增点：运行在内核态的底层程序，职责只有两件事——为虚拟机分配资源（每台虚拟机只能使用已申请并获得分配的资源）与检查这些资源使用的安全性（确保不使用他人的资源，内存访问由内存控制器协调）；其余的资源管理交给每台虚拟机上运行的**库操作系统（libOS）**完成。优点：效率高、灵活；缺点：实现复杂、安全性难保证。

易错点：外核不是”把内核放到外面”，而是内核只管分配与保护，管理策略上移到库 OS；与微内核”把服务搬到用户态”方向不同。

操作系统的引导

引导（Boot）：开机时把 OS 内核从磁盘装入内存并初始化的过程。

  1. CPU 加电后从 **ROM（BIOS）**中的固定地址取第一条指令，执行引导程序
  2. 硬件自检（POST）：检测 CPU、内存、显卡等是否正常
  3. 读入磁盘 0 号扇区——主引导记录（MBR）（内含磁盘引导程序 + 分区表 DPT），扫描分区表找到活动分区
  4. 从活动分区读入分区引导记录（PBR），由它加载启动管理器（如 GRUB）
  5. 启动管理器装入 OS 内核（Windows 的 ntoskrnl / Linux 的 vmlinuz），内核初始化硬件、建立数据结构，创建第一个进程（init/systemd），引导完成
概念 位置 作用
BIOS 主板 ROM（固件） 加电后最先执行的引导程序，负责自检
MBR 磁盘 0 号扇区 存放磁盘引导程序和磁盘分区表
PBR 活动分区首扇区 加载启动管理器
启动管理器（Bootloader） 磁盘（如 /boot 分区） 选择并加载操作系统内核（GRUB）

考点：双系统就是由启动管理器在引导阶段列出菜单、选择进入哪个操作系统。现代机器多改用 UEFI 引导（读 ESP 分区上的 EFI 文件，分区格式只能是 FAT16/FAT32），但 408 的主线仍是 BIOS → MBR → PBR → 启动管理器 → 内核。

虚拟机

虚拟机（Virtual Machine, VM）：利用虚拟化技术把一台物理机器虚拟为多台逻辑上独立的机器，每台虚拟机拥有自己”虚拟的”CPU、内存、磁盘，可以安装运行独立的操作系统（注意与”扩充机器”区分：扩充机器是”硬件+OS”对上层应用的整体抽象，虚拟机强调一机分多台）。

对比项 第一类 VMM（裸金属型） 第二类 VMM（宿主型）
运行位置 直接运行在硬件之上 运行在宿主操作系统之上（作为宿主的一个进程）
是否有宿主 OS 无 有
性能 高（直接管理硬件） 低（经宿主 OS 间接访问硬件）
安全性/隔离 好 受宿主 OS 影响
典型例子 VMware ESXi、Xen、KVM VMware Workstation、VirtualBox

半虚拟化：对客户操作系统进行修改，使其”知道”自己运行在虚拟机上，敏感操作通过 **hypercall（类似系统调用）**与 VMM 协作完成，从而减少全虚拟化中陷入-模拟的开销。

考点：区分两类 VMM 的关键是看它下面有没有宿主 OS——直接跑在硬件上是第一类（性能高，用于数据中心），跑在宿主 OS 上是第二类（方便个人使用）。虚拟机是硬件级虚拟化（每台 VM 独立 OS），容器（Docker）是操作系统级虚拟化（共享宿主内核、启动快、占用小）。

高频考点速记

考点 记忆
OS 的三个视角 资源管理者（四大职能）、用户接口（命令/程序接口）、扩充机器；处理机管理本质 = 进程管理
四大特征 并发、共享互为存在条件（最基本）；虚拟 = 时分复用（虚拟处理器）/空分复用（虚拟内存）；异步 = 并发致走走停停
并发 vs 并行 同一时间间隔 vs 同一时刻；单核只能并发，多核才可并行
OS 正式诞生 多道批处理；前提 = 中断 + 通道；特征 = 多道、无序、调度；缺点 = 无人机交互
分时 vs 实时 分时 = 时间片轮转解决人机交互；实时 = 截止时间内完成，分硬/软实时
特权指令 仅内核态可执行：I/O、置时钟、清内存、改 PSW；用户态执行触发异常
状态切换 用户态→内核态：中断（硬件自动、唯一途径）；内核态→用户态：特权指令修改 PSW（OS 主动）
内中断三类 陷阱 trap = 系统调用（有意）；故障 fault = 缺页/除零（可修复）；终止 abort = 致命硬件错误
外中断 时钟、I/O 中断；INTR 可屏蔽，NMI 不可屏蔽（掉电、校验错）
响应时机 外中断异步（两条指令之间响应）；内中断同步（一条指令执行期间响应）
系统调用 陷入（访管）指令在用户态执行、非特权指令；系统调用是目的、陷入是手段；printf 是库函数、内部调 write()
三种装入 绝对装入（编译时）；可重定位（装入时一次转换、不能移动）；动态运行时（重定位寄存器、现代 OS 采用）
链接 静态链接（运行前拼死）；动态链接（装入时/运行时，便于共享与更新）
宏内核 vs 微内核 宏内核性能高难维护（Linux）；微内核可靠、易扩展但切换+IPC 开销大（Mach/Minix）；外核 = 分配资源 + 安全检查 + 库 OS
引导流程 BIOS(ROM) → POST 自检 → MBR(0 号扇区，含分区表) → PBR → 启动管理器(GRUB) → 内核；双系统由启动管理器选择
虚拟机 第一类直接跑硬件（Xen/ESXi/KVM）；第二类跑宿主 OS（VMware Workstation/VirtualBox）；半虚拟化 = 改造客户 OS + hypercall
