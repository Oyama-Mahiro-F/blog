进程同步与互斥

2026-08-29
  • 操作系统

进程同步与互斥研究的是：多个并发进程共享资源、相互合作时，如何保证执行结果正确且可复现——不加协调的并发会产生竞态条件（结果取决于进程执行的相对次序）。408 对本章的考查集中在：临界区互斥四准则、软件/硬件实现方法、互斥锁（自旋锁 vs 互斥量）、信号量 P/V 原语、三大应用模板（互斥/同步/前驱）与经典同步问题（生产者-消费者、读者-写者、哲学家进餐、吸烟者）——选择题爱考”违反了哪条准则””信号量值的含义””P 操作的顺序”，大题几乎必考”用信号量写完整的同步互斥代码”。

同步与互斥的基本概念

临界资源与临界区

临界资源（Critical Resource）：一次仅允许一个进程使用的资源，如打印机、共享变量、共享缓冲区。临界区（Critical Section）：进程中访问临界资源的那段代码。每个进程访问临界资源的代码都分为四个部分：

同步与互斥的定义（重点对比）

对比项 同步 互斥
起因 直接制约：进程相互合作，前一个进程的输出是后一个进程的输入 间接制约：进程竞争临界资源
要求 协调推进顺序——“必须先做什么，再做什么“ 同一时刻只允许一个进程访问资源
典型例子 生产者-消费者、前驱图任务 打印机、共享变量
信号量做法 同步信号量初值 0（看资源初值），口诀”前 V 后 P“ 互斥信号量 mutex = 1，口诀”进 P 退 V“

考点：同步 = 协作关系（”一前一后”），互斥 = 竞争关系（”一次一个”），互斥可看作特殊的同步。
易错点：同步关系每对一个信号量（互不共用）；互斥则所有进程共用同一个 mutex。

临界区互斥的四条准则（选择题常考）

准则 含义
空闲让进 临界区空闲时，应允许一个请求进入的进程立即进入
忙则等待 已有进程在临界区时，其他试图进入的进程必须等待（互斥的底线）
有限等待 等待的进程必须在有限时间内能进入（不能”饿死”）
让权等待 进不去的进程应释放 CPU（阻塞自己），避免忙等空转浪费处理机

考点：四条准则缺一不可，选择题常问”某算法违反了哪一条”——违反”忙则等待”（如双标志先检查）是正确性错误；只违反”让权等待”（如 Peterson、TSL 忙等）只是效率问题，不算错误。

实现互斥的软件方法

单标志法

用一个 turn 变量表示”当前轮到谁”，谁用完就把使用权让给对方：

缺陷：turn 初始为 0，两进程必须交替进入——若 P0 用完后 P1 暂不申请，turn 停在 1 不变，临界区即使空闲 P0 也永远进不去：违背”空闲让进”（也随之违背有限等待）。

双标志先检查法

flag[i] 表示进程 i 的进入意愿，先检查对方意愿，再表明自己的意愿：

缺陷演示（同时进入）：两进程几乎同时执行 ①——都看到对方 flag = false、都通过检查，随后都置自己的 flag = true，双双进入临界区。根因：”检查”与”上锁”是两步、之间可被打断，不是原子操作——违背”忙则等待”。

双标志后检查法

把顺序反过来：先表明意愿，再检查对方：

缺陷演示（都进不去）：两进程都先置 flag = true，再互相检查时都发现对方想进——都卡在 while 上空转，临界区明明空闲却谁都进不去：违背”空闲让进”；且两进程互等、可能长期得不到服务，也违背”有限等待”（饥饿）。

Peterson 算法

思想 = “表达意愿 + 主动谦让“：先置自己的 flag（愿进），再把 turn 让给对方，最后同时检查两个条件：

  • 空闲让进：对方不愿进（flag[j] = false）或优先权在自己手里（turn == i）→ 直接进入；
  • 忙则等待：双方同时申请时 turn 只有一个值——后写 turn 的一方谦让（turn 被后写者覆盖，先写者进入），不可能同时进入，也不会互等死锁；
  • 有限等待：等待方最多等对方用完一次（对方退出置 flag[j] = false，循环条件失效）；让权等待：不满足（while 忙等）。

考点：Peterson 与”双标志后检查”的本质区别就在 turn——turn 只能赋一个值，保证”必有一方退出竞争”；但它只适用于两个进程且忙等，实际系统采用硬件方法。

软件四法对比：

方法 能否实现互斥 是否忙等 满足让权等待 主要问题（违反的准则）
单标志法 能（强制交替） 是 否 必须交替进入：对方不申请时自己永远进不去——违背空闲让进
双标志先检查 不能 是 否 检查与上锁之间可被打断，双方同时进入——违背忙则等待
双标志后检查 不能 是 否 双方先上锁再互查，谁都进不去——违背空闲让进、有限等待
Peterson 能 是 否 满足前三条准则；忙等、仅限两个进程

实现互斥的硬件方法

中断屏蔽（关中断）

进入临界区前关中断，出临界区再开中断——关中断期间不响应任何中断、不发生进程切换，临界区代码得以”原子”执行（与原语的实现思想相同）：

  • 优点：简单、高效；缺点：不适用于多处理机（关中断只对本 CPU 生效，其他 CPU 仍可进入同一临界区）；只适用于内核进程（开/关中断是特权指令，用户进程无权执行）；关中断期间无法响应时钟、I/O，滥用危险。

TestAndSet 指令（TS/TSL）

一条硬件原子指令：读出旧值的同时把锁置为 true——把软件方法里可被打断的”检查 + 上锁”两步合并为不可分割的一步：

硬件原子交换指令，逻辑上与 TSL 无本质区别——用 old 换出 lock 的旧值，再检查 old：

硬件三法对比：

方法 能否互斥 是否忙等 适用范围 优点 缺点
中断屏蔽 能 否（根本不会被切换） 单处理机 + 内核进程 简单高效 特权指令用户不可用；多处理机失效
TS/TSL 能 是（自旋） 单核、多核均可 简单、无需严谨的逻辑推敲、支持多处理机 忙等，违背让权等待；不保证先来先到，可能饥饿
Swap 能 是（自旋） 单核、多核均可 同 TSL 同 TSL

考点：硬件方法把”检查 + 上锁”合并为一条原子指令，从根本上消除软件方法”两步之间被打断”的漏洞；但 TS/Swap 是”抢锁”而非”排队”——都忙等（不满足让权等待）。TSL/Swap 适用于多处理机，这是与中断屏蔽最常对比的一点。

互斥锁

互斥锁（Mutex Lock）：最简单的同步工具——一个锁变量 + 两个原子操作 acquire（上锁）/ release（解锁）：

  • acquire/release 的原子性由硬件指令（TSL、Swap 等）保证；自旋锁（Spin Lock）：acquire 失败时原地循环等待（忙等）的互斥锁；互斥量（基本锁）：拿不到锁就阻塞自己、进入等待队列，由操作系统在解锁时唤醒（让权等待）。

自旋锁 vs 互斥锁：

对比项 自旋锁（忙等） 互斥锁/互斥量（阻塞）
拿不到锁时 原地空循环反复试探 阻塞自己，挂入等待队列
上下文切换 无（不进内核、不切换） 有（保存/恢复现场、用户态与内核态切换，开销大）
是否满足让权等待 不满足 满足
CPU 消耗 空转占用 CPU 让出 CPU，但切换本身有开销
适用场景 多核、临界区短、持锁时间短 临界区长、持锁时间长、单处理机

考点：自旋锁忙等但无切换开销，临界区很短时反而更高效；单处理机不适合自旋——自旋进程占着唯一的 CPU，持锁进程无法被调度、永远释放不了锁。
易错点：自旋锁只是不满足”让权等待”这一建议性准则，不等于错误实现。

信号量机制

信号量（Semaphore）= 一个整型变量 S + 两个原子操作：**P（wait，申请资源）**与 V（signal，释放资源）。它是 408 大题的核心工具。

记录型信号量（重点，让权等待实现）

数据结构 = 剩余资源数 value + 等待队列 L；P 不够就阻塞自己，V 则唤醒一个等待者：

value 的取值含义（必考）：S.value>0 表示还有 S.value 个可用资源；S.value=0 表示资源刚好用完、暂无人等待；S.value<0 时绝对值 = 等待队列中的进程数（如 S.value=−3 即已有 3 个进程在排队）。

考点：P 操作 = 申请资源（可能阻塞自己），V 操作 = 释放资源（可能唤醒别人）；P/V 都是原语，执行期间不可中断。口诀：P 减 1 后小于 0 才阻塞，V 加 1 后不大于 0 就唤醒。
易错点：整型信号量是”先检查后减“（忙等）；记录型是”先减后判断“（阻塞）——顺序不同，性质不同。

用信号量实现互斥（模板）

  • P/V 必须成对出现：缺 P(mutex) → 互斥失效；缺 V(mutex) → 资源永不释放、等待进程永远阻塞；任何进程都可对同一 mutex 执行 P/V（进临界区者负责解锁），不区分”谁申请谁释放”。

用信号量实现同步（模板）

口诀：“前 V 后 P”——先做的事之后 V，后做的事之前 P；同步信号量初值 0；有几种”先后关系”就设几个同步信号量。

生产者-消费者问题

问题与分析：生产者生产产品放入容量为 n 的有界缓冲区，消费者从中取产品消费。三类关系：缓冲区满时生产者必须等待（同步）、缓冲区空时消费者必须等待（同步）、缓冲区是临界资源须互斥存/取。信号量设计（初值理由）：mutex = 1（互斥访问缓冲区，一次只允许一个进程存/取）；empty = n（空缓冲单元数，初始 = 缓冲区容量 n）；full = 0（产品单元数，初始一个产品也没有）。

考点（必考）：P 操作的顺序不能颠倒——若生产者先 P(mutex) 再 P(empty)，缓冲区满时生产者抱着 mutex 阻塞在 empty 上，消费者 P(mutex) 拿不到锁、无法取走产品 → 死锁；消费者侧 full 与 mutex 的顺序同理（empty/mutex 与 full/mutex 两处都易错）。V 的顺序可以交换，不影响正确性。
易错点：互斥 P(mutex) 必须夹在中间——同步 P 在外、互斥 P 在内；初值 mutex=1、empty=n、full=0。这种”互斥与同步嵌套、P 顺序不当”的死锁，详见姊妹文章《死锁》。

多生产者-多消费者问题（水果盘）

问题与分析：桌上一个盘子，每次只能放一个水果。爸爸专放苹果、妈妈专放橘子；女儿专吃苹果、儿子专吃橘子。爸爸与女儿、妈妈与儿子分别是同步关系（放完通知对应子女）；盘子容量为 1，plate 兼做互斥。信号量设计：plate = 1（盘子空位数）、apple = 0、orange = 0（盘中对应水果数，按种类区分，谁需要谁 P）。

考点：生产者放完 V 对应水果信号量，消费者取走才 V(plate)。盘子容量为 1 时 plate 兼当互斥信号量；若容量大于 1，必须另加 mutex=1 保护”放/取”过程（此时 P(mutex) 与 P(plate) 的顺序同样不能颠倒）。

读者-写者问题

问题与分析：允许多个读者同时读文件；写者必须独占访问（写时不允许任何读者或其他写者）。写者与写者、写者与读者之间互斥，读者与读者共享。关键技巧：用 count 记录读者数，第一个读者负责上锁、最后一个读者负责解锁——读者之间”共享锁”。信号量设计：rw = 1（读写互斥锁，写者直接 P/V）；count = 0（正在读的读者数，共享变量本身也是临界资源，必须用 mutex = 1 保护）。

考点：count 必须用 mutex 保护——count++ 不是原子操作，两个读者并发修改会互相覆盖，导致计数错乱、提前 V(rw)，破坏读写互斥；count == 0 的判断也必须放在 mutex 临界区内。
易错点：读优先策略下读者源源不断时写者可能饥饿；改进为”写优先/读写公平”：再加一个信号量 w = 1，写者整个写期间持有 w，读者申请 rw 的关口也要先过 w——使写者到达后后续读者排队，思想了解即可。

吸烟者问题

问题与分析：三个抽烟者各自无限拥有烟草、纸、胶水中的一种，卷一支烟需要三种材料；两个供应者轮流每次提供三种材料中的两种（随机组合），抽完一支烟的抽烟者发信号通知供应者，供应者才继续提供下一组。关系是双向同步：供应者提供组合 → 对应抽烟者取用（单向）；抽烟者抽完 → 通知供应者（反向），缺一不可。信号量设计：每种材料组合设一个信号量、初值均为 0（一组材料恰好只有一个”有缘人”——拥有其余两种材料者）；finish = 0 保证”抽完才放下一组”。

组合对应关系：提供”烟草+纸” → 有胶水者（offer1）；提供”烟草+胶水” → 有纸者（offer2）；提供”胶水+纸” → 有烟草者（offer3）。

考点：双向同步——供应者 V(offer_i) 与抽烟者 P(offer_i) 一个方向，抽烟者 V(finish) 与供应者 P(finish) 反方向，两个方向都不能省；不需要 mutex：桌上每次只放一套材料，finish 已保证”抽完才放下一轮”，不会同时放/取。本题是 2021 年 408 统考大题原型。

高频考点速记

考点 记忆
临界资源与临界区 一次仅一个进程使用的资源；访问它的代码分进入区、临界区、退出区、剩余区
同步 vs 互斥 同步 = 直接制约（协作，”前 V 后 P”，初值 0）；互斥 = 间接制约（竞争，”进 P 退 V”，初值 1）
四准则 空闲让进、忙则等待、有限等待、让权等待；违反”忙则等待”是正确性错误，忙等只违反让权等待
软件四法 单标志：必须交替，违背空闲让进；先检查：同时进入，违背忙则等待；后检查：互等进不去，违背空闲让进 + 有限等待；Peterson：意愿 flag + 谦让 turn，后写 turn 者谦让，满足前三准则仍忙等，仅两进程
中断屏蔽 关中断保护临界区；特权指令（仅内核进程可用）；多处理机失效
TS/TSL 与 Swap 原子指令”读旧值 + 上锁”一步完成；适用多处理机；都忙等（违背让权等待）
自旋锁 vs 互斥锁 自旋：忙等、无切换开销、适合多核短临界区；互斥量：阻塞让权、适合长临界区、单处理机
信号量 value 正值 = 可用资源数；负值绝对值 = 等待进程数；0 = 资源用完无人等
P/V 原语 P 减 1、小于 0 阻塞自己；V 加 1、不大于 0 唤醒一个；都是原语，P 申请、V 释放
整型 vs 记录型 整型”先检查后减”忙等；记录型 value + 等待队列，”先减后判断”阻塞（让权等待）
三大模板 互斥：mutex=1 进 P 退 V；同步：S=0 前 V 后 P；前驱：每边一个信号量、初值 0
生产者-消费者 mutex=1、empty=n、full=0；P 顺序不能颠倒（empty 与 full 的 P 都须在 P(mutex) 前），否则死锁；V 顺序可换
读者-写者 count 计数 + mutex 保护；第一个读者 P(rw)、最后一个 V(rw)；读优先写者饥饿；写优先再加 w=1
哲学家进餐 5 人同拿左筷 → 循环等待死锁；解法：room=4 限流 / mutex 原子拿齐 / 奇偶号换手
吸烟者问题 每种材料组合一个信号量（初值 0）+ finish 双向同步；无需 mutex；2021 统考大题原型
