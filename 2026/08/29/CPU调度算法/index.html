CPU调度算法

2026-08-29
  • 操作系统

处理机调度（CPU 调度）：从就绪队列中按某种算法选择一个进程（线程），把处理机分配给它。当内存中的进程数远多于 CPU 个数时，”下一个 CPU 给谁用、用多久”就决定了系统的吞吐与响应。408 对本章的考查集中在：三级调度、评价指标、调度器与调度时机（抢占/非抢占、闲逛进程）、六种调度算法的计算与对比、上下文切换，其中画甘特图算周转时间是大题高频模式。

调度的基本概念：三级调度

调度按”做什么”分为三个层次，发生频率从低到高：

层次 别名 功能 频率 对应状态转换
高级调度（长程） 作业调度 从外存后备队列中选作业调入内存，为其建立进程（分配内存等资源） 最低（秒/分钟级） 无 → 创建 → 就绪态
中级调度（中程） 内存调度 决定哪个进程换出/换入内存（挂起 / 激活），提高内存利用率和系统吞吐 中等 就绪 ⇄ 就绪挂起、阻塞 ⇄ 阻塞挂起（内存 ⇄ 外存）
低级调度（短程） 进程调度 从就绪队列中选一个进程/线程，把 CPU 分配给它 最高（毫秒级） 就绪态 → 运行态
  • 中级调度与挂起态直接关联：引入挂起态后的七态模型中，”就绪挂起、阻塞挂起”与”就绪、阻塞”之间的双向转换，正是中级调度（换出到外存 / 换回内存）完成的；暂时不运行的进程被换出到外存，腾出内存给更需要的进程。
  • 三级调度中只有低级调度真正”分配 CPU”；高级调度控制”谁有资格进内存”，中级调度控制”内存里留谁”。

考点：进程调度（低级调度）是最基本、最频繁的调度，所有操作系统都必须配置；中级调度是为提高内存利用率而引入的，与挂起态成对出现。

调度的目标：评价指标

T周转​=T完成​−T到达​T带权​=T运行​T周转​​T等待​=T周转​−T运行​
指标 定义 / 公式 说明
CPU 利用率 总时间CPU 忙碌的时间​ 越高越好
系统吞吐量 单位时间内完成的作业 / 进程数 越高越好（批处理关心）
周转时间 T完成​−T到达​（作业提交到完成的总时间） 越短越好（批处理关心）
带权周转时间 T带权​=T运行​T周转​​ 恒 ≥ 1，越接近 1 越好；常看平均值
等待时间 T周转​−T运行​，即在就绪队列中等待的时间之和 越短越好；纯计算题中 = 周转 − 运行
响应时间 从提交请求到首次产生响应的时间 越短越好，交互（分时）系统最重要

考点：周转时间、吞吐量对批处理系统重要，响应时间对分时（交互）系统重要；调度算法的优劣主要用平均周转 / 平均等待时间衡量。
易错点：响应时间是”首次响应”不是”完成”；带权周转时间一定 ≥ 1（运行时间不可能为负）。

调度的实现

调度器与分派程序

调度程序（scheduler） 运行在内核态，由三部分协作完成一次调度：

组件 职责
排队器 将就绪进程按调度策略排入就绪队列
分派器 取出队首（被选中）进程，准备分配 CPU
上下文切换器 保存旧进程现场到其 PCB，装入新进程现场
  • 一句区分：调度程序（scheduler）负责”选谁上 CPU“（策略）；分派程序（dispatcher）负责”怎么换上 CPU“——切换上下文、从内核态转回用户态、跳转到新进程程序入口（机制），分派本身也有开销，所以时间片不能取得太小。
  • 线程调度一句：用户级线程由线程库在用户态自行调度，内核看不见，仍按进程分配 CPU；内核级线程才是操作系统内核调度的真正对象。

调度的时机

可以 / 需要进行调度与切换的时机：

类别 时机 说明
主动放弃 CPU 进程终止（正常结束 / 异常退出） 必须重新调度
进程阻塞（请求 I/O、P 操作失败、等待事件） 运行 → 阻塞，让出 CPU
进程被挂起、或执行 yield 主动让权 暂停参与调度 / 自愿回队尾
被动剥夺 CPU 当前进程时间片用完 运行 → 就绪，排回就绪队列
更高优先级进程就绪（抢占式方式下） 立即抢占当前进程
也提供调度机会 新进程创建、I/O 完成唤醒某进程 被唤醒者只是进入就绪队列，不一定立即上 CPU

不能进行调度与切换的两种情形（考纲新点）：

情形 原因
① 在处理中断的过程中 中断处理必须快速完成，处理完毕后才能考虑调度
② 进程在 OS 内核程序临界区中 正在修改就绪队列等内核临界资源（信号量 P/V 原语等原子操作同理），中途切换会破坏数据一致性

易错点：区分两种”临界区”——进程在普通临界资源（如打印机）的临界区中可以被调度切换走；只有在操作系统内核程序临界区中才不能切换。
易错点：I/O 完成使进程”阻塞 → 就绪”，只是入队，是否立即切换取决于调度方式与算法，不一定立即被调度。

抢占式与非抢占式

对比项 非抢占式（非剥夺） 抢占式（剥夺）
切换原则 仅当运行进程主动放弃 CPU（终止 / 阻塞）时才调度 时间片到、或有更高优先级 / 更短剩余时间进程就绪时立即剥夺
响应速度 慢，紧急任务要等当前进程让位 快，能及时处理紧急任务
开销与复杂度 小、实现简单 大、需时钟中断与现场保护支持
典型算法 FCFS、非抢占 SJF、HRRN SRTN、RR、抢占式优先级、多级反馈队列

考点：抢占的依据只有时钟中断（时间片）和”更紧急者就绪”两类事件；非抢占方式下一个计算型进程可霸占 CPU 很久。

闲逛进程

  • 就绪队列为空时，CPU 运行闲逛进程（idle），PID 为 0。
  • 特点：优先级最低、不需要调度（队列空时自动上 CPU）、不需要 CPU 以外的资源、因此不会被阻塞。
  • 作用：让 CPU”永远有事可做”，避免空转指令失控，简化”无进程可运行”的边界处理。

先来先服务（FCFS）

  • 思想：按到达的先后顺序调度，非抢占；就绪队列就是一个 FIFO 队列。
  • 优点：公平、实现简单、不会饥饿。
  • 缺点：存在护航效应（Convoy Effect）——一个长作业排在前头，后面一批短作业全部”陪跑”等待，平均等待 / 周转时间长；有利于 CPU 繁忙型作业，不利于 I/O 繁忙型作业（CPU 被长计算占住，I/O 设备闲置）。

易错点：FCFS 单独使用时对短作业极不友好，但它常与优先级、多级反馈队列配合（低级队列内部用 FCFS）。

短作业优先（SJF）与最短剩余时间优先（SRTN）

  • SJF（非抢占）：每次从就绪队列中选预计运行时间最短的进程，运行到完成。
  • SRTN（抢占式 SJF）：新进程到达时（或每个调度时刻），比较剩余时间——新进程的剩余时间 < 当前进程的剩余时间就立即抢占。
  • 优点：在同一组作业下，平均等待时间、平均周转时间最短（理论最优）。
  • 缺点：
    • 运行时间需要预估（用户可”谎报”短时间获得优先）；
    • 长作业可能饥饿——短作业源源不断地到达，长作业被不断插队。
  • 关系：SRTN 的平均等待时间 ≤ 非抢占 SJF ≤ 其他算法（同组作业下）。

考点：考题问”平均等待时间最短的算法”答 SJF（或 SRTN）；问”最公平、不会饥饿”答 FCFS / RR。

高响应比优先（HRRN）

每次调度时为就绪队列中每个进程计算响应比，选响应比最高者运行（非抢占）：

R=要求服务时间等待时间+要求服务时间​=1+要求服务时间等待时间​
  • 同时等待时，运行越短响应比越高 → 体现了 SJF 的优点；
  • 运行相同时，等得越久响应比越高 → 长作业等待足够久后必然被选中，不会饥饿（FCFS 的优点）；
  • 是 FCFS 与 SJF 的折中。
  • 缺点：每次调度都要重新计算所有就绪进程的响应比，开销大；平均性能仍不如 SJF。

综合例题：FCFS / SJF / HRRN

作业信息

作业 到达时间 运行时间
Job1 0 7
Job2 2 4
Job3 4 1
Job4 5 4

FCFS 调度

严格按到达顺序 Job1 → Job2 → Job3 → Job4，均非抢占运行到结束：

作业 到达 运行 完成 周转 带权周转 等待
Job1 0 7 7 7 1.00 0
Job2 2 4 11 9 2.25 5
Job3 4 1 12 8 8.00 7
Job4 5 4 16 11 2.75 7
平均 — — — 8.75 3.50 4.75

只运行 1 个单位的 Job3 被拖到 12 才完成、带权周转高达 8.00——这就是护航效应。

SJF（非抢占）调度

  • t=0：只有 Job1 → 运行 Job1（0~7）。
  • t=7：就绪 {Job2(4), Job3(1), Job4(4)}，运行时间最短的 Job3 先行（7~8）。
  • t=8：Job2 与 Job4 运行时间同为 4，先到达者 Job2 先行（8~12）；最后 Job4（12~16）。
作业 到达 运行 完成 周转 带权周转 等待
Job1 0 7 7 7 1.00 0
Job2 2 4 12 10 2.50 6
Job3 4 1 8 4 4.00 3
Job4 5 4 16 11 2.75 7
平均 — — — 8.00 2.56 4.00

HRRN 调度

  • t=0：只有 Job1 → 运行 Job1（0~7）。
  • t=7 计算响应比（响应比 = 1 + 等待 ÷ 运行）：
作业 等待 运行 响应比
Job2 5 4 1+45​=2.25
Job3 3 1 1+13​=4.00 ← 最高
Job4 2 4 1+42​=1.50
  • t=8（Job3 完成后）：Job2 等待 6、Job4 等待 3 → Job2 R=2.50 > Job4 R=1.75 → Job2（8~12），最后 Job4（12~16）。

指标与 SJF 完全相同：平均周转 8.00、平均带权周转 2.56、平均等待 4.00。

三算法对比

算法 调度顺序 平均周转 平均带权周转 平均等待
FCFS 1 → 2 → 3 → 4 8.75 3.50 4.75
SJF（非抢占） 1 → 3 → 2 → 4 8.00 2.56 4.00
HRRN 1 → 3 → 2 → 4 8.00 2.56 4.00

易错点：本例 HRRN 与 SJF 选中顺序恰好一致（Job3 运行极短，响应比必然最高），不代表两算法总相同——当长作业等待很久后，其响应比会反超新来的短作业，HRRN 会转而照顾长作业，因此永远不饥饿，这是它相对 SJF 的本质优势。

时间片轮转（RR）

  • 思想：就绪队列按 FCFS 排队，队首进程运行一个时间片 q；时间片内未完成则剥夺 CPU、排到队尾，完成了则立即释放 CPU。天然是抢占式（靠时钟中断）。
  • 适用：分时（交互）系统——公平、响应快。
  • 时间片大小的权衡：
    • q 太大：进程在时间片内都跑完了，退化为 FCFS，响应变慢；
    • q 太小：上下文切换过于频繁，切换开销占比过大，真正干活的时间变少；
    • 一般取略大于一次交互所需的开销（如 20~50 ms）。
  • 缺点：不区分作业长短，平均周转时间不一定最优；时间片选择敏感。

考点：RR 下等待时间 = 每次排队时间之和，作业最终总能轮到，不会饥饿；RR 追求的是响应而非周转。

RR 例题（q=2）

同一组作业，时间片 q=2。入队规则：同一时刻新到达的先入队，时间片用完的进程再入队尾。

时刻 事件与就绪队列（队首在左）
0 Job1 到达入队：[Job1] → 运行 Job1（0~2）
2 Job1 时间片到（剩 5）；Job2 先到达入队，Job1 再入队 → [Job2, Job1] → 运行 Job2（2~4）
4 Job2 时间片到（剩 2）；Job3 先入队，Job2 再入队 → [Job1, Job3, Job2] → 运行 Job1（4~6）
5 Job4 到达，排到队尾 → [Job1, Job3, Job2, Job4]（排队中）
6 Job1 时间片到（剩 3）→ [Job3, Job2, Job4, Job1] → 运行 Job3（6~7，只需 1 个单位）
7 Job3 完成 → [Job2, Job4, Job1] → 运行 Job2（7~9，恰好完成）
9 Job2 完成 → [Job4, Job1] → 运行 Job4（9~11）
11 Job4 时间片到（剩 2）→ [Job1, Job4] → 运行 Job1（11~13）
13 Job1 时间片到（剩 1）→ [Job4, Job1] → 运行 Job4（13~15，完成）
15 Job4 完成 → [Job1] → 运行 Job1（15~16，完成）
作业 到达 运行 完成 周转 带权周转 等待
Job1 0 7 16 16 2.29 9
Job2 2 4 9 7 1.75 3
Job3 4 1 7 3 3.00 2
Job4 5 4 15 10 2.50 6
平均 — — — 9.00 2.38 5.00

可见 RR 的平均周转（9.00）反而劣于 FCFS（8.75）——RR 的目标在响应快与公平，不在周转最短。

优先级调度

  • 思想：为每个进程设优先级，就绪队列按优先级排序（可用优先队列 / 分级队列组织），高者优先；抢占、非抢占均可——抢占式下更高优先级进程就绪会立即剥夺 CPU。
  • 静态优先级：创建时确定、运行期间不变。简单、开销小，但低优先级进程可能长期得不到服务。
  • 动态优先级：运行中调整，如”等待时间越长优先级越高“（老化 Aging）、”占 CPU 越久优先级越低”——更公平、可防饥饿，但开销大。
  • 设置原则（越高越优先）：系统进程 > 用户进程；交互型 > 非交互型；I/O 繁忙型 > CPU 繁忙型（I/O 型进程占 CPU 短，让它先跑能提高设备利用率、实现 CPU 与 I/O 并行）。
  • 缺点：低优先级进程可能饥饿，用老化缓解。

易错点：”系统进程优先级高”是原则而非绝对；考试常考”让 I/O 型先运行的理由”——腾出 CPU 的同时让 I/O 设备忙起来。

多级反馈队列调度（MLFQ）

规则：

  1. 设置多个就绪队列，优先级从第 1 级到第 n 级递减；时间片逐级加倍（第 2 级是第 1 级的 2 倍……），最低级可用 FCFS。
  2. 新进程先进入第 1 级队列（最高优先级）队尾。
  3. 仅当第 1~i−1 级队列全空时，第 i 级队首才能上 CPU；高优先级队列可以抢占低优先级队列正在运行的进程。
  4. 进程在本级队列中运行一个本级时间片：用完未完成 → 降入下一级队列队尾；在最后一级用完 → 回最后一级队尾；提前完成 → 立即释放 CPU。
  • 优点：短作业在前几级的小时间片内就能跑完（近似 SJF）；交互作业始终能得到快速响应（近似 RR）；长作业逐级降队列后仍会被运行（FCFS 兜底）——综合了 FCFS、SJF、RR 的优点，是现代操作系统广泛采用的方案。
  • 缺点：实现复杂；若高优先级队列源源不断有新进程，低级队列进程仍可能饥饿（可对低级队列中等待过久的进程提升队列级来缓解）。

多级反馈队列例题（时间片 1/2/4）

三个队列 Q1、Q2、Q3，时间片分别为 1、2、4；高优先级可抢占。两个作业：

作业 到达时间 运行时间
Job1 0 4
Job2 1 8

多处理机调度

多处理机（多核）系统中，调度还要决定进程 / 线程放到哪个处理机上运行，需考虑负载均衡与处理机亲和性（尽量固定 CPU 以复用高速缓存），常见方式有成组调度、专用处理机分配等——408 仅要求概念性了解。

上下文及其切换机制

  • 上下文（Context）：进程在 CPU 上运行所需的全部状态信息——通用寄存器、PC、PSW、栈指针等（记录在 PCB 中）。
  • 上下文切换（Context Switch）：把旧进程的上下文存入其 PCB，再把新进程的上下文从其 PCB 装入。
  • 切换开销是纯系统开销（不给任何用户进程干活）；切换前必先发生调度（先”选人”，后”换人”）。
  • 何时不能切换：① 处理中断的过程中；② 进程在 OS 内核程序临界区中（普通临界资源的临界区可以切换）。

进程切换 vs 模式切换：

对比项 进程切换（上下文切换） 模式切换（用户态 ⇄ 内核态）
切换对象 不同的进程 同一进程的两种模式
是否保存 / 恢复 PCB 是（完整现场） 否（现场仍在，进程不变）
是否经过调度 是（先调度再切换） 否（中断 / 系统调用直接触发）
开销 大 小

考点：陷入内核（系统调用 / 中断）不是进程切换——它只是模式切换，运行进程没变；由”调度”引起的才叫进程切换。

饥饿辨析

算法 会否饥饿 原因 / 对策
FCFS 不会 严格按到达顺序，人人可达队首
HRRN 不会 等待越久响应比越高，迟早被选中
RR 不会 轮流给时间片，谁都能轮到
SJF / SRTN 会（长作业） 短作业源源不断，长作业被无限插队
优先级 会（低优先级） 高优先级持续到达 → 用老化解决
多级反馈队列 可能（低级队列） 高级队列一直不空则低级队列难得运行 → 定期提升队列级

易错点：”饥饿”是调度策略问题，进程仍处于就绪态；”死锁”是资源分配问题，进程互相等待——二者原因不同，饥饿可用合理调度避免。

六种调度算法大对比

算法 是否可抢占 核心思想 优点 缺点 适用 饥饿？
FCFS 否 按到达先后服务 公平、实现简单 护航效应，短作业 / I/O 型吃亏 批处理 不会
SJF / SRTN SJF 否 / SRTN 是 短（剩余）时间优先 平均等待最短 需预知运行时间；长作业饥饿 批处理 会
HRRN 否 响应比 = 1 + 等待÷运行，最高者先 FCFS 与 SJF 的折中，不饥饿 每次重算响应比，开销大 批处理 不会
RR 是（时间片到） 时间片轮转，用完排队尾 公平、响应快，适合交互 时间片难定；平均周转不一定优 分时系统 不会
优先级 均可 优先级高者先 灵活，区分缓急 低优先级饥饿（老化缓解） 通用 会
多级反馈队列 是 多级队列 + 降级 + 时间片加倍 综合各算法优点，长短兼顾 实现复杂；低级队列可能饥饿 通用（现代 OS 主流） 可能

选择口诀：平均等待最短 → SJF / SRTN；交互响应 → RR；折中不饥饿 → HRRN；综合全能、现代主流 → 多级反馈队列。

高频考点速记

考点 记忆
三级调度 高级 = 作业调度（外存 → 内存创建进程）；中级 = 内存调度（挂起 / 激活）；低级 = 进程调度（分配 CPU，最频繁）
中级调度 与挂起态关联：就绪 ⇄ 就绪挂起、阻塞 ⇄ 阻塞挂起，目的是提高内存利用率
周转时间 T完成​−T到达​；带权 = 周转 ÷ 运行（≥ 1，越接近 1 越好）；等待 = 周转 − 运行
指标侧重 批处理看周转 / 吞吐；分时交互看响应时间（首次响应）
scheduler vs dispatcher scheduler “选谁“（策略）；dispatcher “换人“（切上下文、转用户态、跳入口）
调度时机 主动放弃（终止 / 阻塞 / 挂起 / yield）+ 被动剥夺（时间片到 / 更高优先级到达）；被唤醒只是入队
不能切换两情形 处理中断的过程中；OS 内核程序临界区中（普通临界资源的临界区可以切换）
闲逛进程 PID = 0、优先级最低、不需调度、不会被阻塞；就绪队列空时运行
FCFS 非抢占、公平不饥饿；护航效应，对短作业 / I/O 型不利
SJF / SRTN 平均等待最短；长作业饥饿；运行时间需估计；SRTN 到达即比较剩余时间抢占
HRRN R=1+运行等待​，最高者先；折中、不饥饿；每次要重算
RR 时间片轮转、公平响应快（分时）；q 太大退化 FCFS、太小切换开销大；不会饥饿
优先级调度 静态 / 动态；系统 > 用户、交互 > 非交互、I/O 型 > 计算型；饥饿用老化解
多级反馈队列 新进程进最高队列、用完降级、时间片加倍、高队列可抢占低队列；综合优点，现代 OS 主流
多处理机调度 还要解决”放哪块 CPU”：负载均衡 + 处理机亲和性；成组调度 / 专用处理机
上下文切换 存旧 PCB → 恢复新 PCB，纯系统开销；陷入内核 ≠ 进程切换（只是模式切换）
