指令流水线

2026-08-29
  • 计算机组成原理

指令流水线（Instruction Pipeline）是提升 CPU 吞吐率的核心技术：把一条指令的执行过程拆成若干个阶段，让多条指令的不同阶段在时间上重叠进行——第 1 条指令还在执行段时，第 2 条已在译码段、第 3 条正在取指。它以”时间并行“换取性能：不缩短单条指令的执行时间，却能平均每个时钟周期流出一条指令。408 对指令流水线的考查集中在：三种执行方式对比、五段式流水线与时空图、执行时间/吞吐率/加速比计算、三类冒险（结构/数据/控制）及其处理方法、超标量与动态流水线的基本概念，其中流水线性能计算与数据冒险旁路、控制冒险分支预测是大题高频考点。

指令流水线的基本概念

指令执行方式：串行 → 一次重叠 → 二次重叠

一条指令的生命周期可粗分为取指、分析（译码）、执行三个阶段，设每阶段耗时均为 t。按不同方式执行 n 条指令，完成时间差别巨大：

执行方式 原理 执行 n 条指令的时间 设备要求
顺序串行 一条指令的取指、分析、执行全部结束后，才取下一条 T=3nt 无附加要求
一次重叠 第 k 条指令的执行与第 k+1 条指令的取指同时进行 T=(2n+1)t 取指部件与执行（分析）部件分设，增设指令缓冲
二次重叠（流水线） 取指 k+2、分析 k+1、执行 k 三者同时进行 T=(n+2)t 取指、分析、执行部件全部独立；指令/数据存储器分设（多体交叉、指令队列）
  • 串行：每条指令都走完 3 个阶段，T=3nt
  • 一次重叠：第一条耗时 3t，此后每 2t 完成一条 → 3t+2(n−1)t=(2n+1)t
  • 二次重叠：第一条耗时 3t，此后每 t 完成一条 → 3t+(n−1)t=(n+2)t

考点：三个公式按 3nt → (2n+1)t → (n+2)t 递减，重叠程度越高、提速越明显（约 1 倍 → 3 倍），但设备代价也逐级增加——二次重叠要求取指、分析、执行三条通路并行工作。
易错点：一次重叠每条指令平均仍需 2t（分析与执行并未重叠）；别把 (2n+1)t 与二次重叠的 (n+2)t 记混。

流水 CPU 的硬件支撑：主存采用多体交叉存储器并配合 Cache 缩短访存延迟；CPU 内设指令部件（预取指令）、FIFO 指令队列（缓冲已取出的指令）与执行部件（多级流水段），保证各阶段能同时拿到各自的”原料”。

流水线的定义与时空图

指令流水线：把指令周期划分成若干时间大致相等的流水段，每段由独立功能部件完成，各条指令依次错开一个时钟周期进入流水线，使多条指令的不同子过程同时进行。流水线的工作过程用时空图描述：横轴为时间（时钟周期），纵轴为空间上的指令/流水段。

以经典五段流水线（IF → ID → EX → MEM → WB）连续执行 4 条指令为例：

  • 填充阶段（前 k−1 拍）：流水线逐段被”灌满”；
  • 稳定阶段：从第 5 拍起，每个时钟周期流出一条指令（理想情况）——无流水线时每条指令需 5 个时钟周期；
  • 每个流水段恰好占一个时钟周期 Δt，段与段之间用流水寄存器锁存本段结果，时钟上升沿到来时整体向前”节拍推进”。

流水线按并行层次可分为：部件级（运算操作内部再分段，如浮点加法器）、指令级（本章主角，多条指令重叠）与处理机级（宏流水线）（多个处理机串接，任务级并行）。

易错点：流水线不能缩短单条指令的执行时间（单条仍要经历全部 k 段、耗时 kΔt），它提高的是吞吐率（单位时间完成的指令数），并非”让每条指令跑得更快”。

五段式指令流水线的实现

五个流水段的职责

把指令周期划分为五个功能段，各段职责明确：

流水段 名称 主要工作
IF Instruction Fetch 取指 按 PC 从指令存储器（指令 Cache）取出指令，同时 PC + 4 指向下一条
ID Instruction Decode 译码 指令译码、识别操作类型，从寄存器堆读出源操作数
EX Execute 执行 ALU 完成算术逻辑运算，或计算访存有效地址
MEM Memory Access 访存 Load/Store 访问数据存储器（数据 Cache）；ALU 型指令本段直通
WB Write Back 写回 把运算结果（或从存储器取来的数据）写回寄存器堆

五个流水段之间设置四个流水寄存器（IF/ID、ID/EX、EX/MEM、MEM/WB）：每个时钟周期结束时，各段把处理结果锁存进段间寄存器交给下一段——寄存器在段间缓冲是流水线能”节拍化”推进的硬件基础。其中 ID 段读寄存器、WB 段写寄存器，这一”读写关系”正是数据冒险的根源；IF 用指令存储器、MEM 用数据存储器，两者合一则是结构冒险的根源。

执行时间、吞吐率与加速比（必考计算）

设理想流水线共 k 段，每段耗时 Δt（一个时钟周期），连续流入 n 条指令：

T=kΔt+(n−1)Δt=(k+n−1)Δt TP=(k+n−1)Δtn​n→∞​TPmax​=Δt1​ S=T流水​T串行​​=(k+n−1)Δtn⋅kΔt​=k+n−1nk​n→∞​Smax​=k
  • 第一条指令走完全程需 kΔt，此后每隔 Δt 流出一条，故总时间为 (k+n−1)Δt；
  • 吞吐率 TP：单位时间内流出的指令条数，理想极限为每拍一条；
  • 加速比 S：串行时间与流水时间之比，n→∞ 时趋于段数 k（加速比上界）；
  • 效率 E：时空图中有效面积占总面积的比例，E=S/k。

例题 1：某五段流水线每段耗时 Δt=100ns，连续执行 10 条指令。求串行与流水线执行的总时间、吞吐率与加速比。

解：

  • 串行执行：T0​=n⋅k⋅Δt=10×5×100=5000ns
  • 流水线执行：Tk​=(k+n−1)Δt=(5+10−1)×100=14×100=1400ns
  • 吞吐率：TP=Tk​n​=1400ns10​≈7.14×106 条/s（理想极限 TPmax​=1/Δt=107 条/s）
  • 加速比：S=T0​/Tk​=5000/1400≈3.57
  • 用公式验证：S=k+n−1nk​=1410×5​=1450​≈3.57 ✓；效率 E=S/k=3.57/5≈0.71

考点：加速比上界是段数 k，只有 n→∞ 才能接近；指令条数 n 较小时（如本题 10 条），S 远小于 k——填充满流水线的”填充时间”占比不可忽略。
易错点：TPmax​=1/Δt 是 n 充分大时的极限；用 n/Tk​ 算吞吐率时分母必须含 (k−1)Δt 的填充时间，不能直接用 n/Δt。

在五段流水线基础上进一步提高性能的两条路线：超流水线把每个流水段再细分成更多小段、进一步提高时钟频率；**多发射（超标量）**则一个时钟周期同时发射多条指令——详见下文。

流水线冒险及其处理

冒险（Hazard）：使下一条指令无法在设计的时钟周期内执行的因素，共分结构冒险、数据冒险、控制冒险三类。

结构冒险（资源冲突）

定义：多条指令在同一时钟周期内争用同一功能部件。

典型场景：指令存储器与数据存储器合一（未采用哈佛结构）时，某条指令在 MEM 段访存的同时，后续指令正要 IF 取指，两者同时访问同一存储器端口而冲突。

处理方法：

方法 原理
暂停（插入气泡） 硬件互斥：让访存冲突的指令暂停一拍错开访问
资源重复配置（哈佛结构） 分设指令 Cache 与数据 Cache，取指与访存可并行，从根本上消除
多端口/多体交叉存储器 增加存储器访问端口或分体并行，缓解争用

数据冒险

定义：后一条指令需要用到前一条指令尚未写回的结果，取数时读到旧值。

按”读写顺序”分三类：

类型 全称 含义 顺序五段流水线中
RAW Read After Write（先写后读） 后条指令要读前条指令刚写的单元 存在，最主要
WAR Write After Read（先读后写） 后条指令要写前条指令刚读的单元 不出现（顺序发射，写总在读之后）
WAW Write After Write（先写后写） 两条指令写同一单元 不出现（顺序发射）

解决方法：

方法 原理
暂停（Stall） 插入气泡（NOP 指令或硬件阻塞），等前条指令把结果写回再继续
数据旁路/转发（Forwarding / Bypassing） 设置专用通路，不等 WB 写回，把 EX/MEM 段的结果直接送后续指令的 ALU 输入，包括 EX→EX（ALU 结果直接接力）与 MEM→EX（访存结果接力）两条通路
编译器调度 编译器重排指令，把与相关无关的指令插到依赖指令之间，用有效指令填满等待时间

易错点：load-use 冒险——Load 指令的数据要到 MEM 段末才可得，即使有旁路（MEM→EX），紧随其后使用该数据的指令也必须暂停 1 拍，这是旁路无法完全消除的。

例题 2：五段流水线执行下列三条指令，Δt 为一个时钟周期；无旁路时约定：前条指令 WB 写回之后的下一拍，后条指令才能在 ID 段读到新值。

分析：ADD 在 T5（WB）才把 R1 写回。SUB 的 ID 在 T3 就想读 R1 → 读到旧值；AND 的 ID 在 T4 同样不行。无旁路时两条指令各需等待写回，且 AND 还必须排在 SUB 之后使用各流水段。

控制冒险（分支冒险）

定义：遇到转移指令（条件分支、跳转、调用等改变 PC 的指令）时，流水线已按顺序预取的后继指令可能全部作废。

代价：若转移指令在 EX 段末才确定是否转移并改写 PC，则已取入 IF、ID 段的后 2 条指令作废（冲刷 flush），损失 2 拍；若到 MEM 段末才判定，则损失 2∼3 拍。分支越早判定，浪费越少。

处理方法：

方法 原理
分支预测（静态） 总猜一种方向（如”总是猜不转移”），按顺序继续取指；猜错再冲刷重取
分支预测（动态） 用分支目标缓冲器 BTB 等记录转移历史并据此预测，准确率随历史积累提高
延迟分支（延迟槽） 编译器在转移指令后填入一条无论是否转移都必定执行的指令（延迟槽），掩盖判定延迟
提前形成条件码 / 提前判别 把转移判断提前到 ID 段（如专用比较逻辑），减少已取指令的作废条数

考点：控制冒险靠”预测”化解——静态预测简单但方向固定（某分支一半次数转移时命中率仅 50%），动态预测（BTB）靠历史记录适应分支行为，是现代 CPU 的主流做法。

三种冒险对比

冒险类型 产生原因 典型场景 解决方法
结构冒险 硬件资源冲突：多条指令同一拍争用同一部件 指令/数据存储器合一，IF 取指与 MEM 访存相撞 暂停气泡；哈佛结构（指令/数据 Cache 分设）；多口/多体交叉存储器
数据冒险 后条指令用到前条尚未写回的结果 RAW：ADD 写 R1，紧跟的 SUB/AND 读 R1 旁路转发（EX→EX、MEM→EX）、暂停气泡、编译器调度
控制冒险 转移指令改变 PC，按序预取的后继指令作废 条件分支、跳转指令 分支预测（静态/动态 BTB）、延迟分支（延迟槽）、提前形成条件码

考点：三类冒险的”关键词”——结构冒险找部件、数据冒险找寄存器读写顺序、控制冒险找 PC 被改写。其中数据冒险的旁路转发与控制冒险的分支预测是重中之重。

超标量、超流水线与动态流水线

在”一段一拍、一拍一条”的理想流水线之上，进一步提高**指令级并行（ILP）**的三种技术：

技术 并行方式 核心思想 调度者
超标量（Superscalar） 空间并行 配置多套取指/译码/执行部件，一个时钟周期内发射多条指令（多发射） 硬件（动态调度）
超流水线（Superpipeline） 时间并行 把流水段再细分，段更短、时钟频率更高，一拍内可推进多个小段 硬件
超长指令字（VLIW） 空间并行 编译器把多个互不相关的操作打包成一条超长指令字，一条指令同时指定多个部件的操作 编译器（静态调度）

动态流水线：静态流水线在同一时间内各段只能连接同一种子过程（如都做浮点加法），而动态流水线允许同一段时间内各段连接不同的子过程（”浮动”连接），部件利用率更高。与之配套的是动态调度 / 乱序执行：硬件允许后面的指令越过前面因冒险而阻塞的指令，乱序发射、乱序执行、乱序完成，用无关指令填满等待时间；同时必须通过相关性检查保证数据相关与程序语义正确（最后按序提交结果）。

考点：超标量 = 空间维度的多发射（多套部件）；超流水 = 时间维度的段细分；VLIW = 编译器静态打包，硬件简单。三者目标一致：提高指令级并行。
易错点：乱序执行改变的是执行顺序而非程序语义——结果仍需与顺序执行一致；WAR/WAW 冒险只在乱序的流水线中才可能出现。

考点 记忆
