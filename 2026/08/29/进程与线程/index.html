进程与线程

2026-08-29
  • 操作系统

进程（Process）是操作系统中资源分配的基本单位，**线程（Thread）**则是 CPU 调度的基本单位——这一句是本章的总纲。408 对”进程与线程”的考查集中在：进程的定义与进程实体（PCB）、五态模型与状态转换、进程控制原语、线程的实现方式与多线程模型、进程间通信（IPC）。本文对应考纲”（一）进程与线程”全部内容，调度算法、同步互斥、死锁另文整理。

进程的基本概念

进程是一个具有独立功能的程序关于某个数据集合的一次运行活动，是系统进行资源分配和保护的基本单位。多道程序并发执行时，各程序共享 CPU、内存等资源，相互制约、交替推进——静态的”程序”无法描述这种动态的并发执行过程，于是引入进程来描述和管理。

程序是存放在磁盘上的静态指令序列；进程是程序的一次动态执行过程，有创建、有消亡。一个程序可以对应多个进程（多个用户同时运行同一个程序，各自形成独立进程）；一个进程在同一时刻只能执行一个程序。

考点：引入进程的根本原因——使程序得以并发执行，并让操作系统能够描述、控制多道程序的动态执行。

前趋图：用有向无环图（DAG）描述程序段（进程）之间的先后制约关系——节点表示程序段/进程，有向边表示”前者完成后后者才能开始”，它是进程间”同步”关系的图形化来源。

程序 vs 进程（重点对比）

对比项 程序 进程
本质 静态：指令 + 数据的集合 动态：程序的一次执行过程
存在时间 永久（可长期保存在磁盘） 暂时（创建 → 运行 → 撤销，有生命周期）
组成 指令 + 数据 PCB + 程序段 + 数据段（进程实体）
并发性 本身不能并发 可并发执行，独立又相互制约
对应关系 一个程序可对应多个进程 一个进程同一时刻只执行一个程序

考点：进程与程序的本质区别是动态性（最基本特征）——程序是”菜谱”，进程是”照着菜谱炒菜的一次过程”；同一份菜谱可以同时被多人照做（一程序对多进程）。

进程的特征

特征 含义
动态性 进程是执行中的过程，有创建、运行、终止（最基本特征）
并发性 多个进程同存于内存，宏观同时、微观交替地运行
独立性 进程是独立运行、独立获得资源、独立接受调度的基本单位
异步性 各进程按不可预知的速度向前推进（所以需要同步机制）
结构性 进程由 PCB、程序段、数据段三部分组成（结构性 = 进程实体）

进程实体（进程映像）= PCB + 程序段 + 数据段。所谓”创建进程”，实质是为程序建立 PCB 并装入程序和数据；”撤销进程”，实质是回收资源、撤销 PCB。

进程的组成与组织

PCB：进程控制块

PCB（Process Control Block）是操作系统为每个进程建立的数据结构，记录进程的全部信息，是进程存在的唯一标志——创建进程时建立 PCB，进程终止时撤销 PCB。PCB 存放在内核空间、常驻内存，不能换出到外存（调度、中断处理随时要访问它）。

信息类别 具体内容
进程描述信息（标识） 进程标识符 PID、用户标识符 UID
处理机状态信息（现场） 通用寄存器、程序计数器 PC、程序状态字 PSW、栈指针
进程调度信息（状态） 进程当前状态（就绪/运行/阻塞）、优先级、等待的事件
进程控制/管理信息 程序和数据的内存地址、同步与通信机制、资源清单、链接指针（指向同队列的下一个 PCB）

考点：进程切换时，被换下 CPU 的进程要把现场信息（寄存器、PC、PSW）保存进自己的 PCB，新进程从其 PCB 恢复现场——“保存断点 / 恢复断点”就是对 PCB 的读写。
易错点：PCB 是进程存在的唯一标志——程序段和数据段可以被多个进程共享，但 PCB 绝不共享。

进程的组织方式

系统按状态把众多 PCB 组织起来，便于调度和查找：

组织方式 做法
链接方式 按状态把 PCB 链成队列：就绪队列（1 个）+ 阻塞队列（按等待原因可设多个），正在运行的进程由运行指针指向
索引方式 按状态建立索引表（就绪索引表、阻塞索引表），表项记录各 PCB 的起始地址

进程的状态与转换（五态模型）

三种基本状态

状态 含义 数量/队列
运行态（Running） 已获得 CPU，指令正在执行 单处理机上任一时刻只有一个
就绪态（Ready） 万事俱备，只欠 CPU（已获得除 CPU 外的一切资源） 就绪队列，可有多个
阻塞态（Blocked/Waiting） 因等待某事件（I/O 完成、资源到位）而暂停 阻塞队列，可有多个（按原因分队列）

再加上创建态（New）（正在建 PCB、分配资源、尚未进入就绪队列）和终止态（Exit）（运行结束或异常，等待系统回收资源、撤销 PCB），即得五态模型。

状态转换方向与引发原因

转换方向 引发原因 主动 / 被动
创建 → 就绪 系统完成创建工作（建 PCB、分配资源），进入就绪队列排队 系统
就绪 → 运行 进程被调度程序选中，获得 CPU 被动（调度分派）
运行 → 就绪 时间片用完，或被更高优先级进程抢占 被动（进程本身并不想让出）
运行 → 阻塞 进程主动请求等待事件：发起 I/O、申请的资源暂不可得、等待信号等 主动（进程自身行为）
阻塞 → 就绪 等待的事件发生（如 I/O 完成），被其他进程/中断唤醒 被动
运行 → 终止 正常结束 / 异常结束（除零、非法指令、越界）/ 外界干预 —

易错点（选择题高频）：

  • 阻塞 → 运行不可能：被唤醒的进程先回到就绪队列排队，必须等调度程序选中才能运行，不能”插队”直接上 CPU。
  • 就绪 → 阻塞不可能：进入阻塞态是进程主动发出的请求（如请求 I/O），而就绪进程尚未运行，根本没有机会发出这种请求。
  • 运行 → 阻塞是主动行为；运行 → 就绪是被动的（时间片到 / 被抢占）。

状态转换例题推演

例题：单处理机系统中 P1、P2、P3 排成就绪队列，P1 正在运行。按下列事件序列推演状态：

序号 事件 状态变化 说明
① P1 的时间片用完 P1：运行 → 就绪 被动让出 CPU，排回就绪队列尾；调度 P2 运行
② P2 运行中发起磁盘 I/O 请求 P2：运行 → 阻塞 主动请求等待，让出 CPU；调度 P3
③ 磁盘 I/O 完成，中断程序唤醒 P2 P2：阻塞 → 就绪 只进就绪队列排队，不立即运行
④ P3 运行时申请打印机，打印机忙 P3：运行 → 阻塞 资源不可得，主动阻塞；调度 P1
⑤ 调度程序再次选中 P1 P1：就绪 → 运行 P1 第二次获得 CPU

推演结论：

  • P1 经历 运行 → 就绪 → 运行：两次转换分别是”时间片到（被动）”与”被调度选中（获得 CPU）”。
  • ③ 中 P2 唤醒后只回到就绪队列——若当时 CPU 正被占用，P2 不能立刻运行；写成”阻塞 → 运行”即错。
  • 若认为”就绪中的 P1 因缺打印机转入阻塞”也错——就绪进程未运行，无法主动发起资源请求（就绪 → 阻塞不可能）。

考点：唤醒（wakeup）只完成”阻塞 → 就绪“一步；”就绪 → 运行”必须由进程调度完成，两步不能合并。

挂起状态与七态模型

内存紧张时，系统可把某些进程换出（对换）到外存，此时进程处于挂起状态，暂时不参与调度。在五态基础上增加就绪挂起、阻塞挂起，即得七态模型。

转换 说明
阻塞 → 阻塞挂起 内存不足，把阻塞进程换出到外存
阻塞挂起 → 就绪挂起 等待的事件发生了（进程已”就绪”，只是还在外存）
就绪挂起 → 就绪 中级调度（内存调度）把它激活（调入内存）
就绪 → 就绪挂起 内存仍紧张，把就绪进程也换出

易错点：挂起 ≠ 阻塞——阻塞是”等待某事件、位于内存、不参与调度”；挂起是”被换到外存“，原因是系统要腾内存、调负荷，不是进程自身在等事件。

进程控制（原语）

原语（Primitive）：执行期间不允许被中断的程序段，运行在核心态（内核态），要么全部执行、要么全不执行（原子性）。进程的创建、终止、阻塞、唤醒、切换全部用原语实现——因为”修改 PCB 状态 + 从队列摘除 / 插入”必须一气呵成，中途被打断会破坏队列与状态的一致性。

考点：原语靠关中断 / 开中断实现原子性（关中断 → 执行 → 开中断）；这也是开/关中断指令（特权指令）的典型应用场景。

创建原语

创建原语完成”无 → 创建态 → 就绪态”：

步骤 动作
① 申请一个空白 PCB，分配唯一的 PID
② 为新进程分配资源（内存空间、I/O 设备等）
③ 初始化 PCB（状态置为就绪、优先级、PC、PSW 等）
④ 把 PCB 插入就绪队列

引起创建进程的四类事件：用户登录（分时系统）、作业调度（批处理，作业调入内存）、提供服务（用户请求系统服务而建服务进程）、应用请求（父进程调用创建原语生成子进程——进程间存在父子关系，子进程可继承父进程的资源）。

终止原语

终止原语完成”运行/就绪/阻塞 → 终止态 → 消亡”：① 从所在队列摘除 PCB；② 若正在运行则立即剥夺 CPU；③ 撤销其所有子孙进程，资源归还父进程或系统；④ 撤销 PCB。

终止原因：正常结束（任务完成）、异常结束（越界、非法指令、除零等）、外界干预（用户强杀、父进程请求、操作系统介入）。

阻塞原语与唤醒原语

原语 状态转换 特点
block（阻塞） 运行 → 阻塞 进程主动调用；保存现场入 PCB，插入对应阻塞队列，转去调度其他进程
wakeup（唤醒） 阻塞 → 就绪 由事件相关方（完成 I/O 的中断处理程序、释放资源的进程等）调用；把 PCB 插入就绪队列

易错点：block 与 wakeup 必须成对使用——因某事件 block，就必须有对应方在该事件发生时 wakeup，否则进程永远阻塞。阻塞是主动的，唤醒是被动的（进程不能唤醒自己）。

原语对应的状态变化推演

原语 / 事件 状态变化 与 CPU 的关系
创建原语 Create （无）→ 创建态 → 就绪态 进就绪队列，未上 CPU
进程调度（分派） 就绪态 → 运行态 上 CPU
block 阻塞原语 运行态 → 阻塞态 让出 CPU（主动）
wakeup 唤醒原语 阻塞态 → 就绪态 只回就绪队列，不上 CPU
时间片到 / 被抢占 运行态 → 就绪态 让出 CPU（被动）
终止原语 Exit 运行/就绪/阻塞 → 终止态 → 撤销 回收资源、撤销 PCB

线程

为什么要引入线程

在仅有进程的系统中，进程同时扮演两个角色：拥有资源的独立单位 + 调度分派（上 CPU）的基本单位。于是进程的创建、撤销、切换都要付出巨大的时空开销：切换时要更换地址空间、整套保存/恢复 PCB 现场，系统不得不限制进程数目、减少切换频率，并发度上不去。

解决思路是把”资源分配“与”调度执行“两个属性分开：进程仍作资源分配单位，另引入更轻量的线程作调度单位。

线程：进程中的一条执行流（又称”轻量级进程”），是 CPU 调度和分派的基本单位。引入线程后：

  • 进程 = 资源分配的基本单位（拥有地址空间、打开文件等资源）
  • 线程 = 处理机调度的基本单位（只携带少量”执行现场”，轻装上阵）
  • 同一进程内的多个线程共享进程的资源；切换只换线程的少量现场 → 切换开销小、并发度高
  • 代价：一个线程崩溃（如非法访问内存）可能拖垮整个进程（共享的地址空间被破坏）

考点：进程是资源分配的基本单位，线程是 CPU 调度的基本单位——本章第一核心考点，反复以选择题形式出现。

线程的组成与 TCB

线程私有的部分：线程 ID、程序计数器 PC、寄存器集合（现场）、栈（保证独立执行流所必需）。系统为每个线程建立 TCB（线程控制块）作为线程存在的标志，记录线程 ID、所属进程、线程状态、优先级和现场信息；线程创建时建立 TCB，终止时撤销 TCB。

线程共享所属进程的：地址空间（代码段、数据段、堆）、全局变量、打开的文件表等”进程级”资源。

考点：“进程级”资源（地址空间、打开文件）全体线程共享；”执行级”现场（PC、寄存器、栈）各线程私有。同进程两线程切换不动 PCB、只换 TCB 现场——这就是线程切换快于进程切换的根本原因（不需要切换地址空间）。

用户级线程 vs 内核级线程

对比项 用户级线程（ULT） 内核级线程（KLT）
由谁管理 线程库在用户空间实现，内核看不到线程 操作系统内核负责创建、撤销、调度
内核调度对象 仍按进程调度 直接按线程调度
切换开销 小（不进内核、无模式切换） 大（须陷入内核，经模式切换）
一个线程阻塞时 同进程所有线程都被阻塞（内核把整个进程挂起等待） 只阻塞该线程，同进程其他线程仍可运行
多核利用 不能（内核感知不到线程，无法分派到多核） 可以（不同线程分配到不同 CPU 并行执行）
典型代表 早期 POSIX Pthreads 纯用户库、绿色线程 Windows 线程、Linux 线程（现代主流）

考点：线程几乎不拥有系统资源——只保留保证独立运行必需的少量私有物（TCB、PC、寄存器、栈），它所访问的资源都属于进程。判断题”线程同进程一样拥有资源”为错。
易错点：用户级线程”切换快”是优点，但”一个阻塞、全进程阻塞“与”无法利用多核”是它的两大硬伤——都源于内核根本不知道线程的存在。

多线程模型

用户级线程与内核级线程的连接方式称多线程模型。设用户级线程数 n、内核级线程数 m（n≥m）：

模型 映射关系 优点 缺点 / 适用
多对一（Many-to-One） n 个用户级线程 → 1 个内核级线程 线程管理全在用户空间，切换最快 一个阻塞全阻塞；不能利用多核
一对一（One-to-One） 每个用户级线程 → 1 个内核级线程 并行性最好；一个阻塞不影响其他线程 创建、切换都进内核，开销大；线程数受内核限制
多对多（Many-to-Many） n 个用户级线程 → m 个内核级线程（n≥m） 兼顾切换开销与并行能力 实现最复杂

考点：一对一模型是现代操作系统主流（Windows、Linux）；多对一继承了用户级线程的全部缺点；多对多结合两者优点，理论最优。

线程的共享资源与私有资源

类别 具体内容 说明
共享（进程级） 虚拟地址空间（代码段、数据段、堆）、全局变量、打开的文件表、子进程、信号处理方式 一线程修改，全线程可见
私有（线程级） 线程 ID、TCB、程序计数器 PC、寄存器组、栈（含错误码等执行现场） 保证各执行流互不干扰

易错点：栈是私有的——每个线程有自己的运行栈，共享的是堆与全局数据区；”同进程线程共享一切”的说法错误。PC、寄存器私有正是”一条独立执行流”的标志。

进程间通信（IPC）

进程的地址空间相互独立（存储保护），不能直接读写对方变量，必须借助操作系统提供的**进程间通信（IPC, Inter-Process Communication）**机制：共享内存、消息传递、管道、信号。

共享内存

在物理内存中划出一块共享存储区，通信双方把它映射进各自的地址空间，之后像访问自己的变量一样直接读写，不再经内核转发——因此共享内存是最快的 IPC 方式。

  • 低级通信：共享一个数据结构（如定长缓冲区），能传的数据量少，同步互斥要程序员自己写（如生产者-消费者）
  • 高级通信：共享一块存储区（如 mmap、shm），可灵活、大量地交换数据

易错点：”最快”的代价是同步互斥完全由用户进程自己保证——操作系统只提供共享区，不加同步的共享内存程序是错误的。与管道辨析：管道的数据要经内核”写进缓冲区 / 读出缓冲区”搬运，且伴随读写阻塞同步，速度不及共享内存。

消息传递

进程把数据组织成格式化消息（消息头 + 消息体），通过内核提供的 send / receive 原语收发，双方无需共享任何地址空间：

  • 直接通信：send 时指明接收进程的标识符，消息直接挂到接收进程的消息队列
  • 间接通信：消息发送到中间单元信箱（mailbox），接收方从信箱取消息——收发双方解耦，不必同时在场

考点：消息传递要经内核拷贝（发送方 → 内核缓冲区 → 接收方），速度慢于共享内存，但安全、同步简单，不要求共享空间，是网络 / 分布式系统通信的基础机制。

管道

管道（Pipe）：连接一个写进程和一个读进程的共享文件，本质是内核中一块固定大小的缓冲区，按**循环队列（FIFO）**组织：

  • 半双工：数据只能单向流动；需要双向传输时须设置两个管道
  • FIFO 字节流：先写入的先被读出；数据一旦读出就从管道中移除（读一次就没了）
  • 读写进程必须同时在场：管道数据不落盘，读写一方不在场，通信便无法进行
  • 同步互斥由内核自动保证：管道写满时写进程阻塞、读空时读进程阻塞；读写双方互斥访问管道
  • 命令行 ls | grep xxx 中的 | 就是管道：把 ls 的输出接到 grep 的输入（单向）

信号

信号（Signal）是一种异步事件通知机制：内核或进程向目标进程发送信号（如 SIGINT 对应 Ctrl+C、SIGKILL 强制终止、SIGSEGV 段错误），目标进程收到后作出响应：

  • 三种处理方式：执行进程注册的信号处理程序、执行系统默认动作、忽略
  • 信号异步到达（进程在任意时刻可被打断去处理），适合通知异常与紧急事件，不适合批量传数据

易错点：信号 ≠ 信号量——信号是异步事件通知机制；信号量是同步互斥工具（P/V 操作）。名字相近，机制完全不同。Ctrl+C 之所以能”随时打断”前台进程，就是内核向它投递了 SIGINT。

四种 IPC 方式对比

方式 传递载体 经内核转发 速度 同步互斥 要点 / 适用
共享内存 物理内存中的共享存储区 否（映射后直接读写） 最快 用户自己实现 大数据量、高频通信
消息传递 格式化消息（内核缓冲） 是（send/receive 原语） 较慢 内核原语保证 无共享空间；分布式系统
管道 内核缓冲区（FIFO 循环队列） 是（写入/读出搬运） 中等 内核自动（满/空阻塞、读写互斥） 半双工、单向字节流
信号 信号编号（事件通知） 是（内核投递） 不传数据 — 异步异常/事件通知

考点：问”最快的进程间通信方式”选共享内存（不经内核）；管道虽也用内存缓冲区，但要内核搬运且有读写同步，不是最快。问”双向通信”——管道需两个管道。

高频考点速记

考点 记忆
进程实体 进程 = PCB + 程序段 + 数据段；PCB 是进程存在的唯一标志（常驻内核、不可换出）
程序 vs 进程 静态 vs 动态（进程有生命周期）；一个程序可对应多个进程；动态性是最基本特征
基本单位 进程 = 资源分配的基本单位；线程 = CPU 调度的基本单位
五态转换 就绪 ⇄ 运行（调度选中 / 时间片到）；运行 → 阻塞（主动）；阻塞 → 就绪（被动唤醒）
不可能的转换 阻塞 → 运行不可能（须先回就绪队列）；就绪 → 阻塞不可能（未运行无法主动请求）
挂起 换出到外存、暂不参与调度；阻塞挂起 → 就绪挂起 →（激活）→ 就绪；挂起 ≠ 阻塞
原语 内核态、不可中断（关中断实现原子性）；block 与 wakeup 成对使用
PCB 内容 标识（PID/UID）+ 现场（PC/PSW/寄存器/栈指针）+ 调度（状态/优先级）+ 控制（资源清单、链接指针）
线程切换快的原因 同进程线程共享地址空间，切换不换地址空间，只换 TCB 中的 PC、寄存器、栈
ULT vs KLT ULT 内核不可见、切换快、一阻全阻、不能多核；KLT 可并行、切换须进内核
多线程模型 多对一（一阻全阻）/ 一对一（现代主流）/ 多对多（n≥m，兼顾优点）
线程共享 vs 私有 共享：地址空间、全局变量、打开文件；私有：TCB、PC、寄存器、栈
共享内存 最快的 IPC、不经内核转发、同步互斥用户自理
消息传递 直接（指明接收方 ID）/ 间接（信箱）；格式化消息经内核，适合分布式
管道 半双工 FIFO；读写进程必须同时在场；满/空阻塞；数据读出即删
信号 异步事件通知、由信号处理程序响应；信号 ≠ 信号量（后者是 P/V 同步互斥工具）
