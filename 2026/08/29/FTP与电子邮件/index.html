FTP与电子邮件

2026-08-29
  • 计算机网络

FTP（File Transfer Protocol，文件传输协议）是互联网上使用最广泛的文件传输协议；电子邮件（E-mail）则是互联网最早、最受欢迎的异步通信应用。两者都基于 C/S 模式、传输层都使用 TCP 可靠传输。408 对这部分考查集中在：FTP 的两条连接与主动/被动模式、邮件系统的三大组成、SMTP/POP3/IMAP 的端口与”推/拉”方向、MIME 与 SMTP 的局限。

FTP 文件传输协议

FTP 提供交互式的文件访问与传输，并能屏蔽不同计算机系统的差异（各系统文件格式、目录规则不同，由 FTP 统一处理），采用 C/S 模式：

  • 服务器进程 = 一个主进程（等待接收客户请求，负责分配工作）+ 若干从属进程（负责处理单个请求）
  • 主进程与从属进程并行工作，使 FTP 服务器可同时服务多个客户

FTP 最特殊的地方是使用两条并行的 TCP 连接——控制信息与文件数据分开传送，称为控制信息带外传送（out-of-band）。而 HTTP 的控制信息（请求行、首部行）与数据在同一连接上传送（带内）。

控制连接与数据连接

对比项 控制连接 数据连接
服务器端口 TCP 21 TCP 20（主动模式下）
传输内容 命令与应答（登录、切换目录、请求文件） 文件数据
建立时机 客户与服务器接触时（登录前） 每次有文件传输时
生命周期 整个会话期间始终保持 按需建立，文件传完立即关闭
数量 一次会话只有 1 条 每传一个文件建一条（可反复建立）

考点：FTP 用两条 TCP 连接——控制连接（21）全程保持、只传命令；数据连接（20）按需建立、只传文件，传完即关。21/20 是必背端口（配套记忆：DNS 53、SMTP 25、POP3 110、IMAP 143、HTTP 80、HTTPS 443）。
易错点：”控制信息带外传送”指控制信息不与文件数据共用一条连接——这是 FTP 区别于 HTTP 的典型特征。

注意：21 与 20 指的都是服务器端端口，客户机一律使用临时端口；进入被动模式后，服务器的数据端口不再是 20，而是它临时开放的随机端口。

主动模式与被动模式

两者的区别在于数据连接由谁发起：

对比项 主动模式（PORT） 被动模式（PASV）
数据连接发起方 服务器主动连接客户 客户主动连接服务器
服务器数据端口 固定 20 临时开放的随机高端口
过程 客户用 PORT 告知自己的数据端口 → 服务器从 20 端口连过去 客户发 PASV → 服务器告知临时端口 → 客户连过去
防火墙问题 外网服务器主动进内网，客户侧防火墙/NAT 常拦截 客户主动向外连，便于穿越防火墙
适用 客户机可直接被访问时 互联网上更常用

考点：主动模式”服务器从 20 端口主动连客户“，被动模式”客户主动连服务器的临时端口“；客户在防火墙后时应使用被动模式。
易错点：无论主动还是被动，控制连接始终由客户发起（连 21 端口）；变化的只是数据连接的发起方向。

FTP 与 TFTP 对比

对比项 FTP TFTP（简单文件传输协议）
传输层 TCP（控制 21 / 数据 20） UDP 69
功能 文件传输 + 登录认证 + 目录操作 仅简单文件传输，无认证、无目录浏览
典型场景 通用文件传输 无盘工作站启动、嵌入式设备升级

电子邮件系统

系统组成结构

电子邮件系统由三个组件构成：

组成 作用 例子
用户代理（UA, User Agent） 用户与邮件系统的接口：撰写、显示、处理邮件 Outlook、Foxmail、网页邮箱
邮件服务器 收发与暂存邮件：发送方服务器负责把邮件转发给接收方服务器；接收方服务器维护用户邮箱 163、QQ 邮箱服务器
邮件协议 发送（推）：SMTP；读取（拉）：POP3 / IMAP SMTP 25、POP3 110、IMAP 143

邮件传递必须经过邮件服务器中转（收件人 PC 不常在线、地址不固定），方向感要非常清楚：

考点：SMTP 只管”推”（发送/转发），POP3/IMAP 只管”拉”（读取）；收件人的邮件存放在接收方邮件服务器的邮箱里，而不是收件人电脑上。
易错点：服务器之间也用 SMTP（推）；用户代理只和自己一侧的邮件服务器打交道——发信把邮件推给发送方服务器，收信从接收方服务器拉取。

邮件格式与 MIME

一封邮件 = 信封 + 内容，内容又分首部 + 正文：

部分 内容 说明
信封（Envelope） 发件人、收件人地址 供 SMTP 传输时实际使用（对应 MAIL FROM / RCPT TO）
首部（Header） From、To、Subject、Date 等 供人阅读，可与信封地址不同
正文（Body） 邮件内容 与首部之间用空行分隔

SMTP 的三大局限：① 不能传送二进制对象（图片、可执行文件等）；② 只能传送 7 位 ASCII 码文本（中文、附件不行）；③ 拒绝过长的邮件。

MIME（Multipurpose Internet Mail Extensions，多用途互联网邮件扩展）是为解决上述局限对 SMTP 做的扩展（不是替代、也不新建协议），使邮件能携带非 ASCII 数据：

MIME 手段 内容
新增 5 个邮件首部 MIME-Version、Content-Description、Content-Id、Content-Type（内容类型）、Content-Transfer-Encoding（传输编码）
内容类型 Content-Type text/plain、text/html、image/jpeg、application/octet-stream、multipart/mixed
传输编码 Base64：二进制按 6 位一组映射为 ASCII 字符；Quoted-Printable：少量非 ASCII 字节写成 =XX 形式

考点：SMTP 端口 25、只能传 7 位 ASCII 文本；MIME 负责”编码/解码”——发送方把非 ASCII 内容编码成 ASCII 再交 SMTP 传输，接收方解码还原。
易错点：MIME 不替代 SMTP，只是 SMTP 的辅助与扩展；传图片、中文邮件的完整说法是”MIME 编码后仍由 SMTP 传送“。

SMTP 与 POP3

SMTP（Simple Mail Transfer Protocol，简单邮件传输协议）：C/S 模式，TCP 25，通信分建立连接、邮件传送、连接释放三个阶段：

  • 发送方邮件服务器的 SMTP 客户进程与接收方邮件服务器的 SMTP 服务器进程直接建立 TCP 连接，不使用任何中间邮件服务器
  • 若接收方服务器暂时故障，发送方服务器把邮件放入缓存队列，稍后重试
  • MAIL 命令中给出的发件人地址兼作回复路径——邮件无法投递时，差错报告沿回复路径退回发件人

一次完整 SMTP 会话演示（A 的发送方服务器向 B 的接收方服务器投递邮件）：

SMTP 常用命令 作用 常见应答 含义
HELO 向服务器标识发送方 220 服务就绪（TCP 连接建立后）
MAIL FROM: 发件人地址 指定信封发件人（回复路径） 250 命令完成
RCPT TO: 收件人地址 指定信封收件人 354 可以输入邮件内容
DATA 传送正文，以单独一行”.”结束 221 同意关闭连接

POP3（Post Office Protocol v3，邮局协议第 3 版）：C/S 模式，TCP 110，用户代理从接收方服务器拉取邮件到本地，”下载并管理“（下载后服务器上可删除也可保留），适合离线阅读：

POP3 常用命令 作用
USER / PASS 用户名 / 口令（鉴别阶段）
STAT 查询邮箱状态（邮件数、字节数）
LIST 列出各邮件的编号与大小
RETR n 取回第 n 封邮件
DELE n 标记删除第 n 封（QUIT 后才真正删除）
QUIT 结束会话（确认删除操作）

IMAP（Internet Message Access Protocol，网际报文存取协议，TCP 143）：邮件始终保留在服务器上，可在服务器端建文件夹、标记已读/未读，多设备同步方便（一句话：POP3 下载到本地管理，IMAP 留在服务器上管理）。

SMTP vs POP3 vs IMAP 对比：

对比项 SMTP POP3 IMAP
端口 TCP 25 TCP 110 TCP 143
方向 推（发送/转发） 拉（读取） 拉（读取）
使用场合 UA→服务器、服务器→服务器 服务器→UA 服务器→UA
邮件去向 一路推到接收方服务器邮箱 下载到本地，服务器可删可留 保留在服务器，服务器端管理
特点 只能 7 位 ASCII，靠 MIME 扩展 离线阅读，多设备难同步 多设备同步、在线操作邮件夹

例题：邮件收发全链路——A（a@163.com）给 B（b@qq.com）发一封带图片的邮件，写出全过程的协议与端口：

步骤 位置 协议 端口 说明
① A 的 UA → 发送方邮件服务器 SMTP（推） 25 图片先经 MIME 编码，邮件推给 smtp.163.com，放入发送队列暂存
② 发送方服务器 → 接收方服务器 SMTP（推） 25 两个邮件服务器直接建立 TCP 连接推送；邮件存入 B 的邮箱
③ B 的 UA → 接收方邮件服务器 POP3（拉） 110 B 用 USER/PASS 登录，RETR 取回邮件，UA 用 MIME 解码还原图片

追问：为什么取邮件用 POP3，而不用 SMTP？

  • 方向相反：SMTP 是推（push）协议，由发送方发起，把邮件”推”向接收方；读信时数据要从服务器流向用户，必须由用户发起，即**拉（pull）**协议。
  • SMTP 只定义了发送与转发功能，没有”打开邮箱、挑选、读取、删除邮件”的操作（POP3 有 USER/PASS 鉴别与 RETR/DELE 等命令）。
  • 若靠服务器主动把邮件”推”给收件人：收件人 UA 不常在线、无固定 IP 地址，服务器根本无法主动投递——所以邮件必须先存进接收方服务器的邮箱，等用户用 POP3/IMAP 来拉。

考点：一封跨服务器邮件最多用到 2 次 SMTP + 1 次 POP3/IMAP；服务器之间永远用 SMTP，”服务器→用户”才用 POP3/IMAP。

高频考点速记

考点 记忆
FTP 传输层 TCP；C/S 模式，主进程 + 从属进程并行服务多个客户
FTP 两条连接 控制连接 21（全程保持、带外传命令）+ 数据连接 20（按需建立、传完即关）
主动模式 PORT 客户用 PORT 报端口，服务器从 20 端口主动连客户
被动模式 PASV 服务器开临时端口，客户主动连服务器，便于穿越防火墙
TFTP UDP 69，简单文件传输，无认证、无目录操作
邮件系统三大组成 用户代理 UA + 邮件服务器 + 邮件协议（SMTP 发、POP3/IMAP 收）
邮件格式 信封（SMTP 实际使用）+ 首部（供人读）+ 正文，首部与正文空行分隔
SMTP TCP 25，只管推；只能 7 位 ASCII；服务器间直接传输、不用中间服务器；有回复路径
MIME SMTP 的扩展：新增 5 个首部 + Content-Type + Base64 / Quoted-Printable 编码
POP3 TCP 110，拉：下载到本地（可删可留），适合离线阅读
IMAP TCP 143，邮件留在服务器管理，多设备同步
推 vs 拉 发送与转发用 SMTP（推）；读取只能用 POP3/IMAP（拉）
全链路口诀 UA→服务器 SMTP，服务器→服务器 SMTP，服务器→UA POP3/IMAP
