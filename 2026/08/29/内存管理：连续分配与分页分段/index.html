内存管理：连续分配与分页分段

2026-08-29
  • 操作系统

内存管理要解决的根本问题是：程序按逻辑地址（从 0 开始相对编址）编写，CPU 却必须按物理地址访存，中间靠地址变换打通；操作系统还要在多个进程之间分配与回收内存、做内存保护、支持内存共享。408 对这部分基础内容（虚拟内存另行成文）的考查集中在：连续分配（单一连续、固定分区、动态分区与 FF/BF/WF 算法）、基本分页（页表、地址变换、快表 TLB、二级页表）、基本分段（段表、两次越界检查）、分页 vs 分段对比、段页式。

逻辑地址与物理地址

对比项 逻辑地址 物理地址
别名 相对地址、虚地址 绝对地址、实地址
编号起点 从 0 开始（程序内相对编址） 从 0 开始（内存单元真实编址）
空间大小由谁决定 CPU 地址位数（32 位 → 232 = 4GB） 内存条容量
使用者 程序员、编译器、链接器 CPU 访存（送入 MAR 的地址）

易错点：逻辑地址空间大小 ≠ 物理内存大小——32 位系统逻辑空间恒为 4GB，实际装机可能是 2GB；两者互不相干，这也是后面虚拟内存能”逻辑扩充”的基础。

地址重定位（地址变换、地址映射）：把逻辑地址转换为物理地址的过程，由 MMU（存储管理单元） 硬件配合操作系统完成。按转换时机分为绝对装入、静态重定位、动态重定位三种装入方式（详见《操作系统概述》一文）。现代操作系统采用动态重定位：装入时不转换，运行时每次访存由重定位寄存器（基址寄存器）动态相加，进程因此可移动、可换出换入，也为”紧凑”操作提供了前提。

内存保护

目标：各进程只能访问自己的内存区域，越界即产生越界中断。两种硬件机制：

实现方式 寄存器存放内容 判别流程 判别对象
上下限寄存器 上限地址 + 下限地址 检查 下限 ≤ 地址 ≤ 上限 物理地址
重定位寄存器 + 界地址寄存器 重定位寄存器存起始地址（基址）；界地址寄存器存最大逻辑地址（限长） 先判 逻辑地址 < 界地址寄存器，再加基址得物理地址 逻辑地址

考点：重定位寄存器管”起址”、界地址寄存器管”限长”——物理地址 = 逻辑地址 + 重定位寄存器；逻辑地址 ≥ 界地址寄存器则越界中断。
易错点：两种方案判别的对象不同——上下限方案判的是物理地址，”重定位 + 界地址”方案先判逻辑地址再变换；这些寄存器只能由操作系统（内核态、特权指令）修改，用户程序改不了。

内存共享

只有只读的”可重入代码（纯代码）”区域才能被共享。分段共享更容易——段是完整的逻辑单位（如整个代码段），各进程段表项指向同一物理段即可；分页共享困难——页只是物理切块，一个逻辑功能可能被切进多页，且每个进程都要维护自己的页表。

连续分配管理方式

连续分配：为进程分配一整段地址连续的内存空间。三种方式：

方式 划分方法 碎片 支持道数 管理结构
单一连续分配 内存分系统区 + 用户区，一次只装一道 内部碎片（用户区剩余） 单道 无需复杂结构
固定分区分配 用户区预先划分为固定大小分区（可相等、不等），每区一道 内部碎片（分区内剩余）、无外部碎片 多道 分区说明表
动态分区分配 不预先划分，装入时按作业大小动态划 外部碎片（分区之间）、无内部碎片 多道 空闲分区表 / 空闲分区链

考点：固定分区”个数、大小都固定”，作业装不满分区就产生内部碎片；动态分区”要多少给多少”，没有内部碎片，但反复分配回收后内存被切成外部碎片。

动态分区分配与回收

  • 数据结构：空闲分区表 / 空闲分区链，记录每个空闲分区的起始地址、大小。
  • 外部碎片解决：紧凑（Compaction，拼接）——移动已分配分区，把零散空闲区拼成大块。紧凑要求动态重定位支持（分区移动后改基址寄存器即可），且开销大，不能频繁做。
  • 回收：看回收区的上邻、下邻是否空闲——都空闲则三区合并；仅一邻空闲则并入该邻；都不空闲则单独登记为新空闲分区。

内部碎片 vs 外部碎片（重点）

分配方式 内部碎片 外部碎片 说明 / 解决
单一连续分配 有 无 用户区装不满的部分
固定分区 有 无 分区内装不满的部分
动态分区 无 有 分区之间的小空隙 → 紧凑
分页 有（页内） 无 只有最后一页装不满，平均约半页
分段 无 有 段间空隙 → 紧凑
段页式 有（页内） 无 段内以页离散分配

考点：判碎片归属先看”分配单位”——按固定单位切（固定分区、分页、段页式）→ 内部碎片；按需分配但要求连续（动态分区、分段）→ 外部碎片。
易错点：动态分区”无内部碎片”不等于”无浪费”，外部碎片总和可能很可观；分页的内部碎片只出现在最后一个页面（前面的页都装满）。

动态分区分配算法

算法 空闲分区排列 分配策略 特点
首次适应 FF 地址递增 从头找第一个够用的分区 综合性能通常最好：低地址先用，高地址保留大块、查找快；低地址端易积小碎片
最佳适应 BF 容量递增 找最小的够用分区 每次”最省”，但产生大量难以利用的小碎片（外部碎片最多）
最坏适应 WF 容量递减 找最大的分区 切剩部分仍较大，后续中小作业易装入；但大分区被切碎，大作业反而可能装不下
就近适应 NF 地址循环 从上次分配位置继续向后找 查找开销小、空闲区分布均匀；高地址大分区易被切碎

考点：首次适应综合性能最好，是最常用算法；BF 是”选最小的能满足的分区”（不是选最小的分区），WF 反之。
易错点：三种算法都要求空闲分区表有序（FF/NF 按地址递增、BF 按容量递增、WF 按容量递减），每次分配回收后要重新维护顺序。

动态分区分配例题

系统用户区 100KB（地址 0~100K），作业时序如下：

① J1 申请 25KB → ② J2 申请 30KB → ③ J3 申请 25KB → ④ J1 完成，释放 25KB → ⑤ J4 申请 15KB → ⑥ J5 申请 10KB → ⑦ J6 申请 12KB

前 ④ 步始终只有一个空闲分区，三种算法动作一致：

步骤 操作 选中分区 操作后空闲分区
初始 — — [0~100K]：100KB
① J1 申请 25KB 100KB 块 [25~100K]：75KB
② J2 申请 30KB 75KB 块 [55~100K]：45KB
③ J3 申请 25KB 45KB 块 [80~100K]：20KB
④ J1 释放 25KB 下邻 J2 不空闲，单独登记 [0~25K]：25KB；[80~100K]：20KB

第 ⑤ 步起空闲分区不止一块，三种算法开始分化：

首次适应 FF（按地址递增，从头找第一个够用的）：

步骤 操作 命中分区 操作后空闲分区
⑤ J4 申请 15KB 25KB 块（地址最靠前） [15~25K]：10KB；[80~100K]：20KB
⑥ J5 申请 10KB 10KB 块（恰好装满） [80~100K]：20KB
⑦ J6 申请 12KB 20KB 块 [92~100K]：8KB，J6 装入成功

最佳适应 BF（按容量递增，选最小够用的）：

步骤 操作 命中分区 操作后空闲分区
⑤ J4 申请 15KB 20KB 块（20K < 25K，最小够用） [0~25K]：25KB；[95~100K]：5KB
⑥ J5 申请 10KB 25KB 块（5KB 不够用） [10~25K]：15KB；[95~100K]：5KB
⑦ J6 申请 12KB 15KB 块 [22~25K]：3KB；[95~100K]：5KB，成功但剩两块小碎片

最坏适应 WF（按容量递减，选最大的）：

步骤 操作 命中分区 操作后空闲分区
⑤ J4 申请 15KB 25KB 块（最大） [15~25K]：10KB；[80~100K]：20KB
⑥ J5 申请 10KB 20KB 块（最大） [15~25K]：10KB；[90~100K]：10KB
⑦ J6 申请 12KB 无 ≥12KB 的空闲分区 分配失败，J6 等待

三算法结果对比：

算法 最终内存布局（0~100K） 外部碎片 J6(12KB) 结果
首次适应 J4(15K)、J5(10K)、J2(30K)、J3(25K)、J6(12K) 依次排布 8KB（1 块） ✅ 装入成功
最佳适应 J5(10K)、J6(12K)、空闲3K、J2(30K)、J3(25K)、J4(15K)、空闲5K 3KB + 5KB（2 块） ✅ 成功，但碎片更碎
最坏适应 J4(15K)、空闲10K、J2(30K)、J3(25K)、J5(10K)、空闲10K 10KB + 10KB（2 块） ❌ 失败，等待

验算：FF 已分配 15+10+30+25+12 = 92KB + 空闲 8KB = 100KB ✓；BF 已分配 10+12+30+25+15 = 92KB + 3KB + 5KB = 100KB ✓；WF 已分配 15+30+25+10 = 80KB + 10KB + 10KB = 100KB ✓

考点：WF 把 100KB 大块逐步切碎，连 12KB 的 J6 都进不了——“切剩的还大”只对中小作业短期友好；BF 留下的 3KB、5KB 碎片很难再利用；FF 碎片最少且全部装入，印证”首次适应综合性能最好”。

基本分页存储管理

引入动机：连续分配必有碎片——内部碎片浪费分区、外部碎片要靠开销大的紧凑解决。分页把进程逻辑空间和物理内存都切成等大的块，进程的页可以离散放进任意空闲页框——物理上离散、逻辑上连续，从根源上消灭外部碎片（只剩很小的页内碎片）。

页面、页框与页表

概念 定义
页面（页 Page） 进程逻辑地址空间等分出的块，大小为 2 的整数次幂（通常 4KB）
页框（页帧、物理块 Frame） 物理内存等分出的块，大小与页面相同
页表（Page Table） 记录页号 → 页框号映射，每个进程一张，存放在内存中

基本分页的页表项主体就是页框号；扩展到请求分页时再增加访问位、修改位等状态字段（详见虚拟内存一文）。

地址结构与基本地址变换

逻辑地址被硬件自动拆成两部分，程序员无感、程序仍从 0 连续编址——所以分页是一维地址：

关键公式（页面大小 = 2m）：

  • 页内偏移占低 m 位：4KB → m=12 位；1KB → m=10 位
  • 页号位数 = 逻辑地址总位数 − m
  • P=⌊逻辑地址/页面大小⌋；W=逻辑地址mod页面大小

基本地址变换流程（页表寄存器 PTR 存放页表始址 + 页表长度）：

① 拆分：硬件按位拆出页号 P、页内偏移 W
② 越界检查：P ≥ 页表长度 → 越界中断
③ 查页表（访存一次）：到 页表始址 + P × 页表项大小 处取页框号 F
④ 拼接：物理地址 = F × 页面大小 + W

物理地址=页框号×页面大小+页内偏移

考点：无快表时访问一个数据要 2 次访存——① 查页表、② 取数据，速度几乎减半，这是分页的主要缺点，用快表缓解。

分页地址变换例题

某系统按字节编址，页面大小 1KB（210），某进程共 4 页（逻辑地址 12 位），页表如下：

页号 0 1 2 3
页框号 5 10 8 12

求逻辑地址 2500 的物理地址。

第一步 拆分：1KB = 210 → 低 10 位是页内偏移，其余高位是页号。

2500 = 2048 + 452 = 100111000100₂

除法验证：P=⌊2500/1024⌋=2，W=2500mod1024=452 ✓

第二步 查页表：页 2 → 页框号 8。

第三步 拼接：页框号 8 = 0000001000₂（10 位），与偏移直接拼接：

十进制验算：$8 \times 1024 + 452 = 8192 + 452 = $ 8644 ✓

方法：页面大小是 2n 时，低 n 位就是偏移、高位就是页号——二进制/十六进制地址直接按位拆，十进制地址用除法拆；物理地址是页框号与偏移的拼接（千万别用页号相加）。

快表 TLB

页表在内存中，每次访存都要先访存查页表。快表（TLB, Translation Lookaside Buffer）是一组相联存储器（按内容并行查找的高速硬件缓存，不是按地址存取），存放最近访问过的页表项；变换时快表与慢表（内存页表）同时开始查，快表命中则直接取页框号。

情况 访存次数 说明
快表命中 1 次（直接取数） 页表项在 TLB 中
快表未命中 2 次（查页表 + 取数） 并把该页表项装入快表（满了按替换策略淘汰）

有效访问时间 EAT（命中率 a，一次访存耗时 t，快表查询时间忽略）：

EAT=a×t+(1−a)×2t=(2−a)t

例：t = 100ns、a = 90%：EAT = 0.9 × 100 + 0.1 × 200 = 110ns（无快表恒为 200ns）。若快表查询耗时 ttlb​ 不可忽略，则 EAT=a(ttlb​+t)+(1−a)(ttlb​+2t)——命中与未命中都含快表查询时间。

考点：快表能生效靠局部性原理（最近访问的页很快会再访问）；快表是硬件，慢表是内存中的数据结构。
易错点：刚开机或进程切换后快表失效，首次访问某页仍是 2 次访存；快表命中时慢表查询虽然也启动了，但结果作废，不算访存。

两级页表

单级页表的两个问题（32 位逻辑地址、4KB 页面、4B 页表项）：

  1. 页表太大：页号 20 位 → 220 项 × 4B = 4MB，每个进程一张；
  2. 页表必须连续存放、且整个常驻内存——给 4MB 找连续空间，本身就违背了分页”离散存放”的初衷。

两级页表：把 20 位页号再拆成页目录号（一级，高 10 位）+ 二级页号（低 10 位）：

  • 页目录表（外层页表）：210 项 × 4B = 4KB，表项存页表始址，常驻内存；
  • 每张二级页表：210 项 × 4B = 4KB，可离散存放，且可只调入用到的页表。

考点：多级页表不减少页表项总数（反而多出页目录），它解决的是”页表本身也要能离散存放、按需调入“的问题；代价是无快表时访存 3 次（页目录 → 页表 → 数据），每多一级多一次访存。
易错点：各级页表大小不能超过一个页面——每级页表项数 ≤ 页面大小 ÷ 页表项大小，页号按此位数逐级切分；页目录表必须常驻内存。

二级页表例题

32 位逻辑地址、按字节编址、页面 4KB、页表项 4B，采用两级页表，按 10 / 10 / 12 拆分：

字段 位数 作用
一级页号（页目录号） 10 查页目录表 → 得页表始址
二级页号 10 查二级页表 → 得页框号
页内偏移 12 4KB = 212
  • 每张页表的项数 = 页面大小 ÷ 页表项大小 = 4KB ÷ 4B = 210=1024 项 → 每张页表恰好 4KB（正好装进一个页框）
  • 页目录项数 = 210=1024 项，页目录表大小 = 1024 × 4B = 4KB（也恰好一页，常驻内存）
  • 进程最多 220 个页面 → 最多需要 1024 张二级页表
  • 访存次数：无快表 3 次；快表命中 1 次

为什么引入二级页表？ 单级页表 4MB 且要求连续存放 + 全部常驻内存；拆成两级后，页表本身以 4KB 为单位离散存放、按需调入，常驻的只剩 4KB 页目录——用多一次访存的代价，换来”大页表也能像普通页面一样被分页管理”。

基本分段存储管理

动机：分页按物理大小切块，与程序逻辑结构无关；而程序天然按模块组织（主程序段、子程序段、数据段、栈段、共享段）。分段按逻辑模块划分：段长由程序决定、各段不等，对程序员可见（编程时必须显式给出段号）——逻辑地址是二维的：段号 S + 段内偏移 W。

段表与分段地址变换

段表：每个进程一张，表项 = 段基址（段在内存的起始地址）+ 段长——段长不等，必须记录段长做越界检查。

变换流程（段表寄存器存段表始址 + 段表长度）：

① 越界检查一：S ≥ 段表长度 → 越界中断（段号越界）
② 查段表（访存一次）：得段基址 B、段长 L
③ 越界检查二：W ≥ L → 越界中断（段内偏移越界）
④ 相加：物理地址 = B + W

考点：分段有两次越界检查（段号、段内偏移），分页只有一次（页号）；分段物理地址 = 基址 + 偏移（相加），分页 = 页框号拼接偏移——根源是段长不固定、页长固定。

段式地址变换例题

段表如下（段表长度为 4，即段号 0~3）：

段号 基址 段长
0 210 500
1 2350 20
2 100 90
3 1350 590
逻辑地址 判断过程 结果
(0, 430) 0 < 4 且 430 < 500 → 210 + 430 640
(2, 88) 2 < 4 且 88 < 90 → 100 + 88 188
(3, 600) 600 ≥ 590（段长） 越界中断
(4, 10) 段号 4 ≥ 段表长度 4 越界中断

分段的共享与保护

  • 共享：多个进程的段表项指向同一物理段即可（各进程可用不同段号访问）；共享段必须是可重入代码，并配引用计数（减到 0 才回收）。段是完整逻辑单位，所以分段共享比分页容易。
  • 保护：两次越界检查天然提供保护，段表项还可设只读 / 只执行 / 读写存取权限——分页只有一次页号检查，保护能力弱。

分页 vs 分段（重点对比）

对比项 分页 分段
划分依据 物理划分，页大小固定（2 的幂，系统定） 逻辑划分，段长不固定（程序决定）
地址维度 一维（一个数即可定位，硬件自动拆分） 二维（必须显式给出段号 + 段内偏移）
对程序员 透明（不可见） 可见
表项内容 页框号（+ 状态位） 基址 + 段长
越界检查 1 次（页号 ≥ 页表长度） 2 次（段号、偏移 ≥ 段长）
碎片 页内碎片（内部碎片） 外部碎片（段间，可紧凑）
共享 / 保护 困难 / 弱 容易 / 强
物理地址 页框号 × 页面大小 + 偏移（拼接） 基址 + 偏移（相加）
出发点 提高内存利用率（系统需要） 方便编程、共享、保护（用户需要）

考点：一句话——分页是系统视角（一维、透明、仅页内碎片），分段是用户视角（二维、可见、共享保护方便）；”一维/二维、透明/可见、拼接/相加”三组词是选择题常客。

段页式存储管理

思想：先按逻辑模块分段（用户可见），段内再按固定大小分页（系统透明）——用户享受分段的共享与保护，系统利用分页消灭外部碎片。

  • 逻辑地址三维：段号 S / 段内页号 P / 页内偏移 W
  • 每个进程一张段表：表项 = 该段的页表始址 + 页表长度（不是基址！）
  • 每段一张页表：表项 = 页号 → 页框号；一个进程的页表数 = 它的段数
  • 段以页为单位离散存放：无外部碎片、只有页内碎片

段页式地址变换

① S ≥ 段表长度？越界中断 → 查段表得页表始址、页表长度
② P ≥ 页表长度？越界中断 → 查页表得页框号 F
③ 拼接：物理地址 = F × 页面大小 + W

无快表 3 次访存（查段表 → 查页表 → 取数）；快表命中则降为 1 次。

页式、段式、段页式访问过程对比

对比项 页式 段式 段页式
逻辑地址结构 页号 + 偏移（一维） 段号 + 偏移（二维） 段号 + 页号 + 偏移（三维）
表结构 页表（→页框号） 段表（→基址 + 段长） 段表（→页表始址 + 页表长）+ 页表
越界检查次数 1 次 2 次 2 次（段号、页号）
无快表访存次数 2 次 2 次 3 次
快表命中访存 1 次 1 次 1 次
碎片 页内碎片 外部碎片 页内碎片
共享难易 难 易 易（按段共享其页表）

考点：段页式的段表项是”页表始址 + 页表长度“而非段基址——段已被切成页离散存放，不存在连续的”基址”。
易错点：段页式 = 分段 + 分页，但访存 3 次不是 2+2=4 次；它与二级页表（也是 3 次访存）的区别在于：段页式先查段表且对用户可见，二级页表两级都是页号、对用户透明。

高频考点速记

考点 记忆
逻辑地址 vs 物理地址 逻辑空间由 CPU 位数定（32 位 → 4GB），物理空间由内存容量定
内存保护 上下限寄存器判物理地址；重定位寄存器管起址、界地址寄存器管限长，先判逻辑地址再加基址
碎片归属 单一连续/固定分区/分页/段页式 → 内部碎片；动态分区/分段 → 外部碎片（紧凑解决）
分页内碎片 只产生在最后一个页面，平均约半页
动态分区算法 FF 按地址第一个够用（综合最佳）；BF 最小够用（小碎片多）；WF 最大（切碎大分区、中小作业友好）；NF 从上次继续；紧凑仅适用于动态重定位
页 / 页框 页面 = 逻辑等分块，页框 = 物理等分块，大小相同（2 的幂）；页表每进程一张
地址拆分 页面 2n → 低 n 位为偏移；P=⌊A/页面大小⌋，W=Amod页面大小
物理地址 页式 = 页框号 × 页面大小 + 偏移（拼接）；段式 = 基址 + 偏移（相加）
访存次数 无快表 2 次；TLB 命中 1 次；二级页表 / 段页式 3 次（每多一级多一次）
快表 TLB 相联存储器（按内容并行查找的硬件）存最近页表项，与慢表同时查；EAT=at+(1−a)⋅2t
二级页表 不减少页表项总数，让页表离散存放 + 按需调入；各级页表 ≤ 1 页（项数 ≤ 页面大小 ÷ 表项大小）；32 位按 10/10/12 拆
段表项 段式 = 基址 + 段长；段页式 = 页表始址 + 页表长度
分段越界 两次检查：段号 ≥ 段表长度、偏移 ≥ 段长
分页 vs 分段 分页物理划分、一维、透明、页内碎片、共享难；分段逻辑划分、二维、可见、外部碎片、共享易
段页式 先分段再分页；每进程一张段表、每段一张页表；逻辑地址三维；3 次访存
内存共享 共享段 = 可重入代码 + 引用计数；分段共享比分页容易（段是完整逻辑单位）
