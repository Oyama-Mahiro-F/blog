IP组播与移动IP

2026-08-29
  • 计算机网络

单播是一对一，广播是一对所有，而 **IP 组播（Multicast，多播）**介于两者之间——一对一组：源主机只发出一份数据报，由组播路由器在分叉处复制转发，让加入该组的多台主机同时收到。移动 IP（Mobile IP）则解决另一个问题：主机从一个网络移动到另一个网络后，如何不改 IP 地址仍能被找到并继续通信。408 对这两部分考查集中且套路固定：D 类地址、组播 MAC 映射（低 23 位）、IGMP、永久地址/转交地址、HA/FA 与三角路由。

IP 组播

组播的概念

IP 组播：源主机只发送一份数据报，目的地址是一个组地址（标识一组主机，而非某台主机），组播路由器在转发路径的分叉处复制分组，使组内每个成员各收到一份副本。这是一点对多点通信、节省网络带宽的有效方法。

使用组播的前提：

  • 主机和路由器都要运行组播软件，网络中要有能识别 D 类地址、执行复制转发的组播路由器；
  • 组播数据报同样只尽最大努力交付，不保证组内所有成员都能收到。

三种通信方式对比（重点）：

对比项 单播 Unicast 广播 Broadcast 组播 Multicast
通信模式 一对一 一对所有（限本网络） 一对一组
目的地址 单个主机的 IP 地址 广播地址（主机号全 1） D 类组地址（标识”组”而非主机）
分组复制 无复制（逐个发送 N 份） 无复制（链路上每台主机都收到） 路由器只在分叉路径复制
能否跨网络 可以 路由器隔离广播，不转发 可以（由组播路由选择协议转发）
带宽消耗 成员越多发送方负担越重 整个网内所有主机都被打扰 只向有成员的分支发一份，最省
典型应用 普通 Web / FTP ARP 请求、DHCP 发现 视频会议、IPTV、股票行情

考点：组播省带宽的关键是路由器只在分叉路径复制分组——给 N 个成员发送，源端也只需发一份；而单播要发 N 份。
易错点：组播的目的地址标识的是组，不是某台主机；路由器不转发广播，但会转发组播（只向存在组成员的接口转发）。

IP 组播地址（D 类）

D 类地址专用于组播：前 4 位 1110，范围 224.0.0.0~239.255.255.255；去掉 1110 前缀后剩 28 位组号，理论上可标识 228 个组播组。

项目 说明
范围 224.0.0.0~239.255.255.255（第一字节 224~239，前缀 1110）
组号 28 位（1110 之外的其余位）
用途 只能作目的地址，标识一个组播组
分配 不指派给单台主机；作源地址是错误的
交付方式 尽最大努力交付，不保证全部成员收到

组播地址分永久组播地址（IANA 指派、全球通用、永远存在）与临时组播地址（临时创建、组成员动态变化，须 IGMP 维护）：

永久组播地址 含义
224.0.0.1 本子网（同一局域网）内所有主机系统
224.0.0.2 本子网内所有路由器系统
224.0.0.5 / 224.0.0.6 OSPF 中所有运行 OSPF 的路由器 / 指定路由器 DR

考点：224.0.0.1 与 224.0.0.2 最常考——前者代表全部主机、后者只代表路由器；永久组播地址不需 IGMP 维护成员关系（永远存在），临时组才动态变化。
易错点：D 类地址只能作目的地址、不能作源地址；D 类也不像 A/B/C 类那样”减 2”——它不指派给单台主机，没有网络号/主机号之分。

组播 MAC 地址映射（重点）

在以太网上传送组播数据报时，还要把 IP 组播地址（软件组播）映射为组播 MAC 地址（硬件组播），帧才能在局域网内被组内主机接收：

组播 MAC 地址构成 位段
高 24 位固定 01-00-5E
第 25 位 恒为 0
低 23 位 取自 D 类地址的最低 23 位

映射演算例：求 224.128.0.7 的组播 MAC 地址。

映射不完备（必考易错）：D 类地址有 28 位组号，组播 MAC 只装得下 23 位，被丢弃的正是组号的高 5 位——因此 25=32 个 IP 组播地址会映射到同一个组播 MAC 地址（如 224.0.0.7 与 224.128.0.7 都映射为 01-00-5E-00-00-07）。

  • 网卡按组播 MAC 地址收下帧后，主机还要在网际层利用软件过滤：用帧中数据报的完整 D 类地址与本机加入的组比较，不匹配则丢弃；
  • 所以两个组即使 MAC 相同（如 224.0.0.7 与 224.128.0.7），同一局域网内另一组主机的网卡会”误收”对方的帧，但 IP 层过滤后不会误交付。

考点：组播 MAC = 01-00-5E + D 类地址低 23 位；32 个 IP 组播地址对应同一个 MAC 地址。
易错点：映射不唯一的根源是组号 28 位 vs MAC 只取 23 位（组号高 5 位被丢弃）；”误收”的帧由 IP 层软件过滤，不是网卡丢弃。

IGMP

IGMP（网际组管理协议）是让本地组播路由器知道本局域网内有哪些主机加入/退出组播组的组管理协议，它使用 IP 数据报传递（IPv4 首部协议字段 = 2），与 ICMP 一样属于 IP 层的附属协议；IGMP 只管理本地的组成员关系，组播分组在全网如何转发则由组播路由选择协议解决。

移动 IP

移动 IP 的概念

移动 IP 的目标：移动主机从归属网络（永久持有的网络）漫游到外地网络后，不必修改其永久 IP 地址，仍能被通信对端找到并保持通信（TCP 连接不中断）。为此需要三种地址、两个代理：

术语 英文 作用
永久地址（归属地址） HoA, Home Address 移动主机在归属网络中长期使用的 IP 地址，通信对端始终用它寻址
转交地址 CoA, Care-of Address 移动主机在外地网络获得的临时地址，供 HA 隧道投递分组用
归属代理 HA, Home Agent 归属网络中代表移动主机的路由器：截获发往永久地址的分组，隧道转发到 CoA
外地代理 FA, Foreign Agent 外地网络中帮助移动主机的路由器：提供转交地址、拆封隧道分组并交付移动主机

转交地址的两种形式：

形式 说明
外地代理转交地址 直接用 FA 的 IP 地址作 CoA，同一外地网络的多台移动主机可共用
配置转交地址 通过 DHCP 等临时获得一个外地网络自己的 IP 地址，直接配置在移动主机接口上

移动 IP 的通信过程

移动 IP 通信分三大步骤：

  1. 代理发现：移动主机进入外地网络时，接收 FA/HA 周期性广播的代理通告报文（基于 ICMP 路由器通告扩展），从而获得转交地址 CoA（也可主动发送代理请求报文）。
  2. 注册：移动主机（一般经 FA 中转）向 HA 注册 CoA；HA 在其归属表中记录”永久地址 ↔ 转交地址“的映射。
  3. 隧道转发：数据通信阶段，HA 把发往永久地址的分组封装成隧道分组发往 CoA，FA 拆封后交付移动主机。

各阶段 IP 数据报的源/目的地址（核心考点，逐行记忆）：

阶段 数据报 源地址 目的地址
对端 → 归属网络 原始数据报 对端 永久地址
HA → FA（隧道外层） 封装后的数据报 HA 转交地址 CoA
HA → FA（隧道内层） 原始数据报 对端 永久地址
FA → 移动主机 拆封后的原始数据报 对端 永久地址
移动主机 → 对端 普通数据报 永久地址 对端

三角路由（Triangular Routing）：对端发给移动主机的下行分组要绕道归属代理（对端 → HA → FA → 移动主机），而移动主机发给对端的上行分组直接发送、不经过 HA——去程与回程的路径构成三角形，这是间接路由方式的固有缺点（对端不知道移动主机的新位置）。

考点：隧道封装后外层目的地址 = 转交地址 CoA、外层源地址 = HA；FA 拆封后交付时内层目的地址 = 永久地址。
易错点：移动主机向外发送不经过隧道/HA（源地址仍填永久地址）；转交地址只是”投递中转”用的临时地址，通信对端始终只认永久地址。
