Cache与虚拟存储器

2026-08-29
  • 计算机组成原理

Cache（高速缓冲存储器）是位于 CPU 与主存之间的小容量高速 SRAM，依靠程序访问的局部性原理缓解 CPU 与主存的速度差距；虚拟存储器则把主存和辅存统一编址，由硬件（MMU）+ 操作系统配合，给程序员一个远大于实际主存的地址空间。两者一管速度、一管容量，是存储层次结构中并列的两级核心。408 对本部分的考查集中在：命中率与平均访问时间计算、三种映射方式的地址划分与计算、替换算法、写策略组合，以及 TLB 与 Cache 组合下的访存次数分析。

Cache 的基本工作原理

Cache 对程序员完全透明：CPU 只发出访存地址，由硬件自动判断该字是否已在 Cache 中。读一次数据的完整流程：

  1. CPU 送出访存地址，Cache 控制逻辑同时收到该地址
  2. 按映射方式选出待比较的行（或全部行），比较标记 + 有效位
  3. 命中：直接从 Cache 行取出该字送 CPU，结束
  4. 缺失：从主存读取该字送 CPU，同时把整个块调入 Cache（替换算法、写策略此时登场）
  • 命中（Hit）：要访问的字在 Cache 中 → 直接从 Cache 读取，不访问主存
  • 缺失（Miss）：字不在 Cache → 把包含该字的整个主存块调入 Cache（必要时淘汰一行），再从中取字
传送路径 传送单位 原因
CPU ↔ Cache 字 CPU 每次只请求一个字的指令/数据
Cache ↔ 主存 块（Block / Cache Line） 利用空间局部性，一次调入连续多个字

Cache 行的结构 = 有效位 + 标记（Tag）+ 数据：有效位为 1 表示该行数据可用；标记记录该行当前存放的是哪个主存块。Cache 能有效工作全靠局部性原理——时间局部性（刚访问过的数据很快再访问）、空间局部性（相邻数据将被访问），与虚拟存储器同出一源，原理详见《虚拟内存与页面置换算法》。

考点：Cache 缺失分三类——强制缺失（该块首次被访问，”冷启动”）、容量缺失（工作集超出 Cache 容量）、冲突缺失（映射方式导致多个块争用同一行）。
易错点：全相联映射没有冲突缺失；增大块大小主要利用空间局部性，但块太大会增加未用数据的调入开销。

命中率与平均访问时间

设 Nc​ 为命中次数、Nm​ 为缺失次数，命中率 H：

H=Nc​+Nm​Nc​​

平均访问时间有两种口径，做题前先看清题目假设：

口径 公式 含义
先后访问（默认，缺失才去访主存） Ta​=Ht1​+(1−H)t2​ 命中只花 t1​，缺失只花 t2​
同时访问（每次同时启动 Cache 和主存） Ta​=Ht1​+(1−H)(t1​+t2​) 缺失时主存时间叠加在 t1​ 之上

例题：命中率 H=0.95，Cache 存取时间 t1​=10 ns，主存存取时间 t2​=100 ns，求平均访问时间。

  • 先后口径：Ta​=0.95×10+0.05×100=9.5+5=14.5 ns
  • 同时口径：Ta​=0.95×10+0.05×(10+100)=9.5+5.5=15 ns

无论哪种口径，都远小于直接访主的 100 ns；命中率越高，平均访问时间越接近 Cache 速度。

易错点：题目说”Cache 与主存同时启动访问“必须用同时口径（缺失时 t1​+t2​）；无特殊说明一般按先后口径。另外注意 t2​ 有时给的是主存存取周期而非存取时间，读清题面再代入。

Cache 总容量（存储位，不含比较/控制逻辑）：

Cache 总容量=行数×(标记位数+数据位数+有效位)

回写法还要加脏位；带替换计数的还要加替换控制位。408 常考”给定主存/Cache 容量、块大小、映射方式，反推标记位数与 Cache 总容量”。

Cache 和主存之间的映射方式

映射方式决定主存块可以放进 Cache 的哪些行，直接影响命中率与硬件成本。主存地址的通用拆法（按字节编址）：

块内地址位数=log2​(块大小)，行号/组号位数=log2​(行数/组数)，标记位数=地址总位数−其余字段

直接映射

每个主存块只能放入唯一固定的一行：

Cache 行号=主存块号modCache 总行数

主存地址划分 = 标记 + Cache 行号 + 块内地址。访存时用行号直接选中一行，比较该行标记与地址高位标记、且有效位为 1 即命中——硬件只需 1 个比较器，最简单最快；代价是多个主存块轮流争用同一行、互相淘汰（抖动，冲突缺失多）。

例题：主存按字节编址，主存含 64 块、每块 16B；Cache 共 8 行，直接映射。求主存地址划分，并把主存地址 0110110010 定位到 Cache。

  1. 主存容量 = 64 × 16B = 1KB = 210B → 主存地址共 10 位
  2. 主存块号 6 位（64 = 26）；块内地址 = log2​16=4 位
  3. Cache 行号 = log2​8=3 位（块号 mod 8 = 取块号低 3 位）
  4. 标记 = 6 − 3 = 3 位
标记（3 位） Cache 行号（3 位） 块内地址（4 位）
011 011 0010

地址 0110110010 的定位演算：

  • 拆分：标记 = 011，行号 = 011，块内地址 = 0010（块内第 2 字节）
  • 行号 011 = 3 → 定位到 Cache 第 3 行
  • 标记 011 = 3 与第 3 行标记比较：相等且有效位 = 1 → 命中

验算：该地址对应主存块号 = 011011₂ = 27，27mod8=3 ✓（27 = 3 × 8 + 3）；主存块 3、11、19、27…全部映射到 Cache 行 3，靠标记区分是哪一块。

考点：直接映射中行号就是主存块号的低 3 位（低 log2​行数 位），直接截取、无需计算；标记位数 = 块号位数 − 行号位数。

全相联映射

主存块可放入 Cache 的任意一行，无任何限制。主存地址划分 = 标记 + 块内地址（没有行号字段）。访存时把地址高位的标记与所有行的标记同时并行比较（相联存储器 CAM），某行匹配且有效位 = 1 即命中。

例题：条件同上（主存 64 块、块 16B、Cache 8 行），改为全相联。

  • 标记 = 主存块号全部位数 = 6 位，块内地址 4 位，主存地址 = 标记 + 块内 = 6 + 4 = 10 位
  • 地址 0110110010 → 标记 = 011011（即主存块 27）、块内地址 = 0010
  • 块 27 可放在 8 行中任意一行；查找需 8 个比较器同时比较 8 行标记

最灵活、冲突缺失最少、空间利用率最高；但每行都要一个比较器，硬件成本随容量剧增——只适合小容量结构，典型应用就是 TLB（快表）。

组相联映射

Cache 先分组，组间直接映射、组内全相联：

Cache 组号=主存块号modCache 组数

主存地址划分 = 标记 + 组号 + 块内地址。”n 路组相联“指每组含 n 行，访存时用组号选中一组，组内 n 个标记并行比较。

例题：条件同上，改为 2 路组相联（8 行 ÷ 每组 2 行 = 4 组）。求地址划分并定位地址 0110110010。

  1. 组号 = log2​4=2 位；块内地址 4 位；标记 = 6 − 2 = 4 位
标记（4 位） 组号（2 位） 块内地址（4 位）
0110 11 0010
  1. 组号 11 = 3 → 定位到第 3 组（含 Cache 第 6、7 两行）
  2. 标记 = 0110：与第 3 组内 2 行的标记分别比较，匹配且有效位 = 1 → 命中，按块内地址 0010 取字节

验算：主存块号 = 011011₂ = 27，27mod4=3 ✓。两个极端：每组 1 行 = 直接映射，只有 1 组（每组行数 = 总行数）= 全相联——三种映射是同一谱系上的三个点。

考点：n 路组相联 = 组间直接映射 + 组内全相联；路数越多命中率越高但比较器越多；2~8 路组相联是现代 CPU 的主流选择。

三种映射方式大对比

对比项 直接映射 全相联映射 组相联映射
映射规则 行号 = 块号 mod 行数 任意行 组号 = 块号 mod 组数，组内任意
主存地址划分 标记 + 行号 + 块内 标记 + 块内 标记 + 组号 + 块内
标记位数（同参数下） 最短 最长 居中
标记比较 1 次（1 个比较器） 全部行并行比较（CAM） 组内 n 路并行（n 个比较器）
灵活性 / 命中率 最低 最高 高
冲突缺失 多（抖动） 无 少
硬件成本 最低 极高 中等
典型应用 早期 / 大容量 Cache TLB、小容量 Cache 现代 CPU 主流

考点：同参数下标记位数：全相联 > 组相联 > 直接映射；冲突缺失：直接映射最多、全相联为 0。给容量和块大小反推”标记 + 行号/组号 + 块内”三位划分，是 408 计算题的基本盘。

Cache 中主存块的替换算法

缺失且可用行已满时，需要选一行淘汰：

算法 淘汰对象 特点
RAND（随机） 随机选一行 硬件最简单，命中率不稳定
FIFO（先进先出） 最早调入的行 实现简单；可能淘汰热块，有 Belady 异常
LRU（最久未使用） 最久未被访问的行 命中率最高，需硬件记录访问时序，成本稍高

LRU/FIFO 的完整逐帧演算表、Belady 异常与 Clock（二次机会）算法见《虚拟内存与页面置换算法》——Cache 替换与 OS 页面置换思想完全一致，区别只是：Cache 替换由硬件实现，页面置换由操作系统软件实现。

考点：直接映射的主存块只有唯一去处，冲突时只能换掉那一行，无需替换算法；只有全相联和组相联才需要。
易错点：组相联的替换在组内进行——每组独立维护自己的 LRU/FIFO 信息，某个块只可能替换同组内的行，绝不会跨组淘汰。

小例体会 LRU 与 FIFO 的差别——全相联 3 行，访问序列 1, 2, 3, 1, 2, 4：

访问 结果 LRU（右侧最新） FIFO（右侧最新调入）
1 缺 [1] [1]
2 缺 [1, 2] [1, 2]
3 缺 [1, 2, 3] [1, 2, 3]
1 命中 [2, 3, 1]（1 刷新为最新） [1, 2, 3]（顺序不动）
2 命中 [3, 1, 2] [1, 2, 3]
4 缺 淘汰 3 → [1, 2, 4] 淘汰 1 → [2, 3, 4]

两种算法缺块次数同为 4，但淘汰对象不同：FIFO 把刚被访问过的热块 1 淘汰，LRU 淘汰的是真正最久未用的 3。本质区别：LRU 每次命中都要调整该行的”新旧”位置，FIFO 只记录进入顺序，故 LRU 命中率更高但硬件更贵。

Cache 的写策略

读操作缺失只需调块；写操作的难点在于：写入 Cache 后，主存里的旧副本如何处理。

写命中：全写法与回写法

策略 做法 优点 缺点
全写法（write-through，写直达） 同时写入 Cache 和主存 主存始终最新，一致性好，实现简单 每次写都访问慢速主存，写入慢、占带宽
回写法（write-back） 只写 Cache，置该行脏位（dirty bit）；该行被替换出去时才一次性写回主存 写速度同 Cache，大幅减少访存次数 主存暂时”过时”，需脏位支持，实现复杂

全写法常配写缓冲（write buffer）：写主存的请求先进 FIFO 缓冲，CPU 不等主存写完即可继续工作，由写缓冲在后台慢慢写入，缓解速度瓶颈（缓冲满时 CPU 仍需暂停）。

写不命中：写分配与非写分配

策略 做法 说明
写分配法（write-allocate） 先把该主存块调入 Cache，再在 Cache 中写 赌后续还要读写（局部性），通常搭配回写法
非写分配法（no-write-allocate） 不调入 Cache，直接写主存 适合一次写入的大块数据，通常搭配全写法

四种组合与常用搭配

组合 常用度 说明
全写法 + 非写分配 ✅ 常用 经典搭配：写缺失直接写主存，不污染 Cache
回写法 + 写分配 ✅ 常用（现代 CPU 主流） 写缺失也调块，写操作尽量在 Cache 内完成
全写法 + 写分配 少见 逻辑自洽但无益：刚把块调进 Cache 又立即同步写主存
回写法 + 非写分配 少见 写不进 Cache，脏位无从使用

考点：全写法通常配非写分配、回写法配写分配——两两成对记忆。
易错点：写分配/非写分配只针对写缺失，写命中只谈全写/回写；回写法下主存不是最新值，DMA 设备直接读写主存时会读到旧数据，需 OS 或硬件保证 Cache 与主存一致性（考纲边缘，了解即可）。另有写一次法：首次写命中按全写法处理、之后按回写法，用于多处理器一致性场景。

虚拟存储器

虚拟存储器将主存和辅存统一编址：程序员按虚拟地址（逻辑地址）编程，运行时由硬件（MMU）+ 操作系统自动把虚地址转换成物理地址（实地址）。三个地址空间：

地址空间 谁在用 作用
虚拟地址 程序员 / CPU 发出 程序看到的连续大空间
物理地址 MMU 转换后产生 实际访问主存（查 Cache / 主存）用
磁盘地址 OS 内部 缺页时定位辅存上的数据

三种实现——页式、段式、段页式——与 OS 侧的管理机制（《内存管理：连续分配与分页分段》《虚拟内存与页面置换算法》）一一对应；计组只关注地址转换的数据通路。

虚拟存储器与 Cache 的异同：

对比 Cache 虚拟存储器
解决的矛盾 CPU 与主存的速度差 主存与磁盘的容量差
层次 Cache ↔ 主存（SRAM ↔ DRAM） 主存 ↔ 磁盘（DRAM ↔ 磁盘）
传送单位 块（几十 B） 页（通常 4KB）
缺失处理 硬件自动调块 OS 缺页中断调页（软件）
加速手段 本身即高速缓存 TLB 加速地址转换

页式虚拟存储器

虚拟空间与物理空间都划分成固定大小的页（主存侧对应称页框），通常 4KB。

  • 虚拟地址 = 虚页号（VPN）+ 页内偏移；页的划分对程序员透明
  • 页表放在主存中，页表基址寄存器指向页表；页表项含有效位（装入位）+ 物理页框号（及修改位、访问位、权限位等）
  • 转换过程：虚页号查页表 → 有效位 = 1 则取出页框号，拼接页内偏移得到物理地址；有效位 = 0 → 缺页中断，OS 调页并可能触发页面置换

例题：页大小 4KB（212B），虚拟地址 32 位 → 页内偏移 12 位、虚页号 20 位。设虚拟地址 = 0x00005294，页表中页 5 对应页框 0x1B 且有效，求物理地址。

  1. 拆分：0x00005294 → 虚页号 = 0x00005 = 5，页内偏移 = 0x294
  2. 查页表：页 5 有效，页框号 = 0x1B
  3. 拼接：物理地址 = 0x1B × 212 + 0x294 = 0x0001B294

验算：0x1B000 + 0x294 = 0x1B294 ✓，页内偏移 0x294 原样保留。

易错点：页内偏移转换前后不变（页大小 = 页框大小）；页表项存放的是页框号而非完整物理地址。

段式虚拟存储器

按程序的逻辑结构分段（代码段、数据段、栈段…），各段长度不等。

  • 虚拟地址 = 段号 + 段内偏移
  • 段表项 = 段基址 + 段长（+ 有效位、权限位）
  • 转换过程：段号查段表 → 取出段基址，先越界检查（段内偏移 < 段长，否则保护中断）→ 物理地址 = 段基址 + 段内偏移
  • 优点：模块边界清晰，便于共享与保护（按段设置读写权限）；缺点：段长可变，主存易产生外部碎片

段页式虚拟存储器

先按逻辑分段，段内再定长分页：虚拟地址 = 段号 + 段内页号 + 页内偏移。转换需两次查表：段号查段表得该段页表的基址 → 段内页号查页表得页框号 → 拼接页内偏移。兼得”便于共享保护”（段）与”管理规整、无外部碎片”（页），代价是地址转换多查一次表。

对比 页式 段式 段页式
划分依据 固定大小（物理划分） 逻辑结构（可变长） 先逻辑分段、段内定长分页
碎片 内部碎片 外部碎片 内部碎片
共享 / 保护 不方便 方便 方便
地址转换 1 次查表（页表） 1 次查表（段表）+ 越界检查 2 次查表（段表 + 页表）

快表 TLB：页表项的 Cache

页表放在主存 → 每次地址转换都要多访问一次主存（多级页表更多），加上取数本身，一次访存变成两三次，速度损失大。解决办法：TLB（快表，Translation Lookaside Buffer）——页表项的小容量高速缓存，用 SRAM 相联存储器存放最近用过的”虚页号 → 页框号”映射。

  • TLB 条目 = 有效位 + 虚页号 + 物理页框号（附加权限、修改位等）
  • 容量很小（几十~几百项），通常全相联或高路数组相联；命中率 > 99%（页访问局部性极强）
  • TLB 命中 → 直接得到页框号，无需访问主存中的页表；TLB 未命中 → 访主存查页表，并把该页表项调入 TLB
  • TLB 与 Cache 的分工：TLB 缓存的是”页表项”（服务地址转换），Cache 缓存的是”数据”（服务取指令/操作数）——两者都是 SRAM 高速缓存、都靠局部性、都要替换算法，但缓存对象与所处流程不同

完整访存流程：

TLB / Cache 组合例题：查 TLB 需 1ns，查 Cache 需 10ns，访问主存一次需 100ns（页表项与数据都在主存；TLB 未命中时页表项直接从主存读取，忽略 TLB 与 Cache 的更新时间、缺页情形单独讨论）。

情形 TLB Cache 访问主存次数 耗时
1 命中 命中 0 次（最快） 1 + 10 = 11 ns
2 命中 缺失 1 次（取数据） 1 + 10 + 100 = 111 ns
3 缺失 命中 1 次（取页表项） 1 + 100 + 10 = 111 ns
4 缺失 缺失 2 次（先取页表项、再取数据，最慢） 1 + 100 + 10 + 100 = 211 ns
5 — — 缺页：另行触发缺页中断 OS 访磁盘调页，毫秒级，调页后重新执行本指令

平均访问时间：设 TLB 命中率 90%、Cache 命中率 95%。

  • TLB 命中（概率 0.9）：1+[0.95×10+0.05×(10+100)]=1+(9.5+5.5)=16.5 ns
  • TLB 未命中（概率 0.1）：1+100+15.5=116.5 ns
  • 平均访问时间 Ta​=0.9×16.5+0.1×116.5=14.85+11.65=26.5 ns

考点：一次成功访存中 TLB、页表、Cache 各自可命中/缺失——最小访存 0 次（双命中）、最多 2 次（双缺失），缺页另算；TLB 命中则免访主存中的页表。
易错点：必须先生成物理地址、再查 Cache（页内偏移转换前后不变，故实际 CPU 中 TLB 查找与 Cache 索引可部分并行——VIPT 技术，了解即可）。

高频考点速记

考点 记忆
工作原理 CPU↔Cache 按字、Cache↔主存按块；行 = 有效位 + 标记 + 数据
命中率与平均访问时间 H=Nc​/(Nc​+Nm​)；先后口径 Ta​=Ht1​+(1−H)t2​；同时启动则 Ta​=Ht1​+(1−H)(t1​+t2​)
Cache 容量 行数 ×（标记位 + 数据位 + 有效位 + 脏位等控制位）
直接映射 行号 = 块号 mod 行数；1 个比较器；冲突缺失多（抖动）
全相联 可放任意行；地址 = 标记 + 块内；CAM 全行并行比较；成本极高 → 用于 TLB
组相联 组间直接、组内全相联；组号 = 块号 mod 组数；2~8 路为现代 CPU 主流
地址划分 块内 = log2​块大小；行号/组号 = log2​行数/组数；标记 = 总位数 − 其余；同参数标记位数全相联 > 组相联 > 直接映射
缺失类型 强制（首访）/ 容量（装不下）/ 冲突（争行）；全相联无冲突缺失
替换算法 RAND / FIFO / LRU（命中率最高）；直接映射无需替换算法；思想同 OS 页面置换
写命中 全写法（同时写主存，配写缓冲）vs 回写法（脏位，替换时才写回）
写缺失与搭配 写分配（调块入 Cache）vs 非写分配（直写主存）；常用：全写 + 非写分配、回写 + 写分配（主流）；DMA 直接访主存有一致性问题
Cache vs 虚存 速度层次 vs 容量层次；Cache 缺失硬件调块、缺页 OS 中断调页
页式转换 虚页号查页表得页框号，拼接不变的页内偏移；页表在主存
段式与段页式 段表项 = 基址 + 段长（越界检查）；段页式两次查表（段表 + 页表）
TLB 页表项的 Cache，全相联小容量、命中率 >99%；命中则免访主存页表
TLB/Cache 组合 最快 0 次访主存（双命中）、最慢 2 次（双缺失）；缺页毫秒级
