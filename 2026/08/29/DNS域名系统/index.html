DNS域名系统

2026-08-29
  • 计算机网络

DNS（Domain Name System，域名系统）是应用层最基础的协议之一，负责把便于人类记忆的域名（如 www.baidu.com）解析为 IP 地址（如 180.101.50.188），也可进行反向解析（IP → 域名，使用 in-addr.arpa 域）。域名与 IP 的映射分布存储在全世界多台域名服务器上，任何一台都不存储全部映射——因此 DNS 本质上是一个分布式数据库，采用 C/S 模式工作，查询用 UDP 53。408 的考查集中在：网络应用模型（C/S 与 P2P）、层次域名空间、四类域名服务器、递归与迭代查询。

网络应用模型

网络应用（应用层程序）之间的通信模式有两种：客户/服务器（C/S）模型与对等（P2P）模型。

客户/服务器（C/S）模型

  • 角色固定：客户（请求服务）与服务器（提供服务）分工明确，服务器被动等待请求，客户主动发起
  • 服务器集中服务：所有客户的请求都发往同一个（或一组）服务器，集中处理并返回结果
  • 服务器永久在线、拥有固定的周知 IP 地址（和端口）；客户按需发起连接、用完即断

特点：集中管理、实现简单、数据一致性好；但可扩展性差——客户数激增时服务器成为瓶颈，只能升级硬件或加服务器集群，成本随规模增长。

对等（P2P）模型

  • 网络中节点地位平等，没有固定的客户/服务器之分，每个节点（对等方，Peer）既是客户又是服务器
  • 节点之间直接通信、互相提供服务（共享带宽、存储、文件），没有（或仅有轻量）中心服务器
  • 典型应用：BitTorrent、迅雷下载、P2P 直播

特点：自扩展性强——每个新加入的节点既消耗资源也带来服务能力，用户越多系统总吞吐越大；成本分散到各节点，无专用服务器开销，单点失效不影响整体。

C/S 与 P2P 对比

对比项 C/S 模型 P2P 模型
角色 客户（请求）与服务器（服务）分工固定 节点既当客户又当服务器，地位对等
服务器 永久在线、固定 IP、集中服务 无固定中心服务器（或仅做索引/Tracker）
服务方式 集中服务，请求都发往服务器 分布式，节点之间直接交换
可扩展性 差（服务器是瓶颈） 好（节点越多服务能力越强，自扩展）
成本 需专用服务器，硬件/带宽成本高 成本分散到各对等方
可靠性 服务器宕机 → 服务中断 单个节点失效不影响整体
典型应用 WWW/HTTP、FTP、SMTP/邮件、DNS BitTorrent、迅雷、P2P 直播

考点：C/S 与 P2P 的本质区别是服务的集中与分散；P2P 可扩展性优于 C/S（新节点同时带来资源），C/S 胜在易管理、数据一致。
易错点：DNS、HTTP、FTP、SMTP 都是 C/S 应用；文件共享（BitTorrent/迅雷）才是 P2P。别把 DNS 归为 P2P。

层次域名空间

域名空间按树形结构组织，从根向下逐级划分，从左到右层次降低（最右边是顶级域，最左边是主机名）：

顶级域类型 举例 说明
通用顶级域名（gTLD） com（商业）、net（网络）、org（组织）、edu（教育）、gov（政府）、int、mil 按机构类别划分
国家及地区顶级域名（ccTLD） cn（中国）、jp、uk、us 按国家/地区划分
  • 域名标号规则：不区分大小写；每一标号 不超过 63 个字符；整个域名不超过 255 个字符
  • 完整的域名即 FQDN（全限定域名）；以根点结尾的叫绝对域名（书写时根点常省略），了解即可
  • 反向解析（IP → 域名）放在特殊的 in-addr.arpa 域下，与正向域名空间并列

例：拆解 www.cs.tsinghua.edu.cn

从右往左 标号 层级 含义
第 1 级 cn 国家顶级域 中国（ccTLD）
第 2 级 edu.cn 二级域 中国教育机构域（cn 顶级域下的 edu 二级域）
第 3 级 tsinghua.edu.cn 三级域（权限域） 清华大学
第 4 级 cs 子域 计算机系
最左 www 主机名 Web 服务器这台主机

考点：域名中最左边是主机名，最右边是顶级域名；如 www.cs.tsinghua.edu.cn 中 tsinghua.edu.cn 是 edu.cn 顶级（国家域 cn）体系下注册的三级域——注意 cn 是国家顶级域、edu.cn 是其下的二级域，不要混淆。
易错点：域名”从左到右层次降低“——com/cn 在最右，www 在最左。

域名服务器（四类）

域名映射分布存储，由四类域名服务器分工协作完成解析：

根域名服务器

  • 层次结构的”总入口”：知道所有顶级域名服务器的地址，收到查询后指路”该问哪个顶级域服务器”
  • 全球共 13 套逻辑根服务器，用字母 A~M 标识；每套是一个集群，用**任播（Anycast）**技术把镜像分布在全球各地，实际物理服务器有数百台

顶级域名服务器

  • 管理注册在该顶级域下的所有二级域名（如 com 域、cn 域）
  • 收到查询后返回对应的权威域名服务器的地址

权威（权限）域名服务器

  • 保存该区（zone）内域名到 IP 的最终映射，每台对外提供服务的域名都应注册在某个权威服务器上
  • 收到查询后返回最终的 IP 地址（或”域名不存在”）
  • 服务器管辖范围按”区“划分，区 ≠ 域（区可以小于域）；为防单点故障，每个区设主服务器 + 辅助服务器，主服务器定期把数据复制到辅助服务器，更改数据只能在主服务器上进行

本地域名服务器

  • 主机所在网络的域名服务器（通常由 ISP 或校园网提供），不属于层次域名服务器体系
  • 是主机的**”代理查询者”：主机 TCP/IP 配置里填的”DNS 服务器地址”就是它；主机的查询总是先发给它，是递归查询的入口**

四类服务器对比

服务器 作用（知道什么） 数量/分布 地址数量（掌握的地址）
根域名服务器 解析”总入口”，指明顶级域服务器 13 套逻辑名（A~M），集群 + 任播镜像 知道所有顶级域名服务器的 IP
顶级域名服务器 管理本顶级域下的二级域名 每个顶级域一套（com 域、cn 域…） 知道其下权威域名服务器的 IP
权威（权限）域名服务器 保存本”区”的最终映射 每个区一套（主 + 辅） 给出域名对应的最终 IP
本地域名服务器 主机的代理查询者 每个 ISP/校园网若干台 直接向根/顶级/权威发迭代查询

考点：本地域名服务器不在层次结构中，它是主机查询的入口/代理；根服务器知道所有顶级域服务器的地址，是解析的起点。
易错点：13 套根服务器是逻辑名（A~M）+ 集群，不是全球只有 13 台物理机器。

域名解析过程（重点）

递归查询与迭代查询

对比项 递归查询（Recursive） 迭代查询（Iterative）
含义 把解析委托给对方，要求对方给出最终结果 对方只返回**”下一步该问谁”的地址**，自己再去问
返回值 最终 IP 地址（或”域名不存在”） 下一台要查询的服务器地址
负担 被委托的服务器负担重（要替人查到底） 发起方（本地服务器）负担重
实际位置 主机 → 本地域名服务器 本地域名服务器 → 根/顶级/权威

实际使用中两者结合：主机对本地服务器用递归，本地服务器对根/顶级/权威用迭代（也可配置成全递归）。

域名解析全过程例题

主机要访问 www.baidu.com，本地缓存均未命中，走完整链路（所有查询/应答均用 UDP 53）：

步骤 查询源 → 目的 方式 报文 返回内容
① 主机 → 本地域名服务器 递归 查询 UDP 53 （等待最终结果）
② 本地 → 根域名服务器 迭代 查询 UDP 53 返回 .com 顶级域服务器的 IP
③ 本地 → .com 顶级域服务器 迭代 查询 UDP 53 返回 baidu.com 权威服务器的 IP
④ 本地 → baidu.com 权威服务器 迭代 查询 UDP 53 返回 www.baidu.com 的 IP
⑤ 本地 → 主机 递归应答 应答 UDP 53 最终 IP 地址

报文数推演（考频最高的计算）：

  • 最多（全程无缓存、迭代方式）：查询 4 次（①②③④）+ 应答 4 次（②③④⑤）= 8 个报文
  • 若全递归（本地把请求转给根，根逐级委托下去）：查询路径 主机→本地→根→顶级→权威 共 4 次，结果沿原路返回 4 次，同样 8 个报文
  • 最少（本地服务器缓存命中）：仅 ① 查询 + ⑤ 应答 = 2 个报文

考点：主机 → 本地服务器是递归，本地 → 根/顶级/权威是迭代——迭代时每一步返回的都是”下一台服务器的地址”，只有权威服务器才给出最终 IP。
易错点：迭代查询中，根服务器不代替本地服务器去查，它只负责”指路”；做报文数计算时先数清”查询”和”应答”两类报文。

DNS 高速缓存

  • 每台域名服务器（以及主机）都维护一个高速缓存，存放最近解析过的”域名 → IP”映射；再次查询命中缓存即可直接应答，减少查询流量、加快解析
  • 每条缓存记录有生存时间（TTL，Time To Live），到期自动删除
  • 缓存可能过期：域名刚换了 IP 而 TTL 未到时，缓存会返回旧地址——TTL 就是”加速”与”新鲜度”之间的折中

传输层选择：UDP 还是 TCP

场景 协议/端口 原因
域名查询/应答（主机 ↔ 本地、本地 ↔ 根/顶级/权威） UDP 53 一问一答、报文短小，UDP 无需建连、开销小
区域传送（主服务器 → 辅助服务器同步数据） TCP 53 数据量大、要求可靠传输

考点：DNS 查询默认 UDP 53；只有区域传送（主从服务器间复制）用 TCP 53。
易错点：”DNS 用 UDP”不绝对——区域传送用 TCP；反向解析走 in-addr.arpa，与正向解析同一套服务器。

DNS 报文格式

DNS 报文由首部 + 四节构成；查询报文 = 首部 + 问题节，应答报文 = 首部 + 问题 + 回答 + 权威 + 附加：

节 内容 出现在
首部 标识 + 标志字段（QR：0 查询/1 应答；RD：期望递归；RA：服务器支持递归） 查询、应答都有
问题节 要查询的域名 + 查询类型 查询、应答都有
回答节 域名 → IP 的资源记录（RR） 仅应答
权威节 权威域名服务器的记录 仅应答
附加节 附加的辅助记录（如权威服务器的 IP） 仅应答

考点：判别报文类型看首部 QR 位（0 = 查询、1 = 应答）；迭代查询的应答若非最终结果，答案通常放在权威/附加节（给出下一台服务器地址）。
