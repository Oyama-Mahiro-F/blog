传输层与UDP协议

2026-08-29
  • 计算机网络

传输层（Transport Layer）是体系结构中唯一负责端到端（进程到进程）通信的层次：网络层只负责把 IP 数据报送到目的主机，传输层还要再往下走一步——通过端口号把数据交给主机上正确的进程。它在网络层”尽力而为”的服务之上，向应用层提供两种服务模式：无连接的 UDP 与面向连接的 TCP。408 对本部分的考查集中在：传输层功能、端口与套接字、UDP 数据报格式与校验和计算。

传输层的功能

传输层为不同主机上的应用进程提供逻辑通信——两个进程看似直接对话，实际数据仍要经过下层网络传递。它与网络层的分工如下：

对比项 网络层 传输层
通信范围 主机到主机 进程到进程（端到端）
寻址依据 IP 地址 端口号
典型协议 IP TCP / UDP
服务质量 尽力而为（不可靠） UDP 不可靠 / TCP 可靠

传输层的核心功能有四项：

功能 说明
复用与分用 发送方多个应用进程共用传输层发送（复用）；接收方传输层按端口号把报文上交对应进程（分用）
寻址 用端口号标识主机内的应用进程
差错检测 对收到的报文做校验和检测（UDP/TCP 首部都带校验和字段）
流量/拥塞控制 调节发送速率（仅 TCP 提供，UDP 没有）

考点：传输层提供进程之间的逻辑通信，网络层提供主机之间的逻辑通信——两台主机各自同时开着多个应用互不混淆，靠的就是端口分用。
易错点：”端到端”指进程到进程；IP 层只能把数据送到主机，不区分进程，所以必须由传输层补上端口。

传输层寻址与端口

端口号

端口（Port）是传输层的服务访问点（SAP），用 16 位二进制表示，范围 0~65535，在同一台主机内标识一个应用进程。

类别 范围 用途
熟知端口（系统端口） 0~1023 固定分配给常用服务，服务器端使用
登记端口 1024~49151 应用程序向 IANA 登记后使用
短暂端口（客户端口） 49152~65535 客户程序运行时临时选用，通信结束即回收

考点：端口 = 进程标识（SAP）；端口只有本地意义——不同主机独立编号，两台主机都用 80 号端口互不冲突。
易错点：TCP 与 UDP 的端口各自独立（同为 53 号，UDP 的 DNS 与 TCP 的 DNS 互不冲突）；服务器用熟知端口被动等待，客户端用短暂端口主动发起。

常用熟知端口

端口 传输层协议 服务
21 / 20 TCP FTP（控制连接 / 数据连接）
23 TCP TELNET
25 TCP SMTP（发邮件）
53 UDP DNS
67 / 68 UDP DHCP 服务器 / DHCP 客户端
69 UDP TFTP
80 TCP HTTP
443 TCP HTTPS
110 TCP POP3（收邮件）
161 UDP SNMP

考点：FTP 控制 21、数据 20；DNS 53；DHCP 服务器 67、客户端 68；HTTP 80、HTTPS 443、POP3 110、SMTP 25。

套接字

套接字（Socket）=（IP 地址 : 端口号），例如 192.168.1.10:80，唯一标识网络中的一个通信端点。

  • 一条 TCP 连接由一对套接字唯一确定：(socket1, socket2)
  • IP 地址取自 IP 首部，端口号取自传输层首部

考点：套接字 = IP + 端口；”一条 TCP 连接只有两个端点”指两个套接字，不是两台主机。

无连接服务与面向连接服务

传输层向上提供两类服务，分别由 UDP 与 TCP 承担：

对比项 无连接服务（UDP） 面向连接服务（TCP）
建立连接 不需要，发前无握手 必须三次握手建立连接
交付质量 尽最大努力交付（不可靠） 可靠交付（不丢、不重、不乱序）
通信对象 一对一、一对多、多对一、多对多 只能一对一（点对点）
传输单位 报文（保留报文边界） 字节流（无边界）
开销与时延 小、低时延 大（确认、重传、拥塞控制）
典型应用 DNS、DHCP、实时音视频 文件传输、网页、邮件

考点：应用选协议的判断口诀——要可靠选 TCP；要快、要广播组播、要实时选 UDP。

UDP 协议

**UDP（User Datagram Protocol，用户数据报协议）**在 IP 之上只做两件事：端口复用分用 + 差错检测，其余全部交给应用层。

UDP 的特点

  1. 无连接：发送数据前不需要建立连接，省去握手时延；
  2. 尽最大努力交付：不保证可靠交付，不确认、不重传；
  3. 面向报文：应用交来多长的报文就发多长，不拆分、不合并（一次交付一个完整报文，保留报文边界）；
  4. 无拥塞控制：网络拥塞也不降低发送速率，适合 IP 电话、视频会议等实时应用；
  5. 首部开销小：仅 8B（TCP 固定首部 20B）；
  6. 支持一对一、一对多、多对一、多对多的交互通信（TCP 只能一对一）。

UDP 数据报格式

UDP 数据报 = 首部（8B）+ 数据，首部只有 4 个字段，每个 2B：

字段 长度 说明
源端口 2B 发送方端口（不需要回信时可全 0）
目的端口 2B 接收方端口，分用的依据
长度 2B UDP 数据报总长度（首部 + 数据），最小 8（只有首部），最大 65535
校验和 2B 检测传输差错；IPv4 下可选，全 0 表示不校验

UDP 能承载的最大应用层数据（IP 数据报总长度上限 65535B）：

65535−20(IP 首部)−8(UDP 首部)=65507B

考点：长度字段含 8B 首部，最小值 8；UDP 报文整体作为 IP 层的数据部分（应用报文过大时由 IP 层分片，UDP 自身不拆）。

UDP 长度字段例题

题目：应用层交给 UDP 一个 2047B 的报文，求 UDP 长度字段值与 IP 数据报总长度；若收到一个长度字段为 1500 的 UDP 数据报，数据部分多长？

  • UDP 长度 = 首部 + 数据 = 8+2047=2055，长度字段填 2055
  • IP 数据报总长度 = $20 + 2055 = $ 2075B
  • 数据 2047B 为奇数个字节 → 计算校验和时末尾补 1 个全 0 字节（凑成偶数，只参与计算、不发送）
  • 反向：长度字段 = 1500 → 数据部分 = $1500 - 8 = $ 1492B

UDP 校验（伪首部）

校验范围 = 伪首部（12B）+ UDP 首部（8B）+ 数据。

伪首部（Pseudo Header，12B）：只为计算校验和而临时拼在数据报前面的”虚拟首部”，既不传输、也不计入 UDP 长度字段：

伪首部字段 长度 内容
源 IP 地址 4B 取自 IP 首部
目的 IP 地址 4B 取自 IP 首部
全 0 1B 填充字节
协议号 1B 17（UDP 的 IP 协议字段值）
UDP 长度 2B 与 UDP 首部”长度”字段相同

发送方计算步骤：

  1. 校验和字段先置 0；数据若为奇数字节，末尾补一个全 0 字节（不发送）；
  2. 把”伪首部 + 首部 + 数据”按 16 位一组做二进制反码求和——最高位进位回卷加到最低位；
  3. 把结果取反码，填入校验和字段。

接收方：对”伪首部 + 首部（含校验和）+ 数据”做同样的反码求和，结果应为全 1（0xFFFF），否则认为有差错、直接丢弃。

例题（反码求和回卷）：求和过程中已得中间结果 1011 1001 1011 0110，还需加上最后一个 16 位字 0110 0101 1100 0101，求最终校验和。

验算：接收方把校验和放回一起求和：0x1F7C+0xE083=0xFFFF（全 1）→ 无差错 ✓

答案：校验和 = 1110 0000 1000 0011（0xE083）。

考点：伪首部参与校验但绝不传输；校验和只能查错、不能纠错——发现差错直接丢弃，UDP 没有重传机制，这正是”尽最大努力交付”的体现。
易错点：最后一步要先回卷进位再取反（不能对 17 位结果直接取反）；IPv4 下校验和可选（全 0 = 不校验），IPv6 下必须计算。

高频考点速记

考点 记忆
传输层定位 进程到进程（端到端）；网络层是主机到主机
复用/分用 发送复用、接收按端口号分用
端口 16 位 0~65535；熟知 0~1023、登记 1024~49151、短暂 49152~65535
套接字 (IP : 端口)；TCP 连接由一对套接字确定
常用端口 FTP 21/20、TELNET 23、SMTP 25、DNS 53、DHCP 67/68、HTTP 80、HTTPS 443、POP3 110
端口特性 只有本地意义；TCP/UDP 端口各自独立编号
UDP 特点 无连接、尽力交付、面向报文、无拥塞控制、首部 8B、支持一对多
UDP 首部 源端口/目的端口/长度/校验和各 2B，共 8B
UDP 长度字段 含首部，最小 8、最大 65535；最大应用数据 65507B
伪首部 12B（源/目的 IP + 全 0 + 17 + UDP 长度），参与校验不传输
校验算法 16 位一组反码求和、进位回卷、结果取反；接收方求和应全 1
UDP 校验性质 只查错不纠错，出错丢弃；IPv4 可选、IPv6 必选
协议选择 要可靠 → TCP；要快/实时/广播组播 → UDP
