IPv6协议

2026-08-29
  • 计算机网络

IPv4 的 32 位地址早已捉襟见肘，IPv6（IP version 6）用 128 位地址从根本上解决地址枯竭问题，并对首部、分片、安全、配置等机制做了系统性改造。地址长度、冒号十六进制记法等基础对比见《IP协议》一文，本文聚焦 408 考纲要求深化掌握的部分：基本首部 40B 的 8 个字段、地址表示规则与地址类型（单播/组播/任播）、与 IPv4 首部的逐字段对比、双协议栈与隧道等过渡技术。

IPv6 的主要特点

IPv6 仍支持无连接的尽最大努力交付，但对 IPv4 的弊病逐一做了修正，主要有 8 条：

特点 说明
地址空间 128 位 地址数约 3.4×1038 个，彻底解决地址枯竭，地址层次结构更丰富
基本首部固定 40B 字段从 IPv4 固定首部的 12 个精简为 8 个（”选项”移入扩展首部），路由器处理更快
取消首部校验和 链路层与传输层均有校验，路由器每跳不再重算校验和，转发效率显著提高
只在源节点分片 路由器不分片：路径 MTU 过小时回送 ICMPv6”分组过大”报文，由源端调整；分片信息放分片扩展首部
按 8B 对齐 基本首部与扩展首部的长度都是 8 字节的整数倍，便于硬件快速处理
选项 → 扩展首部 基本首部不再有可变”选项”字段，功能移入扩展首部；中间路由器通常只处理基本首部
支持 QoS（流标签） 流量类型 + 20 位流标签，可对同一条”流”的分组预留资源
即插即用 + 安全 无状态地址自动配置（不依赖 DHCP 即可入网）；IPSec 内置于协议体系

考点：IPv6 与 IPv4 最大的不同是地址 128 位 + 首部固定 40B；”取消校验和、源节点分片、扩展首部”三条是简答题常客。
易错点：IPv6 没有广播（用组播/任播替代）；”只在源节点分片”不等于”不能分片”——分片能力仍在，只是收敛到源端。

IPv6 基本首部（40 字节）

IPv6 数据报由基本首部（固定 40B）+ 扩展首部（0 个或多个）+ 数据组成。基本首部的 8 个字段如下：

字段 长度 作用
版本 4 位 取值 6
流量类型 8 位 标记分组的服务类别/优先级（对应 IPv4 的服务类型/区分服务字段）
流标签 20 位 IPv6 新增：标识一条”流“——同源同宿、有同类服务质量需求的一串分组，路由器可为其预留资源（QoS）
有效载荷长度 16 位 扩展首部 + 数据的总长度，不含基本首部，单位 1B
下一个首部 8 位 基本首部后面是什么：扩展首部的类型，或上层协议（TCP/UDP/ICMPv6），承担 IPv4”协议”字段的角色
跳数限制 8 位 相当于 IPv4 的 TTL：每过一个路由器减 1，减到 0 丢弃
源地址 128 位 发送方 IPv6 地址
目的地址 128 位 接收方 IPv6 地址

长度验算：4+8+20+16+8+8+128+128=320 位 =40 字节 ✓

考点：有效载荷长度不含基本首部（IPv4 的”总长度”含首部）；各扩展首部通过”下一个首部“字段链式连接，形成”首部链”。
易错点：跳数限制减到 0 时由当前路由器丢弃并回送 ICMPv6 报文；流标签是 IPv6 新增字段，IPv4 没有对应物。

扩展首部（”选项”的归宿）

IPv4 的可变”选项”字段被拆成若干扩展首部，插在基本首部与数据之间，靠”下一个首部”字段链式串联：

扩展首部 作用
逐跳选项首部 需要路径上每个路由器检查的选项（唯一要求逐跳处理的扩展首部）
路由首部 类似 IPv4 的源路由：指定转发路径上必须经过的节点
分片首部 源节点分片时使用：32 位标识 + 片偏移（8B 为单位）+ M 位（还有后续分片？）
目的选项首部 只由目的节点检查的选项
认证首部（AH） 数据来源认证 + 完整性校验（IPSec）
封装安全载荷（ESP） 加密 + 认证（IPSec）

路由器转发时一般只处理基本首部（至多再处理逐跳选项首部），选项由通信两端处理——这是 IPv6 转发效率高于 IPv4 的又一原因。

考点：扩展首部长度都是 8B 的整数倍；除逐跳选项首部外，其余扩展首部只在目的（或指定）节点处理。
易错点：IPv6 分片的标识（32 位）、片偏移、M 位都在分片首部中，基本首部里没有任何分片字段。

IPv6 地址表示

采用冒号十六进制记法：128 位分成 8 组，每组 16 位写成 4 个十六进制数字，组间用冒号隔开。

简化规则：

规则 示例
每组前导零可省略 0DB8 → DB8；0042 → 42；0000 → 0
连续全 0 组用 :: 压缩，整个地址只能用一次 2001:0DB8:0:0:0:FF00:42:8329 → 2001:DB8::FF00:42:8329
与 IPv4 混合表示（前 6 组冒号十六进制 + 后 32 位点分十进制） ::FFFF:192.168.1.1（IPv4 映射地址）
前缀记法表示网络（IPv6 没有子网掩码的概念） 2001:DB8::/48 = 前 48 位是网络前缀

压缩例题：化简 4BF5:0000:0000:0000:BA5F:039A:000A:2176。

  1. 去前导零：4BF5:0:0:0:BA5F:39A:A:2176
  2. 连续 3 个全 0 组压缩为 ::：结果 4BF5::BA5F:39A:A:2176

考点：:: 只能出现一次——出现两次就无法确定每段补几个 0（二义性）。
易错点：地址中有多段连续 0 时应压缩最长的一段（等长取最左）；4BF5::BA5F::2176 这种两处压缩是非法写法；压缩只针对整组的 0，组内的非零数字不能省。

前缀例题：某机构分得前缀 2001:DB8:AC10::/48，机构内用 64 位作接口标识继续划分子网。

  • 子网号位数 = 64 − 48 = 16 位，可划分子网 216=65536 个；
  • 每个 /64 子网可容纳约 264 个接口——IPv6 不设广播地址，没有 IPv4 那样”减 2”的约定。

IPv6 地址类型

IPv6 取消广播，地址只分三类：单播、组播、任播。

类型 标识对象 交付方式
单播 Unicast 一个接口 逐跳路由，交付给唯一一个接口
组播 Multicast 一组接口（前缀 FF00::/8） 交付给组内所有成员
任播 Anycast 一组接口（通常分属不同节点） 按路由协议的距离度量交付给其中”最近“的一个成员

任播（Anycast，任意播/泛播）：地址标识一组接口，分组只送给最近的一个成员。典型应用：多个 DNS 根服务器或 CDN 镜像共享一个任播地址，用户流量自动落到最近的副本。任播地址只能作目的地址，且只分配给路由器，不分配给主机。

常用地址前缀（必背）：

前缀 类型 说明
::/128 未指定地址 全 0，主机尚未取得地址时作源地址（类似 IPv4 的 0.0.0.0）
::1/128 环回地址 相当于 IPv4 的 127.0.0.1，发往本机
FF00::/8 组播地址 前 8 位为 1111 1111
FE80::/10 链路本地单播 仅同一链路内有效，自动配置的初始地址（类似 IPv4 的 169.254.0.0/16）
2000::/3 全球单播地址 目前实际分配的全球单播块（首 3 位 001，即 2xxx / 3xxx 开头）
::FFFF:0:0/96 IPv4 映射地址 与 IPv4 兼容/过渡时使用

全球单播地址的结构：全球路由前缀（48 位）+ 子网标识（16 位）+ 接口标识（64 位）。接口标识通常由网卡 MAC 地址按 EUI-64 规则生成（中间插入 FF:FE 并翻转 U/L 位），这正是”无状态地址自动配置（即插即用）”的基础，其过程为：

  1. 主机用网卡 MAC 按 EUI-64 生成接口标识，与本链路保留前缀拼出链路本地地址 FE80::/64；
  2. 做重复地址检测（DAD）：向试探地址发组播邻居请求，无应答方可使用；
  3. 监听路由器周期性发送的路由器通告报文，从中取得 64 位网络前缀；
  4. 前缀 + 接口标识拼出全球单播地址——全程不需要 DHCP 服务器。

考点：链路本地 FE80::/10、组播 FF00::/8、全球单播 2000::/3、环回 ::1、未指定 ::——给地址判类型的题每年都变着花样出。
易错点：IPv6 没有广播地址；任播交付给最近一个成员而不是全体；组播地址同样只能作目的地址，不能作源地址。

IPv6 与 IPv4 首部对比（重点）

把 IPv4 首部的字段逐个”对号入座”，分删除、更改、新增三类：

IPv4 字段 IPv6 对应 处理方式
版本 版本 保留（取值 4 → 6）
首部长度 IHL — 删除：基本首部固定 40B，无需此字段
服务类型 流量类型 更名保留，配合流标签实现 QoS
总长度 有效载荷长度 更名，含义改为不含基本首部
标识 / 标志 / 片偏移 分片扩展首部 移出基本首部：只有源节点分片时才用到
生存时间 TTL 跳数限制 更名（功能相同：每跳减 1，防环路）
协议 下一个首部 更名扩展：可指向扩展首部，也可指上层协议
首部校验和 — 删除：免去路由器每跳重算
源地址 / 目的地址 源地址 / 目的地址 保留，扩为 128 位
选项 扩展首部 移出基本首部，改造成链式扩展首部
— 流标签 新增（20 位，支持 QoS）

小结：删除 5 个字段（IHL、标识、标志、片偏移、首部校验和，外加”选项”移出）；更改 4 个（服务类型→流量类型、总长度→有效载荷长度、TTL→跳数限制、协议→下一个首部）；新增 1 个（流标签）。

考点：IPv6 基本首部 40B、8 个字段；分片字段没有消失，而是移入分片扩展首部且只由源节点使用。
易错点：IPv6 首部里没有”总长度”——“有效载荷长度”不含基本首部，直接套用 IPv4 概念会算错；”跳数限制”与 TTL 功能相同，只是名字更贴切。

从 IPv4 向 IPv6 过渡

互联网规模太大，不可能指定某天全网统一升级，IPv4 与 IPv6 将长期共存，因此需要平滑过渡技术：

技术 做法 适用场景与局限
双协议栈 主机/路由器同时安装 IPv4 和 IPv6 两套协议，按对端选用（DNS 需同时提供 A 与 AAAA 记录） 互通最直接、最彻底；但每个节点都要维护两套协议，开销大
隧道（Tunneling） 把整个 IPv6 分组作为数据封装进 IPv4 数据报，穿过 IPv4 网络后由出口拆封还原 适合孤立的 IPv6 岛借助 IPv4 骨干网互联；沿途只需支持 IPv4
翻译（协议转换） 转换网关改写首部字段，把 IPv6 数据报翻译成 IPv4（或反向），类似 NAT 适合纯 IPv4 老设备与纯 IPv6 主机直接通信；转换有损，无法体现 IPv6 扩展特性

易错点：隧道只要求隧道两端（入口/出口路由器）是双协议栈，中间路径只需支持 IPv4；隧道不改变原 IPv6 分组的源/目的地址（只是外面套了一层 IPv4 首部）。

高频考点速记

考点 记忆
地址长度 128 位，冒号十六进制 8 组，地址数 3.4×1038
压缩规则 前导零省略；:: 只能用一次、压最长连续 0 段；混合表示 ::FFFF:x.x.x.x
基本首部 固定 40B、8 个字段：4+8+20+16+8+8+128+128=320 位
有效载荷长度 16 位，不含基本首部（区别于 IPv4”总长度”）
流标签 20 位，IPv6 新增，标识一条”流”以支持 QoS
分片 只允许源节点分片，信息在分片扩展首部；扩展首部 8B 对齐
选项 IPv4”选项” → IPv6 扩展首部，由”下一个首部”字段链接
地址类型 单播 / 组播 / 任播，取消广播
特殊前缀 环回 ::1、未指定 ::、链路本地 FE80::/10、组播 FF00::/8、全球单播 2000::/3
任播 交付给最近的一个成员；只能作目的地址、只分配给路由器
首部对比 删 IHL/标识/标志/片偏移/校验和；TTL→跳数限制、协议→下一个首部；新增流标签
过渡技术 双协议栈（两套协议）、隧道（IPv4 协议字段 41）、翻译（类 NAT）
