TCP可靠传输、流量控制与拥塞控制

2026-08-29
  • 计算机网络

TCP 的可靠传输、流量控制与拥塞控制是传输层三大核心机制：可靠传输在 IP 尽力而为的服务之上保证字节流”不丢、不重、不乱序”，靠序号 + 确认 + 超时重传 + 滑动窗口实现；流量控制防止发送过快导致接收方缓存溢出（点对点，用 rwnd）；拥塞控制防止过多数据注入网络造成全局拥塞（用 cwnd）。408 对这部分考查极密集：RTO 计算、发送窗口取 min(rwnd, cwnd)、四种算法下 cwnd 的逐轮演变是大题常客，本文例题务必动手推一遍。

可靠传输机制总览

TCP 面向字节流，本身不依赖 IP 保证可靠，而是自己实现一套”确认—重传”机制：

机制 作用 要点
校验 检测传输差错 伪首部 + 首部 + 数据一起校验（UDP 可选，TCP 必须）
序号 保证有序、去重、定位丢失 对每个字节编号，32 位序号字段
确认 告知发送方”已收到哪里” 累积确认为主，常捎带在反向数据中
重传 补救丢失/出错的报文段 超时重传（RTO 到期）、快重传（3 个重复 ACK）
窗口 批量发送提效、动态限速 滑动窗口，同时受 rwnd 与 cwnd 约束

考点：确认号 ack = 期望收到的下一个字节序号。”ack = N” 等价于”序号 N−1 及之前的所有字节已全部正确收到“——这就是累积确认（GBN 式确认语义）。

序号与确认：累积确认与捎带确认

  • 按字节编号：报文段首部序号 seq = 本报文段第一个数据字节的序号；每个字节都有唯一编号，因此失序、重复、丢失都能被发现。
  • 累积确认：接收方回一个 ack 即确认之前所有字节；即使失序报文段先到，ack 仍指向期望的下一字节，不随失序报文段后移。
  • 捎带确认：接收方有反向数据要发时，把确认捎带在自己的数据报文段首部中，不必单独发确认报文，节省开销。
  • 重复确认：收到失序报文段时立即重复发”期望字节”的 ack，为快重传提供触发条件。

易错点：ack = N 不是“刚收到 N 号字节”，而是”N 号还没收到、N−1 及以前全收到”。例：已收 1~99 号而 100 号丢失 → 确认号 = 100；若 100 号先到而 99 号未到 → 确认号仍是 99，且 100 号只能暂存缓存。

滑动窗口例题：发送窗口如何滑动

例题：主机 A 向 B 发送数据，发送窗口 W = 10（字节），已发送序号 1~10 号字节（简化为每报文段 1 字节），随后收到 ack = 3。分析窗口滑动。

  • ack = 3 ⇒ 1、2 号字节已正确收到（累积确认），窗口后沿（最小未确认序号）从 1 移到 3
  • 新窗口覆盖 3~12；窗口内已发送未确认：3~10；可发送的新数据：11~12
字节区间 1~2 3~10 11~12 13 及以后
收到 ack = 3 前 已发送、未确认（窗口内） 已发送、未确认（窗口内） 不可发送 不可发送
收到 ack = 3 后 已确认（滑出窗口） 已发送、未确认（仍在窗口） 可立即发送 不可发送

验算：发送窗口 10 = 已发送未确认（3~10 共 8 字节）+ 可用窗口（11~12 共 2 字节）✓

  • 若应用数据就绪，A 立即发送 11、12 号，此时窗口内 10 字节全部”在途”；可用窗口 = 发送窗口 − 已发送未确认字节数。
  • 若超时仍未确认，A 从窗口后沿起重传未确认字节（3~10）并重新计时。

考点：收到累积确认后后沿右移、前沿（后沿 + W − 1）同步右移；窗口内字节四分类：已发送已确认 / 已发送未确认 / 未发送可发送 / 不可发送——选择题常按此分类设问。

超时重传与 RTT 估计

发送方每发出一个报文段即启动超时计时器：若 RTO（Retransmission Time-Out，超时重传时间） 内未收到确认，就重传该报文段。RTO 太短会大量无谓重传、太长则恢复慢，而网络 RTT 本身动态波动，因此 TCP 用自适应加权平均动态计算 RTO。

RTTS新​=(1−α)×RTTS旧​+α×RTT样本​,α=81​ RTTD新​=(1−β)×RTTD旧​+β×∣RTTS新​−RTT样本​∣,β=41​ RTO=RTTS+4×RTTD
  • 首次测量无旧值，直接取 RTTS=RTT样本​，RTTD=RTT样本​/2。
  • RTTS 是 RTT 的加权平均往返时间；RTTD 是 RTT 偏差的加权平均（表征波动幅度），故 RTO 留出 4 倍偏差余量。
  • Karn 算法：发生重传的报文段不采样 RTT（其确认无法区分对应原段还是重传段），且每重传一次 RTO 相应增大。

RTT 加权平均例题

例题：依次测得 3 个 RTT 样本：80 ms、112 ms、60 ms，逐轮求 RTTS、RTTD 与 RTO。

首轮（样本 80 ms）：

  • RTTS = 80 ms（首次直接取样本）；RTTD = 80 ÷ 2 = 40 ms
  • RTO = 80 + 4 × 40 = 240 ms

第 2 轮（样本 112 ms）：

  • RTTS = (7/8) × 80 + (1/8) × 112 = 70 + 14 = 84 ms
  • RTTD = (3/4) × 40 + (1/4) × |84 − 112| = 30 + 7 = 37 ms
  • RTO = 84 + 4 × 37 = 232 ms

第 3 轮（样本 60 ms）：

  • RTTS = (7/8) × 84 + (1/8) × 60 = 73.5 + 7.5 = 81 ms
  • RTTD = (3/4) × 37 + (1/4) × |81 − 60| = 27.75 + 5.25 = 33 ms
  • RTO = 81 + 4 × 33 = 213 ms
轮次 RTT 样本 (ms) RTTS (ms) RTTD (ms) RTO (ms)
首轮 80 80 40（= 样本/2） 240
2 112 84 37 232
3 60 81 33 213

验算：样本增大（112）时 RTTS、RTO 随之上调，样本减小（60）时又回落，符合”自适应”趋势 ✓

考点：RTTD 更新用的是新的 RTTS（不是旧 RTTS）与样本之差的绝对值；RTO = RTTS + 4×RTTD 是固定搭配。
易错点：首次测量 RTTD = 样本/2（不是 0）；重传报文段的确认不作为样本（Karn 算法）。

TCP 流量控制

流量控制（Flow Control）：让发送速率不要太快，使接收方来得及接收，防止接收方缓存溢出，是**点对点（端到端）**的控制。

  • 接收方按缓存余量计算接收窗口 rwnd，通过报文段首部**”窗口”字段**通告给发送方；
  • 发送方的发送窗口不得超过 rwnd；rwnd 随接收方应用读取速率动态变化，发送方随时跟随。

必考关系式：发送窗口=min(rwnd, cwnd) 接收能力（rwnd，接收方通告）与网络能力（cwnd，发送方推测）双重限制取较小值；两者之一变小时发送窗口立即受其约束。

零窗口、死锁与持续计时器

  • rwnd 递减到 0 进入零窗口：发送方必须停止发送，否则接收方缓存溢出。
  • 死锁风险：接收方缓存腾空后发来”rwnd > 0”的窗口更新通知，若该通知丢失——发送方等通知、接收方等数据，双方互相等待形成死锁。
  • 持续计时器（Persist Timer）：发送方收到零窗口后启动；每超时就发一个零窗口探测报文段（携带 1 字节数据），接收方收到后必须回应当前窗口值，从而打破死锁；探测超时则指数退避再探。

流量控制例题：rwnd 从 400 递减到 0

例题：B 的接收缓存为 400 B，A 依次发送 100 B/个的报文段，而 B 的应用进程读取较慢。

步骤 事件 B 缓存已存 (B) B 通告 rwnd (B)
1 连接建立后 B 通告窗口 = 缓存容量 0 400
2 A 发 300 B 到达，应用未读 300 100
3 A 再发 100 B 到达 400（满） 0（零窗口）
4 A 停发，启动持续计时器 400 —
5 应用读走 200 B，B 发出”rwnd = 200”更新 200 200
6 更新丢失 → 互等死锁；A 计时器超时发1 字节探测报文 200 —
7 B 回应当前 rwnd = 200，A 恢复发送 200 200

验算：任一时刻 rwnd = 400 − 缓存已存未读数据（步骤 2：400 − 300 = 100；步骤 3：400 − 400 = 0）✓

考点：rwnd 由接收方决定并通告；零窗口探测报文即使窗口为 0 也允许发送（否则探测本身会被”零窗口”卡死，死锁无解）。
易错点：窗口更新通知不携带数据、不占序号、不专门重传，可能丢失——这正是必须引入持续计时器的原因。

流量控制 vs 拥塞控制

两者都通过缩小窗口放慢发送速率，但控制对象与窗口归属完全不同：

对比项 流量控制 拥塞控制
控制对象 点对点（一对通信端点之间） 全局性（整个网络）
目的 防止接收方缓存溢出 防止过多数据注入网络，路由器/链路过载
窗口与归属 rwnd：由接收方确定，在首部”窗口”字段通告 cwnd：由发送方根据网络状况自行推测
判断依据 接收方读取/处理速度（缓存余量） 超时、重复 ACK（丢包信号）
共同点 都用滑动窗口限速；最终发送窗口 = min(rwnd, cwnd) 同左

高频考点：流量控制是点对点的局部行为，拥塞控制是全局性的网络行为；rwnd 归接收方、cwnd 归发送方，实际发送窗口取两者较小值——两条合并记忆，选择题直接考。

TCP 拥塞控制：四个算法

拥塞（Congestion）：注入网络的数据量超过网络（路由器缓存、链路带宽）承受能力，表现为丢包率上升、时延剧增。发送方维护拥塞窗口 cwnd（单位常用 MSS，最大报文段长度），并维护慢开始门限 ssthresh：cwnd < ssthresh 用慢开始；cwnd 达到 ssthresh 转拥塞避免。

慢开始与拥塞避免

  • 慢开始：连接建立或超时后，cwnd 从 1 个 MSS 起步，每收到一个 ACK 就 +1——于是一个传输轮次（≈ 1 个 RTT）内 cwnd 加倍：1 → 2 → 4 → 8 → …，指数增长。”慢”指起点低，不是增长慢。
  • 拥塞避免：cwnd ≥ ssthresh 后，每轮只 +1（线性 / 加法增大）：16 → 17 → 18 → …，缓慢试探网络上限。
  • 出现超时或3 个重复 ACK即判定拥塞，两种信号对应两种不同力度的处理。

考点：一个传输轮次 ≈ 一个 RTT。慢开始”每轮翻倍”是宏观效果，实现上是”每收到一个报文段的确认 cwnd 就 +1（微观）”——一轮内收齐全部在途确认，cwnd 恰好加倍。

超时后的处理：门限减半、cwnd 归 1

ssthresh=max(cwnd/2, 2),cwnd=1

超时说明网络可能严重拥塞：门限减半（教材口径直接取 cwnd/2），cwnd 归 1，重新慢开始。

快重传与快恢复

  • 快重传：接收方每收到一个失序报文段就立即重复确认；发送方一连收到 3 个重复 ACK（加上第 1 个正常确认共 4 个）后，立即重传丢失报文段，不等超时计时器到期——故称”快”。
  • 快恢复：随之 ssthresh=cwnd/2、cwnd=ssthresh（不归 1），直接进入拥塞避免线性增长。
  • TCP Tahoe vs Reno：Tahoe 无论超时还是 3 个重复 ACK 都把 cwnd 归 1 重新慢开始（无快恢复）；Reno 在 3 个重复 ACK 时执行快重传 + 快恢复——现代 TCP 默认 Reno 风格。

四算法对比

算法 触发条件 动作 cwnd 变化
慢开始 cwnd < ssthresh（初建连接、超时后） 从 1 MSS 起指数增长 每 RTT 翻倍（1→2→4→8…）
拥塞避免 cwnd ≥ ssthresh 线性”加法增大” 每 RTT +1
快重传 收到 3 个重复 ACK 立即重传丢失报文段 本身不改变 cwnd
快恢复 快重传之后 门限减半、跳过慢开始 cwnd = 新 ssthresh，转拥塞避免
对比项 超时 3 个重复 ACK
拥塞程度判断 严重（可能大范围丢包） 轻度（个别报文段丢失，后续段仍能到达）
ssthresh = cwnd / 2 = cwnd / 2
cwnd = 1，重新慢开始（指数） = 新 ssthresh，直接拥塞避免（线性）
版本支持 Tahoe、Reno 均有 仅 Reno（Tahoe 一律 cwnd 归 1）

易错点：”3 个重复 ACK”指连续 3 个内容相同（确认号相同）的重复确认，不含最初那个正常确认；它是”个别丢包、其余正常”的信号，所以处理比超时温和——这正是两个考点最常对比的地方。

拥塞控制全程例题（最重要）

例题：TCP 连接初始 cwnd=1、ssthresh=16（单位 MSS），每轮（RTT）结束后列出 cwnd；设在第 13 轮（cwnd = 24）发生拥塞，分别按”超时”与”3 个重复 ACK”两种情形推演。

前 13 轮（两种情形相同）：

轮次 cwnd 阶段 说明
1 1 慢开始 起点
2 2 慢开始 翻倍
3 4 慢开始 翻倍
4 8 慢开始 翻倍
5 16 慢开始（达门限） cwnd = ssthresh，下一轮转拥塞避免
6 17 拥塞避免 +1
7 18 拥塞避免 +1
8 19 拥塞避免 +1
9 20 拥塞避免 +1
10 21 拥塞避免 +1
11 22 拥塞避免 +1
12 23 拥塞避免 +1
13 24 拥塞避免 本轮发生拥塞（超时 / 3 个重复 ACK）

情形①：第 13 轮超时

  • ssthresh=24/2=12（≥ 2，与 max 公式结果一致）；cwnd=1，重新慢开始
  • 慢开始：1 → 2 → 4 → 8 → 12（翻倍将越过新门限，按”达到门限即转”处理）→ 转拥塞避免：13 → 14 → …

情形②：第 13 轮收到 3 个重复 ACK（快重传 + 快恢复）

  • 立即重传丢失报文段；ssthresh=24/2=12；cwnd=12，直接进入拥塞避免
  • 之后：13 → 14 → …

两种情形后续演变对比：

轮次 14 15 16 17 18 19 20
情形①（超时，cwnd 归 1） 1 2 4 8 12（转拥塞避免） 13 14
情形②（快恢复，cwnd = 12） 12 13 14 15 16 17 18

验算与结论：要回升到 cwnd = 16，情形①需 9 轮（第 22 轮），情形②只需 5 轮（第 18 轮）——超时判定”严重拥塞”、代价更大；快恢复只是”轻踩刹车” ✓

变式训练：同题改为第 9 轮（cwnd = 20）发生拥塞：

  • 若超时：ssthresh = 20 / 2 = 10，cwnd = 1，重新慢开始：1 → 2 → 4 → 8 → 10（达新门限转拥塞避免）→ 11 → 12 …
  • 若 3 个重复 ACK：ssthresh = 10，cwnd = 10，直接拥塞避免：11 → 12 → …

拥塞控制大题解题模板：

  1. 定分界一：慢开始期间逐轮 ×2，找到 cwnd 首次达到 ssthresh 的轮次，此后转每轮 +1；
  2. 定分界二：发生超时或 3 个重复 ACK 的轮次，记此时 cwnd = C；
  3. 超时 → ssthresh = C/2、cwnd = 1 重走指数；3 个重复 ACK → ssthresh = C/2、cwnd = C/2 走线性；
  4. 新阶段从对应起点继续推算，注意”翻倍将越过门限时按达到门限处理”。

考点：cwnd 达到 ssthresh 即由慢开始转拥塞避免；超时 → ssthresh 减半 + cwnd 归 1 走指数；3 个重复 ACK → ssthresh 减半 + cwnd = 新门限走线性。两种情形 ssthresh 相同、cwnd 起点不同，恢复速度不同。
易错点：问”第 N 轮 cwnd = ?”时先定位两个分界（哪轮达到 ssthresh、哪轮发生拥塞），再逐段用”翻倍 / +1 / 归 1 / = ssthresh”推算，切勿全程 +1。

与数据链路层滑动窗口的区别

TCP 的滑动窗口与链路层的停等 / GBN / SR 形似而神不同：

对比项 链路层滑动窗口（停等/GBN/SR） TCP 滑动窗口
编号单位 帧 字节
窗口大小 固定（由帧序号字段位数决定，如 GBN ≤ 2ⁿ−1、SR ≤ 2ⁿ⁻¹） 动态变化（受 rwnd、cwnd 实时调节）
确认语义 按帧号确认（GBN 累积到帧、SR 逐帧选择确认） 累积确认：ack = 期望的下一字节序号
控制范围/目的 相邻结点间的可靠传输与流量控制 端到端可靠传输 + 流量控制 + 拥塞控制

考点：一句话记忆——链路层窗口管相邻结点、按帧、窗口固定；TCP 窗口管端到端、按字节、窗口动态（发送窗口 = min(rwnd, cwnd)）。

高频考点速记

考点 记忆
确认号 ack = 期望收到的下一字节序号；ack=N ⇒ N−1 及以前全收（累积确认）
可靠机制四件套 校验 + 序号 + 确认（累积/捎带）+ 重传（超时重传 / 快重传）
RTTS 更新 新 RTTS = (1−1/8)×旧 + (1/8)×样本；首次 RTTS = 样本
RTTD 与 RTO RTTD = 3/4×旧 + 1/4×(新 RTTS 与样本差绝对值)，首次 = 样本/2；RTO = RTTS + 4×RTTD
Karn 算法 重传报文段不采样 RTT；每重传一次 RTO 增大
发送窗口 min(rwnd, cwnd)；rwnd 由接收方在首部”窗口”字段通告，cwnd 由发送方推测
流量控制 点对点，防接收方缓存溢出；rwnd 随缓存余量动态变化
零窗口死锁 rwnd=0 停发；窗口更新通知丢失 → 互等死锁；**持续计时器 + 零窗口探测（1 字节）**破死锁
拥塞控制 全局性，防过多数据注入网络；cwnd 单位 MSS；cwnd ≥ ssthresh 转拥塞避免
慢开始 cwnd 从 1 起每 RTT 翻倍（更准确：每收 1 个 ACK +1）；”慢”指起点低，增长是指数
拥塞避免 每 RTT +1，线性（加法增大）
超时（严重拥塞） ssthresh = cwnd/2（教材口径，或 max(cwnd/2, 2)）；cwnd = 1 重新慢开始
快重传 3 个重复 ACK 立即重传、不等超时；本身不改 cwnd
快恢复 ssthresh = cwnd/2，cwnd = 新 ssthresh 直接进拥塞避免（Reno 有，Tahoe 无）
流控 vs 拥塞 流量控制点对点（rwnd 归接收方）；拥塞控制全局（cwnd 归发送方）；发送窗口取小
TCP vs 链路层窗口 TCP 按字节编号、累积确认、窗口动态；链路层按帧、窗口固定
