ARP、DHCP与ICMP

2026-08-29
  • 计算机网络

ARP、DHCP 与 ICMP 是网络层的三个”配角”协议：ARP 解决”下一跳的 MAC 地址是多少”——把 IP 地址解析成 MAC 地址；DHCP 解决”主机开机后 IP 地址、子网掩码、默认网关从哪来”——自动配置网络参数；ICMP 解决”分组在网络里走丢了谁来告诉你”——差错报告与连通性探测。408 对这三个协议的考查集中在：ARP 的广播请求/单播响应与跨网段解析网关、DHCP 的 DORA 四步流程与租用期、ICMP 的两类报文与”差错不再产生差错”。

为什么需要 ARP：IP 地址到 MAC 地址的最后一步

IP 层是虚拟互联：分组从源主机到目的主机要穿越多个异构的物理网络，端到端寻址靠 IP 地址。但数据链路层的实际交付用的是 MAC 地址——帧在同一个局域网内必须封装成”目的 MAC = 下一跳”的形式，网卡和交换机才认识。因此主机发送分组前，必须把下一跳的 IP 地址解析成对应的 MAC 地址，这就是 **ARP（Address Resolution Protocol，地址解析协议）**的任务。

为什么不全网只用 MAC 互联：MAC 地址是扁平的、不反映位置，全网按 MAC 路由需要每台设备维护一张”天文数字”规模的表；IP 地址按网络分层编址，路由表才能聚合。所以：IP 负责全局找位置，MAC 只负责本网段交付。

对比项 IP 地址 MAC 地址
所在层次 网络层（逻辑地址，反映位置） 数据链路层（物理地址，标识网卡）
在一次通信中 源到目的全程不变 每经过一个网段就变一次
谁负责转换 — ARP：IP → MAC

考点：分组传输中 IP 地址不变、MAC 地址逐段改变——“源/目的 IP”描述端到端，”源/目的 MAC”只描述本网段一跳。
易错点：ARP 解析的不是”目的主机的 MAC”，而是下一跳的 MAC——同网段时是目的主机，跨网段时是默认网关（路由器接口）。

ARP 报文格式

ARP 报文固定 28 字节，直接封装在以太网帧中（帧类型字段 0x0806），不经过 IP 协议：

字段 长度 说明
硬件类型 16 位 以太网 = 1
协议类型 16 位 要解析的上层协议，IPv4 = 0x0800
硬件地址长度 8 位 MAC 地址为 6
协议地址长度 8 位 IP 地址为 4
操作（op） 16 位 1 = ARP 请求，2 = ARP 响应
发送方 MAC + 发送方 IP 48 + 32 位 发送方自己的地址
目标 MAC + 目标 IP 48 + 32 位 请求时目标 MAC 填全 0（正待解析）

ARP 请求 vs ARP 响应

对比项 ARP 请求 ARP 响应
传播方式 广播（目的 MAC 全 1：FF-FF-FF-FF-FF-FF） 单播（只发给请求者）
操作字段 op 1 2
携带内容 “谁的 IP 是 x.x.x.x？请告诉我你的 MAC” “x.x.x.x 的 MAC 是 xx-xx-xx-xx-xx-xx”
谁更新缓存 收到请求的所有主机均可记下请求方的 IP→MAC 请求者记下响应方的 IP→MAC

考点：ARP 请求是广播，ARP 响应是单播——408 最爱考的一句话。
拓展：ARP 不验证响应真伪，攻击者可伪造”网关 IP → 自己 MAC”的假响应污染缓存，形成ARP 欺骗（中间人窃听/断网），安全拓展了解即可。

ARP 完整工作过程（两种情形）

主机发送前先查 ARP 高速缓存——一张 IP→MAC 映射表，动态条目有生存期，约 15~20 分钟后老化删除，再用到时重新解析（防止映射过期后失效）。

情形一：同网段（A 直接交付给 B）

主机 A（192.168.1.10/24）要发数据给主机 B（192.168.1.20/24）：

  1. A 用本机子网掩码与 B 的 IP 相与，结果 = 本子网网络地址 → 同网段，直接交付；
  2. 查 ARP 高速缓存：命中则直接封装帧发送，流程结束；未命中则继续；
  3. A 广播 ARP 请求（op=1，目的 MAC 全 1）：本网段所有主机都收到该帧；
  4. 主机 B 发现请求中的目标 IP 是自己 → 以单播方式回送 ARP 响应（op=2），告知自己的 MAC；其余主机发现目标 IP 不是自己，丢弃请求；
  5. A 把 B 的 IP→MAC 写入高速缓存，封装帧（源 MAC = A，目的 MAC = B）发送数据；
  6. B 收到数据帧后，把 A 的映射也记入自己的缓存——下次回包免再解析。

情形二：跨网段（A 发给另一网段的主机 C，解析默认网关）

主机 A（192.168.1.10/24）要发给主机 C（10.0.0.5/24）：

步骤 动作 说明
① 判断网段 掩码与 C 的 IP 相与 ≠ 本网络地址 → 不同网段，间接交付
② 确定下一跳 查路由表 / 默认路由，下一跳为默认网关 192.168.1.1
③ ARP 解析网关 广播”谁是 192.168.1.1？”——请求的是网关的 MAC，而不是 C 的 MAC
④ 封装发送 帧首部：源 MAC = A、目的 MAC = 网关；IP 首部：源 IP = A、目的 IP = C
⑤ 路由器逐跳转发 每台路由器在下一个网段重新 ARP 解析下一跳 MAC，IP 首部全程不变

易错点：跨网段通信时 A 广播请求的是默认网关（路由器接口）的 MAC——分组是”逐网段交付”的，源/目的 IP 全程不变，MAC 地址逐段更换（如上图：H1→R1 用 HA₁→HA₃，R1→R2 用 HA₄→HA₅……）。

DHCP：动态主机配置协议

**DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）**给新上线的主机自动分配 IP 地址、子网掩码、默认网关、DNS 服务器地址等一整套网络配置。

  • 层次定位（高频考点）：DHCP 是应用层协议——报文靠 UDP 封装传输、采用客户/服务器（C/S）模式；但它干的活是为网络层服务的（给主机自动配置 IP）；
  • 服务器使用 UDP 端口 67，客户端使用 UDP 端口 68；
  • 早期无盘工作站用 RARP（MAC→IP）获取地址，如今已被 DHCP 取代。

DORA 四步流程

步骤 报文 方向 广播/单播 关键内容
① Discover（发现） 客户端 → 服务器 广播 客户端还没有 IP：源 0.0.0.0，目的 255.255.255.255
② Offer（提供） 服务器 → 客户端 广播（也可单播） 从地址池选一个 IP，连同掩码、租用期一并”报价”
③ Request（请求） 客户端 → 服务器 广播 确认选择某服务器的报价，同时告知落选服务器可收回地址
④ Ack（确认） 服务器 → 客户端 广播（也可单播） 确认租用生效，客户端正式获得该 IP

完整过程（盯住源/目的地址与端口的变化）：

  1. 客户端开机后广播 DHCPDISCOVER：UDP，源端口 68、目的端口 67；源 IP = 0.0.0.0（自己还没有 IP），目的 IP = 255.255.255.255（有限广播，路由器不转发）；
  2. 网段内每台 DHCP 服务器都收到，各自从地址池挑一个 IP，回送 DHCPOFFER（含提供的 IP、子网掩码、租用期）；
  3. 客户端可能收到多个 Offer，通常选最先到达的一个，再次广播 DHCPREQUEST：既向被选服务器正式要地址，也让其他服务器知道自己落选；
  4. 被选中的服务器回 DHCPACK，客户端绑定该 IP 与配置参数；若收到 DHCPNACK（拒绝），则重新从 Discover 开始。

考点：四步中 Discover、Request 一定广播——客户端尚无 IP，源地址只能是 0.0.0.0、目的地址只能有限广播；Offer、Ack 通常广播也可单播。
易错点：DHCP 基于 UDP、属应用层协议，不是网络层协议——但它的任务是为网络层配置 IP。

租用期与地址重用

DHCP 分配的地址带租用期（lease period），不是永久的：

  • 租用期过半（0.5T）时，客户端向原服务器发 DHCPREQUEST 请求续租：同意则继续使用并刷新租用期，不同意则到期后释放 IP、重新走 DORA；
  • 主机正常下线也可主动释放，地址回到地址池供他人使用——同一地址可重用。

DHCP 中继代理

客户端与服务器不在同一网段时，Discover 的有限广播（255.255.255.255）无法穿过路由器。解决办法：在路由器上配置 DHCP 中继代理（relay agent）——它收到本网的 Discover 后，以单播方式转发给其他网络上的 DHCP 服务器，服务器应答再经它送回。这样一个 DHCP 服务器就能服务多个网段。

考点：中继代理解决了”广播不出网段”与”全网只建一台 DHCP 服务器”的矛盾；转发时不再广播，而是单播。

ICMP：网际控制报文协议

ICMP（Internet Control Message Protocol，网际控制报文协议）让主机和路由器能报告 IP 层的问题（不可达、超时、重定向……）并互相询问（连通性探测）。它属于网络层协议，但报文封装在 IP 数据报的数据部分传输，IP 首部协议字段 = 1。

考点：ICMP 只报告差错，不负责改正差错——纠错（如重传）由高层协议（TCP 等）完成。
易错点：ICMP 虽封装在 IP 数据报内，但它本身是网络层协议，不属于传输层。

ICMP 报文格式

  • 前 4 个字节统一：类型（8 位）+ 代码（8 位）+ 校验和（16 位）；接着 4 字节取决于类型；之后是数据部分（长度取决于类型）；
  • 差错报告报文的数据部分 = 出错 IP 数据报的首部 + 数据部分的前 8 字节——带上传输层前 8 字节，源主机才能按端口号找到出错的进程。

两类报文对比（差错 vs 询问）

对比项 差错报告报文 询问报文
作用 发现异常时被动报告问题 主动查询获取信息
类型号 3 终点不可达、4 源点抑制、11 时间超过、12 参数问题、5 改变路由 8/0 回送请求/应答、13/14 时间戳请求/应答
典型场景 路由器/主机处理分组遇阻时发送 ping 测连通性、时间戳测往返时延
依赖它的应用 traceroute 靠”时间超过” ping

五种差错报告报文：

类型号 报文 触发场景
3 终点不可达 路由无匹配、目的端口未监听、DF=1 却必须分片等
4 源点抑制 拥塞时请源站减速（已废弃，仍列入考纲五类）
11 时间超过 TTL 减为 0 被丢弃 / 分片重组超时
12 参数问题 IP 数据报首部字段有错
5 改变路由（重定向） 告诉源主机：有更优的下一跳

考点：源点抑制已废弃，但考纲仍按五类计；重定向只对同一网段的主机有意义。

不发送差错报文的四种情况

ICMP 差错报文本身也要封装成 IP 数据报发送，为避免”差错套差错”无限递归，以下情况不再发送 ICMP 差错报文：

  1. 对 ICMP 差错报文本身出现的问题（差错不再引发差错）；
  2. 对第一个分片之后的后续分片出错（源主机等不到首片自然知道丢分片）；
  3. 对目的地址为组播地址 / 广播地址的分组（否则一发差错就全网风暴）；
  4. 对源地址为特殊地址（0.0.0.0、127.x.x.x 环回等）的分组。

易错点：是”第一个分片以外的后续分片”不发差错报文——第一个分片出错仍然要发。

ping 与 traceroute

命令 使用的 ICMP 报文 原理
ping 回送请求（类型 8）/ 回送应答（类型 0） 发请求、收应答，测连通性与往返时延
traceroute / tracert 时间超过（类型 11）+ 终点不可达（类型 3） 依次发 TTL =1,2,3,… 的探测分组：第 n 跳路由器因 TTL 归零回”时间超过”（暴露第 n 跳）；到达终点（终点不可达）即结束

考点：ping 用 ICMP 回送请求/应答——不是 TCP 也不是 UDP；traceroute 靠时间超过报文逐跳定位路径、靠终点不可达判断到达终点。
易错点：Windows 的 tracert 发回送请求探测、靠”时间超过”定位；Linux 的 traceroute 发 UDP 探测、终点回”终点不可达”——408 按”时间超过 11 + 终点不可达 3“记忆。

例题：ping 全过程与 TTL 反推跳数

过程演示：主机 A（192.168.1.10/24）ping 同网段主机 B（192.168.1.20）：

  1. A 先查 ARP 高速缓存解析 B 的 MAC：未命中则广播 ARP 请求、B 单播响应；
  2. A 发送 ICMP 回送请求（类型 8）：作为 IP 数据报的数据部分（协议字段 1）封装，源 IP = A、目的 IP = B；
  3. B 收到后回送 ICMP 回送应答（类型 0），同样封装成 IP 数据报发回 A；
  4. A 收到应答 → 判定连通，输出往返时延 RTT。（若中间加路由器：目的 IP 不变，目的 MAC 换成网关，TTL 逐跳减 1。）

例题：规定分组初始 TTL = 64，A ping 另一网段的主机 C 时回显 “TTL = 61”，求途经的路由器数。

  • TTL 每经过一台路由器减 1：途经路由器数 = 64−61=3；
  • 若回显 “TTL = 64”，说明未经过任何路由器（同网段直达）。

考点：初始 TTL 减去到达时的 TTL = 途经路由器数；由回显 TTL 还可粗判对端系统类型（Windows 初始 128、Linux 初始 64）。

三个协议的封装层次对比（高频易错）

协议 层次定位 封装方式 协议/端口标识
ARP 网络层辅助协议 直接封装在以太网帧，不经过 IP 帧类型字段 0x0806
DHCP 应用层协议（为网络层服务） UDP 数据报 → IP 数据报 UDP 端口 67（服务器）/ 68（客户端），IP 协议字段 17
ICMP 网络层协议 IP 数据报的数据部分 IP 首部协议字段 = 1

易错点：ARP 不走 IP（直接封装在帧里）；ICMP 走 IP（协议字段 1）但仍是网络层协议；DHCP 走 UDP、是应用层协议——三个协议层次各不相同，选择题最爱混着考。

高频考点速记

考点 记忆
ARP 作用 IP → MAC，解析下一跳的 MAC；链路层实际交付用 MAC
ARP 请求 vs 响应 请求广播（目的 MAC 全 1）、响应单播；op = 1 / 2
跨网段 ARP 解析默认网关的 MAC；IP 全程不变、MAC 逐段改变
ARP 高速缓存 存 IP→MAC 映射，生存期约 15~20 分钟，超时老化重解析
ARP 报文封装 直接封装在以太网帧（类型 0x0806），不经 IP
DHCP 定位 应用层协议、基于 UDP（67/68）、C/S 模式，为网络层配置 IP
DORA 四步 Discover → Offer → Request → Ack；Discover/Request 必广播（源 0.0.0.0，目的 255.255.255.255）
DHCP 租用期 租用期过半（0.5T）请求续租，到期不续则释放；RARP 已被 DHCP 取代
DHCP 中继代理 跨网段时由路由器单播转发 Discover 给别网服务器，一台服务器服务多网段
ICMP 定位 网络层协议，封装在 IP 数据报（协议字段 1）；只报告不改正差错
ICMP 报文格式 类型 + 代码 + 校验和（前 4B 统一）；差错报文带出错数据报首部 + 前 8 字节
ICMP 两类报文 差错：3/4/11/12/5；询问：回送 8/0、时间戳 13/14
不发差错报文 对差错报文自身、首片以后的分片、组播/广播、特殊源地址不发
