路由算法与路由协议

2026-08-29
  • 计算机网络

网络层的两大任务中，分组转发是”查表、从哪个口送出去”的本地动作，而路由选择是”决定走哪条路”的全局决策——路由表怎么来，靠的就是路由算法与路由协议。路由算法是获得路由表中各表项所用的算法，是路由选择协议的核心：静态算法靠人工配置，动态算法（距离-向量、链路状态）让路由器自动适应网络变化；当网络规模大到一定程度，再按自治系统（AS） 划分层次，域内用 RIP/OSPF，域间用 BGP。408 的考查集中在：静态与动态路由、距离-向量算法（RIP）、链路状态算法（OSPF）、层次路由与 BGP，其中”RIP vs OSPF vs BGP 三巨头对比”几乎是历年必考。

静态路由与动态路由

按路由算法能否随通信量或网络拓扑的变化自适应调整，路由选择分为两大类：

对比项 静态路由选择 动态路由选择
别名 非自适应路由选择 自适应路由选择
路由来源 管理员人工配置每一条路由 路由协议（RIP/OSPF/BGP）自动交换、计算
优点 简单、开销较小，结果可靠、可预测 能及时适应网络状态（拓扑/故障/负载）变化
缺点 拓扑变化后不能自动调整（链路故障需人工改表） 实现复杂、开销较大（交换报文占用带宽与 CPU）
适用 简单的小网络、末梢网络 较复杂的大网络

理想路由算法应具备 6 个特点，常以选择题形式考查：

特点 含义
正确、完整 沿路由表指引，分组一定能到达目的
计算简单 不给网络增加太多额外开销
自适应性 能自适应通信量与拓扑变化，均衡各链路负载
稳定性 拓扑稳定时收敛于可接受的解，路由不振荡
公平性 对所有用户平等，不为个别用户损害大家
最佳性 “最佳”是相对特定要求的合理选择（时延小或可靠性高）

考点：动态路由 = 自适应路由；静态路由简单开销小但无法自适应，动态路由反之。
易错点：”稳定性”即收敛性——后文 RIP”坏消息传得慢”与 OSPF”收敛快”都是收敛性的具体体现；”最佳”不等于”绝对最优”。

距离-向量路由算法

Bellman-Ford 思想

距离-向量（Distance Vector，DV）算法基于 Bellman-Ford 思想：到某目的网络的最短距离，等于”到某个邻居的距离 + 该邻居到目的网络的距离”中的最小值：

Dx​(y)=vmin​{c(x,v)+Dv​(y)}

其中 c(x,v) 是本路由器 x 到邻居 v 的代价，Dv​(y) 是邻居 v 到目的网络 y 的距离。每个路由器维护一张”到各目的网络的距离表“，并定期与相邻路由器交换整张距离表——它只知道邻居报来的”二手信息”，从不知道全网拓扑，这是与链路状态算法的根本区别。

RIP 路由协议

RIP（Routing Information Protocol，路由信息协议）是内部网关协议（IGP），把 DV 思想中的”距离”具体化为跳数，最大优点是实现简单、开销较小。

项目 内容
度量 跳数：直连网络 = 1；非直连 = 经过的路由器数 + 1；最大 15，16 = 不可达
和谁交换 仅与相邻路由器交换
交换什么 自己的整张路由表（到本 AS 所有网络的距离 + 下一跳）
何时交换 每 30 秒定期交换；拓扑变化时及时通告；3 分钟收不到某邻居的更新 → 把该邻居记为不可达（距离 16）
承载 UDP，端口 520（RIP 是应用层协议）
选路 只选跳数最少的一条路由，不支持等代价负载均衡
适用 小型网络（15 跳封顶）

收到邻居 X 的 RIP 报文后，按距离向量算法更新路由表（四步）：

步骤 操作
① 修改报文 报文中所有下一跳改为 X、所有距离 + 1
② 逐项比较 目的网络表中没有 → 加入；下一跳相同 → 替换（即使距离增大）；距离更小 → 更新；否则什么也不做
③ 超时 3 分钟未收到 X 的更新 → 到 X 的距离置 16
④ 返回 处理下一个报文

考点：RIP 三要点口诀——“和谁换：仅邻居；换什么：整张表；何时换：30 秒 + 变化即发”。
易错点：RIP 是应用层协议（基于 UDP 520）；跳数 16 表示不可达（不是”还能到第 16 跳”）；RIP 不支持多路由/负载均衡——即使存在低时延但路由器更多的路径也弃用。

RIP 例题：距离向量更新路由表

题目：路由器 B 的原路由表如下（左），现收到相邻路由器 C 发来的距离向量：N2 = 4，N3 = 1（N3 是 C 的直连网络），N4 = 9，N7 = 5。按 RIP 规则更新 B 的路由表。

目的网络 距离 下一跳
N1 1 直接交付
N2 6 C
N3 8 A
N4 4 A

第一步：修改 C 的报文——距离全部 +1、下一跳全部改为 C：

  • N2：4 → 5；N3：1 → 2；N4：9 → 10；N7：5 → 6

第二步：与原表逐项比较并更新：

目的网络 来自 C +1 后（下一跳 C） B 原表（距离, 下一跳） 比较与规则 更新结果
N1 （未通告） — (1, 直接) C 未通告，直连项不受影响 (1, 直接) 不变
N2 4 5 (6, C) 下一跳同为 C → 无条件替换 (5, C) 更新
N3 1 2 (8, A) 下一跳不同，2 < 8 → 更新 (2, C) 更新
N4 9 10 (4, A) 下一跳不同，10 > 4 → 保留原项 (4, A) 不变
N7 5 6 表中没有 新目的网络 → 加入 (6, C) 新增

更新后的 B 路由表：

目的网络 距离 下一跳
N1 1 直接交付
N2 5 C
N3 2 C
N4 4 A
N7 6 C

考点：先”+1、改下一跳”再比较——表中没有 → 加入；同下一跳 → 无条件替换（哪怕距离变大）；不同下一跳 → 更小才更新；否则什么也不做。
易错点：N7 是新表项，不能因为”距离 6 不算小”而拒绝加入；N4 收到的 10 比原 4 大且下一跳不同 → 什么也不做（别把 10 写进表）。

好消息传得快，坏消息传得慢

RIP 的根本隐患：好消息传得快，坏消息传得慢（无穷计数，Count-to-Infinity）。设 R1 直连网 1（距离 1），R2 经 R1 到网 1（距离 2）。网 1 故障后：

轮次 R1 到网 1 R2 到网 1 说明
故障前 1（直连） 2（经 R1） 正常收敛
故障瞬间 16 2 R1 置 16；但 R2 的旧更新（距离 2）先到
第 1 轮交换 3 4 R1 误判”可经 R2”：2 + 1 = 3；R2 收到 3 → 4
第 2 轮交换 5 6 R1 收到 4 → 5；R2 收到 5 → 6
…… 每轮 +2 每轮 +2 两者互相”抬价”
计数到 16 16 16 才真正确认不可达（每轮 30s，感知故障需数分钟）

缓解手段：水平分割——不从”学来这条路由的方向”再通告回去；毒性逆转——把从邻居学到的路由以距离 16 通告回去（熟悉概念即可）。

考点：16 = 不可达正是给”无穷计数”设的上限；”坏消息传得慢” = 收敛慢，是 RIP 的根本缺点，也是 OSPF 诞生的直接动因。

链路状态路由算法

泛洪 LSA 与链路状态数据库

链路状态（Link State，LS）算法与 DV 完全相反：每个路由器把与自己相邻的链路状态（和谁相邻 + 链路代价）封装成链路状态通告 LSA（Link State Advertisement），用洪泛（Flooding）法发给全网（区域内所有路由器）；最终每台路由器都建立一张全网一致的链路状态数据库 LSDB——它就等于全网的拓扑图。之后每台路由器以自己为源点，用 Dijkstra 算法算出最短路径树，生成路由表。

要点 链路状态（OSPF） 对照：距离向量（RIP）
和谁交换 全网所有路由器（洪泛） 仅相邻路由器
交换什么 与相邻路由器的链路状态 LSA（只是部分信息） 自己的整张路由表
何时交换 只有链路状态变化时才洪泛（LSDB 另每 30 分钟刷新） 每 30 秒定期交换

Dijkstra 例题：求最短路径树

某网络拓扑以邻接表描述（无向、代价对称）：

节点 邻接（节点 : 代价）
A B : 2，C : 5
B A : 2，C : 1，D : 6
C A : 5，B : 1，D : 2，E : 7
D B : 6，C : 2，E : 3，F : 6
E C : 7，D : 3，F : 1
F D : 6，E : 1

以 A 为源点执行 Dijkstra：每轮从未选入的节点中取 dist 最小者加入集合 S，并松弛其邻居。

轮次 选入节点（dist） B C D E F
初始 A (0) 2 经 A 5 经 A ∞ ∞ ∞
1 B (2) 2 ✓ 3 经 B 8 经 B ∞ ∞
2 C (3) — 3 ✓ 5 经 C 10 经 C ∞
3 D (5) — — 5 ✓ 8 经 D 11 经 D
4 E (8) — — — 8 ✓ 9 经 E
5 F (9) — — — — 9 ✓

最短路径树与验算：

目的 最短距离 路径 验算
B 2 A-B 2 ✓
C 3 A-B-C 2 + 1 = 3 < 5（直连 A-C = 5 被更新）✓
D 5 A-B-C-D 2 + 1 + 2 = 5 ✓
E 8 A-B-C-D-E 5 + 3 = 8 < 10（C-E = 7 的旧值被更新）✓
F 9 A-B-C-D-E-F 8 + 1 = 9 < 11（D-F = 6 的旧值被更新）✓

考点：Dijkstra 每轮只确定一个当前 dist 最小的节点，一旦选入不再改变；链路状态算法中每个节点都要各自跑一遍 Dijkstra——计算量大是它的代价。
易错点：dist 更新时要连同前驱（经谁而来）一起记录，最后沿前驱回溯才得到路径树；只有新 dist 变小才更新。

OSPF 路由协议

OSPF（Open Shortest Path First，开放最短路径优先）是内部网关协议，1989 年为克服 RIP 的缺点而开发：”开放” = 协议公开发表、不受某一家厂商控制；”最短路径优先” = 使用 Dijkstra 最短路径算法。

项目 内容
核心流程 洪泛 LSA → 全网同步 LSDB → Dijkstra 算最短路径树 → 生成路由表
度量 代价（Cost）：可配置、常与链路带宽相关；无跳数限制
承载 直接封装在 IP 数据报中，协议号 89（不用 UDP/TCP）
组播 通告发往组播地址 224.0.0.5（所有 OSPF 路由器）/ 224.0.0.6（指定路由器 DR）
收敛 快：变化立即洪泛，响应时间 < 100ms，没有”坏消息传得慢”问题
其他特点 等代价多路径负载均衡（RIP 不支持）；分组带鉴别功能；支持 VLSM/CIDR；LSDB 每 30 分钟刷新一次

OSPF 的五种分组类型：

分组 作用
Hello 发现并维持邻站可达性（每 10s 一次，40s 收不到判不可达）
数据库描述（DD） 向邻站给出自己 LSDB 的摘要
链路状态请求（LSR） 请求某些链路状态项目的详细信息
链路状态更新（LSU） 用洪泛法更新链路状态（最复杂、最核心）
链路状态确认（LSAck） 对 LSU 的确认

区域划分（层次化链路状态）

洪泛的通信量随网络规模膨胀，OSPF 进一步把一个 AS 划分为若干区域（Area）：

  • 洪泛被限制在本区域内，区域内路由器只知道自己区域的拓扑，大大减少通信量
  • 主干区域 0.0.0.0：位于上层，负责连通所有下层区域
  • 区域边界路由器（ABR）：连接主干区域与下层区域，概括并转发区域间路由（每个区域至少一个）
  • 主干路由器：位于主干区域内的路由器（可以同时是 ABR）
  • AS 边界路由器（ASBR）：专门与本 AS 之外的其他自治系统交换路由信息

考点：OSPF 与 RIP 的本质区别——洪泛全网 vs 仅邻居、LSA（部分链路状态）vs 整张表、变化才发 vs 30s 定期；OSPF 支持等代价负载均衡、收敛快、分区域、无跳数限制。
易错点：OSPF 分组不封装成 TCP/UDP 报文，直接作为 IP 数据报的数据部分（协议字段 = 89）；”开放”指协议公开不受厂商控制，不是”开源”。

层次路由与自治系统

互联网规模巨大：任何一台路由器都不可能装下全网的路由表，各机构也需要独立管理、自主选路。于是把互联网划分成许多自治系统（AS，Autonomous System）：同一 AS 内部使用统一的路由策略与同一种内部路由协议，对外通过统一的出口呈现为一个整体。

对比项 域内路由（IGP，内部网关协议） 域间路由（EGP，外部网关协议）
作用范围 AS 内部 AS 之间（互联网骨干层）
典型协议 RIP、OSPF BGP
选路目标 找”最好“的路由（代价/时延最优，讲效率） 策略允许下”可达“的路由（讲可控性）
关注因素 跳数、代价、时延 政治、安全、经济等策略

考点：层次路由的两大动因——路由表规模太大 + 管理边界（各 AS 自治）；术语要能写全：Interior / Exterior Gateway Protocol。
易错点：”网关协议”是历史名称，实际就是路由协议；IGP/EGP 是类别，RIP/OSPF/BGP 才是具体协议。

BGP 路由协议

BGP（Border Gateway Protocol，边界网关协议）是 AS 之间的外部网关协议（EGP），基于路径向量（Path Vector）算法：通告的不是距离，而是”到达某目的网络依次经过哪些 AS“的路径序列（如”到 10.0.0.0/8 途经 AS2-AS5”）——见路径中含有自己的 AS 号即可判定环路。

项目 内容
作用范围 AS 之间（域间路由，互联网骨干层）
算法 路径向量：携带完整 AS 序列，天然可检测环路
交换对象 相邻的 BGP 发言人（BGP Speaker）——通常为 AS 边界上的 BGP 路由器
承载 TCP，端口 179（路由信息量大、跨 AS 必须可靠，可靠性交给 TCP）
选路 策略性选路：按政治、安全、经济策略选”好”的可达路径，不保证最短
交换时机 建立连接时交换全表，之后变化时增量更新
  • eBGP（外部 BGP）：不同 AS 的发言人之间交换路由信息；iBGP（内部 BGP）：同一 AS 内部的 BGP 路由器之间传递 AS 间路由信息（报文格式相同，运行场景不同）
  • 四种报文：OPEN（建立邻居关系）、UPDATE（通告新路由 / 撤销旧路由）、KEEPALIVE（周期保活）、NOTIFICATION（报告差错并关闭连接）

考点：BGP 找的不是最短路径，而是策略允许的可达路径（可达即可，”好”优先于”短”）；用 TCP 179 是因为 AS 间路由信息量大且必须可靠交付。
易错点：三个承载要配对——RIP = UDP 520，OSPF = IP 协议号 89，BGP = TCP 179；BGP 是路径向量协议，既非距离向量也非链路状态。

距离向量 vs 链路状态（核心对比）

对比项 距离向量（RIP） 链路状态（OSPF）
算法基础 Bellman-Ford（邻居间迭代分布式计算） Dijkstra（各节点拿着全图本地计算）
认知视角 只知道邻居报来的距离（二手信息） 掌握全网拓扑 LSDB（一手信息）
交换对象 仅相邻路由器 **全网（区域内所有路由器）**洪泛
交换内容 整张距离表（路由表） LSA（本路由器相邻链路的状态）
交换时机 每 30s 定期 + 变化时 链路状态变化时才洪泛
度量 跳数（≤ 15，16 不可达） 代价（可配置，无跳数限制）
收敛速度 慢（坏消息传得慢、无穷计数） 快（< 100ms，无无穷计数问题）
主要代价 报文开销随规模线性增长、规模受限 每台都要跑 Dijkstra，计算与存储开销大

RIP vs OSPF vs BGP（协议三巨头对比）

对比项 RIP OSPF BGP
类别 IGP（域内） IGP（域内） EGP（域间）
算法 距离向量 链路状态 路径向量
度量 跳数（≤ 15，16 不可达） 代价（无跳数限制） 策略 + AS 路径
交换对象 仅相邻路由器 区域内所有路由器（洪泛） 相邻 BGP 发言人
交换内容 整张路由表 链路状态通告 LSA 可达路径（AS 序列）
交换时机 每 30s 定期 链路变化时洪泛 变化时增量更新
承载 UDP 520（应用层协议） 直接用 IP（协议号 89） TCP 179
适用规模 小型网络 大型网络（分区域） 互联网骨干（AS 间）
收敛速度 慢（坏消息传得慢） 快（< 100ms） 较慢（策略决策）
选路目标 跳数最少 最短路径（Dijkstra） 策略允许的可达路径

考点：记忆口诀——“RIP 小、OSPF 大、BGP 管 AS；520 UDP、89 IP、179 TCP”。

高频考点速记

考点 记忆
静态 vs 动态路由 静态：人工配置、简单开销小、不自适应；动态：自适应、复杂开销大
理想路由算法 正确完整、计算简单、自适应、稳定（收敛不振荡）、公平、最佳（相对特定要求）
距离向量核心 与邻居换整张距离表；Dx​(y)=minv​{c(x,v)+Dv​(y)}
RIP 三要点 仅邻居、整张表、30 秒（+拓扑变化及时通告）
RIP 距离 直连 = 1；非直连 = 路由器数 + 1；16 = 不可达
RIP 更新规则 先 +1、改下一跳；没有→加入；同下一跳→替换；更小→更新；否则不动；3min 未收到置 16
坏消息传得慢 无穷计数（互相抬价到 16）；水平分割、毒性逆转缓解
链路状态核心 向全网洪泛 LSA → 全网一致 LSDB → 各自跑 Dijkstra
OSPF 承载 直接封装在 IP 中，协议号 89；组播 224.0.0.5 / 224.0.0.6
OSPF 度量 代价（可配置、与带宽相关），无跳数限制；等代价多路径负载均衡
OSPF 区域 骨干区域 0.0.0.0 连通下层区域；ABR 连接区域、ASBR 连接外部 AS
OSPF 细节 Hello 10s / 40s；LSU 最核心；LSDB 30 分钟刷新；收敛 < 100ms、无坏消息问题
层次路由 AS 划分解决路由表规模 + 管理边界；IGP 域内（RIP/OSPF）、EGP 域间（BGP）
BGP 路径向量、AS 间、TCP 179、eBGP/iBGP、策略选路、不保证最短
三巨头承载 RIP = UDP 520；OSPF = IP 89；BGP = TCP 179
三种算法 距离向量换表、链路状态泛洪链路、路径向量传 AS 路径
